## 2. 发现、根因与处置

| 级别 | 发现 | 根因 | 写回后的规则 | 必须存在的回归 |
|---|---|---|---|---|
| P0 | canonicalizer 接收调用者预切 payload，G1 排除 rate/retry 无法唯一实现 | API 没有闭合 selector 的输入责任 | `canonical_config_sha256(selector,document)` 只接收完整已验证 document，投影只在 `config.py` | partial/extra payload 无入口；rate/retry 只改 full |
| P0 | tracking target/request key 仍有字符串直接拼接描述 | 把“字段有序”误当成“拼接无歧义” | target 调 C0 具名函数；request key 用规范 JSON 数组；所有组合 key 禁止裸拼接 | `("ab","c")` 与 `("a","bc")` 不碰撞 |
| P0 | SQLite/HTTP URI 规则不足以机械编码 | 只写了“规范 URI”，未定义 slash、端口和编码绕过 | 冻结 triple/four slash、userinfo/query/fragment、无 percent path、dot/重复/尾 slash、host/default-port 规则 | 合法相对 SQLite；四 slash、UNC、编码 traversal 失败；HTTP 等价 URI 同 key |
| P0 | endpoint limit 只要求正数 | 类型门禁未反查供应商截断消费语义 | 当前 7 个 endpoint 使用精确冻结值 | 每个 endpoint ±1 均失败 |

## 3. 主 Agent 追加修正

审查意见提示了“配置身份必须按真实消费者闭合”这一通用问题，主 Agent 进一步确认：

1. G1 必须有独立 `g1_config_sha256`，但 rate/max-attempts/retry-base 是纯运行政策，只进入 full；endpoint
   门禁、PIT/对账和 history 参数进入 G1，warmup/tail 另进入 snapshot。
2. `quant.data` 不得反向 import `quant.research.m3.config`。G1 stage handler 在副作用前从同一
   `LoadedM3Config` 复算；data publisher 只绑定 `config_version/g1_config_sha256`；G9 独立复算。
3. `cash_buffer` 是最低现金保留。`top_k * max_weight < 1-cash_buffer` 表示合法的额外现金，不是配置错误；
   loader 只拒绝 top-k 超过 readiness 最小截面等真实不可满足关系。
4. 配置文件 I/O 与 parser 原异常可能泄露路径/值，故新增 `CONFIG_IO_ERROR` 并禁止直接透传标准库消息。

## 4. 给实现与验收 Agent 的方法指导

- 不要从“某字段看起来像 int/float”开始写 if；先从 `_FIELD_SPECS` 证明示例键、类型、值域和 selector
  membership 是闭合的一张表。
- 不要让调用者传已经切好的 hash payload。只要调用者能挑字段，allowlist 就已经复制了。
- 验证配置值时要继续追到实际消费者：若消费者仍假定固定 60/30×20/6000，loader 就不能宣称别的值合法。
- identity 不是“把几个字符串 hash 一下”；字段边界、类型、顺序和 namespace/envelope 必须无歧义。
- “逻辑路径安全”不等于“物理路径安全”。C0 只做 URI/path grammar；root containment 与 no-symlink 留给
  StageRunner/发布器，并在验收中分别举反例。
- 全量 pytest 只能证明已有断言。独立初验必须另造 percent encoding、拼接碰撞、深层 unknown、int/float
  冒充和 selector 隔离反例。
