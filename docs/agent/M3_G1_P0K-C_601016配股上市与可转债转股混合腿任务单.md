## 1. 目标与非目标

目标：扩展既有 CNINFO rights 成功实施证明，使同一上市日还包含可转债转股时，只有在第二份正式
share-change receipt 完整闭包后才接受 rights 事件；让正式零网络候选越过
`601016.SH@2022-11-28`，并记录下一首败。

非目标：

- 不调大 `_RIGHTS_SHARE_REL_TOL/_ABS_TOL`；
- 不硬编码 601016、日期、0.3324 或残差比例；
- 不把可转债转股本身作为除权事件计入 reconciliation；
- 不处理只有增发、回购、定期报告或其他混合原因的股本行；
- HISTORY 成功前不运行 REFERENCE/PREPARE/PUBLISH。

## 3. 接受矩阵

旧严格支路保持原样：`post_total-pre_total ~= actual` 时不需要 mixed proof。

只有旧支路失败且以下条件全部成立，才尝试 mixed proof：

1. actual、pre/post total、pre/post circulating 均为正有限数；
2. total/circulating 均递增；
3. total delta 与 circulating delta 仅在 Decimal 表示等价容差内一致；
4. total delta 明确大于 actual，residual 大于表示误差；不设置业务大小阈值；
5. share response 属于同证券，request 日期范围覆盖 list date；
6. 唯一 raw row 满足：
   - `VARYDATE == rights F038D`；
   - `F003N ~= rights F025N`；
   - `F021N ~= F042N` 且 `F022N ~= F042N`；
   - code/name 按位置对齐后的 token set 恰好为
     `{015005/配股上市, 015012/可转债转股}`，顺序可交换、不得有第三原因。

不要求 share-change before row 等于 rights before。正式最近前序行是 2022-10-17，
total/circulating 均比 rights before 少 0.125 万股；强制 before-row 会错误拒绝期间持续转股。

## 4. Schema 与证据

`CorporateActionLedgerSchema` 增加 nullable：

```text
rights_pre_circulating_shares
rights_post_circulating_shares
rights_mixed_change_proof_sha256
```

`CorporateActionSelectionEvidenceSchema` 同步以上字段，并增加 nullable：

```text
rights_mixed_change_proof_json
```

分支语义：

- dividend/share-consideration：四字段全 null；
- 旧严格 rights：四字段全 null，继续要求 total delta ~= actual；
- mixed rights：两个 circulating 字段必填、双 delta 一致、total delta>actual、proof JSON/hash 必填。

proof schema 固定为 `m3-g1-cninfo-rights-mixed-change-proof-v1`，canonical JSON 至少包含：

- rights request/snapshot/stable digest；
- rights 完整 receipt、完整 response、命中 row canonical JSON 及 row SHA；
- share-change request/snapshot/stable digest；
- share-change 完整 receipt、完整 response、命中 row canonical JSON 及 row SHA；
- actual、pre/post total、pre/post circulating、两个 delta、residual 的 Decimal token；
- list date 与 aligned reason pairs。

`proof_sha256=sha256(canonical proof JSON)`。ledger 只保存 digest，完整 proof 只放 selection evidence。

## 5. 身份与独立复验

- rights event/candidate identity 必须绑定 pre/post circulating 与 proof SHA；
- ledger↔selection closure 逐字段重算；
- selection verifier 必须重建两个 receipt、完整 response content/stable digest、row membership、
  唯一匹配和全部数值/原因条件；
- candidate audit 必须把 proof 中两个 request/stable digest 与正式 `input_receipts` 双向核对；
- 仅同步重算表 digest、proof digest 或 event id 仍不能用伪造 response 替换正式 receipt。

版本至少升级：

- selection v7 → v8；
- reconciliation v8 → v9（事件集合由 no-event 变为 RIGHTS）；
- candidate/planning/reference 的精确版本传播断言同步。

## 7. 失败语义

- F041/F042、日期或 token 结构非法：
  `G1_CORPORATE_ACTION_EVENT_INVALID`；
- residual 超出表示误差但没有唯一 mixed proof、双 delta 不一致、after 不匹配、原因缺失/多余：
  新增 `G1_CORPORATE_ACTION_RIGHTS_MIXED_CHANGE_UNPROVEN`；
- proof JSON/hash、receipt/response/row membership、event/candidate 或正式 receipt closure 漂移：
  `G1_CORPORATE_ACTION_RESULT_INVALID`；
- 选择成功后 factor 仍不解释：
  `G1_CORPORATE_ACTION_FACTOR_UNEXPLAINED`。

actual<=0、post<=pre 等既有失败/未实施行继续省略，不借本任务扩大。

## 8. 强制反例

- total delta 与 circulating delta 相差一个最小表示单位；
- residual=0 或仅是序列化误差：必须走旧严格支路；
- residual<0；
- share total 匹配但 F021/F022 任一不匹配；
- 原因只含配股或只含可转债，或多出定期报告/回购；
- code/name 数量、位置或配对错位；
- 两条同日同 post 的可匹配 share rows；
- VARYDATE 与 list date 差一天；
- 正确 row 来自另一证券/request；
- 篡改任一完整 receipt、response、row、row SHA、stable digest 或 proof SHA；
- 只改 proof 时 event_id/candidate_id 必须变化；
- 不传 proof 时正式 601016 必须报 MIXED_CHANGE_UNPROVEN，不得静默省略；
- 另一证券、另一正 residual 的合成正例也能通过，证明无证券/数值特判。
