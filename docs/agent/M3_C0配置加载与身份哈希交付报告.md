### 2.2 稳定接口

```python
@dataclass(frozen=True, order=True)
class ConfigIssue:
    code: str
    dotted_path: str
    message: str

class M3ConfigError(ValueError):
    issues: tuple[ConfigIssue, ...]

@dataclass(frozen=True)
class LoadedM3Config:
    document: Mapping[str, object]
    config_version: str
    full_config_sha256: str
    g1_config_sha256: str
    snapshot_config_sha256: str
    provider_config_sha256: str
    scientific_config_sha256: str
    provider_validation_config_sha256: str
    label_reconciliation_config_sha256: str
    acceptance_config_sha256: str
    canonical_tracking_uri: str
    tracking_target_key: str

    def section(self, name: str) -> Mapping[str, object]: ...

def load_m3_config(path: Path) -> LoadedM3Config: ...
def canonical_config_sha256(
    *, selector: ConfigSelector, document: Mapping[str, object]
) -> str: ...
def canonical_tracking_target_key(
    *, tracking_uri: str, experiment_name: str
) -> str: ...
```

`load_m3_config` 只接受可读普通 UTF-8 TOML 文件；I/O、解码和 parser 原异常被转换为不含物理路径或原值
的 `CONFIG_IO_ERROR/TOML_PARSE_ERROR`。可独立判断的字段错误一次收集并按
`(dotted_path, code, message)` 排序。`canonical_config_sha256` 对 direct caller 的完整 document 复用同一
validator，不接受调用者预切 payload。成功 document 递归转换为 `MappingProxyType`、tuple 和不可变标量；
日期保留 `datetime.date`，规范 tracking URI 写回只读 document。

新增反例包括：未知根/深层键、缺键、bool 冒充 int、int 冒充 float、空字符串、NaN/Infinity、array
元素非 finite、datetime/time 冒充 date、重复 TOML key、错误日期、不可读/非普通文件、错误稳定排序、
任意深度突变和异常脱敏。

## 3. C0B：字段闭包与跨字段不变量

`config.py` 的唯一 `_FIELD_SPECS` 含 138 个 normalized shape；每项记录 required/optional、strict kind、
literal/range 和 selector membership。生产测试从 `LoadedM3Config.document` 枚举真实示例，确认 151 个
assignment、138 个 shape 与 `_FIELD_SPECS` 精确相等，唯一 optional shape 是末期费用
`effective_to`。未在测试中维护第二份 allowlist。

已覆盖的跨字段/业务反例：

- 固定 `(5,10)` horizon、embargo、label tail、train readiness、step/test 不重叠；
- required/provider fields 精确有序契约；
- `top_k <= minimum_cross_section_symbols <= expected_constituent_count`，同时验证容量不足时额外现金合法；
- coverage、IC 最小证券数、provider gap 和标签容差层级；
- 费用期首覆盖、自然日连续、无重叠/逆序、末期必须 open-ended，五个费用数值字段 exact float；
- friction multiplier、七个 endpoint limit、300 成分、30×20 抽样、60-session warmup 的冻结 literal；
- LightGBM learning rate、fraction、seed、depth、rounds/early-stop/min-delta 等类型和值域关系；
- unknown `api-token`、Bearer/`token=` 大小写、percent encoding、POSIX/Windows/UNC 绝对路径和控制字符。

## 4. C0C：规范化与九类身份

所有 config hash 使用固定 envelope：

```text
{"hash_version":"m3-config-hash-v1","selector":"<name>",
 "config_version":"1.0.0","payload":<内部投影>}
```

序列化固定为 UTF-8、sorted-key、compact JSON、ISO date、保留 array 顺序、拒绝 non-finite，并将 `-0.0`
归一为 `0.0`。所有 digest 是 64 位小写裸 hex，无 `sha256:` 前缀。tracking target 单独使用规范 URI 和
experiment name 的无歧义 JSON envelope，不绑定 config version，不保存 URI 明文。

合法可变字段已做真实运行时 hash 差分：

| 变体 | 实际改变的 identity |
|---|---|
| tracking URI | full、tracking-target |
| acceptance coverage | full、acceptance |
| label reconciliation tolerance | full、label-reconciliation |
| G1 reconciliation tolerance | full、G1 |
| G1 label tail | full、G1、snapshot |
| G1 retry base | 仅 full |
| data start date | full、snapshot、scientific |
| cost period rate | full、scientific |

注释、空白和 TOML 键顺序不改变任何 identity；HTTP(S) scheme/host 大小写和默认端口规范为同一 target；
SQLite 第四 slash、userinfo/query/fragment、percent-encoded separator/dot、重复/尾 slash、Windows drive/
UNC 均 fail-closed。

冻结 literal 的传播证据按主 Agent 裁决分两部分：`_FIELD_SPECS` 精确断言 selector membership，并断言
变体被公开 canonical API 拒绝；没有为制造 hash 差分而放宽 validator，也没有暴露 trusted helper。覆盖
provider sample、provider fields、Qlib version、dump SHA/supported-python、universe、warmup 和 endpoint
limit。

## 6. 实现中发现的问题与反馈闭环

### 6.1 冻结 literal 与运行时 hash 变体冲突

- 现象：C0C 要求对 provider sample、Qlib version、dump spec、universe/source、warmup、endpoint limit
  做“只改字段后的 hash 差分”，但 4.0.1 同时要求这些值在 `1.0.0` 精确冻结，且变体必须由公开 API 拒绝。
- 根因：变化传播矩阵描述跨 config version 的结构边界，而 strict canonicalizer 只允许当前 config version
  的合法 document；两者被写成同一种运行时测试。
- 应遵循规则：不得放宽 `1.0.0` literal，不得让 caller 预切 payload或调用 trusted helper。
- 最小复现：把 `validation.provider.sample_symbols` 从 `3` 改成 `4` 后调用
  `canonical_config_sha256`；预期是 `VALUE_ERROR`，因此没有合法 hash 可比较。
- 新增测试：合法可变字段做真实 hash 差分；冻结字段断言唯一 `_FIELD_SPECS` membership，并断言公开 API
  拒绝变体。
- 通过条件：当前版本 validator 保持 fail-closed；若未来需要运行时比较冻结字段，先由主 Agent 升级配置
  版本和 SSOT 合法域，再测试新版本，不在 C0 私自放宽。

### 6.2 `api-token` 规范化漏项

- 现象：首轮对抗测试中 unknown `api-token` 只产生 `UNKNOWN_KEY`，未同时产生 `SECRET_VALUE`。
- 根因：键规范化正确得到 `api_token`，但初版敏感集合只含 `token/api_key`，没有覆盖任务书点名的
  `api-token` 变体。
- 应遵循规则：安全扫描必须先于 unknown-key 丢弃，hyphen/underscore/case 规范化后的点名变体必须有
  回归测试。
- 最小复现：在任意未知 table 加入 `api-token = "plain"`。
- 新增测试：unknown `api-token`、Bearer authorization、Windows/UNC/encoded absolute path 在同一配置中
  同时检查 `SECRET_VALUE/UNSAFE_PATH/UNKNOWN_KEY`。
- 通过条件：`api-token` 同时产生 sanitized `SECRET_VALUE` 与 `UNKNOWN_KEY`，message/repr 不回显值。
