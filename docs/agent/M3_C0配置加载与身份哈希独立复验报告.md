## 2. 四个返工问题逐项关闭

| 初验问题 | 复验证据 | 结论 |
|---|---|---|
| P1-1 I/O/TOML 异常链泄露 | 缺失文件仍稳定产生唯一 `CONFIG_IO_ERROR`；无 `__cause__/__context__`，formatted traceback 不含物理路径。非法 TOML 仍稳定产生唯一 `TOML_PARSE_ERROR`，traceback 不含输入 sentinel | 关闭 |
| P1-2 percent-encoded 敏感键漏扫 | `%74oken`、额外的三层 `%252574oken` 均同时产生 `SECRET_VALUE + UNKNOWN_KEY`；合法固定 dump SHA、普通 tracking URL 和 unknown 普通 URL 均未被安全扫描误杀 | 关闭 |
| P1-3 loader/direct tracking 安全域分叉 | absolute experiment name 两入口均拒绝；合法 `research/token-study/v2` 经真实临时 TOML loader 与 direct helper 得到相同 `tracking_target_key` | 关闭 |
| P2-1 mapping key 提前 coercion | 非字符串键产生 `TYPE_ERROR`；整数 `1` 与字符串 `"1"` 同时存在时分别保留 `TYPE_ERROR config` 与 `UNKNOWN_KEY 1`，未合并、未碰撞；非法键下的 secret child 仍被扫描 | 关闭 |

静态审查确认修复保持最小范围：

- `load_m3_config` 在私有读取/解析函数返回 sentinel 后才构造公开错误，底层异常不跨边界；
- `_controlled_percent_decode` 被敏感键、敏感值和路径扫描共同复用；
- `_validate_safe_string` 被 loader 递归扫描与 direct tracking helper 共同复用；
- `_thaw` 保留原 key，`_iter_assignment_leaves` 先检查原生字符串类型；后续 normalize/freeze/JSON 只做类型
  cast，不做字符串 coercion；
- selector、literal、九类 identity、snapshot/fetcher 接口未借返工重构。
