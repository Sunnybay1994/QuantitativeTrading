## 2. F1 — 查重前重新自证所有输入

`reduce_order` 在任何 `event_id` membership/no-op 判断之前必须：

1. 重新执行 `OrderAggregate` 当前结构与跨字段验证，关闭构造后被 `object.__setattr__` 破坏的对象；
2. 使用 D0 公开 verifier 重新验证 `command.intent` identity，再验证 command identity；
3. 使用 D0 公开 verifier 按 event 当前 payload 重算并验证 event identity；
4. 完成上述自证后，才允许相同合法 event id 返回原 aggregate。

不得复制 D0 哈希算法或另造第二套 canonical payload。verifier/属性访问抛出的普通合同异常统一映射为稳定
`OmsError`，使用 `from None`，不得回显被篡改字段、路径或原异常文本；不捕获 `BaseException`。

## 3. F2 — 保持既有语义

- 未篡改的同一合法 event 重放仍为 no-op，返回同一 aggregate 对象，不改变 `last_event_at`；
- 已通过的聚合状态、时序非递减、command quantity 和 broker id 单次绑定语义全部保留；
- 不新增 aggregate identity、serializer、store 或 event registry，不扩大为 P5 recovery。

## 4. 必须新增的测试

1. 已应用 event 用 `object.__setattr__` 改 broker id、occurred_at、cumulative quantity、fees 中至少三类，保留旧
   event id，再重放均 `OmsError`，不得 no-op；
2. 篡改 command 内嵌 intent 内容、保留 intent/command id，reducer 在状态处理前拒绝；
3. 篡改 aggregate 为结构非法状态，即使 event id 已在集合中也拒绝；
4. 合法 duplicate 仍返回原对象；合法不同 event 仍按现有状态机推进；
5. 异常 `__cause__ is None`，message/repr 不包含注入 payload。
