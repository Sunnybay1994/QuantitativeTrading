## 4. Schema / 事务 / 唯一约束 / Migration 映射

| 机制 | 实现要点 |
|---|---|
| Schema version | 单行 `schema_version(singleton=1, version, status∈{ready,migrating})`；binary `CURRENT_SCHEMA_VERSION=1` |
| Migration | `MIGRATIONS=[(1, upgrade_v001)]`；升级前标 `migrating`，成功后 `ready`；`migrating` 残留或未知更高 version fail-closed |
| 事务 | open/migration 与 `transaction()` 均 `BEGIN IMMEDIATE`；异常 `ROLLBACK` |
| 唯一约束 | 各业务表 `PRIMARY KEY`；应用层 `_put_row` 先比 identity+payload 再 INSERT |
| 缺口 | `_put_row` **不比较** `extra_columns`（events.`command_id`），故「同 PK 异附属列」被当成幂等 no-op |

## 5. 新增对抗反例（实现者未用）

### 5.1 主反例（阻塞）：同 event_id，异 command_id

- **脚本**：`/tmp/m4_p0_adversarial_verify.py`（A3）
- **手法**：先 `put_event(event_id=evt-a3, command_id=cmd-old, identity=eid, payload=b"body")`；再同 id/identity/payload 但 `command_id=cmd-new`
- **观察**：无 `IdempotencyConflict`；`put` 返回 `False`；SELECT 仍为 `cmd-old`
- **判定**：**fail-closed 被破坏**（同 unique key 下 durable 行不一致却静默 no-op）

### 5.2 补充对抗（均 PASS，实现者测试未见或弱于本脚本）

| 反例 | 期望 | 结果 |
|---|---|---|
| 同 command_id、同 payload、异 identity | `IdempotencyConflict`；无路径 | PASS |
| 同 command_id、同 identity、异 payload | `IdempotencyConflict` | PASS |
| 未知更高 schema / migration 中断消息无 `/` | 稳定 code、无路径 | PASS |
| 非法 URI / 以目录当 DB → `OPEN_FAILED` 无路径 | 无绝对路径泄露 | PASS |
| Store/Repo 无 SQL hatch | 无 `execute` 等公开出口 | PASS |
| 空 key / 空格 / `a/b` / 中文 key | `StoreError` | PASS |
| 双连接 writer `BEGIN IMMEDIATE` | 两命令均持久化、无错误 | PASS |
| SQL 层重复 PK | `IntegrityError` | PASS |

说明：`sqlite:////abs/...` 可打开属 store 设计（与 C0 配置拒绝对绝对 URI 不同）；P0 反例要求的是**错误消息不泄露路径**，非禁止绝对 URI。

## 6. 发现问题（返工）

### P0-1（阻塞）

| 项 | 内容 |
|---|---|
| 现象 | 同 `event_id` + 同 identity/payload、异 `command_id` 时 `put_event` 幂等 no-op，不冲突、不更新 |
| 根因 | `_put_row` 仅比较 `identity`/`payload`，忽略 `extra_columns`（`command_id`） |

| 新增测试（实现侧） | `put_event` 同 event_id、异 command_id → `IdempotencyConflict`；消息无绝对路径 |
| 通过条件 | 上述冲突抛出；其它表回归仍绿；定向 pytest/ruff/mypy 通过 |
