# M4-B6 统一事件回测任务单

只实现纯内存事件编排：场景各自从同一初始账户开账，按 verified session 推进 B5 结算，盘前处理 G7C
recognize/settle，调用 B1/B2 规则与 B3 成本产生 PAPER 事件，收盘 capture 公司行动。禁止 IO、网络、估值、
报告、持久层、Gateway 和复制既有公式。

公开入口为 `simulate_order_plans(plans, snapshots, initial_account, config)` 与完整重放 verifier。`plans` 是
scenario-specific typed stream；后续 plan 必须绑定该场景当前 ledger 对应的账户快照。开发验证不表示正式
G1、Linux/ext4 或 PAPER/SHADOW Gate 通过。

## P1 返工冻结

- `ScheduledOrderPlan.session_date` 纳入 schedule identity；snapshot、全部 intent、close 与 fill 必须属于同一
  session。周五 plan 不得把 close/fill 延伸到周一；下一 session 必须使用新的 snapshot/plan。
- 所有外部对象重验和公司行动异常必须先退出 `except` 再映射为稳定 `EventSimulationError`；错误不得回显
  路径、TOKEN 或 hostile payload，且 `__cause__`、`__context__` 必须均为 `None`。
- 必测反例：Friday plan + Monday fill/close、hostile corporate-action validator，以及篡改嵌套 plan identity。
