## 1. 目标

在不复制大体量数据到 Git worktree 的前提下，建立一套面向个人投研的 Tushare 数据闭环：

1. 第一次运行识别当前 Token 可访问的批量结构化接口，并获取这些接口的完整公开历史；
2. 后续运行只抓取新增、修订或需要重叠复核的数据；
3. 所有供应商响应先写不可变 raw，再由明确 Schema 和质量门禁晋升 clean；
4. 支持限频、断点续传、幂等重放、失败重试和请求级审计；
5. 投研 worktree 只读共享 clean 数据，不拥有或复制数据真源；
6. 存储格式必须支持列裁剪、过滤下推、分区读取和后续跨工具复用。

## 2. 范围定义

本任务中的“全量”指：

> 在一次版本化权限探测时点下，当前账号可访问的全部批量结构化历史接口、全部目录中声明的字段和全部公开历史。

以下数据必须单列计划，不能与普通日频初始化混跑：

- 历史分钟、Tick 与实时流；
- 新闻、研报、公告 PDF 或长文本；
- 需要单独商业授权的港美股或特色数据；
- 当前投研资产范围之外的期货、期权、外汇等大类数据。

它们仍进入权限目录，但只有在计划给出可接受的请求量、容量和授权状态后才允许启动历史回补。

## 3. 权威边界

- Token 仍只存在于 Git 忽略的 `configs/tushare.local.toml`；worktree 不复制 Token。
- `quant.data` 是共享 `data/` 的唯一生产写入层。
- `quant.strategies` 和 `quant.factors` 只消费注入或受控读取的 clean 数据，不联网、不写 raw/clean。
- raw 不覆盖；clean 是经过 Schema、单位换算、唯一键和 PIT 规则验证的可重建派生层。
- 账户核算继续使用不复权行情；复权或总回报序列只用于研究。
- 财务数据必须保留公告时间、报告期、修订标识和抓取时间，不能只保留“最新一条”。

本工作树原交接将 `src/quant/data/` 设为默认只读。用户于 2026-08-14 明确要求本 session 先建设全量数据，
因此本任务获得一个窄例外：只允许为共享数据根、Tushare 目录/探测/规划/采集闭环修改 `quant.data` 及其直接
测试和文档；策略本身仍不得直接下载数据。

## 4. 物理架构

```text
F:\AI_Coding\QuantitativeTrading\data\
├─ raw\
│  └─ tushare\
│     └─ {dataset}\
│        └─ request={request_id}\
│           ├─ data.parquet
│           └─ metadata.json
├─ clean\
│  └─ {dataset}\
│     └─ {partition_key}={value}\
│        └─ part-*.parquet
├─ run_state\
│  └─ tushare_bulk\
│     ├─ permission-report.json
│     ├─ request-plan.json
│     └─ state.sqlite
└─ catalog\
   ├─ dataset-manifest.json
   └─ query.duckdb
```

### 4.1 存储职责

- **raw Parquet**：供应商字段原样保存；每个确定请求独立且不可覆盖；旁车 JSON 记录 endpoint、参数、字段、
  UTC 抓取时间、行数、SHA-256 和目录版本。
- **clean Parquet**：领域类型、单位、业务键、PIT 和数据质量验证通过后的标准表。
- **DuckDB**：直接查询 Parquet，数据库文件只保存可重建视图和目录元数据，不成为数据真源。
- **SQLite**：只保存任务状态、租约、cursor、重试和 checkpoint，不承载大规模行情。

### 4.2 分区原则

| 数据类型 | 推荐 clean 分区 |
|---|---|
| 日频全市场行情、每日指标、资金流 | `year=YYYY`，必要时按季度 |
| 财务报表 | `report_year=YYYY` |
| 公告/公司行动/股东事件 | `ann_year=YYYY` |
| 分钟行情 | `year=YYYY/month=MM` |
| 静态主表 | 当前快照 + 有效期历史 |
| raw | 每个确定请求单独留档 |

不得为新增大表机械沿用“一天一个极小 Parquet”。活动分区允许受控重写；封闭历史分区保持不可变；达到小文件
阈值后执行显式 compaction。

## 5. 接口目录与权限探测

不对 Tushare SDK 做无约束反射。项目维护版本化显式目录，每项至少包含：

- 数据集名、Tushare `api_name`、资产类别和优先级；
- 最小安全探测参数；
- 历史切分轴和最大返回行数；
- 业务键、PIT/修订语义、分区策略；
- 首次初始化策略和增量 overlap；
- 是否需要独立权限或是否暂不支持自动回补。

权限探测只执行每项一个最小请求，并稳定分类：

- `ACCESSIBLE`
- `PERMISSION_DENIED`
- `RATE_LIMITED`
- `EMPTY_BUT_VALID`
- `PARAMETER_INVALID`
- `PROBE_FAILED`

空结果不能当作无权限；权限错误不能自动重试；报告不得包含 Token、完整响应或可还原凭据。

## 6. 第一次全量算法

```text
加载目录
  → 执行最小权限探测
  → 固化 permission-report
  → 生成精确请求计划与资源估算
  → 用户/任务状态允许长运行
  → 有界并发请求
  → 请求级不可变 raw
  → 行数上限/分页完整性检查
  → Schema 与质量门禁
  → 发布 clean 分区
  → 更新 checkpoint 与 manifest
```

要求：

1. `request_id` 绑定目录版本、数据集、API、规范化参数和字段集合；
2. 同一 `request_id` 已完整存在时只验真，不再次联网；
3. 返回行数等于接口上限时必须分页或继续切分，禁止假定完整；
4. 网络/服务端临时错误使用有上限的指数退避；权限和参数错误不重试；
5. raw 成功而 clean 失败时保留 raw，可离线重处理；
6. checkpoint 只在 raw 和该阶段必要验证成功后推进；
7. 一个数据集失败不得破坏其他已经提交的数据集；恢复时不得产生第二个并发写者。

## 7. 增量策略

| 类型 | 增量方式 |
|---|---|
| 日行情、每日指标、资金流 | 每个交易日全市场请求；回看最近 3～5 个开市日 |
| 复权因子、涨跌停、停牌 | 每日请求；公司行动附近扩大 overlap |
| 股票、基金、合约主表 | 周期性全快照并生成有效期差异 |
| 财务报表、指标、预告、快报 | 按公告日期更新，回看 60～120 天，保留修订版本 |
| 分红、回购、股东、质押等事件 | 按公告日期增量，业务键幂等合并且不丢历史版本 |
| 指数/行业成分 | 按生效区间保存，不用当前成员覆盖历史成员 |
| 基金净值和持仓 | 净值按日期 overlap；持仓按报告期和公告时间更新 |

## 8. 资源控制

本任务主要受网络和接口限频约束，GPU 不参与采集。默认资源预算：

- 请求 worker：4；
- Polars/Arrow 线程：4～6；
- 每个共享数据根只有一个 clean 写入者；
- 目标请求速率不超过官方额度的 60%～70%；
- Parquet 使用 Zstd 和统计信息；
- 全量运行前必须生成请求数、预计时长和预计容量，不盲目启动。
