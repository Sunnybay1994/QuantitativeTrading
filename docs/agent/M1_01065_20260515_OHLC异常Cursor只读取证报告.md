## 2. 推断（与事实分开）

**I-1（高可信，非官方证实）：** 提示中的 Tushare 四值不是孤立坏字节。至少 Webb-site 以同一 Close/Low/High/Volume 模式存储该日；Yahoo 在 Close/Low/Volume/Open 上一致，仅把 High 包络到 Close。更合理的分类是 **供应商是否把收市价滚进 Day High**，而不是 Tushare raw 独有损坏。

**I-2（机制可解释，当日成交未证）：** `close = high + 1 tick` 落在 CAS Stage-1 ±5% 之内（相对 4.38 约 0.23%，远小于 5%）。这与“CTS 区间 high/low + CAS IEP 作为 close、部分供应商未更新 high”相容，也与 R0 已接受的“开盘 IEP 落在供应商 high/low 外”对称。Yahoo 的 High=4.390 更接近 HKEX Day High“含 auction matching”的字面定义。

**I-3（不可升级为事实）：** 下列任一机制都能产生同一数字，公开源无法区分：

1. CAS IEP=4.39，CTS 成交最高=4.38，供应商 high 停在 CTS；
2. 官方 Day High 因 “non-direct only” 排除了全部 Direct CAS 成交，官方 high 真为 4.38；
3. 供应商用收市卖一/名义价当作 close，未同步 high。

没有 Sales Records / Daily Quotations，**不得**把 (1) 写成已核实的当日成交路径。

**I-4：** `01065` 作为主板普通股，按 2019-10-08 产品类型规则 **应当** CAS eligible。本轮未下载 2026-05-15 Full List of Securities 的 CAS Eligible 标志，故“该日该代码一定参加了 CAS 撮合”仍是推断。

**I-5：** Webb-site 的 Bid=4.370 与 Tushare/Yahoo Open=4.37 数值相同，**不能**把 Bid 当成 Open。Open 的第二来源只有 Yahoo。

## 3. 四个重点问题

### 3.1 是否 raw 损坏或供应商口径差异？

**结论：优先供应商口径差异；“Tushare 独有 raw 损坏”证据不足。官方 high `INSUFFICIENT`。**

支持口径差异：

- 两家公开源锁定 close/low/volume；
- Tushare high 与 Webb-site High 对齐，且 Webb-site 自己就允许 Close>High；
- Yahoo 做了包络归一化；
- Tushare 文档未定义 high 是否含 CAS；
- 这与已验收的 R0 开盘竞价口径问题同类（供应商 high/low 与竞价价分列）。

反对“已证明是 CAS 成交”：缺 HKEX 当日 quotations/sales；404。

### 3.2 能否安全扩展 HK-only canonical high/low 以包含 close，仍保留 raw？

**结论：结构可做，但不能叫“安全通配”；必须先改 R0 合同。**

可保留的安全边界：

- 只改 `TushareBarMapper`，`_market == HK`；
- raw 四字段原样保留；
- **不**放宽跨市场 `Bar1dSchema`；
- 扩展后的 canonical 仍须满足 `low <= open/close <= high`。

不可忽视的风险：

- 现测试把 HK `close>high` 当作必须失败的反例；R0 明文禁止修正港股 close 越界。扩展 = 合同变更，不是 bugfix。
- 无官方 high 时，无界 `max(high, close)` 会把 `close=10.00` 这类错数修成合法。
- 若官方 high 其实是 4.38 且 4.39 不是非直接自动撮合价，扩展会把错误 close 写进 clean high。

因此：**仅在增加偏离上限、并显式废止/改写 R0 close 反例之后**，才可考虑与 open 包络对称的 HK-only 扩展。本轮只读取证，不实现。

### 3.3 是否影响策略/实盘？

**结论：对收盘计价与下单价影响很小；对 range 类因子和该键能否进入 clean 有影响。不得用 UA-M1-001 口径一笔带过。**

事实层：

- 当前 mapper 不扩展 close → Schema 拒绝 → 该 `symbol×date` 进不了 `Bar1dSchema` clean（HK60 回填 / bulk clean 会 fail-closed 或 quarantine）。
- 若扩展：clean `close` 仍为 4.39，`high` 从 4.38 变为 4.39；开盘不变。
- 项目默认 `auto_trade = false`。
- `01065.HK` 属于 HK60 历史回填目标集合（与 2026-05-05 无交易案同一代码，但是**不同日期、不同语义**）。

推断层：

- 用次日 open / 当日 close 的信号与账户盯市：绝对价格差 0；
- 用 `(high-low)`、`HIGH0`、K 线实体/振幅的因子：该日振幅相对变化约 33%（0.03→0.04），绝对值仍只有 1 个价位；
- 实盘限价/涨跌停（港股无 A 股式涨跌停，CAS 另有 ±5%）不由 clean daily high 单独决定。

**不能**声称“不影响任何策略”。只能声称：没有证据表明它会改变以 close/open 为输入的下单价；它会改变该日 high 与振幅，也会改变该键目前被 Schema 丢弃还是保留。

## 4. 建议的最小 fail-closed 规则

若主 Agent 决定改合同，建议最小集合如下（比“无界包含 close”更紧，比“永远拒绝 close 越界”更窄）：

1. **仅** `TushareBarMapper` 且 `_market == HK`。A 股、其他 mapper、其他市场不扩展。
2. **不写 raw**。供应商 `open/high/low/close/vol/amount` 保持原值。
3. **不改** `Bar1dSchema.ohlc_valid`。
4. 前置：全部 OHLC 有限且为正；`raw_high >= raw_low`。
5. 前置：`raw_open` 已在 `[raw_low, raw_high]`（本例满足）。open 也越界时走既有 R0 规则或单独的联合规则，不在本条偷偷合并。
6. 仅当 `raw_close` 落在原区间外、且相对原区间的偏离不超过 **CAS Stage-1 5%**（参考价建议用 `raw_high` 与 `raw_low` 的中点，或 `raw_open`；须在任务书冻结一个）。本例 0.01/4.365 ≈ 0.23% << 5%。
7. 建议附加：偏离必须是当时有效价位的整数倍。2026-05-15 在 HK$0.50–10.00 为 0.010；2026-08-03 后该区间为 0.005。价位表必须有有效期，禁止写死单一 tick。
8. 满足后：`canonical_high = max(raw_high, raw_close)`，`canonical_low = min(raw_low, raw_close)`。
9. 下列继续硬失败：`high < low`；非正/非有限价格；A 股任何 OHLC 越界；港股 close 偏离 >5%（或非整数价位）；缺少 `_market`。

**不要**用“1 个 tick 通配”作为唯一上限：真实 CAS 允许相对 Reference Price ±5%，1 tick 过窄会漏掉合法 CAS，5% 无其它约束又过宽。两者应同时存在：5% 防损坏，价位整数防脏小数。

## 5. 建议回归反例（实现者当前测试未覆盖 close 包络）

正向（扩展后 Schema 应通过，且 raw 不变）：

- **本例：** HK `4.37 / 4.38 / 4.35 / 4.39` → clean high=`4.39`，raw high 仍 `4.38`。
- **close 低于 raw low、open 仍在区间：** 例如 HK `3.00 / 3.06 / 2.92 / 2.90` → clean low=`2.90`。
- **R0 回归不得破坏：** HK `3.08 / 3.06 / 2.92 / 2.96` → clean high=`3.08`，raw high=`3.06`。

负向（必须仍被 Schema 拒绝）：

- **保留 R0 A 股：** SZ `open=10.6, high=10.5, low=9.8, close=10.2`。
- **保留 `high < low`：** HK `3.00 / 2.90 / 3.10 / 3.00`。
- **损坏 close，超出 5%：** HK `4.37 / 4.38 / 4.35 / 10.00`。
- **A 股 close>high：** 不得因“看起来像港股 CAS”而扩展。
- **非正 close。**
- **open 与 close 同时越界且其一超 5%：** 禁止用一次 `max/min` 把两套未知错误洗成合法。

若采纳 close 包络，现有参数化测试里的 `("HK", 3.00, 3.06, 2.92, 3.08)` **不能**再作为无条件失败反例；应改成“小偏离通过 / 大偏离失败”一对，并在任务书里写明废止 R0 的 close 硬失败句。

## 6. 与 UA-M1-001 / R0 的边界

- 本对象是 `01065.HK@2026-05-15` 的 OHLC 包络，**不是** `01065.HK@2026-05-05` 无交易。两日不可共用例外规则。
