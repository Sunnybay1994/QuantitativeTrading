## 1. 目标与通过条件

基于 P0K-A-REAL1 的正式 CNINFO 双端点 raw 闭包，新增可复用的股份对价语义，使：

1. 600733 的原始 `10送5` 以 `SHARE_CONSIDERATION` 进入 ledger，raw ratio 保持 `0.5`；
2. 事件由停牌合同从 2018-08-23 延迟到 2018-09-27 后，只在 reconciliation 中以
   `0.5/3.5` 计入；
3. 3.5 必须由正式 share-change 总股本、流通股以及期间已选送转链三方一致证明；
4. 2018-09-19 只计既有 Tushare 转增 `2.5`，CNINFO `股改分红` 不重复入账；
5. 正式零网络 HISTORY 越过该首败，再记录下一首败，不提前启动 REFERENCE。

## 2. 权威字段和日期合同

只处理 `stock_dividend` 中 `F044V` 精确等于 `承诺补偿` 的记录：

- `F010N > 0`；
- `F011N/F012N` 为 null 或 0；
- `F007V` 完整匹配 `10送X股`，且 X 与 `F010N` 精确一致；
- `F006D` 为公告日，`F018D` 为登记日；
- 不要求正式记录中为 null 的 `F001V`；
- `股改分红`、年度分红、中期分红等不进入新选择器。

实施日只能来自同证券 `stock_share_change`。候选行拆分后的原因码/名称 token 必须精确对齐并
包含 `015020/股权分置`，且 `VARYDATE >= F006D`。事件与股本行只有唯一完美匹配时接受；
零个或多个匹配均 fail-closed。

ledger 日期固定为：

- `record_date=F018D`；
- `ex_date=VARYDATE`；
- `stock_list_date=VARYDATE`；
- `pay_date=null`。

这里的 `ex_date` 是特殊 action 的生效日，不宣称为 CNINFO 原始除权日。

## 3. Ledger、去重与事件身份

新增 `action_type="SHARE_CONSIDERATION"`：

- `cash_dividend=0`；
- `stock_ratio=F010N/10`，保留原始比例；
- rights 字段全空/零；
- `stock_list_date` 必填且等于特殊 action 生效日。

ledger 与 selection evidence 必须 event_id 一一闭包，事件身份包含 action type、来源、证券、
登记日、生效/上市日、raw ratio 及正式 lineage。

跨源规则：

- 非 `承诺补偿` CNINFO dividend 永不进入该路径；
- 若 Tushare 已有证券、登记日、实施/上市日、原始比例完全相同的股份对价，保留 Tushare event，
  CNINFO 只补语义和归一化证据；
- 日期或比例冲突报 `G1_CORPORATE_ACTION_VERSION_CONFLICT`，不相加、不平均、不按 factor 反推。

## 4. 基数归一化合同

ledger 始终保留 raw ratio。`_assign_events_with_suspension_resume_delay` 完成有效日迁移后，
reconciliation 才计算：

```text
basis_multiplier =
  after_total_shares / before_total_shares
  = after_circulating_shares / before_circulating_shares
  = product(selected whole-share stock-event multipliers)

effective_stock_ratio = raw_stock_ratio / basis_multiplier
```

同日多腿 multiplier 为 `1 + sum(stock_ratio)`，跨日为乘积。计算内部使用 `Decimal`；
只在 Schema Float64 边界转换。

600733 的证据必须重算得到：

```text
basis_multiplier=3.5
raw_stock_ratio=0.5
effective_stock_ratio=0.5/3.5
relative_error((1+0.5/3.5), 9.36/8.192) < 0.001
```

8 月 23 日股本行同时包含增发与股权分置，只用于实施日期和基数快照；不得从总股本增量反推 0.5。

## 5. 可审计证据

`CorporateActionReconciliationSchema` 增加 canonical：

- `stock_ratio_terms_json`
- `stock_ratio_terms_sha256`

每个 term 至少包含：

- event_id、raw/effective ratio、basis multiplier；
- basis_from_date、basis_to_date；
- before/after total shares、before/after circulating shares；
- share-change request_id、snapshot_id；
- 两个 canonical raw-row SHA256。

普通事件 multiplier=1。reconciliation 行的 `stock_ratio` 必须等于所有 term 的
effective ratio 之和。候选审计必须把 term 与 ledger event、selection evidence、正式 receipt、
request/snapshot 双向核对；仅验证 JSON 自身摘要不够。

## 6. 失败语义

- 字段、日期、数值或 `10送X股` 不一致：
  `G1_CORPORATE_ACTION_EVENT_INVALID`；
- 无唯一基数证明、总股本/流通股倍数不一致、期间存在未解释股本变化、与已选送转链不一致：
  `G1_CORPORATE_ACTION_BASIS_UNPROVEN`；
- 同一经济事件跨源冲突：
  `G1_CORPORATE_ACTION_VERSION_CONFLICT`；
- 归一化后仍不解释 factor：
  `G1_CORPORATE_ACTION_FACTOR_UNEXPLAINED`；
- term、摘要或 ledger/receipt 闭包漂移：
  既有 reconciliation/result invalid 错误。
