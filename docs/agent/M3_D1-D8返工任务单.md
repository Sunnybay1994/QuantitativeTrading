## 3. R1：修复 D1 readiness

### 3.1 必须保持的接口

```python
def audit_m3_readiness(
    *,
    bars: pl.DataFrame,
    instruments: pl.DataFrame,
    membership: pl.DataFrame,
    calendars: pl.DataFrame,
    benchmark_bars: pl.DataFrame,
    config: Mapping[str, Any],
) -> list[ReadinessIssue]: ...
```

### 3.2 必须实现

- 从 `config[data]` 读取 `start_date/end_date`，对 TOML 传入的 `date`、ISO 字符串做明确解析；类型
  非法返回结构化配置 `ERROR`。
- 基于区间内 SH 开市日生成稠密的逐日审计，未出现在 bars 中的开市日也必须以 0 覆盖计入。
- 每日只统计当日生效 PIT 成员中的有效行情；任意一日低于阈值即返回
  `CROSS_SECTION_TOO_SMALL`，message 包含最小值、阈值和受影响日数。
- `HISTORY_TOO_SHORT` 使用“截面达标 + 基准有效 + 开市”的可训练 session 数，不使用全日历高度。
- PIT 成员覆盖按 symbol 检查：任一成员在其与配置日期相交的整个生效区间没有有效行情，
  返回 `PIT_BAR_COVERAGE_EMPTY`。
- 字段错误不得使整个 audit 抛出 Polars 异常。依赖字段不足的检查应跳过，已生成的
  missing-field `ERROR` 保留。
- 保持结果排序 `severity,code,message`。

### 3.3 必须新增的测试

1. 两个开市日截面为 2/1，阈值 2，必须返回 `CROSS_SECTION_TOO_SMALL`。
2. 日历有 756 日但只有 10 个可训练 session，必须返回 `HISTORY_TOO_SHORT`。
3. 配置区间外有大量日历，区间内历史不足，不得被区间外数据补足。
4. PIT 成员 A 有行情、成员 B 整段无行情，必须报 PIT 覆盖错误。
5. bars 缺 `symbol`、membership 缺 `universe`、calendar 缺 `date` 分别调用时，audit 返回 issues 而不抛异常。

## 4. R2：修复 D4 staging/manifest/provider fail-closed

### 4.1 staging 复权规则

按 SSOT 2.3 节使用以下公式，不允许其他口径：

```text
normalization_base = first_valid_raw_close * first_valid_adj_factor
qlib_factor        = adj_factor / normalization_base
qlib_ohlc          = raw_ohlc * qlib_factor
qlib_volume        = raw_volume / qlib_factor
```

上述“first”按完成 source/PIT/calendar/合法性过滤后每只证券的最早日期确定。不得用未入选行
计算 normalization base。

### 4.2 处理顺序

1. 检查完成选源所需的最小字段；
2. `bars.filter(source == requested_source)`；
3. 对选中 source 检查唯一键、OHLC/volume/factor 完整性和正值；
4. PIT 区间和 SH/SZ 开市日过滤；
5. 对最终入选行按 symbol 计算归一化因子；
6. 输出固定列和固定排序。

### 4.3 manifest 接口和内容

`build_snapshot_manifest` 新增必需 keyword-only `source: str`。可从 staging Parquet 读取并计算的元数据不允许
由调用者传入一份可伪造的重复数值。

顶层必须包含：

- `source`
- `row_count`
- `symbol_count`
- `min_date`
- `max_date`
- `schema_version`
- `provider_format`
- `adjustment`（包含公式版本、clean 单位、price/factor/volume 公式）
- `config`
- `files`
- `snapshot_id`

每个 staging 文件条目必须包含：`relative_path,size_bytes,sha256,symbol,row_count,min_date,max_date`。
日期统一为 ISO `YYYY-MM-DD`。hash 输入仍不得包含 wall-clock 时间、绝对路径或无序输入。

### 4.4 provider 验证

当前 Python 3.13 环境无可安装 Qlib，本次不伪造 G2 通过：

- provider 目录不存在：`FileNotFoundError`；
- Qlib 不可导入：显式 `RuntimeError`，message 指明 G0/G2 未满足；
- 不允许空目录或仅目录存在就成功返回。

真实的 3 证券 × 20 日期逐字段回读仍属于 G2，在支持的 Qlib 环境中完成。本次交付报告必须
把 D4 写为“staging/manifest 已实现，provider 验证 fail-closed，G2 未验证”。

### 4.5 必须新增的测试

1. 两个 source 包含同 symbol/date，显式选择其一后成功；选中 source 内部重复则失败。
2. 使用至少两日、两只证券的手算 OHLC/factor/volume fixture，逐值对账上述公式，且每只证券首日 close 为 1。
3. 验证 `qlib_close / qlib_factor == raw_close`、`qlib_volume * qlib_factor == raw_volume`。
4. manifest 所有必需顶层和文件级字段存在且值正确；输入打乱 hash 不变，改价/hash 必变。
5. 空 provider 目录与 Qlib 不可导入都不得成功返回。

## 5. R3：修复 D5 evaluate

### 5.1 入口前置条件

- `predictions` 必须通过 `PredictionScoreSchema`；`labels` 必须通过 `ForwardReturnLabelSchema`。
- 每次只允许一个 `(model,model_version,dataset_snapshot_id,fold,horizon_sessions)` 切片。
- predictions 和 labels 的唯一键分别按 SSOT 4.7 节检查，重复时 `ValueError`。
- labels 先过滤到预测的 `horizon_sessions`，再按 `(as_of,symbol,horizon_sessions)` 连接。

### 5.2 输出与覆盖率

`rank_ic_by_date` 每日至少输出：

```text
as_of
n_expected_labels
n_matched_predictions
n_symbols
pearson_ic
rank_ic
computable
```

`n_symbols == n_matched_predictions`。`summarize_prediction_metrics` 的 `prediction_coverage` 定义为：

```text
sum(n_matched_predictions) / sum(n_expected_labels)
```

另外输出 `computable_date_ratio = n_computable_dates / n_dates`，不得混用名称。

### 5.3 必须新增的测试

1. h=5/h=10 同时传入 predictions 时明确拒绝，不得产生 `n_symbols=8` 之类多对多结果。
2. 单一 h=5 predictions 与同时包含 h=5/h=10 的 labels 连接时，只使用 h=5。
3. predictions 重复键、labels 重复键分别拒绝。
4. labels 有 4 行、匹配预测 3 行时，coverage 精确为 0.75；IC 可计算日比例不得影响该值。

## 6. R4：修复 D6 Top-k 切片混用

### 6.1 必须实现

### 6.2 必须新增的测试

3. 资格 `True/False` 冲突拒绝。
4. 正常 top-k 在无 max cap 时总权重精确为 `1-cash_buffer`；有 cap 时校验上界和剩余现金语义。

`n_drop` 仍不在本次返工范围。
