## 1. 完成目标与不做事项

M4 只交付本地 PAPER/SHADOW 日频闭环：

`VerifiedTarget → OrderPlan → PreTradeRisk → Durable OMS/Outbox → PaperGateway → ExecutionEvent → Ledger → Reconciliation → Operator Report`

明确不做：

- MiniQMT/XtQuant/PTrade 等真实 Gateway；
- 市价单、算法单、分钟/逐笔撮合、融资融券、期权；
- 自动打开实盘、无人值守批准、真实账号或 token；
- Web 服务、消息队列、PostgreSQL、微服务拆分；
- 复制 M3 G7 已实现的 A 股规则、公司行动、费用或账户循环。

## 2. 全链共同不变量

1. **安全默认**：只接受 `PAPER`/`SHADOW`；`auto_trade=false`；SHADOW 只读，不生成可发送命令。
2. **数据隔离**：除 `quant.data` repository 实现外，不接收任意路径、不遍历 `data/`；所有消费者只接 verified snapshot/domain objects。
3. **时间**：事件时间为 timezone-aware UTC；交易日是交易所本地 `date`；不得用 naive datetime 混用。信号、计划、发送、成交、交收分别记录。
4. **金额**：执行/账本内部用 `Decimal`，携带 `Currency`；只在报告 DataFrame 边界单向转 finite Float64。禁止跨币种直接相加。
5. **身份**：config、target、market snapshot、account snapshot、plan、command、event、ledger/reconciliation 均用 strict canonical JSON/bytes identity；调用者不可自报 hash。
6. **幂等**：相同 id + 相同 payload 是 no-op；相同 id + 不同 payload 是不可重试契约错误。重复事件不得产生第二次经济影响。
7. **规则版本**：市场规则、费率、board lot、tick、FX、日历均有有效期；历史回放按 session date 选当时版本，缺口/重叠 fail closed。
8. **失败优先**：数据质量失败、快照过期、规则缺失、对账不平时禁止新买；卖出、撤单和人工处置路径按显式安全规则保留。
9. **审计**：日志和异常不得含凭据、完整账号、绝对个人路径、异常 cause/traceback；报告只写稳定 code/subject。
10. **共享语义**：回测、Paper Gateway 和订单计划器调用同一规则/费用纯函数，禁止各写一套。

## 3. 最小领域合同（M4-D0 冻结）

优先使用 `@dataclass(frozen=True, slots=True)`；枚举加入 `domain/enums.py`，值对象放 `execution/contracts.py`。不把以下对象做成可变 ORM 实体。

### 3.1 新枚举

```python
class ExecutionMode(str, Enum):
    PAPER = "PAPER"
    SHADOW = "SHADOW"

class OrderType(str, Enum):
    LIMIT = "LIMIT"

class TimeInForce(str, Enum):
    DAY = "DAY"

class ExecutionEventType(str, Enum):
    ACCEPTED = "ACCEPTED"
    PARTIAL_FILL = "PARTIAL_FILL"
    FILL = "FILL"
    CANCEL_ACCEPTED = "CANCEL_ACCEPTED"
    CANCELLED = "CANCELLED"
    REJECTED = "REJECTED"
```

不得增加 `LIVE`。现有 `OrderStatus` 保持 OMS 聚合状态；event type 与 status 不混为同一枚举。

### 3.2 值对象

```python
@dataclass(frozen=True, slots=True)
class MoneyAmount:
    currency: Currency
    amount: Decimal  # 可正可负，必须 finite

@dataclass(frozen=True, slots=True)
class FeeComponent:
    code: str
    amount: MoneyAmount  # 非负
    statutory: bool
    rule_version: str

@dataclass(frozen=True, slots=True)
class PositionBalance:
    symbol: str
    market: Market
    quantity: int
    sellable_quantity: int
    avg_cost: MoneyAmount

@dataclass(frozen=True, slots=True)
class CashBalance:
    currency: Currency
    settled: Decimal
    available: Decimal
    receivable: Decimal
    payable: Decimal

@dataclass(frozen=True, slots=True)
class AccountSnapshot:
    snapshot_id: str
    as_of: datetime
    positions: tuple[PositionBalance, ...]
    cash: tuple[CashBalance, ...]

@dataclass(frozen=True, slots=True)
class SymbolMarketState:
    symbol: str
    market: Market
    session_date: date
    quote_currency: Currency
    reference_price: Decimal
    limit_up: Decimal | None
    limit_down: Decimal | None
    suspended: bool
    board_lot: int
    tick_size: Decimal
    buy_quota_available: bool
    rule_version: str

@dataclass(frozen=True, slots=True)
class VerifiedMarketSnapshot:
    snapshot_id: str
    as_of: datetime
    session_date: date
    states: tuple[SymbolMarketState, ...]
    calendar_identity: str
    source_identity: str
```

共同校验：集合按稳定 key 唯一并 canonical 排序；`sellable <= quantity`；cash 各项非负且 `available <= settled`；board lot/tick/reference price 正；limit 上下界一致；SH/SZ 只用 CNY，HK 证券 quote currency 为 HKD。港股通结算人民币在 ledger/FX 层表达，不篡改报价币种。

### 3.3 订单与事件

```python
@dataclass(frozen=True, slots=True)
class OrderIntent:
    intent_id: str
    plan_id: str
    symbol: str
    market: Market
    side: OrderSide
    quantity: int
    limit_price: Decimal
    quote_currency: Currency
    session_date: date
    generated_at: datetime
    target_identity: str
    market_snapshot_id: str
    account_snapshot_id: str
    config_identity: str

@dataclass(frozen=True, slots=True)
class OrderCommand:
    command_id: str
    intent: OrderIntent
    mode: ExecutionMode
    order_type: OrderType = OrderType.LIMIT
    time_in_force: TimeInForce = TimeInForce.DAY

@dataclass(frozen=True, slots=True)
class ExecutionEvent:
    event_id: str
    command_id: str
    broker_order_id: str | None
    event_type: ExecutionEventType
    occurred_at: datetime
    cumulative_quantity: int
    last_quantity: int
    last_price: Decimal | None
    fees: tuple[FeeComponent, ...]
    reject_code: str | None
```

`ExecutionEvent` 必须按 event type 校验字段闭包：accepted/cancel 不得伪造 fill；fill 数量和价格为正；累计量单调且不超过 command quantity；rejected 必须有稳定 code。`intent_id/command_id/event_id` 由包内 canonical builder 生成，禁止调用者传任意 hash 冒充身份。

### 3.4 决策和计划

```python
@dataclass(frozen=True, slots=True)
class RuleDecision:
    accepted: bool
    code: str
    normalized_quantity: int
    normalized_limit_price: Decimal
    rule_version: str

@dataclass(frozen=True, slots=True)
class OrderPlan:
    plan_id: str
    target_identity: str
    market_snapshot_id: str
    account_snapshot_id: str
    config_identity: str
    trading_config_identity: str
    intents: tuple[OrderIntent, ...]
    rejections: tuple[RuleDecision, ...]
    residual_cash: tuple[MoneyAmount, ...]
```

`OrderPlan` 按 `(market, symbol, side)` 稳定排序，intent key 唯一，诊断满足 `requested = accepted + rejected + zero_delta` 守恒；不得静默丢目标。

身份语义必须限定名称：`config_identity` 绑定 B4 的 planner composite
（交易配置、市场规则、费用、FX、最小名义金额），供 B6 选择同一规划配置；
`trading_config_identity` 只绑定 C0 `TradingConfig`，供 P3 通过公开 verifier
重算核对。两者均进入 `plan_id`，不得由 service 复制、猜测或互相替代。

- **反例**：重复/乱序 event、fill 超量、cancel-fill 竞态、终态后非法回退、相同 event id 异 payload。
- **内容寻址顺序**：command/intent/event 等内容寻址输入必须先按当前 payload 重新验证 identity，再执行 event-id
  membership 与幂等 no-op；不得把“标识符相同”直接当作“payload 相同”的证据。

### M4-P2 — Paper Gateway

- **前置**：B1–B3/P1。
- **白名单**：`execution/gateways/paper.py`、包导出、`tests/unit/test_paper_gateway.py`、两份报告。
- **入口**：`PaperGateway.submit(command, market) -> tuple[ExecutionEvent, ...]`；`cancel(command_id, ...)`；可注入 deterministic clock/fill policy/fault plan。
- **反例**：延迟 ACK、partial fill、duplicate callback、disconnect/reconnect、cancel 后晚 fill、重启重放。

### M4-P3 — 事前风控

- **前置**：C0/D0/D1。
- **白名单**：`execution/risk.py`、`tests/unit/test_pretrade_risk.py`、安全导出、两份报告。
- **入口**：`evaluate_pretrade(plan, account, market, config, daily_counters) -> RiskDecision`。
- **优先级**：总开关 → 数据/快照 Gate → 冻结证券 → sell-only → 单笔/单票/总仓/日成交/撤单；批次按合计量验。
- **反例**：质量失败仍买、sell-only 误拒卖、单单通过但批次超限、counter 重启丢失、SHADOW 生成 command。
- **输入自证**：读取 quota、cash、position、sellable 或 intent 等经济字段前，必须用 D0/C0 的公开 verifier 按
  当前 payload 重算 plan、market、account、config identity；仅比较调用方携带的 id 相等不足以证明内容可信。

### M4-P4 — Service 与 transactional outbox

- **前置**：B4/P0–P3。
- **P4-P0 存储前置已关闭**：SQLite v2 已提供 delivery、deterministic claim、lease fencing、`SENT/UNKNOWN`
  终态与方法级 SAVEPOINT 原子性；见
  [`M4_P4-P0可恢复TransactionalOutbox存储前置主Agent最终验收报告.md`](M4_P4-P0可恢复TransactionalOutbox存储前置主Agent最终验收报告.md)。
  该结论不替代 B4/P2 等 P4 业务前置，也不代表 service 已实现。
- **白名单**：`execution/service.py`、`tests/unit/test_execution_service.py`、两份报告。
- **入口**：`plan_and_stage(...) -> StagedExecution`；`dispatch_pending(limit) -> DispatchResult`；依赖全部构造注入。
- **约束**：command aggregate 与 outbox 同事务；发送成功回写前崩溃可由稳定 command id 幂等恢复；无后台线程框架。
- **P0-H1 前置**：真实 service 打开 SQLite 前，必须冻结显式 trusted root，并拒绝相对 URI 经 symlink/物理解析
  逃逸到 root 外；不得依赖进程 cwd。该项须有临时目录 symlink 对抗测试。
- **反例**：DB commit/发送边界四个崩溃点、双 worker、重复 plan、同 command id 异 payload、gateway timeout 未知状态。

### M4-P5 — Recovery 与 reconciliation

- **前置**：P0/P1/P4/B5。
- **白名单**：`execution/reconcile.py`、`tests/unit/test_reconcile.py`、两份报告。
- **入口**：`recover_local_state(store) -> RecoveryResult`；`reconcile(local, broker_snapshot, as_of) -> ReconciliationResult`。
- **约束**：差异分类为自动可重放/需查询/必须人工；不得以 broker snapshot 静默覆盖本地账本。
- **反例**：broker 多/少订单、未知持仓、现金差、重复成交、盘中快照、不可解释差异必须 fail Gate。

### M4-P6/P7/P8 — 操作、报告、稳定性

- **P6**：`execution/cli.py` + tests；仅 inspect/plan/approve/paper-submit/cancel/reconcile，M4 无 live 子命令。
- **P7**：`reporting/execution_report.py` + tests；EOD 命令/订单/成交/持仓/现金/风险/对账，结构化脱敏。
- **P8**：`execution/soak.py`、故障矩阵测试和运行手册；四周 PAPER/SHADOW 证据由运行产物生成，不可用 fake 时间冒充真实 soak。
- **反例**：未经批准 submit、报告路径/token 泄露、故障演练后重复经济影响、未解释差异仍 PASS。

## 6. 依赖和可并行矩阵

```text
M4-C0 → M4-D0 → M4-D1
             ├─→ M4-P0 ─┐
             └─→ M4-P1 ─┼─→ P2/P3 → P4 → P5 → P6/P7 → P8

M3-G7 主验 → B1/B3 ─┐
            → B2 ───┼─→ B4/B5 → B6 → B7 → B8
                    └──────────→ P2/P4
```

- 同一波最多十个外部会话，其中最多六个代码写会话、最多四个代码只读审查/验证会话。写会话的生产代码、测试和报告白名单必须完全互斥；只读会话只能写自己的唯一报告，且不得读取正在被写会话修改的验收目标。
- C0/D0/D1 因共享 config/domain/ports 必须串行。
- B1/B2/B3 可并行；P0/P1 可并行；B4/B5 可并行；P2/P3 可并行。
- B 系列不得在 G7 未主验时另造临时 A 股实现。若 G1 正式发布门禁阻塞，可先推进 C0/D0/D1/P0/P1，但其状态仍待主验。

## 7. 每包最低验证矩阵

1. 当前包定向单测和至少一个实现者未使用的独立初验反例。
2. WSL base 对改动文件和直接模块运行定向 Ruff/mypy。
3. 只有跨模块合流、关键发布/迁移、里程碑或 Gate 终验、公共契约大范围变化，或定向测试无法排除回归风险
   时，才运行全量 `python -m pytest -q`、全量 Ruff/mypy；普通实现、返工与独立初验不得机械重复全量检查。
4. import isolation：execution/backtest/portfolio 不 import connector SDK、Qlib、MLflow、LightGBM；非 data 模块不含 `data/legacy`/任意数据根扫描。
5. safety scan：无 LIVE、`auto_trade=true`、真实 broker、token/账号/绝对个人路径。

测试绿色只证明本包代码合同；真实 PAPER soak、程序化交易报备和实盘通道不属于本任务书完成条件。
