# M1-HKEX-02983-P1：HK60 官方补充行情接入任务单

日期：2026-08-02
状态：**实现、独立初验与主 Agent 工程验收 PASS；仅关闭 P1 补充行情接入工程合同，不代表正式 v2 finalize、HK60、M1 或 ext4 Gate**（见 [`M1_HKEX-02983-P1_HK60补充行情接入主Agent最终验收报告.md`](M1_HKEX-02983-P1_HK60补充行情接入主Agent最终验收报告.md)）

## 目标

把 P0 已验证的 HKEX Daily Quotations retained bytes 作为
`02983.HK@2026-07-10` 唯一官方补充日线，接入现有 HK history v2
恢复/finalize 公共路径。不得改变 Tushare raw、request identity、receipt，
不得把 HKEX 行改写成 `source=tushare`。

## 冻结合同

1. `finalize_hk_history` 新增显式可选的 HKEX retained raw bytes 输入。只有
   plan 的 `unresolved` 精确等于 `02983.HK@2026-07-10` 时才允许消费；有
   unresolved 而未给 raw、给 raw 但 plan 没有该缺口、存在任何其他 unresolved，
   均在写 clean 前 fail closed。
2. raw 必须经 `verify_hkex_daily_quotation` 从原始 bytes fresh 验证。不得接受
   `ParsedHKEXDailyQuotation`、普通 DataFrame 或调用者自报 hash/evidence ID。
3. 映射结果必须经 `Bar1dSchema`：OHLC 来自 verified quotation，volume 单位为股，
   amount 为完整 sales turnover（HKD，不使用 quotation 的整数显示值），
   `adj_factor=1.0`，`source="hkex"`。只允许精确一个键。
4. finalize 的 expected key 集合固定为 `effective_expected_dates ∪ supplement unresolved
   keys`；补充行与 seed/request 行合并后必须精确等于该可发布 key 集合且无
   `(symbol, trade_date)` 重复。不得把已有权威 no-trade evidence 排除的 key 重新要求为 bar。
5. `finalize.json` 升级为新版本并绑定 HKEX `evidence_id`、raw SHA-256、source
   record ID、补充行内容摘要；旧 v1 plan/无补充路径保持兼容。重复 finalize 必须
   字节幂等；任一 evidence/clean 漂移必须拒绝。
6. CLI 新增显式 raw 文件参数，仅在 `--finalize` 使用；普通执行与
   `--recover-existing-only` 不读取该文件。错误只输出既有稳定错误码，不泄露路径。

## 禁止项

- 无网络、无 Tushare/HKEX 请求；不扫描 `data/legacy`。
- 不写正式 plan/journal/clean，不修改正式 G1/G2/G8。
- 不把本任务表述为 HK60/M1 Gate 已通过；`01065.HK@2026-05-05` 的官方无行情
  evidence、正式 v2 恢复与最终双 Route Gate 仍是前置条件。
- 不顺带处理港股复权链或其他 M1 Gate。

## 验收反例

- 正常 fixture：一个 request 行加一个 P0 verified HKEX 行，finalize 精确发布全部原始键，
  receipt 绑定补充证据，重复执行幂等。
- 篡改 raw 一字节、合成 Parsed/Frame、raw 与 plan 缺口不匹配、缺 raw、额外 unresolved、
  supplement 与已有 bar 重键、既有 clean 异值：均在错误写入前失败。
- CLI 非 finalize 模式传入 raw 参数必须拒绝；错误消息不得包含物理路径。
- Windows 与 WSL base 定向 Ruff、mypy、pytest 均通过；Windows 结果不替代 Linux Gate。
