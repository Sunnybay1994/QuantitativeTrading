# M4-P4-P1 执行状态持久化前置实现报告

日期：2026-08-02  
状态：实现与自测完成，等待独立审查及主验

## 1. 交付

- schema 从 v2 升至 v3，新增 immutable stage receipt 与 opaque daily counter 表；
- 新增 stage/counter typed put/get；
- 新增 aggregate 与 counter 的严格 identity CAS；
- CAS UPDATE、post-read verification 使用方法级 SAVEPOINT；
- 未改变现有 delivery claim、lease、attempt fencing 或 `SENT/UNKNOWN` 路径。

payload 仍由 store 原样保存；本包没有定义 P4 canonical codec，也没有实现 service、gateway 调用、自动重试或
recovery。

## 2. 对抗覆盖

- stage exact replay、同 identity 异 payload、同 plan id 异内容；
- aggregate/counter CAS success、exact replay、stale expected identity、缺行；
- aggregate + counter + stage 外层事务崩溃整体回滚；
- UPDATE 后回读失败时 SAVEPOINT 回滚，即使调用方捕获异常仍看到旧 row；
- injected SQLite 错误中的路径不进入稳定错误，cause/context 为空；
- v1→current 保留 legacy outbox，v2→v3 保留 delivery row；
- migration interrupted 与未来高版本沿用既有 fail-closed 回归；
- canonical UTF-8 bytes 含非 ASCII 内容精确往返，同一测试在 Windows/WSL 执行。

## 4. 边界与下一步

本包只解除 P4 的 storage prerequisite。P4 仍需冻结 canonical payload codec、stage receipt 内容、service
clock/worker/lease 注入及 dispatch 崩溃矩阵；PaperGateway 也须先完成独立验收。本报告不宣称 P4、P5、M4
或 Linux/ext4 Gate 通过。

## 5. R1 独立初验返工

初验发现 `_put_row` 普通 SQLite SELECT/INSERT 错误可能泄露底层 sentinel。返工后：

- 首次 SELECT 的所有 `sqlite3.Error` 映射为 `<SUBJECT>_QUERY_FAILED`；
- INSERT 保持 `IntegrityError → REFERENTIAL_INTEGRITY`，其余 `sqlite3.Error` 映射为
  `<SUBJECT>_WRITE_FAILED`；
- 映射错误均在离开底层 `except` 后 `from None` 抛出；
- 幂等比较改为严格检查数据库返回值的精确 `str/bytes` 类型，不对损坏 row 做 `str()`/`bytes()` 宽松归一化；
- 新增 stage SELECT 与 counter INSERT fault injection，证明稳定 code、sentinel 脱敏、空 cause/context、无残留；
- 新增 event 外键回归，证明缺 command 仍返回 `REFERENTIAL_INTEGRITY`。

- WSL base/DrvFS：Ruff PASS、mypy 5 files PASS、`180 passed, 1 skipped`。
