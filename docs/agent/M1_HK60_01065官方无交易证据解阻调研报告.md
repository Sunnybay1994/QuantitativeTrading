## 3. 最小原始文件闭包

### 3.1 首选闭包

首选保留 HKEX 对 2026-05-05 issue 实际投递的**完整原始 archive**；若官方直接投递独立文件，则保留：

1. Main Board Daily Quotations 主报告；
2. 同一 issue 的 Daily Quotation Supplement、amendment/correction 文件（如实际投递）；
3. HKEX 投递 manifest/checksum/readme/file specification（如实际投递）；
4. 独立 acquisition receipt，记录订单和 entitlement，不混入严格的 raw metadata sidecar。

不要预先假设付费文件仍名为 `d260505e.htm`。`source_record_id`、archive member 和字符编码必须以取得的真实
投递物及官方 Technical Details/File Specification 冻结。

### 3.2 为什么需要完整报告

HKEX 的官方格式资料显示 Daily Quotations 包含 `QUOTATIONS`、`SALES RECORDS FOR ALL STOCKS`、
`AMENDMENT RECORDS FOR TRADE` 等章节；QUOTATIONS 格式还显式支持 `TRADING SUSPENDED` 行：

- [HKEX Daily Quotations 格式样例](https://www.hkex.com.hk/eng/market/partcir/sehk/Documents/CTMO05610E1.pdf)
- [HKEX 2023 年 Daily Quotations 章节清单](https://www.hkex.com.hk/-/media/HKEX-Market/Services/Circulars-and-Notices/Participant-and-Members-Circulars/SEHK/2023/CT15723E1.pdf)

因此只搜索单个字符串或只留存 Quotation Sheet 片段不能闭合“无可形成日线的交易”：必须同时验证报告日期、
市场、目标证券的 quotation 状态、全部 sales records 和 amendment/supplement。若真实主报告没有明确
`TRADING SUSPENDED`，则只有在官方 File Specification 对零 shares/turnover、sales-record 完整性及更正语义
明确后，才可冻结另一条严格解析规则；不能仅凭 `01065` 在某一章节缺席生成 evidence。

## 4. 与当前代码合同的映射

当前 `HKNoTradeEvidence` / `HKNoTradeEvidenceSchema` 精确要求：

```text
schema_version = hk-no-trade-evidence-v1
symbol = 01065.HK
trade_date = 2026-05-05
market = HK
reason = NO_DAILY_TRADING_V1
source = HKEX_DAILY_QUOTATIONS
source_record_id
source_as_of
raw_selector
raw_file_sha256
raw_metadata_sha256
evidence_sha256
```

`load_hk_no_trade_evidence()` 当前会验证 canonical evidence JSON、raw 文件 SHA-256、严格 metadata sidecar
SHA-256、相对 selector 和 evidence/set identity。metadata sidecar 的现行精确形态为：

```json
{
  "raw_file_sha256": "<sha256>",
  "raw_selector": "<relative-posix-selector>",
  "schema_version": "hk-no-trade-raw-metadata-v1",
  "source": "HKEX_DAILY_QUOTATIONS",
  "source_as_of": "<timezone-aware-ISO8601>",
  "source_record_id": "<frozen-after-real-delivery>"
}
```

字段顺序由 canonical JSON（UTF-8、key sort、紧凑分隔符）决定。`raw_selector` 应指向原始投递 archive/file，
不得包含绝对路径或 `..`。`source_record_id` 应在取得真实文件后由 HKEX 产品 ID、issue date、官方文件名/
archive member 组成并冻结，不能现在猜造。`source_as_of` 应记录实际取得并完成来源验证的 UTC 时点。

## 5. 必须补齐的来源语义 verifier

当前 loader 有一个正式解阻前必须关闭的语义缺口：`_verify_evidence_projection()` 只检查 raw/metadata 字节摘要
和 evidence 字段 Schema，**不会从 HKEX raw 重新推出 `01065.HK@2026-05-05` 确实无交易**。换言之，任意
一份摘要正确的 HKEX 文件与自报 evidence 目前可以形成字节闭包，但没有来源语义闭包。

取得真实 bytes 和官方 File Specification 后，最小实现应新增 source-specific verifier，并由 evidence 的正式
生成路径及 fresh load/验证路径共同调用。verifier 至少应：

1. 对原始 archive/file 做 SHA-256 后再解析，不接受调用者传入的已解析对象；拒绝重复 archive member、路径
   穿越、加密/损坏 archive 和非冻结文件集合。
2. 按真实文件声明/规范冻结字符编码；解析并精确确认报告标题为 Main Board Daily Quotations、报告交易日为
   `05 MAY 2026`，目标 market 不是 GEM 或其他 report。
3. 逐一定位且只允许一个 `QUOTATIONS`、`SALES RECORDS FOR ALL STOCKS`、
   `AMENDMENT RECORDS FOR TRADE` 章节；校验章节边界/终止标记，防止截断文件被当作完整报告。
4. 在 QUOTATIONS 中只允许一个 code `01065`。首选接受官方显式 `TRADING SUSPENDED` 且没有任何 shares/
   turnover 的形态；若真实 raw 为别的零交易形态，先用官方 File Specification 冻结其含义再扩展，不按经验猜。
5. 在全量 `SALES RECORDS FOR ALL STOCKS` 中确认没有 `01065` 成交；在 amendment、supplement 和实际投递的
   correction 文件中确认不存在会形成该日成交的新增/更正记录。
6. 只有以上不变量全部成立，才产出精确单 key `NO_DAILY_TRADING_V1`；报告日期错、目标行缺失、目标重复、
   非零交易、章节缺失/截断、补充文件缺失、格式漂移均返回 `HK_HISTORY_REFERENCE_INVALID`。
7. 新增对抗性 fixture：正确停牌、目标有一笔 sale、目标只出现在 amendment、日期错、GEM 报告、截断于
   sales 前、重复 01065、主报告正确但 supplement 有交易、raw 一字节漂移。

若购买到的 Daily Quotations 原文没有足够语义证明“无可形成日线的交易”，则应停止生成 evidence，转而向
HKEX 购买能列出逐笔成交的官方 Trade File/Historical Full Book 单日产品并先更新冻结的 `source` 枚举、许可和
parser 合同；不得把其他官方产品伪装为 `HKEX_DAILY_QUOTATIONS`。
