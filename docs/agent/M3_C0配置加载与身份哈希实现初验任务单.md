## 1. 目的与边界

C0 只实现 M3 TOML 的唯一加载入口、严格校验、规范化和分层 hash。不得实现 readiness 数据审计、Qlib、
训练、回测、MLflow 或 CLI，也不得读取 Tushare token。完成后 G1/G4–G9 只能复用 `LoadedM3Config`，不能
各自解析 TOML 或复制 allowlist。

采用主任务书 → 实现自测 → 独立初验 → 主终验。开始前完整阅读根 `AGENTS.md`、
`karpathy-guidelines.md` 和 SSOT；不得读取 `_old/`、联网、安装依赖或修改 WSL base。

## 2. C0A：严格解析与错误模型

新增：

- `src/quant/research/m3/config.py`
- `tests/unit/test_m3_config.py`

严格实现 `ConfigIssue/M3ConfigError/LoadedM3Config/load_m3_config/canonical_config_sha256/
canonical_tracking_target_key`。签名以 SSOT 4.0 为准。所有配置错误在
任何副作用前收集，按 SSOT 稳定排序；不得只报告第一个，也不得把错误路径、原始 tracking URI 或疑似
凭据值写进 message。

`document` 必须递归只读：mapping 不可赋值，array 以 tuple 表达；日期保持 `datetime.date`。调用者不能
通过修改返回对象让已计算 hash 与实际参数分离。不要增加 Pydantic 等新依赖，使用标准库 `tomllib`、
`dataclasses`、`types.MappingProxyType` 与 `hashlib` 即可。

`canonical_config_sha256(selector=..., document=...)` 必须接收完整已验证 document 并在内部按唯一 selector
投影；不得公开“调用者先挑 payload”的接口。direct caller 的 partial/extra/version mismatch document
仍须用同一 validator 拒绝；只允许 loader 内部使用不公开的 trusted helper。规范 tracking URI 写回只读 document，并作为
`canonical_tracking_uri` 暴露，后续 tracking 不得使用原始 URI 拼写。

至少测试：合法示例；未知根键/嵌套键；缺键；bool 冒充 int；int 冒充 float 的明确政策；空字符串；
NaN/inf；datetime/time；重复 TOML key；错误日期；多个错误的稳定排序；返回 document 任意深度不可变；
不存在/不可读/非普通配置文件；异常和 repr 不含绝对路径/token。I/O 与 parse 异常不得直接透传标准库
原消息。

## 3. C0B：跨字段不变量

按 SSOT 4.0 实现全部跨字段检查。不得静默排序 horizon/cost period、裁剪 coverage 或自动补默认值；配置
本身必须已经合法。

至少覆盖：

1. `embargo < max(horizon)`；
2. 重复/逆序 horizon，或非 5/10；
3. `step < test` 和产生重叠 test 的组合；
4. required/provider fields 缺列、多列、错序；
5. `top_k > minimum_cross_section_symbols`、最小截面大于期望成分数；同时证明
   `top_k*max_weight < 1-cash_buffer` 仍合法并表示额外现金；
6. 负容差、coverage 越界、`minimum_ic_symbols < 2`；
7. 成本区间重叠、自然日缺口、逆序、首期未覆盖 data 起点或末期错误地封口；
8. friction multiplier 少档、多档、重复或错误数值；
9. provider sample 数不足、gap 数为负、reconciliation tolerance 负值或非 finite，或
   `qlib_expression_atol/benchmark_return_atol > label_return_atol`；
10. tracking URI 内嵌凭据、绝对路径或敏感键。
11. train sessions 小于 readiness 最低训练长度，或 G1 label tail 小于最大 horizon。
12. 七个 endpoint limit 任一与冻结值相差 1；expected constituents 不是 300、G1 抽样不是 30×20、
    Alpha158 warmup 不是 60。
13. LightGBM learning rate/min-delta/bagging freq/seed/depth/rounds 关系，以及五个费用数值字段用 int 冒充
    float。

安全反例至少覆盖：unknown `api-token`、Bearer/`token=` 大小写变体、percent-encoded userinfo、SQLite 第四
个 slash、Windows drive/UNC、`%2f/%5c/%2e%2e`、HTTP 默认端口等价规范化。不得把合法 dump SHA 当 token；
逻辑路径检查不能替代下游 root containment/no-symlink。

## 4. C0C：规范化与九类身份

实现 SSOT 唯一分层规则。canonical JSON 不允许 Python repr、平台路径分隔符、locale 或字典插入顺序影响
结果；hash 输出为 64 位小写十六进制。
输出不得带 `sha256:` 前缀；算法名如需展示使用独立字段，避免 identity 进入 Windows 挂载路径时含冒号。

使用参数化反例证明：

| 只改变 | 必须改变 | 必须不变 |
|---|---|---|
| 注释、空白、TOML 键顺序 | 无 hash | 全部 |
| tracking URI/name | full、tracking target | G1/snapshot/provider/scientific/provider-validation/label-reconciliation/acceptance |
| acceptance 阈值 | full、acceptance | G1/snapshot/provider/scientific/provider-validation/label-reconciliation/tracking target |
| provider 抽样 | full、provider-validation | G1/snapshot/provider/scientific/label-reconciliation/acceptance/tracking target |
| label 对账容差 | full、label-reconciliation | G1/snapshot/provider/scientific/provider-validation/acceptance/tracking target |
| G1 endpoint limit/reconciliation policy | full、G1 | snapshot/provider/scientific/provider-validation/label-reconciliation/acceptance/tracking target |
| G1 feature warmup/label tail | full、G1、snapshot | provider/scientific/provider-validation/label-reconciliation/acceptance/tracking target |
| G1 rate/max-attempts/retry-base | full | G1/snapshot/provider/scientific/provider-validation/label-reconciliation/acceptance/tracking target |
| 费用 period | full、scientific | G1/snapshot/provider/provider-validation/label-reconciliation/acceptance/tracking target |
| provider fields/format | full、provider、scientific | G1/snapshot/provider-validation/label-reconciliation/acceptance/tracking target |
| Qlib version | full、scientific | G1/snapshot/provider/provider-validation/label-reconciliation/acceptance/tracking target；最终 provider key 另变 |
| dump URL/hash/bytes 或 supported-python policy | full | G1/snapshot/provider/scientific/provider-validation/label-reconciliation/acceptance/tracking target；实际 tool hash 由 E3 另入 provider key |
| staging 日期域/universe/source | full、snapshot、scientific | G1/provider/provider-validation/label-reconciliation/acceptance/tracking target |

上表是 selector 传播真值表，不等于当前版本中每个字段都允许生成第二个合法值。对于冻结为唯一
literal 的 endpoint limit、抽样数、Qlib 版本、dump spec、universe/source/provider fields 等，实现
必须用两项证据代替无效变体的 hash 比较：变体被公开 API 拒绝；对应 `_FIELD_SPECS` selector
与表中的必须改变集一致。仅对 `1.0.0` 中真正可合法变化的字段做完整文档运行时 hash
差分。不得放宽 literal，也不得暴露绕过验证的 trusted canonicalizer。

`dump_tool_sha256` 最终仍由 `compute_provider_key` 单独加入 provider identity；C0 的 provider config hash
不得再次拼接 code/dependency 或 snapshot ID。`code_version` 和实际依赖指纹也不属于配置 hash。

## 5. C0D：调用边界迁移

只做最小迁移：实现 `LoadedM3Config.section(name)`，为 `readiness.py` 与后续接口提供只读 section；不
重写现有业务函数。任何新代码中出现第二个 TOML reader、第二套 scientific/snapshot/provider allowlist，
或以整份 config hash 冒充某一分层 hash，均视为 C0 不通过。

本包必须同时修改：

- `src/quant/research/m3/snapshot.py` 与 `tests/unit/test_m3_snapshot.py`：现有
  `build_snapshot_manifest` 删除 `config_path/provider_format`，改收已验证的
  `snapshot_config_sha256/config_version`，manifest 不再保存配置文件名/字节数/整文件 hash。G2 后续再按
  SSOT 最终签名加入 session calendar；C0 不抢做其 calendar/provider 业务。
- `src/quant/research/m3/fetch_qlib_tool.py`、`contracts.py`、最小 provider mapper 与对应测试：删除
  `load_dump_script_spec/DEFAULT_CONFIG_PATH` 和 `tomllib`，定义唯一 `QlibDumpToolSpec`，由
  `build_qlib_dump_tool_spec(LoadedM3Config)` 从扁平字段映射，fetcher 只接收 spec。
- `tests/unit/test_m3_contracts.py`：示例配置断言改用 `load_m3_config`，不得直接 `tomllib.load`。

当前 `snapshot.py` 的 `sha256:` snapshot ID 与 `run_state.py` 的严格 receipt/identity 迁移分别属于 G2/E3
已下发返工；C0 不重复实现，但 E3/G2 未通过前不得宣称 C0 已完成全链集成。C0 自身通过条件是所有 M3
production/test 消费示例配置的入口都已收敛到 loader，snapshot 不再读取/哈希物理 TOML。

若现有测试直接构造 dict，可继续测试纯业务函数；CLI/编排入口未来必须先调用 `load_m3_config`。不要为
兼容旧测试增加隐式默认值。

`execute_m3_plan` 接收已加载的 `LoadedM3Config`，不接收 `config_path`。真正的 CLI 入口只允许在构造
任何 plan/初始化 artifact root/联网前调用一次 `load_m3_config`。

`fetch_qlib_tool.py` 不得保留第二个 TOML reader。保留示例 TOML 的扁平
`runtime.qlib.dump_script_url/dump_script_sha256/dump_script_bytes/version`；C0 只负责验证并暴露只读
`runtime.qlib` section，provider 层通过唯一 `build_qlib_dump_tool_spec` 映射成 `contracts.QlibDumpToolSpec`
后显式注入下载器和 materializer。

G1 同样不得读取 `config_path`。后续 G1 stage handler 在任何写入前从同一 `LoadedM3Config` 复算 G1 hash，
再把 `config_version/g1_config_sha256` 显式注入 `publish_g1_release`；data 层不得反向 import research 层。
C0 不实现 G1 发布，但要提供该调用契约，并证明 G1 selector 与其他八类身份隔离的变化传播测试。

增加字段闭包测试：当前示例必须是 151 个 assignment、归一费用数组下标后 138 种 dotted-key shape，并与
唯一 `_FIELD_SPECS` 精确相等。每个 shape 都要有 required/optional、strict type、literal/range 和 selector
membership；测试从 production spec 参数化，不维护第二份 allowlist。

## 7. 独立初验 Agent

初验 Agent 不修改代码，逐项映射 C0A–C0D，并至少新增五个实现者未使用的变体：深层未知键、数组元素
非 finite、费用边界相接一日、URI percent-encoded 凭据、只改 acceptance 不改 experiment、返回对象深层
突变。检查源代码中是否存在重复 allowlist/TOML reader。

失败报告必须写 P0/P1/P2、最小复现、根因、被破坏的不变量、通用规则和通过条件。只有独立初验通过后
才进入主 Agent 终验。
