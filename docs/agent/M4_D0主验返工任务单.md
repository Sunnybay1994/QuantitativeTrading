## 2. F1 — OrderPlan 来源闭包

- `build_order_plan` 在计算任何 digest 前，必须验证每个 `OrderIntentSpec` 的 `target_identity`、
  `market_snapshot_id`、`account_snapshot_id`、`config_identity` 与 plan 顶层四个 identity 分别完全一致。
- `OrderPlan.__post_init__` 必须对直接构造/replace 后的每个 `OrderIntent` 重复相同双向闭包，不能只检查
  `intent.plan_id`。
- 任一项不一致抛稳定 `ContractError`，不得静默覆盖 spec，也不得让顶层或 intent 任选一边。

## 3. F2 — Event 必须绑定真实 OrderCommand

- 安全 builder 必须接收自证 `OrderCommand`，从中派生 `command_id` 和真实 `intent.quantity`；禁止继续信任调用方
  单独传入的裸 `command_quantity`。
- `cumulative_quantity` 对所有 event type 均不得超过真实 command quantity；fill 继续满足现有字段闭包。
- 不保留仍可被外部调用的旧不安全入口；若为迁移保留内部 helper，必须是模块私有且只接已验证 command。
- event value object 仍只保存任务书冻结字段，不新增一份可漂移 quantity。
- `tests/unit/test_execution_oms.py` 只做调用签名的机械适配，OMS 业务语义留在 P1。

## 4. F3 — Snapshot 交易日闭包

- `VerifiedMarketSnapshot.__post_init__` 必须要求所有 state 的 `session_date` 与 snapshot 顶层完全一致。
- builder 应在返回 verified object 前稳定拒绝混配；identity 不能把矛盾事实一起哈希后视为合法。
- 空 states 是否允许维持现有合同，不在本次擅自改变。

## 5. F4 — 嵌套输入先验真再排序/哈希

- `OrderIntentSpec` 作为公开 builder 输入必须有 strict constructor，校验除 plan/intent ID 外的全部 intent 字段。
- account positions/cash、market states、plan specs/rejections/residual cash、event fees 等 Sequence 在排序或 payload
  访问前先验证容器与 element 类型；错误统一为不含对象 repr 的稳定 `ContractError`。
- 不允许 `AttributeError`、`TypeError`、排序比较异常或底层 enum/Decimal 异常从 strict builder 外溢。
- 不复制第二套字段规则；提取并复用现有 intent/value-object 校验助手。

## 6. 必须新增的定向测试

1. plan 顶层四 identity 分别与单个 intent spec 不一致，四支均拒绝；直接 replace plan/intent 也拒绝；
2. quantity=10 的真实 command，累计量 11 的 fill/non-fill event 均拒绝；合法 0/partial/full 边界保留；
3. snapshot 与一个 state 交易日不一致拒绝；多 state 中仅一项错日也拒绝；
4. `OrderIntentSpec.market="SH"`、bool quantity、naive generated_at、错误币种均为 `ContractError`；
5. positions/states/fees/rejections/residual cash 各取一个错误 element，builder 不得抛非合同异常；
6. 保留既有 12 项 D0 测试，并运行受签名影响的 OMS 定向测试。
