## 1. 现象—根因—规则—最小复现—通过条件

| 项 | 内容 |
|---|---|
| 现象 | 正式零网络续诊在 `corporate_action_selection` 失败：`G1_EXECUTION_FACT_VALUE_INVALID` @ `_parse_strict_scalar`（null 且 `allow_null=False`） |
| 正式样本 | `000793.SZ` 第 121 个 dividend response；`div_proc=实施`，`stk_div=1.2`，`cash_div_tax=null`，`ex_date=20260622`，`div_listdate=20260622`，`pay_date=null` |
| 根因类别 | **实现/解析合同缺口**（非 raw 损坏；供应商对未使用现金腿给 null，同证券其他实施行用 `0.0`） |
| 根因 | `select_g1_corporate_actions` 对 `cash_div_tax`/`stk_div` 一律 `_parse_non_negative_number`（禁止 null）。纯送转实施行现金腿 null 被拒，尽管后续合同已允许 `cash==0 && stock>0`（`pay_date` 可空、`stock_list_date` 必填） |
| 应遵循规则 | 保留 raw 事实；不得静默发明分红事件。允许将**未使用腿的 null 显式规范为 0.0**；若两腿规范后均为 0，仍 `G1_CORPORATE_ACTION_EVENT_INVALID`。非法类型/非有限数仍 fail closed |
| 最小复现 | 合成或正式形状：`实施` + `stk_div>0` + `cash_div_tax=null` + 合法 list/ex/record → 选择应通过；`cash_div_tax=null` 且 `stk_div=null`（或均规范为 0）→ 仍拒绝 |
| 通过条件 | 见 §4 |

## 2. 冻结修复方向

仅在公司行动选择路径解析 `cash_div_tax` / `stk_div` 时：

1. `None` → `0.0`（显式腿规范化，不是填补缺失事件）；
2. 非 None 仍走既有严格数值解析与非负检查；
3. 规范化后若 `cash==0 && stock==0` → 既有 `G1_CORPORATE_ACTION_EVENT_INVALID`；
4. 既有 pay_date / stock_list_date 与现金/送转一一对应规则不变。

**禁止**：改正式 raw/receipt；降低 `event_id` 闭包；进入 REFERENCE/PREPARE/PUBLISH；重复 510300 API；把任意字段 null 一律吞掉。
