## 4. 实现者未使用的对抗性反例（确定缺口）

### 4.1 【确定 FAIL】非法期望 snapshot 被前置错误短路

**现象**

`expected_benchmark_source_snapshot_id` 本身非法（`""` / `"AB"*32` / `True` 等）时，若同时存在下列任一前置条件，`audit_m3_readiness` **不**产生任何 `BENCHMARK_SNAPSHOT_*` ERROR：

| 组合 | snapshot 相关码 | 仅见其他码 |
|---|---|---|
| 非法期望 + `benchmark_bars` 空表 | 无 | `BENCHMARK_EMPTY` |
| 非法期望 + 配置 `source` 在 bars/bench 中不存在 | 无 | `DATA_SOURCE_MISSING` |
| 非法期望 + 配置 `benchmark=H00300.CSI` | 无 | `BENCHMARK_SYMBOL_MISMATCH` |
| 非法期望 + Schema/列门禁失败（缺列或 NaN close） | 无 | `BENCHMARK_MISSING_FIELDS` / `BENCHMARK_INVALID` |
| 对照：非法期望 + 合法 selected_bench | 有 | `BENCHMARK_SNAPSHOT_INVALID` |

**根因**

`readiness.py` 将 `_check_benchmark_snapshot_binding(...)` 嵌在：

```text
benchmark == 510300.SH  AND  selected_bench is not None
```

空表 / source 过滤失败 / Schema 失败 → `selected_bench is None`；`H00300.CSI` → 走 `BENCHMARK_SYMBOL_MISMATCH` 分支，**从不调用**期望身份校验。必填期望参数的 fail-closed 因而被其他前置错误绕过。

**应遵循规则**

- R3 §2：期望值非法（空串、大写、非 hex、长度错误、非 str、bool 等）必须 fail closed，并产生稳定 benchmark snapshot ERROR；函数仍返回 issues、不抛契约异常。
- 原 B1B §5：readiness 对身份不匹配 fail closed。
- 必填上游身份不得因 bars/source/旧基准/Schema 等其他错误而静默跳过自身校验。

**最小复现（只读探针，不改仓库）**

```python
from tests.unit import test_m3_readiness as t

def snap(issues):
    return sorted({i.code for i in issues if i.code.startswith("BENCHMARK_SNAPSHOT_")})

# 非法期望 + 空 bars
empty = t._benchmark_bars().clear()
assert snap(t._audit(
    expected_benchmark_source_snapshot_id="",
    benchmark_bars=empty,
)) == []  # 当前实现：期望身份错误被吞掉

# 非法期望 + H00300
assert snap(t._audit(
    expected_benchmark_source_snapshot_id=True,
    config=t._base_config(data={
        "universe": "CSI300_PIT",
        "benchmark": "H00300.CSI",
        "source": "fixture",
        "start_date": "2020-01-02",
        "end_date": "2020-01-10",
        "minimum_train_sessions": 1,
        "minimum_cross_section_symbols": 1,
    }),
)) == []
```

**新增测试要求**

对每种组合至少一条参数化用例：非法期望 × {空 bars, source 缺失, H00300, Schema 失败}，断言 **无条件** 含 `BENCHMARK_SNAPSHOT_INVALID`（可与其他 ERROR 并存）；消息仍不得包含完整 identity。

**通过条件**

上述组合全部稳定出现 snapshot ERROR；合法期望 + 合法 matched bars 仍无 snapshot ERROR；不得靠“先 return 其他错误”跳过期望身份校验。

### 4.2 【确定 FAIL】v2 manifest 接受 mapper_version=v1（v1/v2 混合）

**现象**

`schema_version=m3-g1-manifest-v2` 且三项 benchmark 身份字段合法时，将 `mapper_version` 设为 `m3-g1-tushare-mapper-v1`，`_parse_manifest_bytes` **接受**为 `G1ManifestV2`（本会话探针：`PASS G1ManifestV2 mapper=m3-g1-tushare-mapper-v1`）。

对照：`G1BuildSpec` 强制 `mapper_version == m3-g1-tushare-mapper-v2`；manifest 读取路径未锁死。

**根因**

`G1ManifestV2.__post_init__` 只冻结三字段 benchmark 身份；`_validate_manifest_common` 对 `mapper_version` 仅要求非空 `str`，不要求 v2 字面量。形成“v2 壳 + v1 mapper”可读混合身份。

**应遵循规则**

- 原 B1B §2：mapper version 升为 `m3-g1-tushare-mapper-v2`。
- 原 B1B §3：v1/v2 字段混合 fail closed；当前发布身份不得静默混入旧 mapper。

**最小复现**

```python
from tests.unit.test_m3_g1_release import _b1b_minimal_manifest_payload
from quant.data.m3_release import _parse_manifest_bytes, _canonical_json_bytes

payload = _b1b_minimal_manifest_payload(schema="m3-g1-manifest-v2")
payload["mapper_version"] = "m3-g1-tushare-mapper-v1"
obj = _parse_manifest_bytes(_canonical_json_bytes(payload))
# 当前：成功得到 G1ManifestV2；合同要求应拒绝
```

**新增测试要求**

`test_m3_g1_release.py`：v2 payload + `mapper_version=m3-g1-tushare-mapper-v1`（及其他非 v2 字面量）必须 raise；v2 + 正确 mapper-v2 仍可读。

**通过条件**

解析失败且错误稳定；不得把 v1 mapper 解释为合法当前 v2 发布身份。

**说明**

R3 白名单禁止改 `m3_release.py`，故该缺口非本轮实现者可修范围，但属原 B1B §2/§3 确定合同失败，初验仍判 FAIL，不得跳过。
