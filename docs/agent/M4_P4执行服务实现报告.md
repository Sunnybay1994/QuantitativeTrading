## 2. 实现结论

`plan_and_stage` 把 projected daily counters 与 sendable PAPER command 全套 durable 记录原子提交；相同
plan_id 重放从不可变 receipt 恢复，不重复扣计数器。`dispatch_pending` 使用 store 已验收的 deterministic
claim、lease 和 attempt fence；调用 adapter 前复核 command/outbox/aggregate，SENT 后把 callbacks、OMS
aggregate CAS 和 SENT 标记置于同一事务。

stage wire 实际只承载 RiskDecision receipt，command wire 承载 OrderIntent，均不承载完整 OrderPlan；
服务用相同公开输入重建 plan 并核验 plan/intent 闭包，故保持各自 v1，不伪称为 plan snapshot。

## 4. 剩余风险

adapter 外部副作用与 SQLite 状态存在不可消除的 dual-write crash window：跨界后、终态落盘前崩溃会在
lease 到期后再次提交同一 command_id。实现提供 at-least-once + stable identity/fencing，不提供
exactly-once。UNKNOWN durable terminal 需要 P5 reconciliation 或人工处置；P4 本包不实现 broker 查询、
cancel 编排或 LIVE。

独立初验返工补充：初版只在 durable 闭包加载前检查时钟，加载期间 lease 过期仍会调用 adapter。现已在
闭包加载后增加 owner/attempt/lease/current-time 最终 fence，并增加“加载期间过期不调用 adapter”反例。
若 `submit` 已开始后才跨过 lease，仍会返回
`LEASE_EXPIRED_AFTER_DISPATCH`/`UNKNOWN_NOT_DURABLE`，且可能由后续 attempt 重发；新增慢 UNKNOWN
对抗测试固定并诚实披露该 P5 对账边界。
