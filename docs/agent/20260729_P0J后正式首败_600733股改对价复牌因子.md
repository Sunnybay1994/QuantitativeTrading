## 5. 数值裁定

`10送5` 是以资本公积转增前的登记股份为基数；vendor factor 在复牌日前已经先吸收 `10转25`
的 3.5 倍。把 0.5 原始送股比例换算为当时当前持股基数：

```text
normalized_stock_ratio = 0.5 / (1 + 2.5)
                       = 0.14285714285714285
declared_resume_ratio = 1 + normalized_stock_ratio
                      = 1.1428571428571428
actual_resume_ratio = 9.36 / 8.192
                    = 1.142578125
relative_error = 0.000244140625 < rtol(0.001)
```

同时：

```text
2.34 × (1 + 2.5 + 0.5) = 9.36
```

两段 factor 的相同量级误差来自三位小数 vendor factor 的舍入；不得据此扩大全局 `rtol`。

## 6. 必须保持的系统不变量

后续 P0K 不得采用以下捷径：

- 不得放宽 no-event 或 `factor_ratio_rtol`；
- 不得硬编码 `600733`、`2018-09-27`、`0.142857...` 或手工录入一条 ledger；
- 不得把 `p_sysapi1139` 投影后的中文列当 raw；正式 raw 必须保存官方字段码和计数元数据；
- 不得只凭 Tushare factor 反推一个事件；CNINFO 必须独立证明事件、原始比例和日期闭包；
- 不得把股份对价与资本公积转增重复计数；
- 不得将 `承诺补偿` 一概视为普通全体股东分红；需表达登记股份基数与后续全体转增的归一化；
- 不得把盘中临停当 `FULL_DAY`；
- 不得用 Windows 绿测代替 WSL base 平台终验。
