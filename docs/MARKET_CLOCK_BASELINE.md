# 盘中同钟点成交额基线

原 `market_snapshot --session` 每5分钟采样一次，完成采样后调用现有 `market_indicators live`。
该诊断入口按 `configs/research/market_intraday_baseline_v1.toml` 生成/读取基线，不新开行情采集。
更新代码不会让已经启动的Python进程自动重新加载；以之后自然启动的任务产物为准。

基线只读 `artifacts/realtime/market_snapshots/` 中完整实际快照：

- 只取前20个交易日，排除当天及未来记录；每股票至少5个有效历史日。
- 使用同一Tushare/Sina来源的人民币累计成交额，同一分钟内选不晚于当前供应商秒数、相差不超过30秒的最近记录，每日最多一个值，跨日取中位数。
- 同时检查供应商/接收时间、历史股票池引用及指纹、连续交易时段、正成交额、重复冲突和累计额回退；缺失不填零，不拿全天成交额代替。
- 当前股票池与历史实际观察池按股票代码取交集，保留当前池分母；新出现或历史缺失的股票不伪造基线，不宣称覆盖上市全量。
- 每日最多64个快照、每个报价文件最多12MB；越界单列原因。有效历史日缓存为Parquet，输入身份变化时重新生成，原始采样不改写。

每个新诊断目录的 `same_clock_baseline/coverage.csv` 保存逐股票有效天数、日期、钟点差、
基线及当日相对值；`summary.json` 保存范围、来源指纹、缓存收据、覆盖和缺失原因。
连续宽度、涨跌家数差、价差和同钟点成交额比值分别保留，覆盖不足时分量为空。
基线环节失败会单独报告，其他有效连续分量仍输出，不中断原采集。

`component_input_status` 描述输入是否齐全；`classification_status=not_implemented`
单独说明盘中分类映射尚未实现。即使积累了足够历史，也不会自动得到市场状态评分。
日频状态仍按原方法在收盘后生成；这些描述性指标不触发仓位调整，不证明择时收益。
