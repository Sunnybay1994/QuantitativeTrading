# 优化工作清单 B · 自动化流水线、LLM 与框架

> 总览、约束与时间盒见 [优化工作清单_20261009.md](优化工作清单_20261009.md)（**2026-10-13 总验收已闭合，见总览 §3.1**）。流水线入口：`quant.research.continuous_mining` → `nightly.execute`（N1 受理 / N2 GP 搜索 / N3 电池评估 / N4 增量准入 / N5 月度模型），配置 `configs/research/nightly.toml`。

## 1. 流水线（P1）

### B1 · GP 目标函数改为"相对 Q10 与准入集的增量"

- 现状：`nightly_gp.py` 目标 `pooled_mean_ic_v1` 或 `cross_stock_min_ic_v1`，fitness = |mean IC| − 复杂度惩罚 − 0.5×与控制的最大秩相关。1,408 候选只有 3 个过 N4，0 个进策略。搜索目标（单因子 IC）与最终目标（相对 Q10 的增量）脱节，GP 在反复发现 SUE/动量/反转的同构体。
- 改动（新版本 `incremental_residual_ic_v1`，新 run 目录，不重解释旧 checkpoint）：
  1. 标签改为残差：月度标签对 Q10 预测分数、三个 `ngp_*` 准入因子及规模/行业做截面回归，取残差（`quant.data.model_forecast_labels` 新函数 `residual_labels(labels, controls)`，残差定义写进 toml 并冻结）；
  2. fitness = 残差标签 IC 均值 − 复杂度惩罚 − 0.5×max 控制秩相关，交叉股票分组沿用 `cross_stock_search.group_fitness`；
  3. N3/N4 对候选仍用原始标签做完整电池（准入规则不变），只有搜索方向变了。
- 配置：`configs/research/gp_incremental_residual_v1.toml`（含 `registered_on`、残差控制清单与哈希、停止条件：连续 10 批 0 准入则回退 `cross_stock_min_ic_v1` 并记录）。
- 产物：`artifacts/research/continuous/batch_*/digest.md` 新增 `search_objective` 与 `incremental_vs_q10`（候选对 Q10 持仓因子的增量 NW-t）。
- 验收：首批 20 候选中与 Q10 持仓因子 |秩相关| >0.6 的比例低于最近 10 批均值；测试 `tests/unit/test_residual_labels.py` 验证残差与控制正交。

### B2 · N5 月度模型加入 "Q10 + 准入因子" 增量模型

- 现状：`nightly_monthly.py` 只跑 `equal_z` / `positive_mean_ic` / `lightgbm` 三种，对象是全部准入因子，均 REJECTED；没有"以 Q10 为底、只加新因子"的对照，所以 N4 准入的因子永远不知道是否对 Q10 有用。
- 改动：新增方法 `q10_plus_admitted`：Q10 预测分数 z + Σ 新准入因子 z × 权重（权重 = 近 48 月增量 IC 符号 × 1/N，无拟合），构建仍用 0.5 换手预算 Top50；对照组为 Q10 本身同窗。写入 `configs/models/q10_plus_admitted_v1.toml`。判定仍走 §1.2，并额外报告 "vs Q10 同窗 2× 超额差"。
- 产物：`artifacts/research/nightly/monthly/<YYYY-MM>/q10_plus_admitted/`；注册表行。
- 验收：2026-11 N5 summary 出现该方法三档结果；若 2× 超额 ≥ Q10 + 1pp 且其他门槛通过 → 自动生成 `configs/paper/<name>_<date>.toml` 草稿与通知，**不自动开户**。

### B3 · 拒绝原因漏斗

- 现状：注册表 2,000 行 REJECTED 只有 `conclusion`，没有"死在哪一道门"。
- 改动：`quant.reporting.experiment_registry` 增加列 `reject_stage`（statistics / fdr / cost / correlation / incremental / strategy_excess / strategy_sharpe / turnover / drawdown / stress / annual_hit）与 `reject_detail`（首个失败门的数值）；`quant.reporting.mining_status` 输出漏斗表（按批次、按因子族、按算子族），追加到 digest 与 `quant status`。
- 验收：`python -m quant report funnel --since 2026-09-25` 打印各门淘汰数；历史行能从已有 `assessment.json`/`scorecard` 回填 ≥90%。

### B4 · 调度与健康

- 现状：退出码 1 告警已有去重；`attempt.json` 指纹探测已覆盖 backtest/data/domain/factors/portfolio/research；无"过去 24h 做了什么"的一页。
- 改动：`quant status` 增加：最近批次号与耗时、当前步骤、上次成功 N5、队列长度、磁盘余量（`minimum_free_gb=50`）、最近 3 次失败的 `failure_kind`；每日 21:30 日更结束后把该页通过 `quant notify` 发送（已有 `automation_alert`，只加成功摘要）。
- 新增每日自动提交：`scripts/run_daily_observation.ps1` 末尾 `git add -A && git commit -m "auto: daily <date>"`（仅 `src/ configs/ docs/ tests/`，排除 `artifacts/ data/`；`.gitignore` 核对凭据文件 `*.local.toml`）。
- 验收：连续 5 个交易日有 `auto:` 提交；通知渠道收到每日摘要。

### B5 · 研究优先级配置结构化

- 现状：`configs/research/research_priorities.toml` 的 `priorities` 是 15 段英文长文（14KB），`research_feedback.prompt_context` 把它整个塞给 LLM。
- 改动：改为 `[[priority]]` 表：`id`、`status`（open/closed）、`mechanism`、`evidence_paths`、`stop_condition`、`next_action`、`updated`；现有 15 段逐条拆入，`closed` 项保留只读；`research_feedback`、`weekly_factor_candidates`、C3/C4 只消费 `status=open` 项。文件 >30KB 则拆 `research_priorities_closed.toml`。
- 验收：`tomllib` 解析通过；单测验证 open 项数量与字段完整；LLM prompt 长度下降 >50%。

### B6 · 排行榜只显示策略级行

- 改动：注册表当前无层级列（列见 `experiment_registry.py`：run_path … excess_2x），先加 `level`（factor / strategy，按 `run_path` 前缀 `artifacts/factors/`→factor、`artifacts/models|portfolio|research/*account*`→strategy 回填）；`quant.reporting.leaderboard` 默认过滤 `level == 'strategy'`，因子级行进 `docs/research/排行榜_因子.md`；两表均加 IS/OOS 列（见 D2）。
- 验收：`docs/research/排行榜.md` <30KB，首行为 Q10。

### B7 · 注册表补字段

`design_date`（配置冻结日）、`data_end`、`oos_start`（= design_date 之后首个月末）、`oos_months`、A2 的四个滚动/集中度列、B3 的两列。历史行从 `config.toml`/`assessment.json` 回填，不可得标 null。

## 2. 让 LLM 真正干活（P2）

现状：DeepSeek 门面 `quant.llm`、预算账本 `quant.llm.budget`（月 ≤$30，周 ≤$5）、缓存 `p7_deepseek_cache.sqlite`、情报管线 `quant.intel`、周度候选 `weekly_factor_candidates`、市场简报 `monthly_market_brief` 全部存在，但 10 月花费 $0.01：没有定时触发，周度候选公式非法后无重试，情报扫描跑过一次就停。**LLM 的四个合法岗位：候选生成、失败诊断、文献提取、文字简报。** 每一笔调用都要落到 `artifacts/research/llm_ledger/<YYYY-MM>.jsonl`（时间、任务、tokens、USD、产物路径）。

### C1 · 情报周扫描定时化

- 改动：注册 Windows 任务 `QuantitativeTrading-IntelWeekly`（周日 20:00，避让挖掘片），执行 `python -m quant intel scan --config configs/research/intel.toml`；`quant.intel.pipeline.run_intel` 必须写 `artifacts/intel/<ISO周>/digest.md`（标题、来源、机制一句话、可实现性评分、是否入队）与 `configs/factors/queue/intel_<周>.toml`；RSS 增加 SSRN FEN 与 GitHub trending `quant` 关键词；去重用 `gp_expression_identity`。
- 验收：两个连续周的 digest 存在；至少 1 个候选被 N1 受理；周花费 ≤$2。

### C2 · 候选生成的 DSL 校验闭环

- 现状：09-28 周度生成 20 个候选全部公式非法，未进电池。
- 改动：`generate_factor_candidates` 中：prompt 附 `factors/expressions.py` 的算子表与 3 个库内合法示例；生成后用 `factors/expressions.py` 的 `compile()` 做语法与算子校验，非法则把错误信息回传 LLM 重试 ≤2 次；通过后与 386 库做表达式同一性与（若可算）秩相关 <0.9 去重；全部产物写 `artifacts/research/weekly_candidates/<date>/{raw.json,validated.json,rejected.json}`。
- 验收：非法率 <20%；入队候选均带 `mechanism`、`direction`、`source=llm_weekly`。

### C3 · LLM 批次诊断 → 搜索提示

- 改动：每批 N4 结束后，`research_feedback.update` 把 B3 漏斗 + 本批 Top20 表达式 + 失败门数值交给 LLM，要求输出结构化 `configs/research/gp_hints/batch_<n>.toml`：`avoid_operator_families`、`avoid_windows`、`suggested_inputs`、`rationale`；N2 读取最新 hints 作为**软约束**（初始化种群偏好与变异算子权重），不改 fitness、不改准入。每批 ≤$0.3。
- 验收：hints 文件由机器写入并被下一批 `search_checkpoint.json` 记录引用；10 批后比较有/无 hints 的 N4 通过率（描述性，不作因果）。

### C4 · 月度研究简报

- 改动：`monthly_market_brief` 扩成 `quant report brief --month YYYY-MM`：输入 = 注册表当月新增行、Q10 月报（A3）、R3 归因（D6）、漏斗（B3）、LLM 账本；LLM 只做中文归纳与"下月建议关注"，所有数字由代码填入模板，LLM 不得改数字（`validate_facts` 已有）。输出 `artifacts/research/brief/<YYYY-MM>.md`，通过 `quant notify` 发送。
- 验收：11-01 自动生成 10 月简报；数字与注册表一致（单测比对）。

### C5 · 论文/开源 → 预注册草稿

- 改动：`quant.intel.extract` 对可实现性评分 ≥0.7 的条目，生成族系 toml 草稿（参照 `configs/research/price_delay_family_v1.toml` 结构：机制、输入字段、列定义、方向、控制集、停止条件），放 `configs/research/drafts/`；Agent 或用户审阅后移入正式目录并入队。LLM 不直接写入 `queue/`。
- 验收：每周 ≤3 份草稿；每份字段齐全可被 `tomllib` 解析。

### C6 · 调度失败解释（低优先）

`automation_alert` 发失败通知时，附 LLM 对日志最后 200 行的一句话诊断与建议命令；≤$0.05/次，缓存同错误签名。
