## 6. 分支与 worktree 生命周期

- 只有活跃 owner、待合流成果或被运行身份绑定的任务可保留 worktree。
- clean 且无进程的闲置 worktree 优先移除；分支可暂留供语义对账。
- 删除含独有或审计价值提交的分支前，先建立指向精确提交的 `archive/*` annotated tag。
- 已完全合入、无 worktree 的冗余分支使用安全删除；禁止未经核对的强制删除。
- detached worktree 必须记录精确 HEAD、活跃输入和退出条件；不得清理其未跟踪正式配置。
- 创建新 worktree 前登记 branch、base、绝对路径、owner 和文件白名单。

## 7. 已冻结的结构风险

当前先记录、后拆成独立治理任务，不在 M2 结果收口中顺手大改：

- 新 daily-basic/financial publisher 复制安全敏感的不可覆盖发布、manifest 和路径校验逻辑，并借用 M3 命名模块；
- 多个 M2 `run_*` CLI 互相导入私有 helper，入口层正在成为公共库；

- M2 成本契约和配置依赖 M3 命名资源，后续需一次性迁到里程碑中立位置；
- 旧研究 code hash 绑定 checkout 物理字节，历史混合 EOL working tree 不能由 commit 单独复算；R10 不追改历史，
  后续单独评估 canonical text hash 或 `.gitattributes` pin；
- `data/`、`research/`、`configs/research/`、`tests/unit/` 已明显平铺膨胀，但当前不做大规模目录迁移；
- 多组包级双向依赖和大型聚合 `__init__.py` 需要后续按契约下沉处理；
- M4 soak runtime 已开始 import sibling underscore helper、穿透 verified composition 私有字段，并重复 finality
  schema literal；当前 fail-closed，但不得在下一条 close/barrier runtime 继续扩大；
- GUI 为满足有界只读校验复制了 lightweight-run V1 manifest parser；当前漂移会 fail-closed，下一次 schema 变化
  或出现第二个只读消费者前应由 research owner 提供公共 bounded manifest-only verifier；
- 通用月末交易日调度当前由 PIT 专属模块持有并被 daily/liquidity runner 复用；出现第三个消费者或新增 runner
  前必须下沉到里程碑中立的 research schedule/calendar 边界。
