# 自动化投研流程：机构实践与实施方案（2026-09-11）

结论：将自动化投研列为当前主线，复用已有 Python 数据、因子、模型、回测和账本模块，补齐数据质量、批量研究续跑、有限搜索、风控和成交反馈。Rust 重构暂停。目标是程序持续产出研究结论、次日订单参考和前向净值；本次调研与排期时间盒半天，各实现切片见 §6。

## 1. 公开机构实践与本项目取舍

以下区分公开事实与本项目设计。公开材料能验证流程思路，无法还原私募内部全部实现；表中“采用方式”是本项目的工程决策。

## 2. 数据：先确定什么时候可知，再确定能否使用

沿用 `quant.data` 作为唯一数据读取边界，扩展 `quant.data.refresh` 串联财务增量与因子增量。每个数据集明确主键、时间粒度、单位、复权口径、交易所日历和必要字段；对重复键、未来日期、单位突变、缺失分区与源间冲突输出可定位的记录。

财务与公告分别保存事件/报告期、公告可用时间、首次观测时间。历史回放使用当时可知的公告版本；新发现的更正只有在当时可知条件满足后才能进入信号，不能用当前最终值回填整段历史。原始响应写新分区，clean 新版本由 raw 重建；需要重算的因子范围由变更分区及回看窗口决定。

质量检查分成两层：单个字段/因子的有效覆盖，以及某个固定模型所需全部输入的共同有效股票池。预期数据量按交易所实际开市日计算；行情未到齐、股票上市未满窗口、合法停牌与计算错误分别说明。订单日期由交易日历生成，不用自然日偏移。

**本次实际缺口**：P4 已确定的 2024–2026 年度名单各含 20 项因子。完整输入预检为 2024 年 12/12、2025 年 12/12、2026 年截至当前可成交调仓月 2/8。2026 年 2 月仅 14 个开市日，冻结的月度流动性因子要求至少 15 个有效日，自由流通换手异常又要求当前及前 12 个月有效，因此共同截面从 2 月信号起为空。这是窗口定义与短交易月冲突；不能靠重新下载补出第 15 天。

现已增加 `model_signal_coverage.parquet` 及模型报告年度覆盖表，区分历史合格因子不足、共同训练样本不足、共同预测截面不足。原 P4 按冻结规则如实回放。下一批将三个相关流动性表达式统一登记为按交易日比例判断覆盖的新版本，在新配置中先固定比例、最小观测数及异常窗口；保留旧结果，不在已观察测试段反复挑阈值。

## 3. 研究：让程序生成、计算、淘汰和推进

研究入口分两类输入：文献及既有库提供的表达式模板，以及预注册的模型/组合模板。程序负责展开窗口和参数、生成批次、计算、评估、选因子、训练、回测和报告；Agent 负责确定经济假设、可用字段语义、搜索范围及读结果后的下一批方向。

首版用现有 DSL 做有限枚举，每批 20–50 个候选，配置固定随机种子（如使用抽样）、窗口集合、表达式最大深度、候选总数、并发和运行预算。限制算子与字段白名单，拒绝负向时移、无意义单位组合、超深表达式与完全重复表达式。计算后剔除常数、严重缺失和数值重复候选；这些淘汰项也保留原因和试验计数。首版不依赖自由生成 Python 代码。

处理次序为：输入质量与覆盖 → 因子计算 → 完整历史统计 → 开发期冗余过滤 → 统一成本与容量 → 年度选择 → 三模型 → 统一账户回放 → 结论。能够确定淘汰的候选先结束昂贵计算；成本尚未完成的候选不能当作成本合格。长期任务结束后程序自动进入下一步，重启时识别已有完整结果，只补缺项，复用现有 run/config，不新建调度治理体系。

统计纪律必须伴随搜索自动化：

- 搜索反馈及模型选参只用 train/validation，按逐年截止日生成当时可用的候选和训练输入。
- ≥96 个月统计、NW t、ICIR、年度符号、分组、多空、冗余及 0.5×/1×/2×成本仍按统一配置执行。不能把短年组合收益当作因子晋级依据。
- 同一搜索活动包含所有尝试及失败项；能够形成检验值的完整家族进入多重检验，不能只对幸存者重算 FDR。自适应搜索的 FDR 不保证消除选择偏差，最终验证依靠预先隔离的测试与前向记录。
- 已经看过的历史测试区间标明为已使用，后续迭代不能重新称作未触碰测试。保留测试仅使用一次；当前历史主要用于开发和滚动诊断，新的独立证据由后续前向数据积累。

策略搜索同样程序化，但限制在预先列出的模型/组合规则模板，例如等权 z、IC 加权、LightGBM 及固定缓冲规则。每个策略级配置一次定义假设、单变量网格和通过条件，程序在 validation 选参并冻结测试方案；不因某次结果不佳自动扩大网格直到通过。达到既定条件自动给出三类研究结论并衔接 PAPER；真实资金动作仍由用户决定。

## 4. 日常生产：从更新数据到实际持仓

每日链路：更新 raw/clean → 数据与共同输入检查 → 因子增量 → 固定模型预测 → 目标持仓 → 风控与整手订单参考 → 用户手工成交记录 → 持仓/现金对账 → PAPER 净值与归因。非调仓日更新数据和账本；月末按既定配置执行重训及调仓。模型版本变更遵循研究配置，日常预测不自行搜索参数。

数据缺口触发明确的受影响模型诊断，阻止依赖缺失数据的新增买入；已有仓位继续计价、记录风险并按预设的暂停/仅卖出规则处理。缺信号不能隐式解释成“清仓”。每个模型在启用前固定缺失数据政策；冻结回测仍按其原规则报告。

风控复用现有账户、交易限制和开关，在策略以外检查：现金及现金缓冲、T+1 可卖股数、整手、涨跌停/停牌、单股及行业集中度、风格偏离、换手、持仓与订单合并后的暴露。阈值放版本化配置，研究/回放/PAPER使用同一语义。新增阈值需新策略配置验证，不把调研建议直接改进旧策略参数。

容量诊断用持仓市值除以“预设参与率 × 历史可用日均成交额”估算变现天数；停牌或无法成交的头寸单列。压力情景包括成交量下降、成本翻倍、连续无法成交和行业共同下跌，参数先固定，再观察表现。持仓回撤触发什么动作由配置规定，避免临时让 LLM 决定减仓。

实际成交导入至少包括交易日期/时间、证券、方向、股数、价格、费用及外部成交编号；重复导入不重复记账。部分成交、拒单、撤单和未成交保留，下一次订单从实际持仓和可用现金计算。费用、分红及出入金分别记录，外部出入金剔除后再计算策略收益。

成交分析以可观测的信号/计划参考价为基准，按方向计算实际成交价偏差，费用单列；分钟信号另报 0/1/3 分钟可成交基准。未成交量与机会成本单列并说明估价方法，避免只看已成交样本。按月用前向记录校准新的滑点参数版本，历史报告保留原口径。

## 5. 自动运行的最小实现边界

在现有 CLI 内按依赖顺序调用模块，利用现有 run 目录和输出判定恢复位置。独立候选可并行，数据发布与同一输出写入串行。失败分为可恢复数据请求、候选计算异常及输入不合格；有限重试后保留原因并继续无依赖工作，不能静默吞掉失败。

成功运行生成简短结果摘要及产物位置；已有完整输入和输出的重复运行应为 no-op。定时运行只在有新结论、数据异常、订单参考或需人工处理的对账差异时通知。默认先把单命令运行和中断恢复验证好，再连接已有日常调度，避免额外引入常驻服务。
