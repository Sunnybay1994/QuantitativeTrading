# 因子挖掘流水线：设计与人机分工（2026-09-10）

> 本文回答两个问题：为什么 93 个假设没有产出"有效策略"；接下来怎样把因子挖掘变成自动流水线，让 Agent 只做机器做不了的事。
> 本文是阶段 B2 的总设计，路线图 §1 的任务从这里来。

## 0. 诊断：不是因子无效，是评估方式没有统计功效，且组织方式是串行的

2026-09-09 → 09-10 的 36 小时里，Agent 完成了 93 个假设、53 个 run、约 180 次提交，平均每 15 分钟一个"预注册 → 跑 → 记录"闭环。这个速度本身说明基础设施已经很好；问题在三处：

**1. 单折窗口太短，"配对增量"是噪声。** 现行协议把 2024 / 2025 / 2026 各当一折测试，用 Top50 等权组合的年度收益差来判定一个因子"加入三因子后有没有增量"。50 只 A 股等权组合一年收益的标准差约 10–15 个百分点，所以 B69 的 +13.28pp、B65 的 −8.07pp、B81 的 −41pp 都在噪声范围内——这些 RETAIN/REJECT 判定基本是抛硬币。它们看起来"预注册且严谨"，但没有统计功效。

**2. 单因子串行，无法形成组合。** 排行榜上已有 30 多个 `RESEARCH_ONLY` 因子，包括 IC 均值 ≥ 0.05 的一批（Alpha#6 0.074、低 β 0.062、Alpha#26 0.064、OCF/P 0.058、CV20 0.058、小市值 0.052、季度 ROE 稳定性 0.050），但它们只被逐个和三因子基线配对过，从未被放进同一个截面模型里一起估计、去冗余、加权。多因子 alpha 的来源恰恰是"很多弱信号的正交组合"，串行流程结构性地拿不到它。

**3. 仪式化的预注册。** "每个假设一个 config、两次提交"对策略级研究是对的，对"再试一个 Alpha101 表达式"是浪费——真正需要预注册的是**因子评估流水线的阈值**（一次写死），而不是每一个表达式。

已经拿到的、被低估的结果：B93 把 CV20 缓冲策略放到 2020–2026 连续 6.5 年上，1× 成本后年化 +8.14%、Sharpe 0.48、MDD −31%，对比 510300 年化 +3.37%、Sharpe 0.27、MDD −41%。这就是一个可用的单因子长多策略；配上上面那批 IC ≥ 0.05 的因子做正交组合，加上规模/行业约束，是本项目最接近钱的路径。

结论：**把"Agent 逐个跑假设"改成"流水线批量算全部因子、统一评估、系统组合；Agent 负责产生候选、读结果、做策略级判断"。**

## 1. 分层架构

```
L5  LLM/Agent 层 —— 读文献/研报 → 批量写因子表达式；读 scorecard 做诊断；策略级与市场状态判断；文本信号
L4  模拟盘 —— 已有（S0 + B20/B32 前向账户）
L3  组合与模型 —— 因子选择/去冗余/加权（等权 z、IC 加权、LightGBM）→ 组合构建（Top-K、规模/行业中性、缓冲区）→ 全历史回测
L2  因子评估流水线 —— 对每个因子自动跑同一套指标 → factor_scorecard.parquet（一行一因子）
L1  因子库 —— 声明式因子定义（表达式 DSL + Python 函数）→ 全市场全历史因子面板 data/factors/
L0  数据 —— 已有：日线 1990–2026、daily_basic、PIT 财务、5 分钟线、ETF、港股
```

L1–L3 是**无人流水线**：一条命令跑完，输出固定格式，每日/每月增量。L5 是 Agent 唯一该待的地方。

### 1.1 L1 因子库

- 因子定义放 `src/quant/factors/library/`，两种形式：
  - **表达式**（覆盖 80%）：Alpha101/Alpha158 风格的算子 DSL，字段来自日线、daily_basic、PIT 财务（按 `ann_date` 对齐）、分钟低频化日频表。算子：`ts_mean/ts_std/ts_rank/ts_corr/ts_cov/delta/delay/decay_linear/ts_max/ts_min/ts_argmax/rank/scale/sign/log/abs/ind_neutralize`。一个因子 = 一行 TOML：`id、expr、family、direction、source_ref`。
  - **Python 函数**（复杂的 20%）：PEAD/SUE、聪明钱、事件类。
- 计算范围：**全市场 A 股、2010-01 起至今**（不是只算 Top800；池过滤放在评估层），输出 `data/factors/<factor_id>/year=YYYY/*.parquet`，列 `trade_date, ts_code, value`。每日增量只算最新一天。
- 现有约 60 个因子实现全部迁入（已有代码，重点是登记与统一接口），再加 Alpha101 全部 101 式、Alpha158 未覆盖部分、PIT 财务 30 个、分钟低频化 9 个。**首批目标 ≥ 200 个因子**。

### 1.2 L2 因子评估流水线（预注册一次，对所有因子相同）

本项目统一称“因子评估流水线”：候选表达式经按日计算与 PIT、缺失值、极值处理后，批量计算 RankIC、Newey–West t、ICIR、分组与多空收益，并评估换手、容量与成本敏感性，最终输出 scorecard，供保留、淘汰或进入组合使用。其中固定的一组检验称“评估指标集”。本节指标表描述具体评估内容，术语统一不表示各项实现已全部完成。现有 `factor_battery_*` 模块名、`battery.toml` 及历史产物路径保留兼容；其含义均为因子评估。

输入：因子面板 + 收益面板（复权总回报，T+1 开盘到 T+h 开盘）。每个因子输出一行到 `artifacts/factors/scorecard/<date>/factor_scorecard.parquet`：

以下为固定的评估指标集：

| 组 | 指标 |
|---|---|
| 样本 | 起止、月数、有效股票数中位数 |
| 预处理 | MAD 3σ 去极值、规模+行业中性化（两版都算：原始 / 中性化）、z-score |
| 可交易过滤 | 剔 ST、上市 < 120 日、停牌、信号日涨跌停、日均成交额后 20% |
| 预测力 | RankIC 序列（月频与 20 日）、IC 均值、ICIR、**Newey–West t**、正 IC 月占比；按日历年分段的 IC 符号 |
| 单调性 | 10 分组年化收益、多空（D10−D1）年化与 Sharpe、Top 分组多头年化与对全市场等权的超额 |
| 衰减 | 1/5/10/20/60 日 IC |
| 换手 | 因子月度自相关、Top 分组月换手 |
| 冗余 | 与库内所有已评估因子的截面秩相关最大值及对应因子 |
| 成本 | Top 分组 1× 成本后年化（沿用 `daily_account` 费用）|

**通过阈值（写死在 `configs/factors/battery.toml`，看结果前不改）**：样本 ≥ 96 个月（2018–2026）且优先 2013 起；|NW t| ≥ 3.0（Harvey–Liu–Zhu 对因子动物园的多重检验门槛）；ICIR ≥ 0.3；年度 IC 符号一致率 ≥ 70%；多空 Sharpe ≥ 0.5；与已有更高分因子最大秩相关 < 0.7（否则标 `REDUNDANT`）；Top 分组 1× 成本后超额全市场等权 > 0。全部通过 → `ADMITTED`；预测力过而成本/冗余不过 → `WEAK`；否则 `REJECTED`。对每期 scorecard 做 Benjamini–Hochberg FDR 5%，报告"多少个通过是偶然的预期数"。

基准：**同时报对 510300、中证 800 等权、全市场等权**三个基准。Top50 组合天然偏小市值，只对 510300 比较会把规模暴露误认为 alpha。

### 1.3 L3 组合与模型

- **因子选择**：从 `ADMITTED` 中按 ICIR 贪心加入，带相关性惩罚（ρ > 0.6 不再加入），或直接把全部 ADMITTED 因子交给模型。
- **三种组合方式并排跑**：① 等权 z-score；② 滚动 12 个月 IC 加权；③ LightGBM/岭回归 rank 模型，**逐年扩展窗口 walk-forward**（训练 ≤ T−1 年，预测 T 年），标签为下月超额收益 rank。
- **组合构建**：Top-K（50/100）等权或分数加权；可选规模/行业中性（对中证 800 权重）；Top75/Top100 缓冲区；月度或双周调仓；单边年化换手上限 6×。
- **全历史回测**：2015-01 → 今，用 `daily_simulator`（T+1、涨跌停、停牌、整手、历史税费、分红），报 1×/2× 成本、三基准超额、年度收益表、MDD、水下期、极端窗口（沿用 B93 的四个窗口）。
- 输出 `artifacts/models/<model_id>/`：`report.md`、`nav.csv`、`holdings/`、`factor_weights.csv`，以及一条排行榜行。

### 1.4 增量运行

- `python -m quant.factors.update --to today`：因子面板增量 → 接入 `quant.data.refresh`。
- `python -m quant.factors.battery --as-of <month_end>`：月末重跑 scorecard（全历史，约 200 因子，目标 < 1 小时）。
- `python -m quant.models.rebalance --model <id> --as-of <month_end>`：生成目标持仓 → 模拟盘。

## 2. 人机分工

| 事项 | 流水线（无人） | Agent（LLM） |
|---|---|---|
| 计算因子、跑评估、算 scorecard、FDR | ✅ | 不做手工单因子 run |
| 因子选择、加权、组合回测、报告 | ✅ | 读报告，不手工挑因子 |
| 每日数据/因子增量、月末调仓单 | ✅ | 看失败日志 |
| **产生候选因子** | — | ✅ 从文献、卖方研报、Alpha 库、开源项目批量写表达式：**一次 20–50 个**，登记进库后交流水线 |
| **读 scorecard 做诊断** | — | ✅ 哪些族系有效/失效、为什么、缺什么族系、下一批往哪找；写一页月度诊断 |
| **文本/另类信号** | 评估仍走因子评估流水线 | ✅ 公告、业绩预告、研报摘要、新闻 → 结构化特征（情绪、事件类型、超预期程度）→ 注册为因子。这是 LLM 相对传统量化的真实比较优势 |
| **策略级决策** | 提供回测 | ✅ 选模型、定风险预算、换手上限、是否行业中性、何时切换模拟盘策略——每个决策仍是一页预注册假设 |
| **市场状态研判** | 系统性指标（200 日线、宽度、信用利差、成交额分位） | ✅ 月度市场简报：宏观、政策、资金面叙事 + **明确可打分的预测**（下月 510300 方向、风格：大/小、价值/成长）。预测入库，季度算 Brier 分；**12 个月内不得影响任何持仓** |
| **基础设施维护** | — | ✅ 流水线本身的代码、测试、性能 |

三条 Agent 行为规则（进 AGENTS.md）：
1. **工作单元是"因子批次"和"模型"，不是单因子。** 不再为单个表达式写假设卡；假设卡只用于模型/策略/组合规则级别。
2. **凡是 1 年窗口上 Top50 组合的收益差，都不构成证据。** 证据是全历史 IC 序列的 NW t、多空 Sharpe、年度符号一致率。
3. **先读 scorecard，再写下一批。** 每批因子必须说明"针对 scorecard 里哪个缺口"。

## 3. 关于 TradingAgents 类框架与"LLM 行情研判"的判断

[TradingAgents](https://www.zdoc.app/zh/TauricResearch/TradingAgents) 的结构是：基本面/情绪/新闻/技术四类 LLM 分析师 → 多空研究员辩论 → 交易员 → 风控/组合经理，对单只美股给出买卖决策；数据来自 Yahoo/Alpha Vantage/Reddit/StockTwits；其 README 明确说明"专为研究目的设计"、"同一代码和日期两次运行可能不同"、"回测结果不保证与任何公开数据一致"。

专业判断：

- **不能借用的**：让 LLM 讨论后直接输出交易决策。这是不可回测、不可归因、不可复现的判断链；A 股上没有任何公开证据表明这种方式能稳定跑赢因子模型。个人投资者用它做个股择时，期望值为负（成本 + 噪声）。
- **可以借用的**：① 分角色的**文本摄取**结构——把公告、研报、新闻按来源分工解析成结构化特征，是产生文本因子的好工程模板；② 它的**反思记忆**（决策 → 实现收益 → 反思注入下次提示）——对应我们的"预测入库 + Brier 打分"；③ 决策日志。
- **A 股落地方式**：LLM 产出的一切都先变成**可评估的信号列**，走 §1.2 同一套因子评估流水线。第一个试点：用 Tushare `forecast`/`express`（业绩预告、快报）与巨潮公告标题，让 LLM 打"超预期程度 / 事件类型"分，注册为因子，看它相对 SUE 数值因子有没有增量 IC。有 → 扩到研报摘要与新闻；没有 → 说明 LLM 文本信号在这个数据条件下没有增量，把时间还给因子库。
- **行情研判的定位**：LLM 擅长把宏观/政策/资金面信息组织成叙事，不擅长预测。所以月度简报必须附带可打分预测，攒 12 个月记录再决定它能否影响风险预算（比如仓位 70%–100% 之间的调节）。在此之前它是给用户读的，不是给策略用的。

## 4. 自动搜索（遗传编程 / 随机表达式）——可选，排在文献批次之后

- 在 §1.1 算子集上做符号回归（gplearn 风格），适应度 = 训练期（2013–2021）ICIR，惩罚项 = 表达式深度 + 与库内因子相关性；产出只有在 2022–2026 保留期通过 §1.2 因子评估流水线才可登记。
- 预期产出低、过拟合风险高，**时间盒 3 天、算力盒一晚**；不通过就停。它是文献驱动批次的补充，不是主路。

## 5. 统计纪律（这些就是"预注册"，只写一次）

- 因子评估必须用全历史（≥ 96 个月）；单折 ≤ 3 年的组合收益差只做描述，不做判定。
- 多重检验：t ≥ 3；每期 scorecard 报 BH-FDR；报告"本期评估 N 个，预期偶然通过 M 个"。
- 模型 walk-forward 只能逐年扩展，不得在测试年内调参；组合规则（K、缓冲、换手上限）在 `configs/models/*.toml` 中固定。
- 三基准并报；小市值暴露单列。
- 任何模型进模拟盘前必须过 B93 那四个极端窗口和"最长水下期"表。
