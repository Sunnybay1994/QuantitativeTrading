```powershell
D:\Miniforge3\python.exe -m quant.research.run_research_cycle --config configs/research/research_cycle_p3_v1.toml --output artifacts/research/<新循环目录>
```

默认只做离线诊断计划，后续候选与评估等待真实诊断。显式`--execute`后按诊断、候选生成、既有搜索函数依次运行，两个LLM阶段共用配置中的累计限额；当前20次额度已耗尽，本配置不增加授权。每批最多20候选、252日历史，继承既定评估日期和门槛。
失败、延期或预算不足会保存阶段结果并返回非零；不执行模型输出的命令。循环要求新目录，成功模型请求可由同一缓存复用，评估中断可直接用既有搜索入口恢复。
真实离线集成在`artifacts/research/research_cycle_p3_plan_20260912_01/`：282条事实与直接诊断完全一致，包含三个模型，候选/评估未运行，累计请求仍20。完整循环费用因候选输入尚未知而留空。16项模块测试、Ruff及mypy通过。

入口把已保存、事实引用有效的诊断想法整理为DSL候选，复用既有 `expand` / `prepare`，只准备批次，不自动运行收益评估。

```powershell
$env:PYTHONPATH = 'F:/AI_Coding/QuantitativeTrading/src'
D:\Miniforge3\python.exe -m quant.research.generate_factor_candidates --diagnosis artifacts/research/deepseek_diagnosis_live_20260912_01 --design configs/factors/search/p6c_finite_batch01_window02_20260911.toml --scope "价量归一化相关性；历史诊断仅用于提出假设" --fields adj_close volume --operators delay ts_mean ts_corr --maximum-candidates 4 --maximum-history 60 --output artifacts/research/dsl_candidates_new
```

默认dry-run：不读密钥、不请求API、不生成占位因子；冻结请求和输入，输出费用规划。允许列/函数必须是选定设计的子集，候选数不得超过设计上限。
算术及量纲检查复用现有search的有限词汇，不扩展成任意Python表达式。嵌套窗口按DSL的真实累计历史检查。

按AGENTS月度LLM授权设置显式累计预算，真实生成增加 `--execute --max-requests <累计上限> --max-usd <累计美元上限>`。
默认复用 `artifacts/research/p7_deepseek_cache.sqlite`；历史20次测试上限配置仍会正常阻止新增请求；修改预算只适用于新循环，本次恢复开发未增加调用。
真实调用只有成功生成至少一个合格候选才返回退出码0；预算耗尽、非高峰延期、调用失败或全部候选被拒绝时，保存结果后返回1，供上层流程决定重跑。离线规划仍返回0。16项候选模块测试、Ruff及mypy通过。
默认只在谷时发请求，`--development-test`仅放开时段，不放开预算；成功生成可从相同缓存复用。

模型只输出 `candidates` 数组，每项为 `expression`、整数 `direction`（±1）、`rationale`、`sources`。
来源必须是请求中 `diagnosis#/candidates/<序号>`；上游诊断的事实引用先由现有解析器核验。
不合格候选逐条保存：字段/方向/来源错误、未来窗口、未知算子/列、深度/历史超限、既有库或本批AST重复。
模型内容始终是数据，不通过eval、Python或shell执行。

在生成前保存设计、日期、API预算、提示词、诊断和事实，并复制选定battery/refresh配置。
训练/验证/未来日期及费用和评估阈值来自原设计，模型不能制定。每个研究目录建立独立registry副本，
合格候选写入该副本和 `prepared/library/`，不修改项目因子库。

成功时输出 `batch.toml`、`candidates.json`、`run.json`（包含所有尝试及原因）。`run.json.next_command`

## 研究循环同目录恢复

`run_research_cycle` 默认仍在新目录干跑诊断；真实循环显式加 `--execute`。中断后使用原配置、原目录及相同执行模式：

```powershell
D:\Miniforge3\python.exe -m quant.research.run_research_cycle --config configs/research/research_cycle_p3_v1.toml --output artifacts/research/<原循环目录> --execute --resume
```

`--resume` 核对原始评分表、全部assessment、设计、因子库及battery/refresh/LLM配置内容，同时核对已完成阶段的保存文件。成功诊断复用引用校验后的JSON；合格非合成候选复用原批次及prepared库。评价继续直接调用原 `run_factor_search`，复用它的阶段与成本检查点；完整循环重复恢复不再调用LLM或评价函数。

未完成LLM目录保留为 `diagnosis_partial_001` / `candidates_partial_001` 等，然后使用相同共享缓存重建该阶段；成功请求可从缓存取回，未知请求状态不会自动重发。请求数和金额上限不能通过恢复扩大、换缓存或添加 `--development-test` 重置。开发参数只放开时段；生产仍在谷时请求。

变化输入、修改/缺失的完成产物、合成候选、缺失或累计用量回退的缓存都会拒绝恢复并保留原结果。旧版本未记录输入指纹的循环不能直接迁移恢复；干跑目录也不能通过resume切换为真实执行。需要新研究输入时新建循环，仍沿用共享累计缓存，按现行AGENTS授权配置预算。

失败/预算耗尽/未知状态仍退出1，恢复输入无效退出2。根目录 `run.json` 保存各阶段结果、文件核对信息和累计缓存用量；中断时原有成果不会删除。大体量因子面板继续由因子搜索的既有恢复逻辑管理。
