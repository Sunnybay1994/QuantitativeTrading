# 时间序列基础模型与金融迁移

**当前优先级：保留为后备模型研究方向，暂不投入新的训练或部署。** 已读金融实证不足以支持“下载通用预训练权重即可改善A股月度收益排序”；更有价值的近期工作，是把序列输入、预测期、反归一化和实际收益标签先对齐。这个判断针对当前项目的投入顺序，不是对所有时间序列基础模型的否定。

研读日期2026-09-12，时间盒45分钟。主体精读Chronos、TimesFM初代方法，以及一篇真正使用全球股票日收益的金融研究；另核官方新版说明，避免将2024年能力当成2026年现状。下文合成例只演示定义差异，未运行基础模型。

## 2. 三篇分别提供什么证据

### Chronos：把通用数值序列学成概率预测

初代Chronos按历史上下文的平均绝对值缩放，再量化为离散token，以交叉熵训练T5结构。其训练集合有28个公开数据集，并用混合序列和高斯过程合成数据扩充；主训练上下文512步、输出64步。表3明确区分训练集、同域留尾测试和27个未用于训练的数据集。评估采用WQL与中位数预测的MASE；“finance”还包括ATM取款和汇率，并非A股截面选股。§5.5.2脚注5另承认，严格时间隔离比数据集不重叠更强。[方法、评估与脚注](https://arxiv.org/html/2403.07815v3)。

对本地的增量是提供一种已学通用动态的序列预测器。它不需要P7公告文本，也不是通过语言模型的财经常识直接给订单。采用语言模型结构、加载语言权重、用数值序列预训练是不同操作，不能统称“LLM已懂股票”。

### TimesFM：分块提高序列处理效率，预测目标仍需另定

初代TimesFM将连续数值分块，经解码器预测未来块，以MSE训练点预测。§5所列资料以Google Trends、Wikipedia浏览量、合成序列及公共时间序列为主；使用上下文首输入块的均值、标准差进行归一化。§6.1比较Monash、Darts和ETT等留出的任务，主要指标是相对朴素预测的MAE；ETT使用末尾测试窗，预测96/192步。它不是以可交易股票月收益训练的排序模型。[原方法](https://arxiv.org/html/2310.10688v4)。

本地需要问的是“这些通用动态在给定股票历史中提供什么额外信息”，而不是模型能否输出一条平滑曲线。已有复杂度专题讨论的是特征到收益的截面映射；把每只股票自己的历史序列交给基础模型，又改变了输入信息和模型结构，不能将差异全部归因于网络大小。[已有比较](20260912_机器学习复杂度与简单基线.md)。

### 金融研究：领域训练、零样本与成本结论必须分开

该文使用1990–2023年全球股票日超额收益，主美国测试期2001–2023；比较原权重零样本、逐年微调和逐年从头训练。输入窗口5/21/252/512日，目标均为下一日收益。表6的512日全样本R²，Chronos Large为−1.37%、TimesFM 2为−2.80%、CatBoost为−0.03%；表值是各年统计的平均。金融从头训练改善部分表现，但表12的每日等权多空十分位在作者20bps情景下均为负Sharpe。[§3–5、表6与12](https://arxiv.org/pdf/2511.18578v1)。

这比“有一个finance类别”更接近本项目，却仍有关键迁移限制：**表12未在已读段落明确20bps究竟按成交额、双边换手还是组合日额扣除。** 因此只能引用作者情景结果，不能对齐为本地1×成本，也不能反推本地盈亏平衡费率。作者同时比较了更便宜的树模型，说明有必要将强基线和成本放在同一个问题里，而非只在基础模型内部排榜。

## 3. “零样本”并没有一次性解决无前视

下面四种说法对应不同证据，不能相互替代：

|说法|真正承诺|本地需要补问|
|---|---|---|
|推理时零样本|没有对这批输入更新模型参数|权重训练时是否见过未来？是否在历史测试结果上挑了权重或窗口？|
|目标数据集未参与预训练|这份命名数据集被留出|同一标的、同一事件或同一序列的其他来源是否重叠？|
|按时间切断训练资料|训练信息截止早于待预测时期|预处理、特征选择、超参选择及外部权重是否也满足截止？|
|真实前向预测|结果发生前实际保存预测|输出目标、发布时间、交易端点和失败样本是否保持原定义？|

例如，在2026年下载一个通用模型，把2015年的股票序列作为上下文。即使本地只提供2015年前的数据，模型权重仍可能来自2020年以后的资料。因果注意力只限制当前输入位置之间的访问，不能消除权重中已经学到的信息。这是输入无前视与预训练无前视的区别。

反过来，2025年发布一个仅以1990–2000年资料训练的权重，并不会因为发布日期晚，就自动证明它使用了2001年后的标签。它可以用于“按历史信息训练程序”的回顾研究；只是不能声称投资者2001年已经实际拥有该模型，也仍有后来的研究者选择问题。报告应保留训练截止、权重版本、下载/发布时点三个概念。

金融研究正好显示这个区别：其§5使用一个公开通用权重覆盖整个历史测试期，脚注17承认可能存在预训练前视；年度从头训练是另一个研究设定。后者的改善并不证明“原权重已有金融迁移能力”，也没有替本地解决数据修订、股票池及历史模型选择问题。

### 已有本地无前视机制该怎样复用

当前[固定预测入口](../../../src/quant/research/run_fixed_model_forecast.py)约束已知训练退出日和年度模型范围，[评分入口](../../../src/quant/research/score_model_forecasts.py)区分及时前向记录与演练。新序列模型若进入研究，也应生成同样的股票—信号日预测对象，沿用这些时点含义。

“冻结现成权重”本身不提供2010年以来的严格因果训练记录。若无法核实预训练截止，长历史输出最多是兼容性和机制探查；真正新增的前向证据从冻结后开始累积。不能通过增加历史月份数量，把时间污染的不确定性变成满足96个月研究门槛的证据。

## 4. 归一化、缺失和股票池会改变问题

### 按历史缩放与按全历史缩放不同

归一化可以帮助跨资产共享模型，但均值、尺度、异常阈值都必须来自当时可用区间。将整个2010–2026序列先标准化，再截取2015年上下文，已经把后期分布带入输入。按训练前缀或当前上下文计算才符合本地时点要求。

还需区分模型内部缩放与人工再次标准化。初代两模型采用的缩放并不相同，新版实现也可能变化；不能以“都是归一化”为由套同一前处理。是否还原尺度，会直接决定最终排序的是原收益还是某种风险调整后的量。

合成例：A股票的历史尺度为1%，B为4%；模型对缩放后下一期收益分别给0.2、0.1。直接按输出排序是A优先；还原后分别为0.2%、0.4%，排序变为B优先。这不是数值精度问题，而是目标不同。若有意按风险调整分数排序，应把它登记为明确的组合或模型规则，不能在回测后选表现更好的解释。

### 输入缺失与收益标签缺失必须分别处理

序列模型能接收PAD、mask或插补值，不意味着某只停牌股票产生了真实可成交收益。对输入历史做插补，是为模型表示提供一项假设；对目标收益补出一个值，会改变评分对象。二者不能因为使用同一个DataFrame就混在一起。

金融论文§4.2按国家—日期对内部缺口用当日截面中位数插补，并保留上市期边界；本地不应直接抄成“缺退出价就用当日市场收益”。当前[收益标签](../../../src/quant/research/factor_labels.py)与[前向标签读取](../../../src/quant/data/model_forecast_labels.py)要求实际端点价格，已有[退市与幸存者偏差专题](20260912_退市收益与幸存者偏差.md)解释了缺标签与实际持有延长的差异。

对于序列输入，可先记录缺失mask和有效历史长度。删掉缺失日并重新编号，会把隔三天才观察到的价格伪装成相邻交易日；补零收益又可能人为制造稳定性。这些需要基于交易日历和停牌含义选择，不能交给通用预测库默认行为决定。

金融论文主美国样本筛去低价股并限制普通股；其全球训练范围也不等于单独证明A股有效。本地应保留既定`eligible`、规模及行业口径，另看模型是否仅改善易预测但难成交的股票。新增模型需要更多历史才能输出时，被排除的短历史股票也会改变样本；比较时同时报共同样本结果与全池覆盖。

## 5. 从未来数值到本地持有期收益，中间还有两步

### 预测第21个日收益，不是预测一个月的累计收益

`prediction_length=21`通常表示输出未来21个序列值。若输入是日收益，最后一个输出对应第21天的日收益，不能直接拿它与一个月的`label_rebalance`比较。若输入是价格，最后一个点只是未来价格水平，还要选择正确进入端点和复权口径。

当前本地标签为下一开盘进入、下次月度调仓开盘退出的复权价格比。两次月度调仓间的交易日数不固定，因此“21步”也不是交易日历合同。模型历史窗口长252日，不代表目标持有期长252日；金融论文的5/21/252/512是输入长度，预测始终一步。[本地月度日历](../../../src/quant/data/model_forecast_labels.py)。

合成端点：信号日收盘100，下一可进入开盘110，下一次调仓开盘109。相对信号收盘看似上涨9%，本地持有期实际为`109/110−1≈−0.9091%`。即使未来退出价格预测完全正确，错误分母也会产生虚假的收益优势。先匹配端点，再讨论模型大小。

### 每日边际分位数并没有给出跨日联合分布

考虑两个未来交易日，每日收益边际分布均为各50%的+10%或−10%，因此每天期望收益都是0。下面两种联合分布却有不同累计回报：

|未来路径的依赖关系|两条等概率路径|各路径两日累计收益|平均累计收益|
|---|---|---|---:|
|同方向|(+10%,+10%)；(−10%,−10%)|+21%；−19%|+1%|
|相反方向|(+10%,−10%)；(−10%,+10%)|−1%；−1%|−1%|

把每天均值0直接复合，两种情况都会得到0；每天的分位数也无法区分它们。一般而言，`E[∏(1+r_h)−1]`不能替换为`∏(1+E[r_h])−1`。这不是说多步点预测无用，而是其直接复合输出并未自动成为期望月收益。

同理，每日10%分位数逐日复合，不自动等于月度10%分位数。若输出的是联合采样路径，才可以对每条路径按本地进入/退出日期计算持有期收益，再对这些收益求均值或分位数；若只有各步边际分位数，还缺少跨期依赖假设。输出接口能生成多列quantile，不能据此声称已解决这个问题。

这与[预测校准专题](20260912_预测校准与排序能力.md)相连：必须先说清最后的预测列是收益均值、中位数、价格水平还是排序分数。对数收益取均值后再指数还原，也不能自动解释为算术收益均值。

## 6. 新版能力与公开复现能力分别核对

### 2026年能看到的接口，不止初代单变量

- **Chronos-2**：官方仓库记2025-10-20发布；已读模型卡的Overview与Training data。当前支持多变量及过去/未来已知协变量，训练资料列Chronos数据子集、GIFT-Eval Pretrain子集及合成数据。本文未精读其新技术报告，因此不沿用初代token化描述解释Chronos-2内部实现，也不转述其榜单排名作为金融结论。[官方发布记录](https://github.com/amazon-science/chronos-forecasting)、[模型卡](https://huggingface.co/amazon/chronos-2)。
- **TimesFM-3**：官方博客2026-08-31发布；已读架构、协变量和模型卡Data。原生多变量能力已改变初代边界；模型卡对Wikipedia列2023年11月截止、对Trends列2022年末截止，但未提供覆盖所有新增训练来源的单一截止。源码许可与权重许可也不同，3.0权重当前限制为非商业、非生产用途；2.5及以前权重仍为Apache-2.0。[官方发布](https://research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/)、[模型卡](https://huggingface.co/google/timesfm-3.0-pytorch)、[仓库许可说明](https://github.com/google-research/timesfm)。

“未来已知协变量”只允许预测时已经知道的数值，例如已发布的交易日历。未来实际成交额、未来实现波动率、事后修订财报，即使API容许传入，也不能因此变为合法输入。跨股票联合建模还需处理当日名单变化和不同时区的信息时点；本轮不会因接口新增而自动扩大输入范围。

金融v1的主表是初代Chronos及TimesFM 1/2；后续多变量模型可能改变结果。现有证据支持“该研究中的直接迁移不强”，不支持“2026全部新版已被同一实验否定”。

### 开放权重不等于原表完整可复现

初代两模型均有官方代码、权重和数据来源说明，可供未来固定版本评估。但权重可下载与本机Windows Python 3.13能稳定运行、一次全池推理成本可接受，是不同事实。当前[依赖文件](../../../pyproject.toml)未列Chronos、TimesFM、PyTorch或Transformers，本地性能与适配工作量尚未测定。

金融作者[官方仓库](https://github.com/DeepIntoStreams/TSFM_Finance)README实际描述权重加载和两只美股的小型预测示例。它不能作为已经取得全部CRSP/Compustat样本与表12交易成本实现的证据。本轮没有核到公开完整训练数据或对应费用计算式。

另外核了一张具体金融权重卡：[FinText/TimesFM_20M_2022_Global](https://huggingface.co/FinText/TimesFM_20M_2022_Global)。卡片明确训练数据为1990–2022全球超额收益、19.8M参数；这比只写“金融大模型”更可定位。但它的每日收益任务、国家清洗和归一化仍须核对，不能凭年份名称直接接进本地月收益模型。未来也不必重做作者的全规模训练，先讨论已有权重的一个明确用途即可。

## 7. 对当前项目的投入排序与一个有界下一步

|方向|当前优先级|理由|
|---|---|---|
|替换现有多因子LightGBM、直接进入持仓|暂不投入|已读金融证据的输入、预测期与成交设定不同，尚无本地增量|
|从头训练金融基础模型或遍历多个大模型|暂不投入|同时改变资料、初始化、架构和搜索规模，当前没有测得必须这样解决的瓶颈|
|固定一个权重，作为独立预测列做小范围研究|后备；先完成下面的输入/标签诊断|可检验序列动态是否增加信息，但需要可解释的目标及时间边界|
|仅看价格曲线视觉贴合或通用榜单|不足以触发新模型假设|持久价格水平、季节规律与可交易月度超额是不同任务|

### 下一步：先做序列到月标签的对齐诊断

复用已保存的月度信号、交易日历和端点行情，固定少量股票—月案例，覆盖连续行情、内部缺行、进入或退出端点缺失三种情形。这是按已保存缺失类别取例的接口核对，不用于估计预测准确率；未来正式评价的股票池仍只能由信号时点可知信息确定，不能按未来标签缺失删选。

只回答四个问题：

1. 输入最后一个数值的经济时点是什么？截至信号收盘可知的历史长度和缺失位置是否正确？
2. 未来序列的哪些索引分别对应进入、退出？固定21步会在哪些月份错位？
3. 常数价格路径应得到零持有期收益；单位缩放后正确反变换应恢复同一个收益。前节端点与联合路径合成例应得到给定数值。
4. 缺失目标端点能否仍保留原预测总体、仅将该条标签待评分，而不伪造收益或移动日期？

如果这四项不能一致回答，增加权重没有研究价值。诊断通过后再固定一个模型、一个输入定义、一个输出统计量和上下文长度；先比较同信息的简单基线，再与现有完整因子模型看互补性。前者检验函数提取能力，后者检验实际组合信息增量，不能混称同输入公平比较。

零收益是收益点预测的参考，因预测恒定，其RankIC未定义；不能给它强行填0参与相关排名。需要排名参考时，应使用已有有截面差异的冻结简单分数。覆盖、月度RankIC、分组以及与目标相容的误差均从同一预测总体出发；成本检验仍走本地统一回测器的0.5×/1×/2×配置。

若只能得到几十个月可靠时间隔离的数据，就把结果保留为有限前向或方法研究，不为凑满历史证据使用无法核实的早期权重。模型大小、预训练条数和通用排名都不改变本地的有效时间样本数。

## 8. 已运行的独立算例

下列标准库代码不依赖行情或任何模型，复核§4–5中的算术：

```python
from math import prod
from statistics import mean

cases = {
    "aligned": [[0.1, 0.1], [-0.1, -0.1]],
    "offset": [[0.1, -0.1], [-0.1, 0.1]],
}
for name, paths in cases.items():
    cumulative = [prod(1 + r for r in path) - 1 for path in paths]
    print(name, [round(v, 6) for v in cumulative],
          round(mean(cumulative), 6))
print("wrong_anchor", 109 / 100 - 1)
print("entry_exit", 109 / 110 - 1)
print("return_scores", [0.01 * 0.2, 0.04 * 0.1])
```

输出：同向路径为`[0.21, -0.19]`、均值`0.01`；反向路径为`[-0.01, -0.01]`、均值`-0.01`。两种锚点给`0.09`与约`-0.0090909`；还原收益分数为`[0.002, 0.004]`。这些数字证明接口解释会改变研究问题，没有衡量任何模型的实际盈利能力。
