# 模拟盘执行价与真实成交成本

**现有账本已能记录实际分批成交、费用和净值；最值得补的是“原计划全部数量在统一截止时点付出了什么代价”。** 只看已成交部分的平均价差，会奖励容易成交的订单，并把未提交、未完成的交易从评价中隐去。最小路径是复用手工账本、固定股数回放和 Q5 日志，增加截止估值及交易意图完成情况，形成同一份订单的 PAPER—实际执行对照。

研究日期：2026-09-12。对象为收盘后生成目标、下一开市日人工执行的 A 股/ETF。本文的合成例和改进方案是独立分析，尚无新增真实成交样本；文献中的美国机构订单成本不是本地滑点参数。

### 1.1 花旗真实订单：Almgren、Thum、Hauptmann、Li（2005）

*Direct Estimation of Equity Market Impact*，实际阅读 **2005-05-10、26 页作者稿**，首页注明初稿 2004-12-20。Almgren 当时列多伦多大学及花旗，另三位列花旗量化研究。全文由宾夕法尼亚大学课程网站收录，属于原论文副本，非讲解文章。[完整作者稿](https://www.cis.upenn.edu/~mkearns/finread/costestim.pdf)

## 3. 一份清单、三个价格基准、两个不同问题

日频人工执行至少有三个时点：信号日收盘参考价 `P_D`，下一开市日的开盘参考价 `P_O`，事前指定的评价截止价 `P_H`。第一轮把 H 固定为**该执行日收盘**，与现有 `manual_nav` 对齐。实际各笔成交另有股数 `q_j`、价格 `p_j` 和实际时间。

### 3.1 评价完整交易意图

令方向 `s=+1` 为买入、`s=−1` 为卖出；固定计划股数 `Q>0`，累计已成交 `f=Σq_j≤Q`，实际归属费用为 F。在股份与价格口径一致、截止前没有影响该差额的公司行动时，定义：

```text
完整意图差额 C = s × Σ q_j(p_j − P_D)
               + s × (Q − f)(P_H − P_D)
               + F
               = 已成交价差 + 未完成机会成本 + 实付费用
```

正值表示实际实施落后于以参考价完成全部意图的理想账户。它是一个可核算的机会差额，不要求未完成股份在 H 真能成交。负值也保留：未买入后价格下跌、未卖出后价格上涨都可能带来负机会成本。

该基准刻意保留信号后的价格变化，适合回答“策略意图到实际组合损失了多少”。收盘后才形成信号时，`P_D` 不是可执行承诺价，因此 C 不能全部归咎于交易人员或填入滑点参数。风险拦截和人工取消也要有阶段标签，避免把所有意图偏离统称执行失败。

### 3.2 评价开盘以后额外付出的代价

对于开盘参考可用的同一订单，恒等式还可写为：

```text
C = s × Q(P_O − P_D)
  + s × [Σ q_j(p_j − P_O) + (Q − f)(P_H − P_O)]
  + F
    全意图隔夜差额 + 开盘后实施差额 + 费用
```

注意第一个数量是 **Q，不是 f**；分解的是全部意图，所以未成交部分也经历隔夜价格变化。若只想分析已成交部分，另列 `s×Σq_j(p_j−P_O)`，并同时报告完成率，避免它替代完整 C。

开盘后价差仍混合了日内市场移动、人工等待、订单限制和真实执行摩擦。我们没有“相同市场但本订单没发生”的反事实，因此不把它命名为已识别的市场冲击。现有日线开盘足够完成第一轮粗分；若后续已有五分钟数据，可按实际提交时间使用**此前已闭合的 bar**作辅助基准，并记录价格年龄。这种 bar 参考也不是报价中点或保证成交价。

### 3.3 评价 PAPER 对实际的预测误差

以同一份风险过滤后清单、同一期初账户及同一 H，分别计算实际 C 与统一回放得到的 `C_M`。`C − C_M` 才是该模型与实际执行的总体差异；它包含完成量差异，不能仅对双方都成交的订单求均价。

如果只有模拟成交，能验证的是规则运行和场景差额，不能估实际预测误差。若已有实际成交但只比较共同成交部分，也可以报告“已成交子样本价差”，但要旁列全部意图的金额覆盖率及未完成数量。

对于同一期初、无外部资金流且公司行动口径一致的单日，两者截止权益的差额应等于上述 C 差额。这提供了比“看起来像合理滑点”更强的记账核对。遇到入金或跨日分红，先走现有账户处理再对齐权益，不能直接拿两个不同 Modified Dietz 分母的收益率相减当成本。

## 4. 原创合成例：成交样本改善 50 bps，完整意图却落后 641.25 bps

以下全部是假设数值，用来检验测量口径，不是本地交易实测。期初现金 20,000 元，持有可卖 B 股票 1,000 股，信号收盘价 20 元；总权益 40,000 元。冻结的次日意图是买 A 1,000 股、卖 B 1,000 股，两者 `P_D=20`。

|订单|次日开盘参考|实际动作|截止收盘|实际费用|
|---|---:|---|---:|---:|
|买 A 1,000 股|20.20|仅成交 400 股，均价 19.90|21.00|5 元|
|卖 B 1,000 股|19.80|人工未提交，0 成交|18.00|0 元|

只看成交：A 价差 `400×(19.90−20)=−40` 元；以已成交股数对应的信号金额 8,000 元为分母，得到 **−50 bps**，表现为有利成交。费用另计 5 元。

完整意图：

```text
A：−40 + 600 × (21−20) + 5 = 565 元
B：−1 × 1,000 × (18−20) = 2,000 元
合计：2,565 元
计划总买卖金额：1,000×20 + 1,000×20 = 40,000 元
完整意图成本：2,565 / 40,000 × 10,000 = 641.25 bps
```

用实际账户核对：现金变为 `20,000 − 400×19.90 − 5 = 12,035`，A 市值 8,400，B 市值 18,000，截止权益 **38,435**。理想参考账户买足 A、卖完 B，截止权益为现金 20,000 加 A 市值 21,000，即 **41,000**。差额正好 2,565。

开盘分解也一致：A 隔夜差额 200 元，开盘后差额 `−120+480=360`，加费用得到 565；B 隔夜差额 200，开盘后差额 1,800。两单合计隔夜 400、开盘后 2,160、费用 5。

B 的损失来自已冻结意图未落实，不能写成“券商冲击 2,000 元”。若 B 在冻结前就被风险规则拦下，则它应留在拟议清单的流程解释中，而不进入最终执行清单的完成率。**分母必须先固定在哪个阶段，再计算完成率和差额。**

这里的 −50 bps 和 +641.25 bps 分母不同，正是两个问题的区别；不是同一成本估计从负变正的统计检验。对跨股票汇总，采用人民币差额相加再除以计划总金额，不对每股价差或各单 bps 简单平均。

## 5. 最小记录法：给已有订单旁加执行事实，不改成交账本的职责

不再收集每笔市场成交。以现有订单目录为起点，已有字段保持原值；一份小型补充记录用原订单的 `execution_date + symbol + side` 关联同日净订单，用实际 `event_id` 关联成交。若一天出现多份清单版本，保留来源目录，选定哪份曾实际执行，不能合并冲突计划后猜测。

|记录阶段|优先复用|真正需要补的内容|
|---|---|---|
|信号后冻结|`targets.csv`、`proposed_orders.csv`、`orders.csv`、配置与风险摘要|只选一份待执行清单；保存事前选定 H 与基准口径|
|次日人工动作|订单清单与用户操作记录|是否提交、提交时间及精度、实际委托数量；取消/改量或未提交原因。没有记录填未知，不从成交倒推出提交|
|实际成交|`manual_fills` 的事件编号、时间、股数、价格、费用|保留每次实际部分成交及原始回单；只把真实发生的成交写入现金/股份账本|
|截止核对|Q5 的观察状态、成交/拒单与未完成量；`manual_nav` 收盘估值|为全部计划证券取得同一 H 价格及其日期/状态；增加机会成本和完整 C；缺值单列金额覆盖率|
|PAPER 对照|`replay_orders` 的成交、拒单及截止账户|与实际使用相同原计划、期初账户、公司行动口径及 H；标明模型成交来源|

其中“实际委托数量”可以小于原计划，但不能拿它悄悄替换 Q。例如因个人判断把计划买入 1,000 改成 100，后者即便全部成交，也只是提交层 100% 完成；原意图层只有 10%。这让策略偏离和提交后执行质量都可解释。

### 5.1 费用只记一次，归属可以暂时未知

`manual_fills.import_events` 接受成交附带费用和独立 `FEE` 事件；`execution_deviation` 只汇总 BUY/SELL 的附带费用。[费用处理](../../../src/quant/execution/manual_fills.py:98)、[成交偏差聚合](../../../src/quant/execution/manual_fills.py:153)

因此独立现金费用可以已经影响净值，却尚未归属到订单 TCA。最小核对为：**已归属订单费用 + 未归属费用 = 同一评价期间账本实际费用**。不能默认每个部分成交都再次收最低佣金；按券商实际回单记账，无法分配的日汇总费用先保留未归属。已随成交记录的费用不再以 FEE 重记，也不从净值再扣一次。

### 5.2 已观察无成交、未知成交、风险拦截分别计数

沿用 Q5 的三种观察状态，只有确知实际成交为 0 时才置 `f=0`。未收到成交文件是未知，不是免费完成，也不是确定未成交。对存在未解释残量的订单，先补人工原因；不要自动推断为涨跌停拒单。

风险拦截前后的清单都保存，以便解释总流程。用于执行成本校准的主分母固定在最终计划；拟议却拦截的部分单列意图差异。这样既不会把保护性风控当券商拒单，也不会因整批清空清单而让流程报告只剩下“0 成本”。

### 5.3 估值与可成交价继续分开

官方停牌可以让 `manual_nav` 沿用旧价格维持账本，但旧价算出的零机会成本不证明机会差额为零。TCA 需要保留 H 价格日期；没有有效当日市场参考时，该单经济成本先记未知，同时展示残余数量及账面估值。涨跌停若有当日市场收盘价，可以作机会差额的估值参考，并附成交受限原因，不能称该价保证可成交。

第一轮以无公司行动的单日订单做恒等式核对。除权除息与股份变更仍复用现有账户处理，避免把价格机械变化误计执行成本。跨日重复尝试同一意图时，累计 C 是对同一基准更新到新 H 的结果，不能把每天相对原信号价的累计机会差额再相加；或改为以昨收作滚动基准的增量核算。取消原意图后，后续新增意图另留当时依据。

## 6. 两个可检验应用，先形成证据再动滑点

### 应用一：用合成事件核对已有账本和 TCA 差额

**问题：** 新增差额是否只补了正确的机会项，保持现金/股份账本和原有成交偏差不变？

本轮根任务已实际调用 `execution_deviation` 完成四个独立合成场景，保存了脚本和 JSON，并用期末现金加持股市值独立核对恒等式：部分买入后涨、部分卖出后跌均为原价差 −40、机会成本 600、费用 5、完整差额 565 元；全部未买后涨为 1,000 元；部分买入后跌为 −635 元。四项均通过。本文已读取脚本及输出，没有重复运行。[证据与说明](../../../artifacts/research/paper_reading_partial_fill_cost_20260912_01/README.md)、[原函数结果](../../../artifacts/research/paper_reading_partial_fill_cost_20260912_01/summary.json)

后续可复用 `import_events`、`execution_deviation` 和 Q5 观测汇总，用 §4 的无公司行动单日例补一个双股票 fixture。纯计算期望为：已有成交价差 −40 元、费用 5 元；补充的未完成机会成本 2,600 元；完整 C 为 2,565 元，与理想/实际截止权益相差一致。它与上面已完成的四个单股票场景不同，重点核对合并订单的分母及未提交分类。

只加几项有业务意义的边界：把 B 改为“未供观察”，完整总额应变成已知部分并报告未知覆盖，而不是仍给出完整 2,565；把同一 5 元费用由成交附带改为独立 FEE，账户总费用保持 5，订单归属可暂未知；同一成交事件重复导入不应改变 C 所用的唯一成交集合。评价精度以人民币小数误差容差核对，例如总差额误差 ≤0.01 元，不要求浮点逐位相等。

**通过含义：** 只证明记录和公式与账本一致，不能证明某个滑点值适合实盘。本轮未执行这些新增 fixture。

### 应用二：下一次正常调仓开始积累成对前向记录

**问题：** 统一模型在哪些阶段偏离人工执行，偏离是价格还是完成量？

先冻结一套当前基准配置、H、清单阶段和费用口径。仅跟随本来就会生成的日频调仓清单记录，使用现有 PAPER 和手工账本。若尚无真实手工成交，只报告模拟结果及记录完整性；实际样本来自用户正常、已授权的交易活动，不为估参数增加交易。

第一批报告只需四项并列：

- 全部最终计划的数量/金额完成率；“提交前偏离”与“提交后未完成”分开。
- 已成交部分的信号价差、开盘后价差、实际费用；列明价格及费用可归属的金额覆盖率。
- 统一 H 的完整 C 与 PAPER 的 `C_M`，以及两者差额；单列市场参考未知的意图。
- 按调仓日列示买/卖、是否有执行限制的简单分组，保留每个调仓日的总差额及样本数。

同日几十单受共同行情和人工操作影响，不是几十个独立月份。首月或一个调仓批次能发现记账/规则偏差，不足以拟合新的多参数冲击模型。成本档位只作事先固定的场景对照；逐笔落在 0.5×–2× 之外也不能直接判模型失败，因为该范围不是价格波动的统计置信区间。

一个可证伪的首阶段标准是：每份计划都能在 H 找到“有明确结果”或“明确未知原因”，且所有有完整价格、费用与股份口径的配对样本，订单 C 差额与账户权益差额在记账容差内一致。若已成交价差较小而整体完成率低、完整 C 偏差大，就优先处理人工流程/未完成订单；只有在完整记录积累后，才评估是否需要调整当前滑点或执行时点。

## 7. 本轮结论与阅读范围

本项目距离可用 TCA 主要差一层**完整意图的统一截止对照**，不是差一个新的成交引擎。已有手工账本、固定股数回放和 Q5 风险日志足够承担大部分工作；最小新增量为 H 价格状态、未完成机会差额、人工动作解释和费用归属核对。
