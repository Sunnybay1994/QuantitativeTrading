# 历史分钟级股票行情 API：免费与低成本专项调研

**核验日期：2026 年 9 月 10 日**  
**重点市场：沪深 A 股、港股（用于筛选港股通标的），兼顾美股。**  
**用途：个人投研、技术指标、分钟级回测与本地历史库；不以实时逐笔或 Level-2 为采购目标。**

> 证据边界：本报告核查的是提供商现行公开文档、权限页、价格页和项目维护者文档，不是登录各家账户后的下载实测。明确区分“官方已说明的能力”“需要账户验证的权限”和“本轮没有核准的历史范围”。价格为页面公开档位，不包含可能另收的交易所授权、税费、商业再分发或机构使用费用。

## 一、结论：按个股分页的免费方案，确实值得优先考虑

你的判断成立：**没有免费全市场打包接口，不等于不能免费取得一批股票的多年分钟线。** 富途和长桥最符合“逐个股票、逐次请求”的需求；美股还应把 Alpaca 和 Massive 纳入优先名单。[S01–S04][S12–S16]

本次选型建议是：

| 具体需求 | 优先路线 | 决策理由 |
|---|---|---|
| 几十至约 100 只 A/HK/US 股票，取数月至数年 1 分钟线 | **先核验富途或长桥的账户、市场权限** | 免费/附条件免费，限制主要是不同股票数和调用频率，并非只能取最近几天 |
| A 股，已有券商 QMT / MiniQMT 权限 | **先验收 xtquant 的历史下载能力** | 不应忽略现有券商提供的单股历史下载；费用及深度必须按券商版本确认 |
| A 股，可接受 5 分钟而非 1 分钟 | **保留 BaoStock 作为免费验证候选** | 不能把常见的 5 分钟路线误当成 1 分钟替代品；本轮其分钟范围未完整复核 |
| 大量 A 股、跨多年、必须 1 分钟，不希望受百只股票配额制约 | **TuShare 历史分钟包** | 公开个人价 2,000 元/年，按代码和时间分段获取，权限与积分分开 |
| 美股，主要做历史分析而非实时交易 | **Alpaca Basic 优先，Massive Basic 备选** | 前者提供多年历史且可取延迟的 SIP；后者免费档明确包含近两年分钟聚合 |
| 只需最近几个交易日或从今天开始积累 | **AKShare / efinance / yfinance，通达信项目作补充** | 现金成本低，但近期窗口、字段完整性、上游服务及授权限制必须单独检查 |

**对上一份综合报告的修正：不应把“需要历史分钟线”直接等同于“先购买 TuShare 分钟包”。先看股票池大小、最低周期、最早日期和账户权限，少量个股的零独立数据费路线可能已经够用。**

## 二、先分清六种容易混淆的限制

| 文档中的描述 | 真正限制的是什么 | 能否靠逐股/分页解决？ |
|---|---|---|
| 单次最多 800 / 1,000 / 8,000 根 K 线 | 每页数据量 | **有分页或可移动时间边界时，可以** |
| 每分钟若干次请求 | 下载速度 | 可以降低请求频率；不能超限并发 |
| 每 7 天最多 100 只不同股票 | 股票池广度 | 可以反复拉同一股票；不能在同一额度窗口无限换股票 |
| 分钟数据只保留最近 5 个交易日 | 服务器/接口可见历史窗口 | **不可以**。循环旧日期不会产生已经不可访问的数据 |
| 最新 15 分钟不可用 | 新鲜度/延迟 | 不妨碍取过去的 **1 分钟** K 线；不是只能取得 15 分钟周期 |
| End-of-day / 日终更新 | 交付时间 | 不必然是日线；可以是日终提供完整的分钟线 |

前三项分别影响单页大小、速度和股票数，后三项影响历史可见范围或新鲜度。富途的滚动配额、长桥的逐股限额、Alpaca 的延迟和 Massive 的日终分钟数据，正好说明这些不能混为一谈。[S01–S04][S12–S16]

另一个边界是：**5 分钟 OHLCV 不能逆向恢复真实 1 分钟 OHLCV。** 更粗周期会丢失区间内部价格路径，不能通过插值补成真实的分钟回测样本。

**全市场的另一层含义：**即使接口能对每个股票代码循环，也不代表它含有所有退市股、暂停交易证券或完整历史证券列表。做全市场回测，还要检验历史股票池，不能只循环今天仍上市的股票。

## 四、最符合“逐只请求”的券商接口，如何理解

### 4.1 富途：股票数配额与历史年数是两个维度

`request_history_kline` 接受一只证券的代码、起止日期与 K 线周期。结果分页通过 `page_req_key` 续取。默认日期和单页条数都不是数据库的全部历史长度。[S01]

当前 v10.10 权限文档的基础档为 100 只不同证券；同一只股票在滚动 7 天内重复请求、或换不同 K 线周期，不会重复累计历史股票额度。更高资产档可提高可查股票数；这些是资产门槛，不是按年订阅费。[S02]

所以，研究一个固定股票池与扫描整个市场是两个不同问题。前者可以反复补历史和增量；后者可能先遇到不同证券数额度，而不是下载页数限制。

**必须保留的权限条件：**当前文档区分境内认证客户与国际客户，并说明以 OpenD 登录 IP 区分；A 股行情对前者免费开放 LV1，对后者暂不支持。港股和美股也应分别核对 API 权限；App 能看不等于程序能取。登录限制已放开也不等于所有市场无条件开放。[S02]

此外，常规时段的历史长度不能直接套用到美股盘前、盘后和夜盘，后者的历史可能更短。[S01]

### 4.2 长桥：每月可查股票数，以及账户能看多远

长桥的历史接口包含 `history_candlesticks_by_date` 与 `history_candlesticks_by_offset`。股票池配额按自然月计算，而不是每次请求重算。[S03]

**避免静默截断：**同时给出起止日期，区间超过 1,000 根时，接口会优先返回靠近结束日期的数据。因此，请求“去年全年”成功，不代表全年已经取齐；应移动偏移/时间边界继续查，并核对最早时间。[S03]

市场代码用 `.SH/.SZ/.HK/.US` 等后缀；行情权限与 App 分离。[S04] 具体可用年限与股票数见上表。不要把“数据库拥有更早历史”当成“基础账户可以访问全部历史”，也不要只为提高配额而增加不必要交易。

### 4.3 QMT：不要漏掉现有券商接口，但不假定它天然免费

迅投官方说明，XtQuant 依赖 MiniQMT 环境，其行情模块提供历史及实时 K 线等数据。[S10] 与纯 HTTP 数据商相比，它还涉及本地客户端和券商授权环境。

选型时可优先检查 `xtdata.download_history_data`、`download_history_data2` 及读取接口 `get_market_data_ex` 所对应的本地版本文档。**需要逐项验证 1m 权限、历史最早日、单股/批量下载、后续增量及费用。** 本轮没有从可访问官方资料中核准所有券商版本的统一权限，不把安装 SDK 或开通模拟环境直接算作长期免费分钟数据。

## 五、免费开源库：重点是上游历史窗口，不只是函数是否有日期参数

### 5.1 AKShare：逐股可取，但近期窗口不能靠改日期突破

重点函数包括：

| 函数 | 使用重点 |
|---|---|
| `stock_zh_a_hist_min_em` | A 股东财分钟，1m 文档限定近 5 个交易日 |
| `stock_zh_a_minute` | 新浪近期分钟，周期可选，不能据此确认多年回溯 |
| `stock_hk_hist_min_em` | 港股近期分钟，注意延迟与复权限制 |
| `stock_us_hist_min_em` | 美股近期分时，注意延迟 |

上述能力与窗口以项目文档为依据。[S08] **日期默认写得很早，不是可用历史起点的证据。**

还有一个实际质量问题：东财 1 分钟分时接口的文档示例存在旧交易日 `open=0` 的情况。不要把这种占位值当成真实开盘价；依赖分钟开盘价的因子或回测，应换用完整 OHLC 来源，或明确排除缺失字段，不能填造价格。[S08]

### 5.2 efinance：支持单股和列表，但“列表调用”不证明有更深数据库

`stock.get_quote_history` 可传一个代码，也可传列表；`klt` 指定分钟周期，`beg/end` 指定日期，支持按市场筛选。[S09]

对于你强调的“我愿意一只只请求”，它应当列入调查范围。但本轮文档没有证实某个固定的多年免费分钟深度，所以把它放在**需要日期探测的候选**，而不是已经核实的长期库。

工程上也不应把 AKShare 的东财接口与 efinance 的东财接口当作两个完全独立的数据源：两套封装可能仍依赖同一上游服务。[S08–S09]

### 5.3 通达信 / pytdx：800 是单页，不是全部历史

`get_security_bars` 的 `start` 和 `count` 提供偏移查询；单次最多 800 根。另有按证券、日期查询历史分时的接口。[S11]

因此可按以下逻辑验证：第一页取回后移动偏移，检查后一页最早日期是否继续向过去推进。若返回空页、重复页或触及服务器保留范围，应停止，而不是认为无限加大偏移总能得到更早数据。

**分时曲线与分钟 OHLC 还要分开：**按日得到价格、成交量序列，不代表同时拥有每分钟完整的开高低收。项目库的可用性与行情数据的使用授权也不是一回事。[S11]

### 5.4 BaoStock：值得保留的 5 分钟候选，但本轮核验有缺口

BaoStock 发布者仍将其定位为免费中国股票数据项目，示例展示按单股、起止日期进行历史查询。[S20]

其常见分钟使用路线是 5/15/30/60 分钟，而不是 1 分钟。**本次未能完整取得现行官方分钟说明，不能确认统一起始年、所有股票的覆盖深度与当前分钟服务可用性。** 因此：不能简单漏掉它，也不能把它写成已经实测通过的“免费全市场多年分钟库”。

采购决策上，它适合进入“接受 5 分钟时的免费验收队列”；必须 1 分钟时，不应把它作为替代方案。

### 6.1 Alpaca：免费实时 IEX，不代表免费历史只能是 IEX

IEX 是单一交易场所；SIP 是综合美国交易所的行情口径。Alpaca 官方 FAQ 明确：查询历史时，`end` 至少早于当前 15 分钟，可以在无付费订阅时请求 SIP。[S13]

建议请求中**明确指定 `feed='sip'`**，不要依赖默认值，更不要把 IEX 成交量直接当成全市场成交量。历史 Bar 请求支持 `timeframe='1Min'`，需持续使用返回的分页令牌；10,000 条上限是整个响应页的总量，而不是每只股票各 10,000 条。[S14]

免费档的 **30 只股票限制指实时 WebSocket 订阅**，不是说历史数据库一共只能查询 30 只。[S12]

### 6.2 Massive：日终数据也可以是分钟颗粒度

这个方案适合收盘后研究：分钟级别没有变，只是交付时点延后。不要因为页面写 End-of-day，就误删它。[S15]

`/v2/aggs/ticker/{ticker}/range/{multiplier}/{timespan}/{from}/{to}` 按证券和区间查询；读取 `next_url` 续页。文档所说最多 50,000 个是**参与聚合的基础条目上限**，不要一概理解为每个周期都返回 50,000 根最终 K 线。[S16]

### 6.3 yfinance：不同周期的历史边界不一样

项目当前实现对 `period='max'` 的默认回溯设置分别为：1m 约 8 天，2/5/15/30/90m 约 60 天，1h/60m 约 730 天。[S19]

**这是库的请求边界设置，不是 Yahoo 对全部证券、全部日期的服务保证。** 即使拆成许多小区间，也不能证明可以取回任意过去年份的 1m。它更适合近期观察和核对，而不是多年分钟库的唯一来源。[S18–S19]

## 七、TuShare 的购买边界，以及其他未纳入免费长期首选的服务

### 7.1 TuShare：历史分钟独立开通，不用为纯历史需求买实时包

A 股历史分钟权限的公开价格、范围和限额已经列在第三节。`stk_mins` 的说明明确允许按股票代码和时间循环。[S05–S06]

应避免两个误购：**500 元/年的常规积分不包含分钟权限；只做历史回测，也不必因此购买按月收费的实时分钟权限。** 港股 `hk_mins` 的少量查看权限则是试用，不是持续免费取数。[S05][S07]

对于港股分钟，本轮没有找到足以确认单独现价和统一最早日期的公开价格条目，不能把 A 股历史分钟的 2,000 元包直接理解为同时包含港股和美股分钟数据。

### 7.2 试用、云端研究权限、正式本地 API 不是同一种免费

| 服务 / 类别 | 本次保留的判断 | 未据此作出的推断 |
|---|---|---|
| **聚宽 JQData** | 官方 SDK 有专业研究数据和试用入口，值得需要完整量化生态的人比较 [S24] | 不沿用网上旧的“永久免费百万条/日”等额度；不把云端回测免费等同本地批量下载免费 |
| **米筐 RQData** | 有正式数据 API 文档，可作为商业/试用候选 [S25] | 未核准当前永久免费长期 1m 额度，故不列免费首选 |
| **掘金 / GM、BigQuant、SuperMind 等平台** | 保留为平台型候选 | 本轮未核准各家的“当前免费本地 API + 多年分钟 + 个股循环”完整条件，不给未经验证的金额和年限 |
| **iTick、AllTick 等跨市场服务** | 需要进一步核对具体历史 K 线端点，而非只看实时接口和免费请求数 | 不能从“免费 token”或“支持历史”推断全市场多年 1m 免费 |
| **Wind / Choice / iFinD** | 不属于本次零成本和轻量采购的优先路线 | 没有公开统一分钟 API 零售报价时，不用传闻价格作比较 |
| **券商 PTrade、IBKR、Tiger 等** | 有现成账户时可核验历史权限，不宜先排除 | 本轮没有逐家完成当前股票分钟年限、配额和费用验证，不能列为已证实的免费供给 |

这一节是**未确认范围清单**，不是对这些服务的数据质量作负面评价，也不是声称市场上只有前面列出的选项。

## 八、把“逐只请求”量化：小股票池与全市场差多少

以下是容量演示，不是对当前 A 股上市公司数的统计，也不是实际下载测速。假定一个完整交易日每股约 240 根 1 分钟 Bar，一年按 250 个交易日，忽略停牌、上市时间和竞价口径差异。

$$
\text{总行数}=\text{股票数}\times\text{交易日数}\times\text{每日 Bar 数}
$$

| 假设股票池和区间 | 1 分钟行数 | 若改成 5 分钟，约为 |
|---|---:|---:|
| 100 只 × 20 个交易日 | 480,000 | 96,000 |
| 100 只 × 250 个交易日 | 6,000,000 | 1,200,000 |
| 5,000 只 × 250 个交易日 | 300,000,000 | 60,000,000 |

在“每个股票分开请求、每页能装满”的简化条件下：

| 单股分页上限 | 100 只 × 20 日：估算请求数 | 100 只 × 250 日：估算请求数 |
|---|---:|---:|
| 800 根 | 600 | 7,500 |
| 1,000 根 | 500 | 6,000 |
| 8,000 根 | 100 | 800 |

计算方法为 `股票数 × ceil(每股区间行数 / 单页上限)`。真实请求数还受按日边界、额外字段、空页和重试影响；**此表不证明相应供应商一定拥有整个区间，也不突破其股票数配额。**

这意味着：

**固定百只股票的补历史，在分页层面并不离谱；几千只股票的多年初始化则是另一类工程任务。** 后者需要同时解决股票数授权、历史股票池、分页调度、数据修订和存储，不能只比较每月现金价格。

对有滚动股票数限额的服务，正常等额度释放后可研究其他股票；但持续覆盖几千只股票的每日增量仍可能不符合基础额度。不要通过多账号、共享 token 或规避访问控制来绕过限制。

## 九、针对你的市场范围，建议分三种实施方案

### 方案 A：先覆盖重点股票，尽量零独立数据费

**适用假设：主要维护几十至约 100 只股票，做数月到数年的历史分钟分析。**

A 股和港股先验证富途或长桥。验证顺序不是先充值，而是：证券可查 → 分钟权限 → 最早日期 → 股票配额 → 分页完整性。美股单独使用 Alpaca 的历史 SIP，或用 Massive 免费档满足近两年收盘后分析。免费开放库仅作近期核对。[S01–S04][S12–S16]

这比先购买全市场历史包更匹配一个有限股票池。

### 方案 B：A 股大量股票、必须多年 1m

**适用假设：需要数百至数千只股票，开展横截面因子挖掘与多年份回测。**

先看已有券商 QMT 数据授权是否实际覆盖所需范围；若没有，或数据权限/部署环境不合适，用 TuShare 历史分钟包作为公开可核价的基准方案，再比较其他正式数据商的样本质量及合同。[S05–S06][S10]

不必额外为了“已经付了分钟费”购买日线积分，也不要把实时套餐与历史采购绑在一起。港股仍可保留券商接口，美股仍可保留免费历史源。

### 方案 C：预算为零、没有可用券商权限

对于多年 A 股 **1 分钟完整 OHLCV**，本轮没有核实到同时满足“公开低门槛、长期免费、全市场可持续下载、完整历史和稳定服务承诺”的单一来源。

这不意味着所有免费路线不存在，而是不能把近期接口、5 分钟接口或未验证服务器库存当作已经解决了该需求。可接受更粗粒度时，验证 BaoStock；只需近期时，验证 AKShare/efinance/通达信；从当前开始每天合规归档，也能逐渐积累自己的历史，但不能补出归档前缺失的数据。[S08–S11][S20]

## 十、下载前的验收清单：避免买到“有接口、无历史”

下面是建议的技术验收流程，不是本轮已执行的测试结果。

### 10.1 先做小样本日期探测

每个市场挑选数只证券，覆盖老上市、新上市、曾除权、低流动性或停牌样本。分别查询最近 20 个交易日、约一年前、约三年前，以及策略真正需要的最早月份。

记录：请求起止日期、响应最早/最晚时间、行数、分页令牌、字段、费用/额度变化。只看 HTTP 成功或返回非空不够；接口可能成功返回很短的一段。

### 10.2 对每页做连续性检查

后续页应推进到新的时间区间。对页间重复行去重，但保留原始数据和审计记录。不要把空页自动解释为“这一段停牌”，应先排查权限、日期格式、服务器窗口和无行情时段。

长桥的区间截断、富途分页令牌、Alpaca 多股票合并响应和 Massive 的基础聚合上限，各自语义不同，不能用一个未经适配的通用翻页函数处理全部供应商。[S01][S03][S14][S16]

### 10.3 对字段和口径做检查

| 检查项 | 建议方法 |
|---|---|
| OHLC 是否完整 | 正常交易数据应满足 `low ≤ open/close ≤ high`；检查 0 值、缺失和占位值 |
| 成交量单位 | 区分股、手、张；跨数据源统一单位后再比较 |
| 分钟时间戳 | 核实代表区间起点还是终点，避免整段错位一分钟 |
| 交易时段 | 明确午休、集合竞价、港股半日市、美股盘前盘后与夜盘是否包含 |
| 时区 | 保存交易所本地时区信息；美股额外处理夏令时 |
| 复权 | 保存未复权原始价与公司行为/复权版本；实际成交价不能直接拿复权价替代 |
| 零成交分钟 | 区分无成交不生成 Bar、生成平价 Bar、真实数据缺失；不能一律前向填充 |
| 数据修订 | 保留采集时刻和来源；允许正式修订覆盖规范层，同时保存原始版本 |
| 历史股票池 | 不只取今天仍上市的证券；记录退市、更名和上市时间 |

### 10.4 港股通名单与行情数据分开维护

研究港股通标的时，行情按港股证券代码取；**是否在研究时点可经港股通买入，应由当时的适用证券名单决定**，不是由行情 API 是否能查到决定。

建议存储 `symbol`、市场、名单生效日期和可交易状态，回测时按当时名单筛选。不要用今天的可买名单覆盖全部历史，也不要因程序能下载某港股，就推断它可通过你的交易通道成交。TuShare 数据目录将沪深港通股票列表与港股分钟行情分别列为不同接口，也可作为分离建模的参照。[S07]

## 十一、采购与维护：最终推荐顺序

**第一步：**先选市场、股票数、周期和最早日期，不以“支持分钟”四个字选服务。

**第二步：**对小股票池，优先验证富途/长桥的历史权限；对已有券商环境，验证 QMT；对美股，优先验证 Alpaca/Massive。[S01–S04][S10][S12–S16]

**第三步：**只有免费候选的历史、股票数或部署权限确实不够时，再购买 A 股专业历史分钟权限。TuShare 2,000 元/年可以作为可公开核验的比较基准，而不是所有分钟需求的默认起步价。[S05]

**第四步：**建立本地缓存并按许可保存，后续增量更新；用不同上游的数据源核对异常，不把多个同上游封装算成独立备份。

最终取舍可以概括为：

> **少量个股先用免费历史权限，真正的大范围多年分钟库再付费；分页能解决单次返回限制，不能解决历史不存在、权限不足和股票池配额。**
