## 官方接口与预算

核对 [当前模型和价格](https://api-docs.deepseek.com/quick_start/pricing/)、
[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) 和
[Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/) 后，首版使用
`POST https://api.deepseek.com/chat/completions`、`deepseek-flash`，官网对应 DeepSeek-V4.1-Flash。
请求显式设置 `thinking.type=disabled`、`temperature=0`、`response_format.type=json_object`。
JSON 模式后仍做本地严格验证，空内容、截断、非法字段/分数、非原文证据均不产生分数。

费用按高峰美元价：输入未命中缓存 US$0.30/百万 token、输出 US$1.20/百万 token。
预算预留不依赖缓存命中或低峰折扣；输入以 UTF-8 字节数加消息开销估计保守 token 上界，输出最多768 token。
官方峰时为 UTC 周一至周五01:00–04:00、06:00–10:00，即北京时间周一至周五09:00–12:00、14:00–18:00；其余谷时，价格减半。
用户指定自动化先搜集文本，非紧急 LLM 分析在谷时统一处理；开发测试不受时段限制。两个入口现均默认逐请求检查谷时（含每次重试）；峰时返回`deferred_off_peak`及`deferred_until`，不发送请求、不预留费用。已成功缓存仍可读取；到谷时使用同一输入、缓存和预算上限、新输出目录再次运行。请求已发送后跨入峰时不强制中止，只阻止下一次请求；程序不长时间阻塞等待时段。

显式增加`--development-test`允许开发请求跨时段执行，仍需`--execute`和正的请求/美元上限；产物记录`request_schedule=development_test`。该标志不改变评分提示词或缓存键。dry-run和文本采集不受时段限制；本功能只控制请求时机，费用预留仍使用配置中的峰价，不把估值当实际扣费。时段边界、周末、跨峰重试、缓存恢复及原评分/诊断合计48项定向测试通过。

## 评分口径与产物

冻结设计为 `configs/factors/p7_text_evaluation_v1.toml`，提示词版本 `p7_reason_v1`。
只给模型 `reason_text` 和不含证券身份的文本编号，原始证券代码与公告日期在本地关联。

- `text_operating_improvement`：经营改善，方向正。
- `text_nonrecurring_gain_dependency`：非经常性**收益**依赖，方向负；一次性亏损不属于该项。
- `text_operating_pressure`：经营压力，方向负。

统一0–3分：无相关证据、明确轻微、明确重要、明确主导。0仅表示提供的原因摘录缺乏该维度相关证据，
不表示公告全文或公司的整体情况无该事件。输入是原因摘录，不保证是全部原因；产物以
`evidence_scope=provided_reason_excerpt` 明确这一语义。
空文本、含糊到无法判断、API错误以及纯利润数字复述均保持缺失。非零分要求1–80字连续原文证据。
代码验证结构与原文匹配，首批真实评分后还需人工抽查语义量表执行情况。

每个新run目录保存 `scores.parquet`、`run.json`、`requests.json`、提示词和配置副本。
`scores.parquet` 保留 symbol/publication_date/report_period/reason_text/input_id/cache_key、三个信号、
各维度状态与证据、实际响应模型名和提示词版本。`requests.json` 保留每次尝试的实际模型、token用量、
计价或预留额、错误类别；不把厂商未返回的内部模型版本冒充已验证版本。
`run.json` 沿用轻量输入/输出哈希与研究结论记录，不生成虚构回测折或收益指标。
