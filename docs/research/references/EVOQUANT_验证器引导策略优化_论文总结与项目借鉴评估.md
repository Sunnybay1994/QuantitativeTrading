# EVOQUANT：验证器引导的自进化策略优化——论文总结与项目借鉴评估

> - 论文：*EVOQUANT: Self-Evolving Verifier-Guided Strategy Optimization for Robust Quantitative Trading*
> - 版本：arXiv:2607.12455v1，2026-07-14
> - 原文：[arXiv HTML](https://arxiv.org/html/2607.12455)；[arXiv 摘要页](https://arxiv.org/abs/2607.12455)
> - 许可证：CC BY 4.0
> - 评估日期：2026-08-30
> - 本文定位：投研方法参考，不是本地因子有效性证据、实现任务书或真实回测授权

## 1. 技术摘要

EVOQUANT 把策略优化建模为“验证器约束的程序演化”：大语言模型负责诊断策略为什么失败、提出有边界的修改假设；回测器和验证器决定候选是否可接受。系统不是一次生成“更好的策略”，而是反复执行以下闭环：

1. 将原始策略转成分层、带类型的策略表示；
2. 对当前策略建立训练、验证、测试、交易行为、市场状态和风险证据包；
3. 根据证据诊断瓶颈并限定本轮可修改的层、允许操作、禁止捷径和候选预算；
4. 生成候选，检查可执行性、策略漂移、交易覆盖、回撤和稳健性；
5. 将候选分为采用、孵化或拒绝，并保存修改及失败原因；
6. 在预算耗尽、收敛或没有可接受修改时停止。

论文的核心判断是正确的：在量化投研中，“生成候选”并不稀缺，真正稀缺的是能阻止幻觉、策略漂移、低样本伪优和数据挖掘的验证协议。

对本项目的结论是：**应吸收其“诊断—受控修改—证据门禁—失败记忆”方法，但不应在当前阶段引入可自主循环 20 轮、反复选择 OOS 表现的自进化策略优化器。** 最合适的落地方式是增强现有研究任务书、假设卡、trial ledger 和 ResearchRun，而不是新增一套策略 AST、自动搜索平台或通用 Agent 框架。

## 2. 论文解决的问题与主要贡献

### 2.1 研究问题

论文关注的是已有策略的迭代优化，而不是从零枚举海量因子。作者认为直接让 LLM 重写策略会产生三类风险：

- 生成不可执行或没有金融含义的规则；
- 修改范围失控，原假设在不知不觉中变成另一策略；
- 在有限验证窗口上反复尝试，制造数据挖掘和回测过拟合。

因此，其目标不是最大化搜索空间，而是让每次修改都回答五个问题：改哪里、为什么改、允许怎么改、什么证据算通过、失败后如何避免重复。

### 2.2 四个模块

#### 模块一：策略摄取与“策略基因组”

策略被拆成：

- 信号层；
- 风险层；
- 仓位层；
- 入场层；
- 出场层；
- 来源、策略家族、父版本和修改历史。

修改必须指定目标层，并满足非前视、风险暴露和可重新编译等约束。这个表示的价值不在“基因组”这个名字，而在于它为策略修改提供了显式作用域和 provenance。

#### 模块二：基线证据包

系统为 train、validation、test 分别记录收益、Sharpe、最大回撤、交易次数和胜率，同时记录：

- 交易稀疏性、持有期与收益集中度；
- 市场状态敏感性；
- validation 到 OOS 的衰减；
- 异常止损、截断上涨等风险现象。

这使诊断不只依赖一个综合收益指标。

#### 模块三：诊断、候选生成与验证

每轮搜索计划包含：目标、修改层级、允许操作、禁止捷径和候选预算。修改从保守到激进分为：

1. repair：参数和局部规则修复；
2. bridge：调整过滤器、退出或信号组合；
3. redesign：围绕同一机制重构策略图；
4. family migration：多次局部失败后迁移到相邻策略家族。

候选先过硬门禁：validation/OOS 最少交易数、OOS 最大回撤、语义漂移和金融不变量。通过后再按 validation/OOS Sharpe、OOS 收益，以及回撤、验证—OOS 差距、费用/滑点、延迟和参数扰动等惩罚评分。

最终决策分为：

- `adopt`：证据足以替代当前策略；
- `incubate`：机制合理但证据不足；
- `reject`：零交易、OOS 崩溃、漂移或回撤等原因明确失败。

#### 模块四：迭代和输出

系统保留最佳候选、完整修改轨迹、采用/拒绝决定和失败记忆；达到轮数预算、证据收敛或没有可接受修改后终止。

## 3. 实验设计与主要结果

### 3.1 实验范围

- 数据：AKShare 日频数据，2020-01-01 至 2025-12-31；
- LLM：DeepSeek-R1；
- 每次优化：20 轮；
- A 股：随机抽取 30 只股票，对每个“策略×股票”单独优化，再把 30 个优化后的单股策略等权汇总；
- A 股策略：EMA-RSI 趋势延续、Bollinger-RSI 均值回归、成交量突破、低波质量；
- 加密资产策略：MACD-RSI-Bollinger、ATR 趋势突破、超卖反转；
- 稳健性：双倍费用/滑点、时间切分移动、滚动 walk-forward；
- 消融：参数搜索、随机修改、无 promotion、无诊断、无 memory。

### 3.2 主结果

| 市场 | 策略 | Sharpe：基线→优化 | 年化收益：基线→优化 | MDD：基线→优化 | 观察 |
|---|---|---:|---:|---:|---|
| A 股 | Bollinger Reversion | 0.351 → 0.966 | 4.89% → 9.02% | 5.01% → 6.71% | 收益改善，但回撤扩大 |
| A 股 | EMA-RSI Trend | -0.465 → 0.367 | 1.64% → 16.83% | 14.36% → 10.41% | 三项均改善 |
| A 股 | Low-Vol Quality | -0.500 → 0.386 | 1.58% → 17.86% | 9.30% → 8.26% | 三项均改善 |
| A 股 | Volume Breakout | -0.493 → 0.489 | -2.21% → 15.74% | 4.81% → 6.62% | 收益改善，但回撤扩大 |
| Bitcoin | ATR Trend Breakout | -1.536 → -1.050 | -14.48% → -9.67% | 14.06% → 12.01% | 有改善但仍不可用 |

论文报告七个策略平均测试 Sharpe 从 `-0.298` 提高到 `0.538`。消融实验中，完整系统在 A 股成交量突破任务上的 Sharpe 增量为 `0.982`；仅参数调整为 `0.274`，随机修改为 `0.645`，去掉 promotion engine 后只有 `0.128`。这支持“有诊断的候选生成 + 明确筛选机制”优于只调参数，但并不能证明发现的策略可直接用于实盘。

压力测试并非全部稳定。例如成交量突破在切分移动后，年化收益从基线 `4.94%` 变为优化后 `4.86%`，MDD 从 `5.95%` 扩大到 `9.25%`。作者也明确承认部分 A 股策略以更大回撤换取更高收益。

## 4. 证据质量与关键局限

### 4.1 论文已经主动承认的局限

作者将系统定义为研究原型，不是投资建议或实盘系统，并承认：

- 使用本地日频数据和简化成交假设；
- 没有充分处理流动性、市场冲击、幸存者偏差、公司行动、融券和运营风险；
- A 股使用随机可得股票，而不是重建可投资历史证券池和退市样本；
- LLM 比较受本地模型、API 配置和预算约束。

### 4.2 本评估额外识别的风险

#### 反复使用 OOS 的选择污染

论文的候选评分公式直接包含 OOS Sharpe 和 OOS return 的增量，并且每次优化运行包含 20 轮。若同一 OOS 区间在这些轮次中反复参与 promotion，它实际上已成为优化集，而不是一次性封存的测试集。论文报告“test improvement”时，应按“迭代选择后持有区间表现”谨慎解读，不能等同于真正未触碰的最终 test 或前向结果。这是根据论文方法公式作出的推论。

#### 自由度过高

每只股票分别优化策略，再等权汇总 30 个单股策略，会引入大量单股参数和规则自由度。它难以证明同一个可迁移机制在完整历史可投资证券池中成立，也不对应本项目希望维护的低复杂度、可执行组合规则。

#### 样本与制度语义不足

随机 30 股不能替代 A 股历史成分、上市/退市、ST、停牌、涨跌停、T+1、复权与公司行动的 Point-in-Time 闭包。论文压力测试的费用和滑点扰动有价值，但不足以替代真实可交易时间和统一撮合。

#### 指标改善不等于可部署

部分策略 MDD 明显扩大；另有策略优化后 Sharpe 和收益仍为负。系统展示的是“在自身评估协议下比基线更好”，不是“达到实盘准入标准”。

#### 可复现性仍待独立核验

论文提供匿名代码仓链接，但本次评估未对仓库代码、随机种子、完整参数、30 股名单、具体切分点和全部执行假设逐文件复核。因此本文只依据论文正文总结，不把代码可用性或数值复现写成已确认事实。

## 5. 与当前项目的映射

| EVOQUANT 思路 | 当前项目已有基础 | 建议 |
|---|---|---|
| 分层策略表示 | 因子目录、策略配置、`target_weight`、费用和 ResearchRun identity 已分层 | 不建新 AST；在任务书中增加轻量的策略修改合同 |
| 基线证据包 | RankIC、fold、方向、coverage、冗余、成本、group returns、不可变运行产物 | 吸收交易稀疏、收益集中、regime 与 validation 衰减诊断 |
| 诊断后限定搜索 | 已有预注册假设卡、exact scope、trial budget、禁止项 | 强化为“故障→允许修改层→候选预算→停止条件”映射 |
| typed edit contract | 已有 taskbook、配置 identity、代码 SHA 和职责分离 | 以文档/config 实现，不新增通用程序演化框架 |
| adopt/incubate/reject | 已有 `RESEARCH_ONLY`、`UNASSESSED/HOLD`、`REJECTED` | 可吸收结构化 failure reason，但不改变既有状态语义 |
| 失败记忆 | 交付/审查报告、trial ledger、不可覆盖 attempt receipt | 建立可检索失败原因索引，继续把失败计入 trial 历史 |

| 自动 family migration | 当前每个经济假设拥有独立 identity 和预算 | 不自动迁移；必须新任务书、新 hypothesis 和新 trial 授权 |

## 6. 值得纳入当前投研工作的内容

### 6.1 立即纳入：策略修改合同

未来每个策略或因子研究任务书可增加以下字段：

- `parent_hypothesis_id`：当前修改基于哪个经济假设；
- `diagnosed_failure_mode`：覆盖不足、方向不稳、成本侵蚀、回撤扩张、状态不匹配、冗余或其他；
- `target_layer`：signal / risk / position / entry / exit / execution assumption；
- `allowed_edits` 与 `forbidden_shortcuts`；
- `mechanism_rationale`：为什么该修改应修复已识别问题；
- `expected_metric_movement`：预期改善什么，以及允许牺牲什么；
- `semantic_drift_boundary`：修改后是否仍属于原假设；
- `candidate_budget` 与 `trial_consumption_rule`；
- `negative_controls`、`stop_conditions` 和 `promotion_gates`。

这些字段只需要进入任务书、配置 identity 或 trial receipt，不需要开发一套“策略基因组”平台。

### 6.2 立即纳入：诊断输出必须导向一个有界下一实验

现有失败报告已经比较严格，但可进一步要求每个诊断明确落入三类之一：

1. **机制被证伪**：停止该假设；
2. **证据不足**：保持 HOLD，补数据或前向观察，不修改经济规则；
3. **存在单一可解释修复**：在新的预注册 identity 下，只修改一个已冻结层。

禁止把“表现不好”直接翻译成增加更多条件、搜索更多参数或迁移策略家族。

### 6.3 立即纳入：结构化失败记忆

建议为未来研究报告统一记录以下 failure reason：

- `LOW_TRADE_COVERAGE`；
- `DIRECTION_INSTABILITY`；
- `VALIDATION_OOS_DECAY`；
- `COST_FRAGILITY`；
- `DRAWDOWN_EXPANSION`；
- `REDUNDANCY_EXCEEDED`；
- `PIT_OR_TIME_SEMANTICS_INVALID`；
- `OUTCOME_GRID_INCOMPLETE`；
- `SEMANTIC_DRIFT`；
- `DATA_CONTRACT_STOP`。

它们用于检索和避免重复犯错，但不应自动生成新策略或自动恢复已消耗的 trial。

### 6.4 可选诊断：延迟与参数扰动

论文使用一根 bar 延迟和参数 jitter 作为轻量压力测试。对本项目而言可以借鉴，但边界必须更严格：

- 一根 bar 延迟只用来暴露信号对精确成交时点的脆弱性；
- 参数扰动只检查局部平台，不允许从扰动结果中挑最优参数；
- 两者只作预注册诊断，不能挽救主 Gate 失败，也不能改变 fixed direction、形成日或成本身份。

## 7. 不建议纳入的内容

当前不建议开发以下能力：

- 自动解析任意策略代码并生成通用 AST/“基因组”；
- 让 LLM 自主循环修改、执行和 promotion；
- 对同一验证/OOS 数据进行 20 轮候选选择；
- 每只股票分别定制策略参数或规则；
- 根据结果自动从 repair 升级到 family migration；
- 把 LLM 的解释文本当作经济机制证据；
- 新建通用 memory/vector database、Agent 平台或策略搜索服务。

这些工作会扩大基础设施、候选自由度和运维面，却不能解决当前项目最关键的 PIT、历史证券池、费用、容量、真实前向和 PAPER 准入问题。

## 8. 对当前研究队列的具体影响

### 8.1 首个 PIT 与 annual asset growth

首个 PIT 四因子和随后 annual asset growth 的经济身份已经高度冻结，不应因为本论文而修改公式、方向、形成日、trial budget 或 Gate。可借鉴的只有：

- 把失败诊断映射到允许的下一动作；
- 保存 rejection 原因；
- 对成本、延迟和参数稳定性形成统一证据摘要。

### 8.2 公开经典策略研究

对于 52 周高点、10 个月均线趋势、12–1 动量等公开策略，EVOQUANT 的方法适合**在首次经济运行前**使用：

- 冻结原始公开规则作为 baseline；
- 预先限定最多允许哪些本地制度适配，例如 next-open、T+1、停牌和成本；
- 把本地适配与经济规则修改分开；
- 先运行 baseline，再决定是 `REJECTED`、`HOLD` 还是进入前向观察；
- 不在看到 test 后循环修改公开策略，避免把“复现”变成数据挖掘。

### 8.3 R18 Alpha101

R18 已消耗的 trial 和 `EXACT_ONE_SELECTED_RETURN_NULL` 边界不能因 EVOQUANT 的“repair”概念而重开。该案例可作为失败记忆中的反例：如果修复会依据未来 outcome 过滤、替补第 51 名或跳过调仓期，它属于禁止捷径，不是合法局部修复。

### 8.4 ETF 趋势与波动率目标

现有 ETF 趋势/波动率目标前向候选已经进入冻结观察阶段，不应加入新的自动优化循环。EVOQUANT 的证据包思想可用于前向报告：记录信号覆盖、换手、持仓集中、成本、状态暴露和相对历史区间的漂移，但不得据短期前向结果即时调参。

## 9. 推荐落地路线

### 阶段 A：文档协议增强，不写新平台

在下一次投研方法论或任务书独占窗口中，将“策略修改合同、failure reason、候选预算、禁止捷径、停止条件”纳入研究模板。该工作属于投研业务协议，不属于框架工具开发。

### 阶段 B：在一个新策略包上前瞻试用

选择一个尚未读取经济结果的新公开策略包，先冻结 baseline 和最多一个局部适配候选：

- baseline 与适配候选使用不同 identity；
- 适配原因必须来自制度或执行约束，不来自测试收益；
- 每个候选都计入 trial；
- validation 用于筛选，最终 test 保持一次性；
- 若首次结果失败，不自动生成下一轮。

### 阶段 C：真实前向后再评估是否扩大

只有当多个独立策略包证明以下事实后，才考虑更自动化的诊断工具：

- 结构化诊断确实减少了无效实现和重复试验；
- 失败记忆能跨任务复用且没有诱导结果后修改；
- 候选预算、test sealing 和 forward Gate 没有被绕过；
- 投研吞吐提升足以覆盖新增复杂度。

即使达到阶段 C，也优先做“只读诊断助手”，而不是能自主执行回测和 promotion 的自进化 Agent。

## 10. 建议的项目裁定

建议将本论文的项目价值裁定为：

> `METHOD_ADOPT_WITH_STRICT_ADAPTATION`

具体含义：

- **采用**：证据包、故障诊断、受控修改合同、候选预算、拒绝记忆、压力诊断；
- **改造后采用**：把 adopt/incubate/reject 映射到现有研究状态，把 memory 映射到 Git 管理的任务/交付/审查和 trial ledger；
- **拒绝当前实现**：自动 20 轮演化、反复 OOS 选择、单股定制优化、自动家族迁移和新平台建设；
- **不改变现有 Gate**：PIT、不可覆盖 attempt、历史证券池、next-open、费用、容量、独立审查、forward/PAPER 与人工准入继续优先。

## 11. 后续问题

1. 论文代码能否完整复现实验的 30 股名单、切分、随机种子、20 轮候选和交易成本？本次尚未核验。
2. promotion 使用的 OOS 是否在迭代期间反复可见？若是，应如何重新设计为 validation-only selection + sealed test？
3. 语义漂移距离如何定义，是否能区分制度适配与新经济假设？
