# M2 近期策略研究进展与后续工作安排

> - 报告日期：2026-08-30
> - 证据截止：`main@c9aba0df0f31e4f265186f7aa9590228dfeb00b5`
> - 报告对象：项目用户与项目统筹
> 结论口径：区分 `REJECTED`、`UNASSESSED/HOLD`、开发闭包与真实研究结论；不把代码、测试或静态审查通过写成因子有效。

## Executive Summary

- **近期没有新增因子被证明可进入 PAPER。** Amihud/换手、downside beta 和 Alpha158 形态/量价候选被方向、冗余、覆盖率或 2 倍成本门禁否决；MAX corrective lineage 与 R18 则因证据边界保持 `UNASSESSED/HOLD`。这说明现有研究流程正在淘汰弱信号并阻止无效证据晋级，而不是“没有进展”。
- **R18 的三个 Alpha101 价量候选没有形成有效性结论。** `alpha101_006 / alpha101_012 / alpha101_041` 已完成实现和 Windows 开发验证，但唯一真实运行在发布前因固定 Top50 中 exact 一个持有期收益缺失而 fail closed；三者必须保持 `UNASSESSED/HOLD`，既不能称有效，也不能称无效。
- **首个 PIT 财务质量研究的经济合同已接近可执行，但数据发布链尚未 READY。** R13、R14、R16、R17 已分别关闭成本身份、财务版本链、PIT 冗余覆盖和 classic 冗余对称性；R19 明确剩余核心是 PIT 固定方向与 h20 分组单调性、singleton report type 和运行身份闭包。真实 audit-v4 的有界证据目前指向 `BLOCKED`，因此尚不能发布 financial snapshot 或启动 PIT 试验。
- **后续主线改为业务优先。** 工具链、compiler、parser、wrapper、capability fixture 和大 JSON 流式证据工具归框架领域；投研线集中完成首个 PIT、annual asset growth、GPOA、NOA、SUE/PEAD 的预注册、经济合同、回测和研究结论，不再由投研经理承担工具性质开发。

## 1. 真实策略研究结果：淘汰多，晋级为零

近期最重要的结果不是出现了新“明星因子”，而是多个看似合理的候选在预注册门禁下被诚实否决。当前没有任何新增候选具备 `PAPER_CANDIDATE` 资格。

| 研究批次 | 真实证据摘要 | 当前结论 | 业务含义 |
|---|---|---|---|
| Amihud 非流动性、自由流通换手水平、12 个月异常换手 | 三个候选均完成不可变运行；2026 年 2 月只有 14 个开市日，低于预注册的 15 日要求，coverage 因而归零；Amihud 还未通过方向/折数与 `<0.80` 冗余门禁 | `REJECTED` | 不为保住结果降低有效日阈值，不原地重跑 |
| Downside beta vs 510300 | coverage、31 个预注册调仓日及冗余闭合；平均 test RankIC `0.006225`，仅 `1/3` folds 为正，2 倍成本后链式收益 `-25.7147%` | `REJECTED` | 防御性机制在本地样本和成本下不足以支持继续投入 |
| RESI20 / IMXD20 / VSUMD20 | coverage 和调仓日闭合；IMXD20 冗余 `0.80127` 超过严格上限，RESI20 平均 test RankIC 仅 `0.00565`，VSUMD20 方向不稳且平均 RankIC 为负，三者成本后收益均为负 | `REJECTED` | Alpha158 形态/量价家族没有形成可晋级的独立增量 |
| MAX 家族 | 早期 raw MAX 结果受 R11/HOLD 边界约束；后续规模与换手残差化运行曾记录平均 test RankIC `0.04570`、`3/3` folds 为正、2 倍成本后链式收益 `-5.0079%`，但 R11 后该成本腿不再具有有效经济证伪资格 | 历史 run 状态保留 `REJECTED`；R11 后 corrective hypothesis 为 `UNASSESSED/HOLD`，lineage 不晋级 | `-5.0079%` 仅作历史记录；不授权据此重跑、翻案或晋级 |
| R18 Alpha101 #006 / #012 / #041 | 实现与开发验证闭合；唯一真实运行在 artifact 发布前停止。受控诊断定位到 `alpha101_006`、fold 1、2022-01-04 的 Top50 中 exact 一个 holding-period return 为 null | `UNASSESSED/HOLD` | 没有 run id、manifest 或完整结果；不得过滤未来 outcome、替补第 51 名、跳期或重加权来“救活”试验 |

**结论：** 近期因子挖掘的有效产出主要是排除了弱候选和伪稳健路径。它降低了未来组合污染和过拟合风险，但不能被包装成正向 alpha 进展。

## 2. 研究闭包进展：首个 PIT 已从“能算”推进到“差最后几道经济门禁”

R12—R19 的工作重点是修正评估合同，使真实运行不能通过删样本、方向翻转、冗余漏算或成本身份漂移获得伪通过。

| 包 | 已关闭的精确边界 | 尚未证明的范围 |
|---|---|---|
| R12 | outcome grid/cohort、未来标签缺失不得重排候选、漂移后持仓与换手 | 不代表历史 HOLD 结果恢复有效 |
| R13 | 首个 PIT 的主配置与成本配置 single-payload identity、canonical cost semantic SHA | 不代表所有 legacy runner 的 provenance 全局闭包 |
| R14 | 财务 revision chain、current available-date cutoff、`comp_type=1` 在 latest selection 前过滤 | 真实 singleton `allowed_report_types` 仍须 audit-v4 证据冻结 |
| R16 | 首个 PIT direct-call chain 的 redundancy incident/coverage 对称闭包 | 不扩大为全部 runner 的全局闭包 |
| R17 | classic corrective-replay 的 candidate-candidate 对称冗余聚合 | 不关闭 PIT h20 单调性或全局 Gate |
| R19 | latest-main 六项影响矩阵与最小剩余实现候选 | 结论仅 `IMPACT_MATRIX_FROZEN`；`M2-EVAL-STOP-001` 仍为 `OPEN` |

R19 已把首个 PIT 的最小剩余研究包收敛到 runner、runner test 和版本化 config：四个 PIT 质量因子复用同一 universe、fold、cost 和 signal identity，分别固定方向后评估，再以 canonical schema 合并；h20 必须按 signal date 等权验证方向调整后的 `group1 <= ... <= group5`，至少 `2/3` folds 且 pooled 通过，h1/h5 只作诊断。任何缺组、缺日期、重复键、coverage 失败、非有限值或身份漂移都只能从 `RESEARCH_ONLY` 降级为 `REJECTED`。

**业务含义：** 研究框架已经能够更可靠地回答“候选为什么失败”，但这些闭包本身不是 alpha，也不能替代一次真实、不可覆盖的 PIT 运行。

## 3. 当前关键阻塞：不是缺策略想法，而是首个财务证据链尚未 READY

财务采集已经达到四表各 `44,296`、合计 `177,184` 个请求全部 COMPLETE，noncomplete 和 active lease 均为 0；UA-M2-001 的 1,365 条 cashflow 有界恢复也已完成。audit-v4 实现与 Windows integration 验证已经合流。

唯一真实 audit-v4 进程已自然 exit 0，原生 stdout 约 1.112 GB。当前有界证据显示：

- top status 为 `BLOCKED`；
- blocking issue 为 `FINA_INDICATOR_END_AFTER_AVAILABLE`，count=`1`；
- `verify_bytes=true`；
- `publication_allowed=false`；
- `flow_semantics.status=NOT_EVALUATED` 且 `buckets=[]`。

但承载层在整块解析 1.112 GB JSON 时内存失败，完整流式证据闭包尚未完成。因此当前只能诚实表述为：**业务输出高度指向一个精确数据阻断，但完整 audit 证据尚未封板；financial snapshot、R3 和 PIT 均不得启动。**

根据用户最新分工，compiler/toolchain/parser/wrapper/streaming evidence 等工作由框架领域负责。投研经理只消费框架线交付的已验证 audit 结论，不再设计或实现解析工具。

## 4. 后续工作安排：按业务 Gate 推进，不按日历强行承诺

### 4.1 立即开展：投研侧只做经济合同和预注册收口

1. **首个 PIT R3 业务合同整理。** 将四因子方向 `(+1,+1,+1,-1)`、h20 单调性、singleton report type、trial budget、attempt receipt、universe/folds/cost、13 outputs 和失败语义整理成可实施任务书；在 audit-v4 与 allowed report type 未闭合前不运行、不创建结果 artifact。
2. **建立 `quant_factor_research_v2` 候选增量地图。** 只做机制、字段可得性、与现有因子重复度、预期方向、负对照和成本敏感性审计；不把论文结果当成本地 alpha，不新增 trial，不再盲目堆 bar-only 因子。
3. **预注册 annual asset growth。** 主定义固定为 `(TA_FY_t - TA_FY_t-1) / TA_FY_t-1`，prior assets 必须大于 0，低资产增长优先、方向 `-1`，单独 trial；主板、剔除最小市值 30%、long-low-AG 与 `1x/3x/10x` 容量成本只作诊断，不能替代主试验。

### 4.2 框架/数据 Gate 闭合后：完成首个 PIT，而不是继续扩候选池

1. 框架线完成大 JSON 的完整、单遍、低内存证据闭包；若确认 audit-v4 `BLOCKED`，由数据 owner 对 exact 一条异常及其 fail-closed 处置另立任务，不由投研层绕过。
2. audit-v4 达到可发布状态后，冻结 singleton `allowed_report_types`，再由统筹基于 latest clean main 冻结 R3 exact base、worktree 和白名单。
3. R3 完成实现、独立审查和平台验证后，发布不可覆盖 financial snapshot。
4. 对四个 PIT 质量因子执行唯一预注册试验：
   - `pit_roe_ttm`，方向 `+1`；
   - `pit_roa_ttm`，方向 `+1`；
   - `pit_cash_profit_quality_ttm`，方向 `+1`；
   - `pit_total_accruals_ttm`，方向 `-1`。
5. 只按预注册的 fixed direction、RankIC、fold 稳定性、h20 分组单调、coverage、冗余和 0.5x/1x/2x 成本给出 `REJECTED` 或最高 `RESEARCH_ONLY`；不使用组合来挽救单因子失败。

### 4.3 首个 PIT 后：按经济机制逐包推进

| 优先级 | 研究包 | 预注册重点 | 启动条件 |
|---|---|---|---|
| P1 | Annual asset growth | 年频资产增长、方向 `-1`、单 trial、规模/流动性/容量诊断 | 首个 PIT 完成且 annual pair lineage/字段 coverage 闭合 |
| P2 | GPOA | 年度收入与营业成本形成 gross profitability，方向 `+1`；不以 margin proxy 替代 | 本地 raw 字段、income/balance PIT join 与 clean contract 闭合 |
| P3 | NOA | 方向 `-1`；现金、债务、权益分量及 prior-FY 资产分母必须会计闭合 | 字段 mapping、缺失策略和重复扣减风险全部 fail closed |
| P4 | SUE / PEAD | classic EPS SUE 与公告事件研究分开；announcement→next-open、季度链和标准化窗口预注册 | EPS/季度 revision provenance、公告可知时点与更高换手成本闭合 |

GPOA、NOA、SUE/PEAD 不能混成一个“基本面大礼包”。每个候选必须拥有独立 trial identity、方向、时间语义、成本和停止条件；只有单项通过后，才允许另开低维、冻结权重的组合试验。

## 5. 暂不做的工作

- 不再由投研经理承担 compiler、parser、wrapper、streaming JSON、通用 runtime 或工具链开发；
- 在首个 PIT READY 前，不继续启动新的 bar-only 实现/回测包；如用户希望额外并行，必须先单独批准候选族和 trial budget；
- 不为 R18 过滤 null outcome、替补第 51 名、跳过调仓期或恢复已消耗的三个 trial slots；
- 不把历史 `RESEARCH_ONLY/HOLD`、开发测试绿灯、静态 review PASS 或论文结果写成可交易 alpha；
- 不在同一测试集上事后选择方向、阈值、形成日、成本倍率或组合权重；
- 不在 PIT、真实 forward、S2 admission 和人工准入前进入 PAPER。

## 6. 建议的管理节奏与下一次汇报点

1. **周内投研产出：** 完成首个 PIT R3 业务合同清单、`quant_factor_research_v2` 增量候选地图和 annual AG 预注册草案；这些是业务文档，不启动真实 trial。
2. **Gate 事件汇报：** 框架线给出 audit-v4 完整流式证据结论后，立即汇报 `PASS/BLOCKED`、exact issue、是否允许 snapshot，以及 R3 可否冻结。
3. **首个 PIT 汇报：** 唯一运行完成后，按四因子逐项报告方向化 RankIC、3-fold 稳定性、h20 单调、coverage、冗余、成本和最终 disposition，不只汇报组合收益。
4. **候选队列汇报：** annual AG 完成后再决定是否进入 GPOA；NOA 与 SUE/PEAD 继续按字段和时间语义 Gate 排队，不因论文吸引力插队。

## 7. 仍需回答的问题

- audit-v4 的 exact 一条 `FINA_INDICATOR_END_AFTER_AVAILABLE` 在完整证据闭包后是否仍为唯一阻断；其正确处置是数据隔离、请求重取还是契约拒绝，需要数据 owner 裁定。
- 首个 PIT 的 singleton `allowed_report_types` 最终取值必须来自 terminal、bytes-verified audit 证据，不能由实现者或投研经理猜测。
- R18 的一个 missing holding outcome 是 immutable bar snapshot 的真实缺失、公司行动边界还是结果构建合同问题；在新任务身份和用户明确授权前，不建议第二次真实运行。
- annual AG 的最终形成日、持有窗口和 China replication benchmark 仍须在任何收益读取前写入独立任务书。

## 8. 口径与风险提示

- 本报告汇总的是截至 2026-08-30 已合流代码、任务/交付/初验文档、Git ancestry 与已保留真实运行结论；没有重新运行 Python、回测、audit 或读取 raw/clean 数据。
- 数字型结果只用于说明已完成 run 的冻结结论；不同候选、fold、时间窗和形成频率不能横向排名。
- `REJECTED` 表示在预注册门禁下不晋级，不等于经济机制永久无效；`UNASSESSED/HOLD` 表示证据不足，不能解释为接近通过。
- 当前最可能改变计划的外部事实是 audit-v4 完整证据结论。该结论未闭合前，任何 financial snapshot、PIT 收益或 post-PIT 因子运行都不是已授权工作。
