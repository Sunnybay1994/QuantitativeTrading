## 5. 因子库与策略库的最小维护模型

### 5.1 因子定义

每个稳定因子应有一个版本化 `factor_spec` 概念，至少记录：

- factor id/version、经济机制、方向；
- 输入字段和数据契约；
- PIT 延迟、信号频率、适用宇宙；
- 公式/实现哈希、缺失/异常值规则；
- 推荐控制变量、容量与成本敏感性；
- 状态：`IDEA / EXPLORATORY / RESEARCH_ONLY / REJECTED / RETIRED`。

当前不急于新增通用注册框架；先用代码常量、假设卡和不可变 run 证明实际需求，避免过早抽象。

### 5.2 因子实现边界

- `quant.factors`：只接受标准 DataFrame，纯函数计算，不读磁盘、不下载数据、不下单；
- `quant.research`：组织 snapshot、PIT、标签、walk-forward、成本压力和发布；
- `quant.strategies`：未来把已冻结因子转换为 `target_weight`；
- `quant.backtest`：统一市场规则和账户，不接受研究 runner 自报成交；
- `quant.execution`：只消费人工准入后的不可变策略产物。

### 5.3 策略定义

一个可维护策略至少绑定：

- 因子版本和组合规则；
- `as_of`、最早成交时点、调仓频率；
- 股票池和风险/容量约束；
- `target_weight` 归一化和无信号处理；
- 成本、市场规则和 benchmark；
- forward、暂停和退役条件。

### 6.3 评估闭包 STOP（`M2-EVAL-STOP-001`）

TARGET R11 只关闭了 Top-K 目标选择的未来标签替补，不等于共享评估与成本门禁已经正确。2026-08-16
只读代码审计确认首个 PIT 前还必须关闭六项：

1. `evaluate_factor_period` 仍在 factor rank、RankIC 和分组前按未来 label/exit 可用性缩小截面；factor cohort、
   `group_score_rank` 与 group membership 必须先由信号时点可知的有限因子冻结，未来 outcome 缺失只能降低
   各固定组的 observed count，不得重分组或替补。标准 RankIC 可在真实 label 配对样本内重新计算
   `ic_score_rank` 与 `label_rank`，validation direction 也只能来自该 paired RankIC，但必须显式记录
   factor/label symbols 与 coverage；未形成完整 outcome closure 时须稳定 fail-closed，不能静默删行或跳日。
   每个 signal date 的 exit 必须是唯一、完整的 calendar-wide 值，mixed/null exit 不得逐证券静默过滤。必须形成
   `factor × fold × period × horizon × 预注册日期` 的 expected/emitted grid，并分别记录 signal-eligible 与
   label-complete 数量；signal coverage 不能替代 outcome coverage；
2. diagnostic simulator 在持有期收益后仍把上期目标权重当作本期调仓前持仓计算 turnover；若要继续让
   0.5x/1x/2x 成本腿参与门禁，必须携带所选证券逐一 holding return，按持有期后漂移权重计算调仓和末端
   清仓；分母非正、收益非有限或 `1 + return` 非法时 fail-closed。仅改名为 target-change 诊断量不能关闭
   PIT 的 2x 成本门禁；
3. PIT 首个 direct-call chain C 的日期 coverage 已在 `M2-EVAL-R16`（`STATIC_DONE`/`STATIC_ONLY`）边界内按
   `factor_a`/`factor_b` 两侧
   对称收集全部 incident pairs，严格 Boolean 全部通过且无 incident fail-closed；summary 候选行集与顺序保持，
   已有 `REJECTED` 不升级。该包不关闭 classic runner 中仍按 `factor_a` 聚合的 candidate-candidate gate；
   classic corrective replay 前仍须另行冻结和关闭该边界，本包不扩大范围或宣称运行 Gate 通过；
4. 主配置当前先 `read_bytes` 计算 SHA、再第二次打开解析，存在同一次 run 执行字节与 manifest hash 不一致的
   TOCTOU；外部成本配置又只绑定相对路径。首个 PIT 新 run 前必须让主 config 与 cost config 分别由同一份
   稳定 payload 完成 parse+hash，并把严格、完整的 `[costs]` canonical semantic digest 作为标准 run input。
   tracking/model/acceptance、注释、EOL 或等价 TOML 小数拼写不得制造 M2 假 lineage；任何成本版本、来源、
