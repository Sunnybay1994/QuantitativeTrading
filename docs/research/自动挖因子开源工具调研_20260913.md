# 自动挖因子开源工具调研

日期：2026-09-13。目标：用一轮短时调研筛出可接入现有表达式与评估流水线的候选生成工具。

结论：优先考察 **DEAP（定制遗传搜索）与 gplearn（快速基线）**，金融专用算法对照选 **AlphaGen**；LLM 路线借鉴 **RD-Agent** 的研究反馈循环。新工具应输出候选表达式，沿用本项目计算与评估口径。本次依据官方文档、作者仓库与论文进行选型，运行兼容性和收益尚未经本地实验验证。

## 1. 七个主要选择

| 工具与官方来源 | 方法与产物 | 对本项目的判断 |
|---|---|---|
| [DEAP](https://github.com/DEAP/deap) | 进化计算库；遗传编程生成表达式树，可自定义算子、类型和适应度 | 最适合将搜索树转换成现有 DSL；金融目标函数与搜索循环需自行连接 |
| [gplearn](https://gplearn.readthedocs.io/en/stable/) | 符号回归、SymbolicTransformer 自动生成相关性较强的组合特征 | 适合预计算特征上的快速 GP 基线；日期分组、滚动算子与金融评估需适配 |
| [PySR](https://github.com/astroautomata/PySR) | 符号回归，搜索兼顾误差与复杂度的公式 | 适合非线性关系发现；Python 接口依赖 Julia 搜索引擎，运行环境更重 |
| [AlphaGen](https://github.com/ICT-FinD-Lab/alphagen) | 强化学习生成公式因子，优化因子集合的联合预测能力 | 金融专用方法首选对照；研究代码的旧依赖需要适配 |
| [AlphaForge](https://github.com/DulyHao/AlphaForge) | 生成式因子挖掘，加动态因子组合 | 适合研究“挖掘后如何组合”；挖掘与组合两个贡献应分开验证 |
| [AlphaSAGE](https://github.com/BerkinChen/AlphaSAGE) | 结构感知 GFlowNet 搜索，重视候选多样性 | 可作为较新方法储备；图编码与训练系统增加接入成本 |
| [Microsoft RD-Agent](https://github.com/microsoft/RD-Agent) | LLM 提出研究方向、实现、实验、读取反馈并迭代 | 与自动投研目标接近，但整套框架和现有系统重复较多；优先借鉴流程 |

前三个是通用搜索库；中间三个更接近论文配套的金融研究实现；RD-Agent 是更完整的自动研究框架。不能仅凭“支持自动挖因子”就认为它们可互换。

## 2. 关键核验与接入限制

### DEAP 与 gplearn

DEAP 的强类型遗传编程可以区分不同节点类型，适合约束“面板表达式”和“窗口常数”。建议只使用它生成、变异和交叉表达式树，计算仍交给项目已有引擎。这样可保持滚动历史、缺失值和截面排序的含义一致。这是基于接口能力的工程判断。[官方 GP 文档](https://deap.readthedocs.io/en/stable/tutorials/advanced/gp.html)

gplearn 的 SymbolicTransformer 可按 Pearson／Spearman 相关性搜索，并筛选较少相互相关的输出特征，也允许自定义函数与适应度。其通用表格接口不会自动理解股票与日期两个维度；直接把全市场面板摊平成 X、y 后计算一个相关系数，不能替代逐期截面 RankIC。最简单的用法是先在项目中计算滞后、滚动特征，再搜索这些列的算术组合。[实现与接口](https://gplearn.readthedocs.io/en/stable/_modules/gplearn/genetic.html)

维护状态有一个容易被旧资料误导的细节：gplearn 已在 **2026-01-06 发布 0.4.3**，要求 Python ≥3.11、scikit-learn ≥1.8.0，不能再据 2022 年的旧版本判断长期无更新。项目实际依赖组合仍需安装前检查。[发行记录](https://gplearn.readthedocs.io/en/stable/changelog.html)

### PySR

PySR 支持自定义算子、损失与复杂度限制，适合挖掘预处理特征之间的可读公式。其 README 明确说明首次导入会安装 Julia 依赖；这不是一个只有 Python 依赖的轻量替换件。金融时间窗口和分期相关性目标需要额外设计。[官方仓库](https://github.com/astroautomata/PySR)

### AlphaGen、AlphaForge 与 AlphaSAGE

AlphaGen 对本项目最有价值的思想是：**搜索因子对现有因子池的贡献，而非只追逐单因子 IC**。作者仓库同时包含强化学习和 LLM 生成入口，并提供可读的因子池输出。其依赖固定了 numpy 1.20.1、pandas 1.2.4、torch 2.0.1 等旧版本，不能将原 requirements 当作当前 Windows Python 3.13 环境的直接安装方案。[作者实现](https://github.com/ICT-FinD-Lab/alphagen)、[依赖文件](https://github.com/ICT-FinD-Lab/alphagen/blob/master/requirements.txt)、[KDD 2023 论文](https://arxiv.org/abs/2306.12964)

AlphaForge 应认准 **DulyHao/AlphaForge**，同名项目较多。作者实现对应 AAAI 2025 工作，区分因子生成和动态组合；依赖含 gym 0.21.0、torch 1.13.0 等旧版本。建议先研究方法，不整体移植训练环境。[作者仓库](https://github.com/DulyHao/AlphaForge)、[原始依赖](https://raw.githubusercontent.com/DulyHao/AlphaForge/master/requirements.txt)、[论文](https://arxiv.org/abs/2406.18394)

AlphaSAGE 使用结构感知图编码与 GFlowNet，提供因子池生成、组合及部分基线入口，值得关注它能否减少大量近似重复公式。该判断需要在相同候选预算下检验，不能用不同搜索次数下的最优 IC 直接比较。[作者仓库](https://github.com/BerkinChen/AlphaSAGE)、[2025 年预印本](https://arxiv.org/abs/2509.25055)

### RD-Agent

RD-Agent 的优势是研究想法、实现与反馈的闭环，量化场景覆盖因子和模型研究。当前 README 明确写明只支持 Linux，多数场景需要 Docker；与本项目 Windows 原生运行约束有冲突。建议吸收候选生成与反馈策略，保留本地执行器。[官方安装与场景说明](https://github.com/microsoft/RD-Agent)

## 3. 对项目的具体建议

本地 `src/quant/research/generate_factor_candidates.py` 已有诊断想法到 DSL 候选的入口，包含字段／算子限制、来源关联、表达式去重与历史长度校验，引用 `quant.factors.search` 执行候选展开。因此可以在已有入口旁接一个遗传搜索生成器，而无需再建因子平台。

建议顺序：

1. **先验证 DEAP 路线**：复用允许的字段、算子与窗口，输出同格式表达式。若只需快速比较预计算特征组合，可用 gplearn 缩短首个实验时间；两者先选一个。
2. **与现有候选生成方式公平比较**：固定数据、算子集合、候选评估次数与随机种子安排，比较有效独立候选数、验证期增量 IC、稳定性和计算时间。
3. **GP 基线成立后再考虑 AlphaGen**：重点验证联合因子池目标是否带来增量。AlphaForge、AlphaSAGE 暂作方法储备。
4. **继续完善现有 LLM 候选反馈闭环**：借鉴 RD-Agent，将评估结果转成下一批表达式建议，候选仍经现有校验和统一评估。

搜索使用训练数据，选择使用验证数据，冻结后评估留出测试集；记录搜索过的候选数量并评估多重尝试影响。沿用项目逐期 RankIC、长期稳定性、冗余、成本和组合风险评估。用全历史搜索后再在同一历史计算长期 t 值，不能成为独立检验。

补充工具：[Featuretools](https://docs.featuretools.com/en/stable/) 适合多表与时间关系的特征合成；[tsfresh](https://tsfresh.readthedocs.io/en/latest/text/introduction.html) 适合时间序列统计特征提取，可关注分钟数据低频化。它们更偏自动特征工程，仍需要金融目标筛选。固定因子集、技术指标库与评估工具也不能单独替代公式搜索。

**下一步最有价值的产出是一个有界 GP 搜索基线的本地结果，而非同时接入七套工具。**
