# M3 G1 BENCH-B1B：510300 总回报映射与全链身份重基线任务单

## 1. 目标与前置

在 BENCH-B1A 已完成外部实现、外部独立初验和主 Agent 终验后，把 M3 G1 benchmark 从不可取得的
`H00300.CSI index_daily` 切换为 `510300.SH` 可交易 ETF 总回报代理，并使 planner、candidate、clean 表、
readiness、label、build spec、manifest 和 release identity 同步重基线。

本包属于科学身份与不可变发布高风险变更。实现与初验必须由两个全新的外部 Cursor 会话承担，均显式使用
`cursor-grok-4.5-high`；实现者不得宣布 Gate 通过，初验者除自己的唯一报告外保持只读。B1A 未完成时
不得开始本包写入。

权威证据：

- 数据能力、字段、重复分红事实和除息对账公式见
  [`M3_G1_BENCH-B0_510300ETF基准源探针与合同冻结任务单.md`](M3_G1_BENCH-B0_510300ETF基准源探针与合同冻结任务单.md)；
- endpoint、row-limit、请求参数和 `fund_adj` 分段规则见
  [`M3_G1_BENCH-B1A_基金端点与分段请求基础设施任务单.md`](M3_G1_BENCH-B1A_基金端点与分段请求基础设施任务单.md)；
- 原有 M3 G1 时间、标签、PIT、source-closure 和不可变发布合同继续成立，未被本任务明确替换的语义不得改变。

## 2. 冻结科学合同

配置和运行时只接受以下精确身份：

- `benchmark = "510300.SH"`
- `benchmark_mode = "TRADEABLE_ETF_TOTAL_RETURN_PROXY"`
- `benchmark_method_version = "tushare_510300_fund_daily_fund_adj_hfq_v1"`
- `benchmark_dividend_reconciliation_version = "tushare_fund_div_implemented_cash_v1"`
- `label_version = "theoretical_next_open_to_h_close_510300_etf_hfq_proxy_excess_v3"`
- mapper version 从 `m3-g1-tushare-mapper-v1` 升为 `m3-g1-tushare-mapper-v2`

上述三项 benchmark 身份不得只隐藏在配置 SHA 中；必须作为 build spec、当前 manifest 和所有直接派生
identity 的显式字段参与 canonical JSON/hash。旧 identity 与新 identity 必须不同，禁止仅替换展示字符串。

### 2.1 正式请求闭包

规划区间沿用当前 G1 配置。原 3185 个证券 HISTORY request_id、排序与 receipt 必须逐个保持不变；删除当前
计划中的唯一 `H00300.CSI index_daily` 请求，并新增且仅新增：

1. 一个全区间 `fund_daily(510300.SH)`；
2. 三个由 B1A helper 确定的 `fund_adj` 分段（当前区间应覆盖 2015-2018、2019-2022、2023-配置结束日）；
3. 一个无日期参数的 `fund_div(510300.SH)`。

当前配置下正式 history 闭包应为 3190 个 receipts。旧 H00300 raw/receipt 是不可变失败事实，只从新 plan 排除，
不得覆盖、删除或伪装成 510300 数据。探针 raw 不得直接充当正式 receipt。

### 2.2 clean benchmark 构造

- 恰好消费计划内一个 `fund_daily`、全部且仅计划内三个 `fund_adj` 分段和一个 `fund_div` verified response；
  少、多、重复、顺序不稳定、目标外 endpoint/request_id/代码均 fail closed。
- `fund_adj` 分段拼接后交易日必须严格唯一、递增，并与 `fund_daily` 每个交易日一一覆盖；因子必须有限且
  大于零。clean OHLC 精确为对应 raw OHLC 乘同日 `adj_factor`，不得把 raw `pre_close` 或未来分红另加到
  收益中。
- clean `benchmark` 为 `510300.SH`，`source` 为 `tushare`；`source_snapshot_id` 是按
  `(endpoint, request_id, stable_response_sha256)` 排序后的五个正式 response 身份生成的 canonical SHA-256，
  因而任何分段、行情或分红 receipt 改变都会改变 snapshot identity。
- `BenchmarkBar1dSchema` 现有代码模式已容纳六位 `.SH/.SZ`，本包不得为此放宽 Schema 或引入旁路表。

### 2.3 分红经济事件与因子对账

只接受 `div_proc == "实施"` 且核心日期/现金字段可解析的事件。供应商重复行先投影到经济事件核心：
`ts_code,ann_date,imp_anndate,record_date,ex_date,pay_date,div_cash`；完全相同投影只计一次。能映射到同一经济
事件但 `ex_date` 或 `div_cash` 冲突时 fail closed，`net_ex_date/base_unit` 差异不得造成双计。

对配置窗口内每个现金事件，必须找到前一开市日和除息日，并同时验证（既有 `rtol=0.001`，不增加宽松绝对
容差）：

1. `ex_day.pre_close ~= previous_close - div_cash`；
2. `ex_day.factor / previous_day.factor ~= previous_close / ex_day.pre_close`。

非正分母、缺失相邻日、事件存在但因子不跳变、无可解释事件的因子跳变均 fail closed。窗口首日因子相对
窗口外历史是否跳变不可判定，不得猜测失败；但窗口内所有可比较相邻日都必须检查。2026-01-19 的真实冻结
反例数值见 B0-R2。

`fund_adj` 已把现金分红反映在复权价格中，因此 label 继续使用“entry 下一开市日 open 到 horizon close”的
benchmark 调整价收益，禁止再人工加一次现金分红。entry 前、entry 日、持有区间内和 exit 后的事件必须有
边界测试，证明没有未来信息穿越或双重计入。

## 3. 版本与向后兼容

- 新增当前发布格式 `m3-g1-manifest-v2`（建议显式类型 `G1ManifestV2`）；v2 必须包含第 2 节三个 benchmark
  身份字段并纳入 manifest hash/signature 输入。
- 已落盘的 v1 manifest 仍可按其原字段集合读取和验证，重建时固定解释为旧
  `H00300.CSI/index_daily/close-only` 合同；v1 不得被静默补成 v2，也不得由当前 publish 路径再次生成。
- 当前 publish、read-after-write、candidate build 和 planning 全部生成/要求 v2；v1/v2 字段混合、缺字段、
  多字段、未知 schema version 均 fail closed。
- 若需要 union/Protocol 只允许服务于显式 v1 历史读取与 v2 当前发布，不得弱化 exact-type/exact-field 审计。

## 5. 必测对抗性反例

- 五份响应少一份、多一份、重复 request_id、错 endpoint、错代码、错分段或非稳定排序；
- `fund_daily` 与合并因子的日期缺失/额外/重复，因子为零、负数、NaN 或无穷；
- 复权 OHLC 被再次加现金、使用 raw close、或只替换 benchmark 而 label/build/manifest identity 未变化；
- `fund_div` 完全重复、仅 `net_ex_date/base_unit` 不同、核心现金冲突三类分别覆盖；
- 2026-01-19 正例，以及错误 `ex_day.pre_close/(ex_day.pre_close-div_cash)`、无事件因子跳变、事件无跳变；
- entry 前、entry 当日、持有区间、exit 后四种分红边界；
- 旧 v1 可严格重读但不能作为当前 publish 输入，v1/v2 混合、未知字段和伪造 benchmark method 被拒绝；
- 3185 个证券 request_id 与切换前完全一致，新闭包精确 3190，旧 H00300 请求不存在于新 plan；
- readiness 对 `H00300.CSI`、raw 510300、不完整 source snapshot 或身份不匹配均 fail closed。
