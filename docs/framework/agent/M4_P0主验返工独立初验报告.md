## 4. 失败项（阻塞）

### F4 / P0-D：`__context__` 路径注入未清除

- **现象**：`raise StoreError(...) from None` 后 `__cause__ is None` 且 `traceback.format_exception` 不展示 context，但 `exc.__context__` 仍为原始 `OSError` / `sqlite3.Error`，其 `str` / `filename` / `args` 含绝对路径。
- **根因**：`from None` 只切断 cause 链并抑制默认 traceback 打印，**不擦除** `__context__` 对象上的路径载荷。实现者 `_assert_scrubbed_store_error` 只查 `__cause__` 与 formatted traceback，未断言 `__context__`。
- **应遵循规则**：任务单 F4 与初验指令要求 URI/parent/connect/PRAGMA/migration/TX 边界映射为稳定 code，且 **`__cause__` / `__context__` / traceback 均无注入路径**；不得回显 URI/path/原异常文本。
- **最小复现**（WSL `conda run -n base python`，cwd=临时目录）：

  1. parent 为普通文件：`ExecutionStore.open("sqlite:///blocked/child.db")`  
     → `StoreError("PARENT_CREATE_FAILED")`；  
     `exc.__context__` 为 `FileExistsError`，`str(exc.__context__)` 含 `'/tmp/.../blocked'`，`filename` 同为绝对路径。
  2. mock `sqlite3.connect` 抛 `OperationalError("unable to open: /tmp/.../secret.db")`：  
     → `StoreError("OPEN_FAILED")`；  
     `exc.__context__` 的 `str`/`repr`/`args` 含该绝对路径。
  3. 对抗变体：CONN 包装使 `COMMIT` 失败（消息含路径）后 `ROLLBACK` 再失败：  
     → 主错误仍为 `TX_COMMIT_FAILED`（cleanup 未覆盖主错，此点合格）；  
     但 `exc.__context__` 的 `str` 仍为 `commit failed near /tmp/.../rb_cover_secret.db`。

- **新增测试（返工必须覆盖）**：对 PARENT/OPEN/PRAGMA/MIGRATION/TX_BEGIN/TX_COMMIT 等路径，除 `__cause__ is None` 与 traceback 外，显式断言 `exc.__context__ is None`，或断言对 `__context__` 的 `str`/`repr`/`filename`/`args` 序列化结果不含注入绝对路径。
- **通过条件**：上述三条复现中，`__cause__`、`__context__`、formatted traceback 均无注入绝对路径；主错误 code 不变；cleanup 失败仍不得覆盖更早主错误。
