## 2. 独立对抗（实现者未落盘）

一次性探针（Windows `%TEMP%` / WSL `/tmp`），未写入仓库测试：

1. **hostile recursive exception**：CAS 二次 SELECT 注入带绝对路径 + `__cause__`/`__context__` 的 `OperationalError` → 仅 `ORDER_AGGREGATE_CAS_FAILED`，异常链空，旧 row 不变。
2. **stage COMMIT 失败**：首个 `COMMIT` 注入失败 → `TX_COMMIT_FAILED`，重开库无 command/receipt/counter。
3. **NOT_SENT + 双 worker fencing**：w1 NOT_SENT 保持 LEASED；过期后 w2 reclaim attempt=2；w1 旧 attempt mark SENT → `OUTBOX_DELIVERY_LEASE_MISMATCH`。
4. **callback 中途 CAS 爆炸**：event/aggregate/SENT 全回滚，delivery 仍 LEASED，返回码无 TOKEN。
5. **writer busy**：外连接持锁时 `dispatch_pending` → `SERVICE_CLAIM_FAILED`，cause/context 空。
6. **重放幂等 / UNKNOWN 不 reclaim / 外层三表回滚 / 同 identity 异 payload CAS**。

结果：Windows **16/16 PASS**；WSL base/DrvFS **14/14 PASS**（同核心集合）。

## 4. 后续主验是否掩盖基础合同

只读核对已主验的 P4-R / P4-C / P4-R2 / P5 报告与当前代码：

- 独立 A1–A9 在合流后的 store/service 上仍成立 → **未发现后续包掩盖 P4-P1/P4 基础 durable 缺陷**。
- 注意：P5 主验 cold import 仅断言未加载 Qlib/LightGBM/MLflow，**未覆盖 httpx/connector 模块加载**；属导入卫生证据不完整，不是对 CAS/lease/callback 原子性的掩盖。

## 5. 边界与非结论

- 本 PASS 只覆盖 P4-P1 storage primitive 与 P4 执行服务工程合同（含当前 worktree 已合流的 ledger/cancel/exact 扩展下的基础不变量回归）。
- **不宣称**完整 P4 Gate、P5 Gate、M4 Gate、PAPER soak、真实券商或 Linux/ext4 通过。
- 已知诚实窗口：adapter 副作用与 SQLite 非原子；`LEASE_EXPIRED_AFTER_DISPATCH` / `UNKNOWN_NOT_DURABLE` 需 P5 对账收敛。
- 残余：`get_command`/`get_order_aggregate` 等部分 P0 get 路径未像 stage/counter get 那样映射 SQLite 错误（service 外层多已重映射）；`quant.backtest.__init__` 桶导致的 httpx 冷加载。
