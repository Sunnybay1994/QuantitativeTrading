## 3. 代码审计：映射均离开 except 后抛

逐项核对 `store.py`，确认 OS/sqlite → `StoreError` 均在捕获原异常的 `except` 内仅构造待抛对象，离开 `except` 后再 `raise ... from None`；未发现对 `__cause__` / `__context__` / `__suppress_context__` 的私有字段赋值。

| 边界 | code | 控制流 |
|---|---|---|
| parent mkdir | `PARENT_CREATE_FAILED` | `except OSError` → 赋值 → 离开后 `raise ... from None` |
| sqlite connect | `OPEN_FAILED` | 同上（`sqlite3.Error`） |
| PRAGMA | `PRAGMA_FAILED` | 同上 |
| migration BEGIN/apply/COMMIT | `MIGRATION_FAILED` | 同上；既有 `StoreError` 子类 bare re-raise |
| transaction BEGIN | `TX_BEGIN_FAILED` | 同上 |
| transaction COMMIT | `TX_COMMIT_FAILED` | except 内 `_safe_rollback` 后赋值，离开后抛 |
| close | `CLOSE_FAILED` | except 内赋值，`finally` 清 `_conn`，离开后抛 |
| FK / IntegrityError | `REFERENTIAL_INTEGRITY` | 同上 |

`_safe_rollback` / `_safe_close` 仍吞掉 cleanup 失败；不捕获 `BaseException`。
