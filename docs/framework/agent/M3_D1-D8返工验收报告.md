## 3. 未关闭问题

### 3.1 D1 数据源选择契约缺失

`audit_m3_readiness` 对整个 bars 直接以 `(symbol,trade_date)` 检查重复，但 M3 TOML 没有
`data.source`。clean 层合法保留多个来源时，跨源同键会错误产生 `BARS_DUPLICATE_KEYS`。

必须冻结 `[data].source` 为必需配置；readiness、staging、manifest 和 provider 使用同一 source；
重复、覆盖、截面和基准检查均在选源后执行。请求源不存在时返回
`DATA_SOURCE_MISSING`。这也是原契约缺口，不只是实现 Agent 疏漏。

### 3.2 D4 混入其他股票池

`prepare_qlib_staging` 在 join membership 前没有按 `universe` 过滤，也没有 universe 参数。
独立复现加入 `universe=OTHER,symbol=600999.SH` 及其行情后，staging 实际包含该证券。
这会直接污染 CSI300_PIT 的 Alpha158 和模型样本。

必须给 `prepare_qlib_staging` 新增必需 keyword-only `universe: str`，先过滤 membership 再 join；
manifest 也必须记录 universe。

### 3.3 D4 接受 NaN 行情

`_reject_invalid_rows` 只检查 null 和大小比较，没有检查 NaN/infinity。构造 `close=NaN` 的行可成功
输出 `close=NaN` 的 staging。OHLC/volume/adj_factor 任一 null、NaN 或正负 infinity 都必须被拒绝，
readiness 的“有效行情”应使用同一 finite 语义。

### 3.4 D4 接受空 snapshot

`build_snapshot_manifest(files=[])` 会返回 `row_count=0,symbol_count=0,min_date=None,max_date=None`
及一个 snapshot ID，与 `DatasetSnapshot` 的正行数/正证券数契约矛盾。必须拒绝空 files、空 Parquet、
重复文件名、重复 symbol，以及文件名与 symbol 映射不一致。

### 3.5 D5 评估日期域污染

`rank_ic_by_date` 选择 horizon 后把 labels 的所有日期加入 `all_dates`。预测只有 2026-01-05，
labels 另外带 2025-12-01 时，结果被扩成 2 日，coverage 从 1.0 变成 0.5。真实
walk-forward 传入完整标签表时，训练/验证日期会污染测试指标。

应由调用者显式传入 `evaluation_dates: Sequence[date]`，或传入 `DateSegment + open_dates`；
labels 只在该日期集合内构造 denominator，区间外 predictions 显式拒绝，区间内缺预测日仍以
0 coverage 计入。

### 3.6 D7 mapping key 安全检查不完整

`_assert_safe_value` 对 mapping key 只检查敏感键片段，没有调用 `_assert_safe_string`。
`{"/home/user/private": "ok"}` 会通过扫描，之后绝对路径作为 MLflow param key 记录。
应对 `key_text` 先执行完整字符串安全检查，再检查敏感键片段。

## 5. 二次返工门槛

1. 配置新增必需 `data.source`，readiness 只审计选中 source。
2. staging 必需 `universe`，非指定股票池成员不得输出；manifest 记录 universe。
3. staging/readiness 使用共享 finite 语义，拒绝 null/NaN/infinity。

5. evaluate 使用显式 evaluation dates，区间外 labels 不影响日数、IC 和 coverage。
6. tracking 对 mapping key 执行与字符串 value 同级的路径/Bearer 检查。
7. 针对性反例、全量 pytest、Ruff、mypy 和 import 隔离全部通过。
