## 2. 阻断现象与根因

独立复验唯一阻断 P1：benchmark 同时存在未知 extra 列与配置区间缺开市日时，只报 `BENCHMARK_INVALID`，不报 `BENCHMARK_DATE_COVERAGE`。

根因：一次返工把「列超集」与「缺必需列」一并设为 `bench_ok=False`，导致 source 过滤与 dense coverage 整段跳过；而规则要求结构错误不得阻止其他独立 readiness issue 的确定性收集（任务单 §4.2 / §7.2）。

## 4. 最小修复

- `_benchmark_column_gate` 改为返回 `(has_required, is_exact, issues)`：
  - 缺必需列 → `has_required=False`，仅 `BENCHMARK_MISSING_FIELDS`
  - 列超集 → `has_required=True, is_exact=False`，报 `BENCHMARK_INVALID`，仍允许下游覆盖收集
  - 精确列 → 两者均为 `True`
- Schema 仅在 `is_exact` 时调用，避免超集二次 Schema 报错或重复 INVALID
- 覆盖路径：`exact+schema` 通过，**或仅列超集**时，投影 `_REQUIRED_BENCHMARK_FIELDS` 后交给 dense coverage；exact 但 Schema 值失败仍跳过，避免 OHLC 过滤二次异常
