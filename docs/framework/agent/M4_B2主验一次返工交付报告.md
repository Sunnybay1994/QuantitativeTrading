## 1. 现象—根因—规则

| 项 | 内容 |
|---|---|
| 现象 | `evaluate_connect_intent` 在 `limit_price=Decimal("1E+999999")`、`tick_size=Decimal("1E-999999")` 时抛 `decimal.Overflow` |
| 根因 | `_is_tick_multiple` 用 `price / tick_size` 再比 integral，绑定进程级 Decimal context 的 Emax/precision/traps |
| 规则 | tick 判定必须是 coefficient/exponent 的精确十进制整除；不读改全局 context；不做除法/quantize/rounding；大正指数差用 modular pow 或有界 valuation，禁止构造巨大 `10**k` |

## 2. 修改文件（白名单）

## 3. 冻结行为自证

- `1E+999999` / `1E-999999` → multiple → `ACCEPTED`（价格带闭合为该价）
- `1E-999999` / `1E+999999` → not multiple → `PRICE_TICK_INVALID`
- `0.30/0.05` → multiple → `ACCEPTED`
- `0.3/0.2`、`1.00/0.03` → not multiple → `PRICE_TICK_INVALID`
- `localcontext(prec=2, Emax=10, Emin=-10, Overflow/Inexact/Rounded traps=True)` 下结论相同，且调用后 prec/Emax/Emin/traps 与调用前一致
- 永不抛 `DecimalException`；不读改全局 context

拒绝优先级未改：not multiple 仍为 `PRICE_TICK_INVALID`。
