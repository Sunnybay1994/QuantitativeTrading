## 2. F1 — TradingConfig 必须严格构造并递归不可变

- 任何公开可构造的 `TradingConfig` 都必须满足与 `load_trading_config` 相同的完整字段、类型、跨字段、安全路径和
  PAPER/SHADOW 校验，且内部 document 必须递归不可变；不能只靠 dataclass `frozen=True`。
- 允许采用“唯一 loader/factory + 不可伪造内部构造边界”，或让公开构造器本身执行同一 strict normalization；
  不允许复制第二套校验规则。
- `trading_config_identity` 只能消费已严格自证且当前仍不可变的配置；不能把 `isinstance` 当作验真。
- 禁止用私有 marker 常量、可由调用方导入的布尔位或 `assert` 冒充信任证明。

## 3. F2 — schema version 单一事实来源

- `TradingConfig.schema_version` 与 canonical document 中的 schema version 不得成为两个可独立传入、可漂移的事实。
- 可以把属性派生自 canonical document，或在 strict constructor 中强制一致；无论采用哪种方式，identity envelope
  必须只消费已经验证的同一版本事实。
- 构造时版本不一致必须稳定拒绝，不能生成 identity，也不能静默选择其中一边。

## 4. F3 — version selector 不是 URI 或路径

- A 股、港股通、fee、FX 四个 selector 使用同一严格、可审计的版本 selector 语法；至少拒绝 `/`、`\\`、`:`、
  `%`、控制字符、URI scheme 和 `.`/`..` 路径语义。
- `file:///home/...`、`https://...`、Windows/WSL 绝对路径必须在 loader 阶段稳定拒绝且不回显原值。
- SQLite URI 继续走其专用的相对 POSIX 路径合同；不要用放宽通用 URI 的方式修 selector。

## 5. 必须新增的回归测试

1. 合法示例 thaw 后改成 `LIVE`，直接构造 `TradingConfig`：构造或 identity 前稳定拒绝；
2. 直接构造时删除必填键、加入 unknown key、注入 NaN/Inf：全部走同一 strict 合同拒绝；
3. 调用方传入普通可变 dict/list，构造成功后再修改原对象：已构造 config 与 identity 不得改变；
4. 对合法 loaded config 伪造不同 `schema_version`：稳定拒绝，不能得到与原配置相同的 identity；
5. 四类 selector 分别覆盖 `file:///home/user/private` 与 `https://example.invalid/rules`，全部拒绝且异常不含输入值；
6. 保留现有 14 项测试；字段重排、注释/空白、frozen symbol 顺序仍保持 canonical identity 稳定。

## 6. 禁止项

- 不新增 LIVE、真实券商、账号、token 或 `auto_trade=true` 路径；
- 不把 `TradingConfig` 改为松散 dict/duck type，不使用 `strict=False`；
- 不在 identity 函数中静默修补非法配置后继续；
- 不复制 `_FIELD_SPECS` 或另建第二份 schema/version 常量；
- 不修改任务书来迁就现有实现；不读取项目数据目录；不联网；不初始化 Git。
