## 2. F1 — InMemory key/content/identity 自证

- market fake 构造时逐项验证 mapping key exact type、`key.session_date == snapshot.session_date`、key symbol set
  与 snapshot states symbol set 完全相等、value exact `VerifiedMarketSnapshot`，并调用公开 identity verifier。
- account fake 构造时验证 datetime key 为 UTC、`key == snapshot.as_of`、value exact `AccountSnapshot` 且 identity
  重新验真；不能用 mapping key 做 PIT、却用 value 的另一时间做返回排序。
- 任一混配必须在构造阶段稳定 `RepositoryContractError`，不允许等 exact lookup 后直接返回。

## 3. F2 — Reader bundle strict boundary

- `CleanMarketFactsBundle` / `CleanAccountFactsBundle` 必须在公开构造边界或 repository 消费前完成 exact-type
  校验：UTC known_as_of、tuple 容器、正确 element 类型、裸 64 hex identity、`quality_passed` exact bool。
- `quality_passed=1/0`、list 冒充 tuple、字符串/duck object element 均稳定拒绝；不得用 truthiness。
- repository 在访问 element 属性、排序或调用 domain builder 前完成全部容器/element 门禁。
- 不复制 D0 的经济字段校验；通过 D0 builder/identity verifier 完成领域对象自证。

## 4. F3 — Reader 和 domain 异常稳定脱敏

- 注入 reader 抛出的普通 `Exception` 统一映射为稳定 `RepositoryContractError` code/message，使用 `from None`，
  不包含原异常文本、repr、绝对路径或凭据。不得捕获 `BaseException`。
- domain builder/verifier 的失败同样从 None 映射稳定 code；禁止 `str(exc)` 和 `raise ... from exc`。
- market/account 两条 production 路径、`InMemoryMarketDataRepository.from_states` 均遵守同一规则。
- 不把错误伪报为成功/partial；错误 code 应区分 reader failure、invalid reader result、domain contract。

## 5. 必须新增的定向测试

1. market mapping key 的日期或 symbol set 与 snapshot 不一致，构造即拒绝；损坏 snapshot identity 也拒绝；
2. account mapping key 与 `snapshot.as_of` 不一致、非 UTC key、损坏 identity 均拒绝；
3. 两种 bundle 的 `quality_passed=1/0`、wrong element、list container、非法 identity 分别拒绝；
4. market/account reader 分别抛含 WSL/Windows 绝对路径的 OSError，结果为稳定 typed error，`__cause__` 为空，
   `str/repr/traceback` 不含注入路径；
5. domain contract 错误与 from_states 错误也无 cause/path/repr 泄露；
6. 保留现有 11 项 D1 测试。
