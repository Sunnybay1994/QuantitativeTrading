## 2. 需要裁定和纠正的

### 2.1 裁定：Q10 进模拟盘第二账户

换手上限 6× 的目的是防成本模型误差。Q10 在 **2× 成本下年化仍 18.29%、超额仍为正**，目的已经达到；6.30 中约 78% 来自口径差。裁定：

- 换手统一口径：**单边成交金额年度合计 / 该年日均净值**，按日历年计，报中位数与最大值；预算参数与年化口径必须一致。
- 规则修订（写入路线图 §1.2）：换手 ≤ 6× 为硬线；**6×–8× 且 2× 成本后年化超额最强基准 ≥ 5pp 时视为通过**，因为成本已被双倍计入。
- Q10 按新口径重算一次；落在 6–8× 即 `PAPER_CANDIDATE`，进第二观察账户，从下一个月末调仓日起前向记录。2024-01 窗口 −23.9% vs −21.4% 的规模暴露问题留给 §4 的风险模型解决，不阻塞进模拟盘。

2. 手写文档每天 ≤ 2 篇；`paper_reading/` 每周 ≤ 1 篇，且必须对应一批已登记候选。
3. 已有 302 篇：09-11 → 09-13 的实验结论页移入 `docs/research/experiments_2026-09/`（一次性搬移，不改内容），`docs/research/` 顶层留下 ≤ 30 个文件。

### 2.3 风险模型仍未建（Q3）

Q10 唯一失败的压力窗口是 2024-01（−23.9%），三模型同窗口 −19% ~ −25%。没有风险模型就无法把它归因到规模/行业/特质，也无法在组合层约束。Q4 被实现成"缺风险字段持仓隔离"，不是原设计的"分层选股 + 暴露约束"。这两项是当前**最有价值的剩余工程**，见 §4。

### 2.4 GP 与 LLM 循环的规模问题

- GP：种群 24 × 4 代 × 深度 3 × 9 个终端，只有加减乘负。首批 3 个入选候选测试 RankIC 0.060 / 0.015 / 0.031，随机对照 0.046 / 0.043 / 0.028——Agent 正确地写了"尚不足以判定 GP 优于随机"。这个规模什么都判定不了。
- LLM 循环：前两轮格式失败，第三轮 3 个候选中唯一通过者是 `-ts_corr(adj_close, volume, 20)`，与库内因子秩相关 0.979。**没有把因子库清单和 scorecard 缺口喂给它，它就只能重新发明库里已有的东西。**

## 3. 后台自动挖因子：怎样从零件装成机器

目标：**工作日夜间与周末，机器自己产生候选 → 评估 → 去冗余 → 入库 → 月度重训模型 → 写摘要；Agent 每周读一次摘要。**

### 3.1 一个新的计划任务：`QuantitativeTrading-NightlyResearch`

工作日 22:30 启动（日更 21:30 复查之后），周六 09:00 启动长任务；时间盒工作日 6 小时、周末 20 小时；启动前检查日更写入者互斥（复用现有保护）。入口 `scripts/run_nightly_research.ps1 → quant.research.nightly`，配置 `configs/research/nightly.toml`。步骤全部幂等、可恢复：

| 步 | 内容 | 来源 |
|---|---|---|
| N1 队列摄取 | 读 `configs/factors/queue/*.toml`（Agent、报告提取器、用户放进来的候选批次），移入 `processing/` | 已有 DSL 校验 |
| N2 GP 搜索 | 每夜一个配置族轮换（价量 / 财务 / 分钟低频化 / 混合）；**种群 200、代数 30、深度 5**，终端 = 库内全部 raw 因子 + 基础字段，算子 = DSL 全集；适应度用**子样本**（300 只 × 72 个月）算 RankIC 均值 − 复杂度惩罚 − 与库内因子最大秩相关 × 0.5；Top 20 进 N3 | 现有 `run_genetic_factor_search` 扩参数与算子 |
| N3 评估电池 | 新候选全历史面板 + 电池 + 三档成本 + **对 ADMITTED 集合正交化后的增量 IC** | 现有电池 + Q7 增量 IC |
| N4 自动入库 | 通过电池且增量 IC 的 NW t ≥ 2.5 且与库内最大秩相关 < 0.6 → 写入 `configs/factors/library/auto/`，`source = "nightly_gp"`；否则归档到 `artifacts/factors/rejected/` 只留 scorecard 行 | 新 |
| N5 月度模型 | 每月第一个周六：ADMITTED 全集 → 三种加权 × 两种构建 → 2015–今 walk-forward；结果写注册表 | 现有 `follow_factor_models` |
| N6 摘要与排行榜 | `artifacts/research/nightly/<date>/digest.md`（新候选数、通过数、库规模变化、最佳模型变化、失败步骤）；重写 `docs/research/排行榜.md` | 新 `quant.reporting.leaderboard` |
| N7 可选 LLM 步 | 每周一次、$5 封顶：把 digest + 库清单 + scorecard 缺口族系喂给 DeepSeek，要求产出**不与库内任何因子秩相关 > 0.6** 的 20 个表达式，直接进 N1 队列 | 现有 `run_research_cycle` 改提示 |

资源护栏：磁盘剩余 < 50GB 停；单步超时杀进程并在 digest 记"未完成"；连续三夜同一步失败 → digest 顶部标红，其余步骤照常。

### 3.2 Agent 的角色变成什么

每周一读 digest 与排行榜，做三件事：往队列放一批有针对性的候选（针对缺口族系）；对进入 `PAPER_CANDIDATE` 的模型写一页决策；修流水线故障。不再手工跑评估。
