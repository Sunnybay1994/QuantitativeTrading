# 项目审查与流程重构报告（2026-09-08）

> 审查对象：`QuantitativeTrading` 全部代码、文档、Git 历史和 2026-07-11 至 2026-09-08 的任务记录。
> 目的：解释为什么两个月来"进度慢、总在纠结细节、投研工作很少"，并给出已经落地的重构。
> 本文是一次性诊断，后续不续写；当前规则见 [`AGENTS.md`](../../../AGENTS.md)，当前工作见 [`项目实施路线图.md`](../../../项目实施路线图.md)。

## 1. 一句话结论

这个项目把"不可逆生产系统 + 多团队冲突"级别的控制体系，套在了一个人的日频研究上。Agent 在这套
规则下理性地最大化"合同完整、STOP 合规、身份闭包"，于是产出了约 1,200 份流程文档和 16 万行代码，
却在 **8 月 16 日以后再没有跑出一个新的回测**，模拟盘和实盘为零。纠结细节不是模型偶然低效，
而是规范的直接激励结果。

### 2.2 流程摩擦链（来自治理规范的字面要求）

角色链：用户 → 统筹 → 领域经理 → Worker(+隔离 subagent) → 独立 reviewer → 领域验收 → 统筹合流/退休。
状态机：`PROPOSED → FROZEN → DISPATCHED → IMPLEMENTING → SELF_VERIFIED → REVIEW_REQUIRED → REWORK →
READY_FOR_INTEGRATION → INTEGRATED → RETIRED`，另有 `BLOCKED / RESOURCE_WAIT`。
每个任务必产文档：准入单、任务书、交付报告、独立审查报告、合流申请；必须申请：exact base、worktree、
写白名单、共享文件锁、CPU/内存/I/O/网络/DB writer/端口租约、资源等级、用户授权。
"实现一个 Alpha101 因子并跑一次回测"按规范下限约需 **15–20 轮交互、9–13 份文档**，且规范明文要求
"静态实现包"与"经济 trial 包"分开立项——即写完因子代码不允许直接跑回测。

### 2.3 任务书和审查在写什么

- R21（Alpha101 #002）任务书 44,945 字节、654 行、16 章："不得"45 次、"禁止"14 次、"必须"22 次、"STOP"11 次；
  真正描述因子公式的 §2–§3 只占约 **15%**，§12–16（公共 rank 身份、Windows 验证载体、Temp 目录、SHA、Ruff argv）占 **54%**。
  开篇自带状态 `TASKBOOK_ONLY / STATIC_ONLY / IMPLEMENTATION0 / ECONOMIC_IO0 / TRIAL0`，资源上限 `CPU NONE / PYTHON0 / DATA0 / NETWORK0`。
- R15（Alpha101 #011）独立审查 60,489 字节、894 行、经历 `PASS → FAIL P1=4 → PASS → PASS → PASS → FAIL P1=1 → PASS` 七轮；
  文中 "STOP" 约 34 次、"SHA" 约 33 次、"identity" 约 71 次、"经济" 8 次、"公式" 4 次。全部 P1 都是 cwd/argv、pytest 环境、
  manifest、untracked SHA、PowerShell 载体问题；因子逻辑首轮就 P0=P1=P2=0。

  `economic_execution = "BLOCKED_PENDING_PUBLIC_RECEIPT_AND_RUN_TASKBOOK"`。

### 2.4 授权瘫痪

`用户待批示与参与事项.md` 共 23 条 UA 条目，其中 8–10 条是向用户申请"允许运行 Python / 读数据 / 用 CPU /
联网 / 清缓存 / 使用外部 Agent"。`UA-GOV-001` 是一条长期授权，却明确"不含经济 trial / 真实策略 run"。
CODEX_HANDOFF 里反复出现"Python/data/network 仍 0"、"未授 Python/CPU、真实 data read、network 或执行"。
2026-09-07 用户明确说"允许补齐 ETF 数据"后，系统的反应是"框架/data 经理形成任务包并向统筹申请 exact worktree、
网络与数据 I/O 资源"，两次派发"以空 items 结束"，标记 `DISPATCH_NO_PROGRESS / STOP`。数据至今没有补。

### 2.6 规范本身的激励问题

- 旧 `AGENTS.md` 25 KB，几乎全是禁止句；`.ai/` 通用规则把"独立审查、任务模板、返工闭环"作为默认。
  LLM 读到这种文本，会把"多加一层校验、多写一条 caveat、遇疑先 STOP"当作正确行为。
- 每段结论都附三个以上"不代表/不等于/不得"，状态标签越来越长
  （`STATIC_REWORK6_REVIEW_PASS / DIRECT_VALIDATION_PREFLIGHT_STOP / PRODUCT_NOT_EVALUATED / ECONOMIC_CONTENT_UNREAD / trial_delta=0`），
  这些是合规产物，不是研究产物。
- 双平台（Windows 开发 + WSL Gate）+ py312 隔离环境让每个改动都要证明两次，且 WSL 实际是 WSL1，Gate 永远关不上。
