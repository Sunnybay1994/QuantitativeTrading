# 人的能力与接管清单

Agent 可以显著减少样板劳动和卡住的时间，让工程工作更偏向问题选择、设计和判断；不同工程师对这种
分工的体验可能不同。流程应约束质量和安全，而不强迫所有人采用相同的手写比例。

长期使用 Agent 时，代码生成能力、语法/API 记忆和从空白开始构造实现的能力可能比阅读能力更快退化。
能看懂代码不等于能在 Agent 不可用或判断错误时接管系统。

## 周期性自检

- [ ] 我能在没有 Agent 的情况下定位并修复一个普通缺陷。
- [ ] 我能手写一个小型核心模块、关键算法或数据转换。
- [ ] 我能解释系统主要数据流、状态变化、边界和失败模式。
- [ ] 我逐行阅读了关键 diff，而不是只接受测试摘要。
- [ ] 我能指出方案中的隐含假设、复杂度来源和替代路径。
- [ ] 我能判断测试验证了业务行为，还是只迎合当前实现。
- [ ] 我保留了使用调试器、日志、版本控制和构建工具的基本能力。
- [ ] Agent 节省的时间主要用于更高层判断，而不是制造更多低价值代码。

## 建议练习

- 定期亲自完成小而完整的任务，包括实现、测试和调试。
- 对核心算法先独立写出不变量、反例或朴素版本，再查看 Agent 方案。
- 在关键改动中先自行预测 diff 和失败模式，再与实际结果比较。
- 偶尔进行“无 Agent 接管演练”，确认文档、构建和回滚流程足以由人执行。

目标不是拒绝工具，而是持续保有独立思考、审查、接管和停止错误自动化的能力。
