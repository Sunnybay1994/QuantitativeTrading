## 1. 目标

把已上传的经典因子调研结论转成一个可重复、可证伪、可逐批扩展的研究流程，而不是一次性抄录全部公式。

第一轮交付必须同时回答：

1. 哪些经典因子在当前 clean 日线数据上可以诚实实现；
2. 因子在严格 `as_of=收盘可知`、最早下一开市日开盘成交的条件下是否仍有样本外预测能力；
3. 结果是否经过 walk-forward、换手和 0.5x/1x/2x 成本压力后仍成立；
4. 哪些结果应被否证，哪些最多保留为 `RESEARCH_ONLY`；
5. 现有框架缺什么，只补最小公共能力，不复制 M3 formal 或交易基础设施。

## 2. 从调研材料吸收的原则

本计划采用以下结论作为研究约束：

- 因子不是单一公式，而是“数据定义—经济机制—预测目标—持有期—股票池—预处理—组合构建—成本—失效条件”的完整对象；
- 评价不能只看全样本 IC，需要同时看 RankIC、ICIR、分组单调性、跨期稳定性、换手和成本后收益；
- 方向、窗口和阈值只能在训练/验证期确定，不能看到测试集后再改；
- 相近公式先去重。例如 Alpha101 #33 与 Alpha158 `OPEN0`、Alpha101 #101 与 Alpha158 `KMID2` 只保留一个 canonical 实现，别名进入因子目录；
- 日线不能冒充分钟、逐笔、Level-2 或财务 PIT 数据。数据不足的因子进入 backlog，而不是用近似字段替代；
- 第一批优先使用简单、可解释、无 `delay=0` 前视争议的表达式，复杂组合与机器学习留到基线稳定后。

## 3. 当前数据与框架判断

### 3.1 可用数据

当前共享 clean snapshot 已包含经质量分类后的 A 股日线：`open/high/low/close/volume/amount/adj_factor`。研究代码只通过 `quant.data` 的窄读取接口消费指定 snapshot，不自行遍历共享 `data/`。

该数据足够支持：

- 日内价格位置、收益、波动、区间位置；
- 20/60 日滚动价格和成交量统计；
- 下一开市日开盘到未来开盘的收益标签；
- 基于历史成交额的冻结流动性股票池。

该数据不足以诚实支持：

- 分钟、逐笔、订单簿、Level-2 因子；
- 财务报表、公告时点、分析师、新闻和另类数据因子；
- 历史 ST、行业分类、完整停复牌和公司行动账户重放；
- 可用于 PAPER 准入的完整 A 股成交可行性与容量证明。

### 3.2 需要补的最小框架能力

| 缺口 | 最小改进 | 不做什么 |
|---|---|---|
| 研究层不能直接读取共享 snapshot | 在 `quant.data` 增加按 snapshot、日期、证券筛选的只读 repository API | 不在 `quant.research` 拼路径或扫描 `data/` |
| 没有经典因子目录 | 增加 factor spec：名称、来源、公式、机制、字段、窗口、别名 | 不先建设通用表达式 DSL |
| 没有日线横截面标签闭包 | 增加 `as_of close -> next session open -> h-session open` 标签函数 | 不按“下一条有行情记录”跳过停牌日 |
| 轻量研究缺少横截面评估 | 增加 RankIC、ICIR、分组收益、覆盖率、方向稳定性 | 不引入完整 M3 artifact 链 |
| 现有正式账户回放依赖更多市场事实 | 第一轮使用明确标注的非重叠 20-session 诊断组合 | 不声称等价于正式 A 股 backtest |

## 5. 数据、股票池与时间语义

### 5.1 Snapshot

- 输入必须是 `verify_tushare_bulk_clean_snapshot` 验真的不可变 snapshot；
- `run.json` 绑定 snapshot id、manifest SHA-256、数据日期范围和实际使用行数；
- 研究开始后 snapshot 不得切换；新数据必须形成新 run。

### 5.2 冻结股票池

第一轮固定使用“2019 年可知数据冻结的流动性 Top 800”：

- 冻结观察窗：2019-01-01 至 2019-12-31；
- 至少 120 条有效日线；
- 平均成交额不少于 2,000 万元；
- 按平均成交额降序取 800，只使用冻结日前信息；
- 测试期不使用当前成分股回填，不因后续退市删除证券；
- 新上市证券在本轮不进入股票池，作为冻结股票池的已知局限。

### 5.3 信号与标签

- 因子 `as_of`：交易日收盘后；
- 最早成交：交易所下一开市日开盘；
- 标签：`open(t+1+h) / open(t+1) - 1`，`h ∈ {1,5,20}`；
- 跨日价格使用同一复权因子口径；
- 目标开盘或退出开盘缺失时标签为 null，不跨停牌日寻找“下一条记录”，不 forward-fill；
- 验证/测试期末必须保证标签退出日在本期内，自动形成与 horizon 等长的 purge。

## 6. Walk-forward 设计

参数在配置文件冻结，第一轮使用三折：

| 折 | 训练期 | 验证期 | 测试期 |
|---|---|---|---|
| 1 | 2020 | 2021 | 2022 |
| 2 | 2020–2022 | 2023 | 2024 |
| 3 | 2020–2024 | 2025 | 2026-01-01 至 snapshot 末日 |

规则：

- 固定公式不在训练期拟合；训练期用于覆盖/稳定性与未来组合模型预留；
- 每折只根据验证期 20-session RankIC 确定因子方向；
- 测试期开始后不得改方向、窗口、股票池、Top-K、成本或通过阈值；
- 同时报告 1/5/20-session 测试 RankIC，但组合选择固定使用 20-session；
- 任何事后修改都必须更换 hypothesis id、配置哈希并生成新 run，不覆盖旧结果。

## 7. 横截面评估

每个因子、每折、每个 horizon 输出：

- 每日有效证券数、覆盖率；
- Pearson IC、Spearman RankIC；
- RankIC 均值、标准差、ICIR；
- Newey-West 调整后的均值显著性（lag 至少覆盖 horizon）；
- 五分组等权未来收益及单调性；
- 因子方向在三折是否一致；
- 极端值比例、重复值比例和缺失比例。

最低可计算要求：每个交易日至少 100 只有效证券。少于该数量的日期明确标记不可计算，不用 0 替代。

## 8. 诊断组合与成本压力

第一轮组合是“因子研究诊断”，不冒充正式账户回放：

- 每 20 个交易 session 形成一个非重叠区间；
- 使用验证期确定的方向，在当期横截面取 Top 50；
- 等权输出符合 `TargetWeightSchema` 的 `target_weight`；
- `as_of` 为信号收盘日，另记录 `execution_date` 为下一开市日；
- 采用 `configs/research/m3_qlib_example.toml` 的历史 A 股费率 SSOT；
- 运行 0.5x/1x/2x 三档成本，倍数只缩放佣金、最低佣金和滑点，不缩放印花税与过户费；
- 以 100 万元初始资金按每个目标权重变化计算最低佣金；
- 输出换手、总成本、毛/净收益、Sharpe、最大回撤和逐期 NAV；
- 无开盘、停牌、涨跌停、T+1、整手和公司行动不能完整回放的部分必须写入 caveat。正式晋级前由统一 backtest 重跑。

## 9. 预注册结论标准

每个因子只有两种第一轮结论：

### `RESEARCH_ONLY`

同时满足：

- 三折测试期有方向 RankIC 均值不低于 0.01；
- 至少两折测试 RankIC 为正；
- 三折验证期确定的方向一致；
- 三折串联后的 2x 成本诊断组合净收益为正；
- 没有时间穿越、股票池漂移、缺失数据填充或输出身份错误。

### `REJECTED`

任何一项不满足即拒绝。本轮不允许 `PAPER_CANDIDATE`。即使因子通过，也只能进入下一轮正式市场事件回放、容量和前向观察。

## 11. 实施阶段

### 阶段 A：数据读取闭包

- 在 `quant.data` 增加 bounded snapshot repository；
- 支持 snapshot id、日期范围、可选 canonical symbol tuple、受限线程数；
- 验证 snapshot 后读取，不允许研究层拼接路径；
- 单测覆盖非法 snapshot、越界日期、重复 symbol、缺分区和确定性排序。

通过条件：同一查询逐字段一致，读取过程中 snapshot 漂移时失败。

### 阶段 B：因子与标签

- 建立六因子 canonical catalog；
- 因子函数只接 clean DataFrame，不做 I/O；
- 建立交易所 session 映射和 1/5/20-session next-open 标签；
- 单测覆盖拆股复权、20 日边界、零量、平价区间、停牌缺 open 和同收盘前视反例。

通过条件：小型手算 fixture 逐值一致，`as_of` 当日 close 改变只影响当日因子，不改变当日执行价格。

### 阶段 C：评估与诊断组合

- 实现每日 IC、Newey-West、分组收益和 fold 汇总；
- 实现验证期定方向、测试期只读；
- 输出 TargetWeightSchema 和非重叠 20-session 诊断 NAV；
- 引用历史成本 SSOT，不复制费率。

通过条件：row shuffle 结果不变；测试期收益变化不能反向改变已冻结方向；2x 成本不可能低于 1x 成本。

### 阶段 D：真实 snapshot 运行与报告

- 使用当前 verified snapshot 运行一次完整六因子研究；
- 默认最多使用 4 个 CPU worker，或不超过逻辑核心的一半，取更小者，给其他任务保留资源；
- 纯滚动统计默认不用 GPU；进入 LightGBM 组合阶段时单独基准测试 CPU/GPU 后再决定；
- 运行中只做低频状态检查，不与 Tushare/正式长 Gate 抢占资源；
- 发布不可覆盖 run，并逐因子给出 `REJECTED/RESEARCH_ONLY`。

通过条件：定向测试、Ruff、mypy 通过，真实 run 可由相同 snapshot/代码/配置重放并逐字节复用。

### 阶段 E：第二批与组合研究（后续）

- 仅从第一批未覆盖的机制选择增量因子；
- 先做相关性去重，再建立等权/线性/LightGBM 组合；
- LightGBM 只能在训练期拟合，validation 选型，test 一次性报告；
- 若第一批没有稳定因子，先记录否证，不为得到正结果而扩大搜索空间。

## 14. 计划完成定义

本计划实施完成需要同时具备：

1. 六个因子和标签的可复现实现与小型手算测试；
2. 三折 walk-forward、三档成本和逐因子研究结论；
3. 符合 `TargetWeightSchema` 的目标权重；
4. 不可覆盖 `run.json` 及完整输出；
5. 一份明确区分“数据支持、研究证据、正式回测缺口、下一步”的结果报告；
6. 若没有因子达标，诚实输出全部 `REJECTED`，这同样视为研究任务完成。
