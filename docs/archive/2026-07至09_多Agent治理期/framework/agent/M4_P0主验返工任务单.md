## 2. F1 — SQLite URI 防御性一致

- `ExecutionStore.open(uri)` 只接受与 C0 一致的 canonical `sqlite:///<relative-posix-path>`；拒绝绝对路径、盘符、
  `.`/`..`、空 segment、反斜杠、percent encoding、query/fragment、控制字符和 scheme 大小写漂移。
- 不在 P0 另造更宽松 URI 合同；合法示例 `sqlite:///artifacts/trading/execution.db` 保持可用。

## 3. F2 — durable identity wire format

- 所有 put 方法的 `identity` 必须是 exact str、裸 64 位 lowercase hex；bool/子类、大小写、非 hex、其他长度拒绝。
- get 读取持久数据时也应 fail closed 检查 key/identity/payload 类型，数据库损坏不得伪装成 `StoredRecord`。
- P0 不负责按业务 payload 重算 identity；该闭包留给 serializer/service，但 wire format 不得放宽。

## 4. F3 — command/event 关系完整性

- v001 `events.command_id` 外键引用 `commands.command_id`；保持 `PRAGMA foreign_keys=ON`。
- orphan event 必须在同一 transaction 内稳定拒绝并映射为 typed non-retryable store error；已有 command 的 event、
  同 event 幂等与异 command conflict 保持原语义。
- 当前 schema 尚未通过主验且无正式生产 DB，本次直接修正 v001；不得伪造已发布 migration 历史。

## 5. F4 — 文件与 SQLite 错误稳定脱敏

- URI parse、parent 创建、connect、PRAGMA、BEGIN/migration/COMMIT、close cleanup 的 OS/sqlite 异常均在明确边界
  内映射为稳定 `StoreError` code，使用 `from None`，不回显 URI/path/原异常文本或 repr。
- 失败时尽力 rollback/close；cleanup 失败不得覆盖更早的主错误。不得捕获 `BaseException`。
- transaction 的 BEGIN/COMMIT/ROLLBACK sqlite 失败同样 typed；用户在 context 内主动抛出的业务异常仍按原异常返回，
  不被伪报为 store success。

## 6. 必须新增的定向测试

1. WSL/Windows 绝对 URI、scheme 大小写、遍历/编码变体均拒绝；合法相对 URI可建库；
2. 六类 put 至少参数化覆盖非法 identity；损坏 DB row 的 get 稳定失败；
3. orphan event 拒绝；先 command 后 event 成功；同事务 rollback 不留半行；
4. mkdir parent 冲突、目录当 DB、connect/PRAGMA/migration 失败：异常 typed、`__cause__ is None`，
   `str/repr/traceback` 无注入绝对路径；
5. 保留既有 10 项及 event extra-column 返工测试。
