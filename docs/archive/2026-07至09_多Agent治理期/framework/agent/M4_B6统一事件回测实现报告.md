## P1 返工闭环

### 跨 session fill/close

- 现象：原 schedule 只比较时间上下界，周五 plan 可接受周一 close/fill，并在周五 checkpoint 提前落账。
- 根因：schedule identity 未包含显式 session，空 plan 也没有可推导日期。
- 规则：新增 `ScheduledOrderPlan.session_date` 并绑定 identity；plan intents、snapshot、close、所有 fills 必须
  同日。下一 session 只能由新 snapshot/plan 承担。
- 测试：新增 Friday plan + Monday fill/close 反例。

### 稳定异常完全断链

- 现象：在活动 `except` 中调用稳定错误 helper 会留下 hostile 异常 `__context__`。
- 根因：`raise ... from None` 只抑制展示，不清空异常对象的 context。
- 规则：统一使用两阶段 `_sanitized` 边界，记录失败后退出 `except` 再抛稳定码；顶层转换亦执行相同模式。
- 测试：hostile corporate-action validator 与嵌套 plan identity 注入路径/TOKEN sentinel，要求无回显且
  cause/context 均为 `None`。
