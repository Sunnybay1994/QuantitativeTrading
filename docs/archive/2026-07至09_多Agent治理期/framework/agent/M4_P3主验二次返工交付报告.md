## 2. F1–F2 实现摘要

### F1 经济字段消费前的输入自证

`evaluate_pretrade` 在读取 mode / quota / cash / position / sellable / intent quantity|side 之前，由 `_prove_pretrade_inputs`：

1. 调用 D0 `build_order_plan_identity(plan)`；
2. 调用 D0 `build_verified_market_snapshot_identity(market)`；
3. 调用 D0 `build_account_snapshot_identity(account)`；
4. 调用 C0 `trading_config_identity(config)`；
5. 以当前字段重构造 `DailyRiskCounters`，复跑 `__post_init__` 结构校验。

未复制 D0/C0 哈希算法。普通验证异常映射为稳定 `RiskInputError(ValueError)`，消息仅为固定 code：

- `PLAN_CONTRACT_INVALID`
- `MARKET_CONTRACT_INVALID`
- `ACCOUNT_CONTRACT_INVALID`
- `CONFIG_CONTRACT_INVALID`
- `COUNTERS_INVALID`

采用与 OMS 一致的「except 内构造、块外 `raise ... from None`」模式，保证 `__cause__ is None` 且 `__context__ is None`；不捕获 `BaseException`。异常即 fail closed，不返回 commands。

自证通过后，保留既有 plan↔market/account/config id 等值绑定与第一轮 F1–F4 业务规则。
