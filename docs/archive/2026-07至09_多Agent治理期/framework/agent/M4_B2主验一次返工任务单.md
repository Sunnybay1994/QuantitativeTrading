# M4-B2 主验一次返工任务单：Decimal tick 精确整除

状态：**主 Agent 终验未通过，退回外部实现—独立复验闭环**  
日期：2026-07-17  
范围：仅关闭 P1-TICK；不扩大 B2，不宣称 M4 Gate 通过

## 1. 现象

D0 合同接受任意 finite positive `Decimal`。B2 `_is_tick_multiple` 直接执行 `price / tick_size`，受当前
Decimal context 的 `Emax/precision/traps` 影响。主 Agent 从公共 `evaluate_connect_intent` 复现：

```text
limit_price = Decimal("1E+999999")
tick_size   = Decimal("1E-999999")
→ decimal.Overflow: [<class 'decimal.Overflow'>]
```

该输入已经通过 `OrderIntent` 与 `SymbolMarketState` strict builder，属于合法 finite 领域输入；公共规则入口
不得抛未映射算术异常。

## 2. 根因与应遵循规则

根因：用 Decimal 除法再比较 integral value，把“精确十进制整除”错误绑定到进程级 Decimal context。

规则：tick 判定必须是纯精确整数/指数关系，结果不依赖当前 Decimal context，不做 rounding，不把合法极值
误报 typed input error，也不得产生大指数对应的巨大 `10**k` 中间整数/字符串。

## 3. 冻结行为

`_is_tick_multiple(price, tick_size) -> bool` 对 D0 已验证的 finite positive Decimal：

- 永不抛 `DecimalException`；
- 不读取/修改全局 Decimal context；
- 不做除法、quantize 或 rounding；
- 可基于 `Decimal.as_tuple()` 的 coefficient/exponent 做精确整除；大正指数差应使用 modular exponentiation 或
  等价有界算法，禁止构造 `10**1_999_998`；
- `1E+999999` / `1E-999999` → multiple（之后按价格带决定是否接受）；
- `1E-999999` / `1E+999999` → not multiple；
- `0.30/0.05` → multiple；`0.3/0.2`、`1.00/0.03` → not multiple；
- 在调用者设置低 precision、小 Emax/Emin、开启 Overflow/Inexact/Rounded traps 时结论完全相同，函数不得改变
  调用者 context。

建议但不强制的精确算法：设 coefficient 为正整数 A/B、指数差 k。k>=0 时用
`A * 10**k mod B` 的 modular pow；k<0 时先要求 A 可被 B 整除，再比较商的十进制尾零数与 `-k`。实现需
自己证明所有上述反例。

规则入口中的既有拒绝优先级不变。not multiple 仍返回 `PRICE_TICK_INVALID`；multiple 且其他条件合法时
返回 `ACCEPTED`。
