## 目标与完成边界

实现可恢复的 PAPER/SHADOW soak harness、严格证据格式、故障矩阵与 Gate decision。代码/fixture 通过后
状态只能是 `WAITING_FOR_SOAK_EVIDENCE`；M4 的“连续运行 4 周以上”必须由至少 28 个自然日、覆盖期间全部
预期交易 session 的真实调度产物关闭，fake clock、回放、development example 和一次长测均不得冒充。

## 身份与路径边界

- 开发测试根：`artifacts/development_example/m4_p8/`，manifest 固定
  `evidence_kind=development_example`、`formal_gate_eligible=false`。
- 正式 PAPER soak 根由 CLI 显式注入，禁止默认发现/扫描 `data/`、`data/legacy/` 或正式 G1 根；manifest 固定
  `evidence_kind=paper_real_time`。
- 每个 run 使用独立 content-addressed `run_id` 和 append-only journal；禁止覆盖 observation/fault receipt。
- 开发与正式 verified 类型分离；development 证据不能构造正式 Gate PASS。

## 证据闭包

1. run manifest 绑定 exact M4 source/config identity、gateway identity、store identity、账户的不可逆 identity、
   verified expected-session schedule identity、开始时间和 evidence kind；不得记录绝对路径、token 或账户原文。
2. 每个 session 只能由 P6 公开 PAPER 操作、P5 `recover_local_state/reconcile` 与 P7 execution report 的已验真
   输出构造；重新计算 command/event/ledger 摘要，不能相信调用者携带的 id。
3. session 日期严格唯一连续覆盖 expected schedule；重复相同 bytes 幂等，异 bytes 冲突。intraday、local
   QUERY/MANUAL、reconcile 差异、report Gate false、UNKNOWN/LEASED delivery 均为 BLOCKED。
4. 正式 PASS 同时要求：`last_observed_at - first_observed_at >= 28 days`；期间 expected sessions 全覆盖；
   每日 invocation 时间真实递增；零未解释 issue；所有强制 fault drill PASS；source/config/gateway/store 未漂移。
5. harness 不通过 fake sleep 判断自然时间。测试可构造 development receipt，但 verifier 必须保留 kind，Gate 决策
   对 development 永远不返回 PASS。

## 强制故障矩阵

- stage 后进程退出、重启恢复，再 exact submit：经济影响一次；
- gateway started 后 exception/malformed/UNKNOWN：永不自动重发，转 QUERY；
- duplicate callback bytes 幂等、同 id 异 bytes关闭；乱序 callback 关闭；
- cancel callback transaction/link/checkpoint 任一步失败整体回滚并 UNKNOWN；
- SQLite busy/commit failure/disk write error 不产生部分 command/event/ledger；
- scheduler clock 非 UTC/回退、market/account/target 缺失、EOD broker evidence 缺失稳定阻断；
- 重跑已完成 session/approval/submit/cancel 不产生第二次经济影响；
- 报告或 journal 中注入路径/TOKEN/broker text 后，公开产物和异常均不可恢复原文。

## R2：可信时间、物理根与 retained facts 返工（2026-08-09）

### 失败闭环

- 现象一：一次进程内用调用方自报的过去 `started_at/invocation/as_of`、两个自选 session 和十个 fixture
  drill，即可让 `PAPER_REAL_TIME` 返回 `PASS`，伪造 29 日自然运行。
- 现象二：修改 session 的 `recovery_id`、command 摘要并同步重算 invocation/receipt identity 后，磁盘
  verifier 仍接受并返回 `PASS`；append 时检查过 P5/P7 对象，但 durable verifier 没有 retained facts 可重建。
- 现象三：完整 canonical run 复制到另一物理 root 后 identity 不变并继续 `PASS`。
- 根因：正式时间完全由调用方提供；manifest 未绑定不可逆物理根 identity；receipt 只保存派生摘要，没有保存
  verifier 可严格重读的 P5/P7 事实闭包。
- 应遵循规则：正式 Gate 必须同时绑定可信本机时钟、原物理根和 retained semantic facts。content hash 只能证明
  自洽，不能把调用方自报历史、复制目录或整包重哈希升级为真实运行证据。

### 冻结 R2 设计

1. `SoakRunManifest` 增加 `root_identity`，只保存规范化绝对 root 的不可逆 SHA-256，不保存路径原文；run id
   必须绑定它。每次 append/verify/decision 都从实际传入 root 重新计算并 exact 比对。复制到任何不同物理 root
   必须在读取 session 前失败。Windows 使用 `normcase` 后的 resolved absolute path；Linux 保持大小写；不得把
   Windows 与 WSL 路径视为同一正式 run。
2. 正式 `PAPER_REAL_TIME` 使用模块内生产 wall-clock（UTC）建立时间锚；不开放 clock 参数或 Protocol 给正式
   调用方。build 的 `started_at`、append 的 `completed_at`、decision 的 `as_of` 必须不晚于当前时钟，且与调用
   当时 UTC 的偏差不超过冻结的五分钟容差；session/fault start 仍须满足有序和非负时长。development 路径可
   保持确定性 fixture 时间，但永远不 PASS。测试只可 monkeypatch 私有时钟验证边界，报告不得把 fake-clock
   formal 正例记作 Gate 证据。
3. session 改为精确目录 `sessions/<date>/{receipt.json,facts.json}`；fault 改为
   `faults/<drill>/{receipt.json,before_facts.json,after_facts.json}`。facts 使用显式 versioned canonical JSON，
   禁止 pickle、动态 import、任意 Mapping 或未知字段。
4. session facts 至少保留并绑定：P5 recovery/reconciliation 与 P7 report 的稳定 public identity、disposition、
   issue/difference codes；所有 command/event 原始 wire bytes 及其重算 identity/link；delivery/cancel delivery
   state；ledger entry/state 的 canonical bytes 与重算摘要；execution report canonical bytes。receipt 增加
   `facts_sha256`，其 session 摘要只能由 strict decoded facts 重建，不能信任 receipt 自带 id/hash。
5. fault before/after facts 至少保留生成经济影响闭包所需的 command/cancel/event/ledger canonical bytes、delivery
   状态、disposition 与 recovery identity；fault receipt 增加两个 facts digest。verifier 必须从 retained facts
   重算 before/after effect set、outcome、stable codes 和 receipt identity。
6. retained facts 的 writer 使用与 receipt 相同的 exclusive/no-clobber 语义；同 bytes 重试幂等，任一 sidecar
   异 bytes 冲突。verifier 要求精确目录/文件集合，拒绝 symlink、未知项、缺 sidecar、同 bytes 异物理别名。
7. 所有 decode/上游异常在专用边界外换译为稳定 P8 code，cause/context 为空且不得泄露路径、token、broker
   原文。R2 不修改 P4–P7 业务语义；若缺少安全 public wire codec，只在 P8 内写窄 strict codec，不开放通用
   反序列化框架。

### R2 必测反例与通过条件

- 原独立复验的单进程伪 29 日正式 PASS 必须在首个 backdated formal build/append/decision 边界失败；
- canonical run 全目录复制到另一绝对 root 后，`verify_soak_evidence` 必须稳定拒绝；
- 只改 receipt 后重哈希、只改 facts 后重哈希、receipt+facts 一起 whole-rehash，至少因 retained semantic
  identity/link 或 trusted manifest/root anchor 失败；
- 删除/增加/交换 session 或 fault sidecar，command/event link 漂移，ledger/report bytes 漂移均 fail closed；
- development 满 29 日、全 session、全 drills 仍为 `WAITING_FOR_SOAK_EVIDENCE`；
- 正式缺自然时间、expected session 或 drill 仍为 `WAITING_FOR_SOAK_EVIDENCE`，已有业务阻断为 `BLOCKED`；
- Windows P8 与 P5–P8 合流 pytest、Ruff、mypy 通过；WSL base `/mnt/f` 对应定向通过但明确为 DrvFS。只有
  未参与 R2 实现的全新独立复验 PASS 后才能注册正式 runner；代码/fixture 仍不得宣称四周 Gate 已关闭。

## R3：独立 append anchor journal（2026-08-09）

### R2 失败闭环

- 现象：保持原 manifest、evidence root 与时间不变，把某 session 的 retained facts 整体替换为另一份语义
  完全合法的 P5 recovery + reconciliation + P7 report 闭包，再同步重算 receipt/facts/command/event/ledger/
  invocation identities，磁盘 verifier 接受并可继续 Gate。
- 根因：R2 sidecar 关闭了局部摘要伪造，但所有 session facts 与 receipt 仍属于同一个可整体重算的自哈希域；
  manifest 在 run 开始时尚不知道未来 observation，无法绑定“首次实际追加”的结果。
- 应遵循规则：正式 evidence verifier 除证明每份业务闭包自洽外，还必须 fresh-verify 一个独立物理域中的
  append-only completion anchor。anchor 记录首次落盘的 receipt/facts digest 与顺序前驱；后续替换 evidence
  bytes 不能通过不变 anchor。

### 冻结 R3 设计

1. `build_soak_run` 新增显式绝对 `anchor_root: Path`。manifest 增加不可逆 `anchor_root_identity` 并纳入
   `run_id`；anchor root 必须与 evidence root 不同、互不为祖先/后代、无 symlink/reparse 祖先。正式推荐路径
   属于独立 artifacts 根，不写 data、G1 journal 或正式候选目录。
2. 新增 versioned `SoakAppendAnchor`，精确字段至少为：schema、run id、sequence、entry kind、entry key、
   evidence root identity、previous anchor id、receipt id、facts digest tuple、anchored_at、anchor id。
   `anchored_at` 使用同一私有生产 UTC clock，正式路径满足五分钟窗口；anchor 不能接受调用方自报时间。
3. anchor journal 精确目录为 `<anchor_root>/<run_id>/anchors/<sequence>.json`；sequence 从 1 连续，文件名固定
   十位十进制。每条 canonical JSON 用 exclusive/no-clobber 写入；同 bytes 重试幂等，异 bytes 冲突。目录中
   未知项、缺口、重复 key、错误 previous id、symlink 或非普通文件均 fail closed。
4. session/fault writer 先完成 R2 receipt+facts exact 集合并自验，最后写 anchor 作为唯一 completion marker。
   若进程在 anchor 前退出，恢复只允许在 evidence bytes exact 相同后补写预期下一 anchor；不得覆盖、跳号或
   为另一份合法闭包重签已有 key。相同 session/fault key 只能对应首次 anchor 的 exact receipt/facts digests。
5. `verify_soak_evidence` 必须显式接收 `anchor_root`，先核对两个 root identity，再 strict 读取完整 anchor chain；
   每个已观察 session/fault 与一条 anchor exact 双向对应，不能有未锚定 evidence 或无 evidence 的 anchor。
   verified capability 和 evidence identity 必须绑定 terminal anchor id。
6. `decide_soak_gate` 只接受带 terminal anchor id 的 capability及显式 evidence root/anchor root；决策前必须
   fresh 调用磁盘 `verify_soak_evidence` 并要求返回 capability 与调用方传入值 exact equal，再计算状态，关闭
   verify 后磁盘漂移的 TOCTOU。development 即使 anchor 完整仍永不 PASS。
7. 稳定边界错误不泄露两个绝对路径，cause/context 均为空。R3 不使用 pickle、动态 import、网络、密钥或
   自签名，不修改 P4–P7 业务实现。

### 信任边界

本地 anchor journal 是“可信本机 + exclusive append + 保留首次字节”合同，不是数字签名、硬件可信时间或
WORM。具备同机任意文件改写权限的攻击者若同时重造 manifest、evidence root、anchor root 与所有业务 wire，
仍超出 R3 防护边界；报告必须如实披露。若未来 Gate 要抵抗本机管理员，应另接外部签名/远端不可变审计，
不能把 path hash 或 hash chain 表述为密码学来源证明。

### R3 必测与通过条件

- R2 独立复验的“另一份完全合法 closure 整体替换 + 全量重哈希”在 anchor 不变时 fail closed；
- 同时重写 evidence 与现有 anchor bytes 的测试应触发 exclusive/已注册 terminal anchor mismatch；不得通过公开
  writer 覆盖旧 anchor；
- anchor 删除、增加、交换、跳号、重复 key、错误 predecessor/receipt/facts digest、复制到另一 root、symlink
  全部失败；
- facts/receipt 已落盘但 anchor 缺失的进程退出恢复：exact bytes 可补 anchor，异 bytes 失败；
- verify 后删除/替换 evidence 或 anchor，再把旧 capability 传入 decision，必须在状态计算前 fail closed；
- session/fault idempotent retry 不增加 anchor；并发两个不同 next entry 只有一个 sequence 成功，另一个稳定
  retry/conflict，不能产生分叉；
- R2 clock/root/retained semantic tests、development never-PASS、P5–P8 回归保持绿色；Windows 与 WSL base
  `/mnt/f` 定向通过，DrvFS 非 ext4。全新独立复验 PASS 后才能注册正式 runner；真实 28 日仍须自然产生。

R2 对公共 Gate 调用补充为 `decide_soak_gate(verified, *, root, as_of)`；`root` 必须与产生 verified evidence
时的实际显式根一致。R1 的两参数写法不再适用于 R2。

## R4：公共导出冷启动解环（2026-08-09）

### R3 失败闭环

- 现象：R3 的 anchor journal、TOCTOU、可信时间与 development never-PASS 合同均通过独立对抗，
  但全新进程直接导入 `quant.backtest.event_simulator` 或单跑 `test_event_simulator.py` /
  `test_trading_metrics.py` 时在 Windows 与 WSL base 均发生循环导入。
- 根因：`quant.execution.__init__` eager 导入 `quant.execution.soak`，而 `soak` 又依赖
  reporting/backtest 合同，形成 `backtest -> execution.__init__ -> soak -> reporting -> trading_metrics ->
  event_simulator -> backtest` 的包初始化环。大套件因其他测试预先导入了部分模块而遮蔽回归。
- 应遵循规则：包根公共导出不得为了便利反向拉入高层 reporting/backtest；正确性不得
  依赖 pytest 文件顺序或先导入副作用。

### 冻结的最小返工

1. 保留任务已公开的 `quant.execution` soak 符号集和 `__all__`，但必须改为 PEP 562
   `__getattr__` 等价的惰性导出；导入 `quant.execution` 本身时不得加载 `quant.execution.soak`。
2. 惰性导出只处理冻结的 soak 符号 exact set；未知属性必须标准抛出 `AttributeError`。不得改动
   P4-P7 业务实现、reporting/backtest 公共契约、P8 anchor/facts/clock/Gate 语义。
3. 为静态类型可见性可在 `TYPE_CHECKING` 分支引用 soak 符号；运行时分支不得 eager import。
   不得通过改 pytest 顺序、测试预导入或删除公开导出来规避问题。
4. 新增四个全新解释器冷启动回归，分别独立导入 `quant.backtest.event_simulator`、
   `quant.reporting.trading_metrics`、`quant.execution.soak` 以及从 `quant.execution` 导入至少一个
   soak 公开符号。子进程必须继承当前项目 `PYTHONPATH`，并检查真正退出码，不依赖用例顺序。
5. `test_event_simulator.py`、`test_trading_metrics.py`、`test_execution_soak.py` 必须各自单文件
   可收集并通过；随后运行 P5-P8 合流范围、Ruff、mypy 及 WSL base 对应定向验证。

R4 只关闭冷启动依赖环；R3 已通过独立挑战的 anchor/TOCTOU 主体不得借机重写。R4 仍是
开发契约返工，须由全新独立初验 PASS 后才进入主验；M4 状态继续为
`WAITING_FOR_SOAK_EVIDENCE`，不得因导入回归绿测注册正式 runner 或宣称 28 日 Gate 通过。
