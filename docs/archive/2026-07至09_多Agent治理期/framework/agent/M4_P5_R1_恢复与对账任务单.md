# M4-P5-R1：本地恢复与 PAPER 对账任务单

日期：2026-08-02  
状态：实现、外部独立初验与主 Agent 最终验收均已通过；仅关闭本地恢复与 PAPER 对账工程合同，不关闭 P5/M4 Gate

## 目标与边界

在已验收的 P0A/P0B/P0C wire、SQLite store 与 ledger transaction 基础上，新增两个公开能力：

1. `recover_local_state(store)`：从一次原子 `RecoveryRows` 快照恢复严格、可自证、确定性的本地状态；
2. `reconcile(local, broker_snapshot, as_of)`：以零 IO 纯函数比较本地状态与已验证 PAPER broker 快照，
   输出差异分类和继续运行 Gate。

P5 不发送、查询、撤单、重试、修复、回填或覆盖任何本地/broker 状态，不新增表，不写
`reconciliation_runs`。CLI、broker query port、展示与退出码属于 P6。

## 公开合同

生产代码只新增 `src/quant/execution/reconcile.py`。冻结类型：

- `RecoveryDisposition = Literal["READY", "QUERY_REQUIRED", "MANUAL_REQUIRED"]`
- `DifferenceAction = Literal["AUTOMATIC_RETRY", "QUERY_REQUIRED", "MANUAL_REQUIRED"]`
- `BrokerSnapshotFinality = Literal["INTRADAY", "END_OF_DAY"]`
- `RecoveryIssue(code, subject, action)`
- `RecoveryResult(recovery_id, disposition, commands, events, order_aggregates, deliveries,
  ledger_entries, ledger_contexts, checkpoint, issues)`
- `BrokerOrderObservation(broker_order_id, command_id, status, cumulative_quantity,
  observed_event_ids)`
- `BrokerSnapshot(snapshot_id, source_identity, as_of, finality, account, orders, events)`
- `ReconciliationDifference(code, action, subject, local_identity, broker_identity)`
- `ReconciliationResult(reconciliation_id, local_recovery_id, broker_snapshot_id, as_of,
  gate_passed, disposition, differences)`

所有 dataclass 均 `frozen=True, slots=True`。所有 identity 由本包对 canonical payload 计算，调用者自报值必须
重算相等。时间必须是 UTC aware；序列必须按冻结主键排序且唯一。

```python
def recover_local_state(store: ExecutionStore) -> RecoveryResult: ...

def reconcile(
    local: RecoveryResult,
    broker_snapshot: BrokerSnapshot,
    as_of: datetime,
) -> ReconciliationResult: ...
```

broker order observation 不得伪装为本地 `OrderAggregate`；broker account 复用 `AccountSnapshot`，broker event
复用 `ExecutionEvent`。如果现有公开类型不足，实现者必须停止扩仓并回报，不得顺手修改 store/service/OMS。

## 本地恢复语义

1. 一次且仅一次进入 `ExecutionStore.transaction()`，只调用 `read_recovery_rows()`，事务内零写入。
2. 只复用 P0B/P0C codec 与 verifier，重证 row key、identity、canonical bytes 以及以下闭包：
   event/aggregate/context/delivery → command，delivery → outbox，checkpoint canonical key/tail/origin，
   applied event ids → ledger entries，经济事件不重复。
3. corrupt/hostile/non-canonical bytes、身份漂移、父项断链整体 fail closed，不返回部分状态。
4. 空库是合法 `READY`，`checkpoint=None`；不推断 broker 也为空。
5. `UNKNOWN` delivery 产生 `QUERY_REQUIRED`；缺 legacy context/checkpoint 产生 `MANUAL_REQUIRED`，不得补造。
6. `recovery_id` 绑定全部 typed identities、delivery attempt/fence/terminal state、checkpoint tail 与 issues；
   相同数据库字节重复读取结果完全相同。

## 对账语义

1. `reconcile` 是零 IO 纯函数；先重算 local/broker identity，并验证 `broker_snapshot.as_of == as_of`。
2. 复用现有 OMS reducer 重证本地 aggregate；不得复制 OMS 或 ledger 公式。
3. 分类优先级固定 `MANUAL_REQUIRED > QUERY_REQUIRED > AUTOMATIC_RETRY`。
4. 只有差异为空、local 为 `READY` 且 broker 为 `END_OF_DAY` 时 `gate_passed=True`；`INTRADAY`
   至少为 `QUERY_REQUIRED`。
5. `AUTOMATIC_RETRY` 只表示上层可重新调度；P5 不执行重试。SENT/UNKNOWN 或跨 adapter 边界状态不明
   不得标为自动重试。
6. cash、position、order、event 任一差异只形成 immutable difference，绝不倒灌 broker 快照修复本地。
7. differences 按 `(action, code, subject, local_identity, broker_identity)` canonical 排序，subject 唯一；
   `reconciliation_id` 绑定 local/broker/as_of/differences。

## 错误与脱敏

新增稳定 `RecoveryError` 与 `ReconciliationError`，只暴露固定错误码。异常翻译必须离开 active `except`
后再抛；最终 `__cause__`、`__context__` 均为空，异常对象图不可恢复 payload、broker text、SQL、路径或 TOKEN。

## 必须覆盖的反例

1. event/context/checkpoint tail 任一断链：恢复整体稳定失败、零部分结果、零写入。
2. command/context/checkpoint/broker event 含 `TOKEN`：错误 cause/context/object graph 不可恢复。
3. local UNKNOWN delivery：只为 `QUERY_REQUIRED`，不 claim、不重试、不写 ledger。
4. legacy SENT/PENDING 缺 context 或 checkpoint：`MANUAL_REQUIRED`，broker 数据不得倒灌修复。
5. broker 缺本地已接受/成交订单，或出现 `command_id=None` 的未知订单：Gate false。
6. broker 重复 event id 或重复经济 fill：`MANUAL_REQUIRED`，不得集合去重吞掉。
7. cumulative quantity、status、cash、position 任一差异：Gate false，本地 bytes 不变。
8. `INTRADAY` 即使数值一致：`QUERY_REQUIRED`，Gate false。
9. NOT_SENT 且确认未跨 adapter 的项才可为 `AUTOMATIC_RETRY`；SENT/UNKNOWN 不可。
10. 相同输入重复恢复/对账 identity 完全一致；同 identity 异 payload 与可构造伪 verified 对象必须拒绝。
11. SQLite snapshot 读取期间并发写入：只允许事务前或事务后一致视图，不得撕裂。
12. 任一 API 执行前后 store 所有表逐字节/逐行不变。
