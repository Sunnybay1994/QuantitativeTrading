# M4-B5 多币种结算与公司行动账本实现报告

日期：2026-08-02

## 结论

M4-B5 开发合同已在冻结白名单内实现并完成 P1/P2 返工。实现只消费内存中的 D0 领域对象、B3 FX 快照和 G7C entitlement transition，不访问网络或数据目录。Windows 原生与 WSL Miniforge base 定向验证均通过。

本结论仅表示开发工程合同通过，不表示 PAPER 稳定运行 Gate、正式交易验收或 Linux/ext4 发布 Gate 已关闭。

## 实现边界

- `SettlementRule` 的 identity 覆盖市场、币种、有效期、lag、日历来源 identity 和严格有序的交易/结算 session；T+N 只按冻结 session 序列计算。
- BUY 成交减少 `available`、增加 `payable`，到期才减少 `settled`；SELL 成交增加 `receivable`，可选创建具有到期日的可复用 credit。
- 同日到期严格先收 SELL receivable、再付 BUY payable；credit 只消费一次，避免 settled 双扣或卖款重复可用。
- A 股买入证券在下一真实交易 session 解锁 sellable；HK 证券 T+0 可卖但现金和证券 pending 保持 T+2 session。
- 晚到 fill 使用 `max(current as_of, original intent session)` 推进账本，due session 仍由原始 intent session 与冻结日历计算；不从 `event.occurred_at` 的自然日期推导交易日。
- HK 仅接受事件时点仍有效且同 session 的显式 HKD/CNY 直接 FX；金额复用 B3 的 HALF_UP 到分口径。
- 公司行动直接消费 G7C `EntitlementTransition`，覆盖 capture、recognize、stock/cash settle 与独立 `rounding_delta`，不复制权益日历或 entitlement 算术。
- 每个 transition 通过 identity-safe entries 反向核对现金四桶、持仓、sellable、credit 与 pending 前后差额，不守恒时稳定失败。

## P1 返工闭环：同 command 事件连续性

- 现象：原投影仅保存 command_id 与 cumulative quantity，后续事件可更换 broker order、回退事件时间或漂移 settlement rule，而累计数量检查仍可能通过。
- 根因：事件幂等 identity 与 command 级连续性是两个不变量；只记录已应用 event id 不能证明后续事件仍属于同一 broker/rule 时间线。
- 应遵循规则：`CommandProjection` 冻结 `cumulative_quantity`、`broker_order_id`、`last_event_at` 与 `settlement_rule_id`。broker 使用等价单次绑定：尚未绑定时可由后续事件首次提供，绑定后允许事件省略 broker 并继承冻结值，只有已有值和输入值均明确且不同才冲突；`occurred_at` 非递减、rule_id 不变。重复 event 在 no-op 前仍先自证 command/event/rule identity，并核对冻结 rule_id。
- 新增测试：`None → 首次明确 broker`、`已绑定 broker + 输入 None` 两个正例，以及外来明确 broker、事件时间回退、同 command rule 漂移、重复 event 内容篡改和重复 event 使用漂移 rule 等反例。
- 通过条件：首次明确 broker 写回投影，后续省略 broker 保留已绑定值；两个明确 broker 异值在任何状态变更前以 `LEDGER_EVENT_PROJECTION_CONFLICT` 失败，其余身份/连续性反例同样稳定闭锁，精确重复保持 no-op。

## P1 返工闭环：UTC 语义判断

- 现象：`CommandProjection.last_event_at` 原先用 `tzinfo is dt.UTC` 判断 UTC，会拒绝合法的 named/fixed 零偏移 UTC；直接调用 hostile `tzinfo.utcoffset()` 还可能泄漏底层异常。
- 根因：对象身份比较不是 UTC 时间语义；第三方 `tzinfo` 方法也是不可信输入边界。
- 应遵循规则：只接受 exact `datetime`、aware 且 `utcoffset() == timedelta(0)`；在受控异常边界内调用 `utcoffset()`/`astimezone()`，任何异常统一收敛为无 cause/context 的 `LEDGER_INPUT_INVALID`。写入投影时规范化为 `dt.UTC`，仍拒绝所有非零 offset。
- 新增测试：fixed named zero-offset、定制 named UTC 两个正例，以及 hostile `tzinfo` 脱敏拒绝反例。
- 通过条件：两个零偏移正例成功入账且投影为 `dt.UTC`；hostile timezone 稳定失败且不泄漏异常文本或异常链；此前全部账本测试保持绿色。

## P2 返工闭环：初始账本日期下界

- 现象：可用早于 `AccountSnapshot.as_of` 的日期打开账本，形成快照信息从未来倒灌到过去的账本状态。
- 根因：初始状态只验证 `as_of_date` 类型，没有冻结可审计的时间下界。
- 应遵循规则：当前最小合同以 `AccountSnapshot.as_of` 的 UTC 日期作为确定性下界，较早日期以 `LEDGER_BACKDATED` 失败。
- 新增测试：UTC 快照前一日拒绝、UTC 快照当日成功。
- 通过条件：初始账本不允许早于快照 UTC 日期；错误码稳定且无底层异常链泄漏。

市场本地会计日与 UTC 日期在跨日时可能不同。该转换规则尚无 SSOT，本任务不自行猜测；未来若要求在市场未来会计日开账，必须先冻结市场时区、会计切日和跨市场账户聚合规则，再修改公开合同和测试。

## 对抗性覆盖

- A 股周五买入在周末不解锁，下一真实 session 才 sellable；HK T+2 使用第二个 eligible settlement session。
- 卖出 credit 融资买入、单次消费、关闭复用、到期先收后付及现金四桶精确值。
- 重复 fill、累计量缺口、冻结 event 篡改、SHADOW fill、日历尾部不足和 FX 过期。
- 晚到 fill 不回拨 as_of，已过 due 在同一 transition 按原 due session 交收。
- G7C capture 到 recognize/settle、重复 action、错误日期和 HALF_UP rounding。
- frozen value objects、exact-session rule identity、command 投影连续性及 UTC 开账下界。

## 剩余边界

- B6 编排必须持续调用 `advance_ledger_state`，不能只在收到 execution event 时推进结算。
- `settlement_sessions` 必须由上游 verified 日历预先生成；B5 不自行求 SH/HK 日历交集，也不从 route 猜结算日。
- 本包不持久化 ledger；后续通过公开对象和 identity 写入 store、执行恢复与对账。
