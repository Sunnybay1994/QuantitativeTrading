# M3 C0 配置设计审查记录

日期：2026-07-13  
状态：设计缺口已写回 SSOT；实现未开始

## 1. 结论

现有代码没有 `load_m3_config`。`readiness.py` 直接读取宽泛 `Mapping`，G8 又要求 scientific、snapshot、
provider 等多种 hash，但没有唯一 canonicalizer 或可执行 allowlist。继续下发会让实现 Agent 在各模块复制
解析、默认值和 hash 逻辑，产生“同一配置、多个身份”的系统性错误。

## 2. 已关闭的设计问题

### P0-1：没有唯一 TOML 入口

- 根因：把示例 TOML 当成了足够的机器契约。
- 规则：只有 `config.py` 可以读取 M3 TOML；其他模块只接收已验证只读对象。
- 回归：搜索不得出现第二个 `tomllib.load/loads` 的 M3 业务入口。

### P0-2：配置可变导致 hash 与执行参数分离

- 根因：冻结 dataclass 不能冻结内部 dict/list。
- 规则：递归只读 mapping 和 tuple；hash 后不得被调用者突变。
- 回归：深层赋值、append 和替换均失败。

### P0-3：身份边界只有自然语言

- 根因：scientific、snapshot、provider、tracking 和 acceptance 的变化传播未被分开。
- 规则：九类 hash/target key 使用同一套规范序列化和一组权威 selector；provider 抽样与 label 对账配置
  分开，避免无关证据失效；变更矩阵写入任务单。
- 回归：每种单字段变化同时断言“应变”和“不应变”的身份。

### P0-4：未知键与隐式默认可能静默改变科学结果

- 根因：现有函数使用 `.get(..., default)`，拼写错误会退回默认。
- 规则：当前版本所有键显式必需，未知/缺失/类型错误在副作用前统一失败；纯业务函数不再承担配置默认。
- 回归：`early_stoping_rounds` 等近似拼写必须失败，不能被忽略。

### P0-5：凭据可能通过 tracking URI 或深层值进入产物

- 根因：只扫描 tracking 登记参数，配置加载阶段没有统一安全门禁。
- 规则：任意层级敏感键/值、URI userinfo、绝对工作区路径均在加载期拒绝；Tushare local 配置永不合并。
- 回归：普通、percent-encoded 和大小写变体凭据均失败，错误文本不回显原值。

### P0-6：G1 仍接收 config path，且配置变化没有独立身份

- 根因：把 G1 当成 M3 外部数据准备步骤，遗漏它同样消费 M3 TOML 且会改变 release 结论。
- 规则：C0 增加窄化的 `g1_config_sha256`；G1 stage handler 从只读 section 复算，data publisher 只接收
  version+hash 并绑定 release，禁止第二次解析 TOML或由 data 层反向 import research 层。纯限频/重试政策
  只进入 full，不伪造新 release。
- 回归：修改 endpoint limit/对账策略只改变 full 与 G1；修改 warmup/tail 另改变 snapshot；修改 retry 只改
  full；G1 发布源码不含 `tomllib`、`config_path` 或 `quant.research` import。

### P0-7：字段“正数”约束比下游冻结业务口径更宽

- 根因：只验证通用类型/值域，没有反查消费端用的是参数还是硬口径。endpoint 上限放宽会漏判截断；CSI300
  数量、30×20 对账和 Alpha158 warmup 改动会让 C0 通过而 G1/G4 固定失败。
- 规则：当前 `1.0.0` 对这些字段使用精确 literal；若未来参数化，必须先让全部消费者读取同一配置，再升级
  config version，不能单方面放宽 loader。
- 回归：每个 endpoint ±1、299/301、29/31、19/21、59/61 全部在 C0 失败。

### P0-7A：冻结 literal 与“改值后比较 hash”不能同时执行

- 发现：实现 Agent 按任务书编写传播测试时指出，公开 canonicalizer 必须先验证完整文档，
  而 endpoint limit、抽样数、Qlib 版本等在 `1.0.0` 中只有一个合法值，因此无法同时构造两份
  有效文档来运行时比较 hash。
- 根因：任务书把“selector 归属应如何传播”与“当前版本允许的参数空间”混成了一种
  测试方式。
- 裁决：保持生产 literal 严格；合法可变字段做运行时 hash 差分，冻结字段则同时测试公开 API
  拒绝变体和 `_FIELD_SPECS` selector 归属。不放宽 validator，不暴露 trusted helper。
- 通用规则：验收矩阵必须区分“逻辑传播规则”和“当前 schema 的合法变量”；要扩大后者必须先
  升级 config version 并同步消费者。

### P1-1：通配字段描述可能漏掉模型/费用细约束

- 根因：`model.*`/`costs.*` 的自然语言不能证明每个字段有 strict type 和 selector 归属。
- 规则：生产 `_FIELD_SPECS` 是唯一机器 allowlist；示例 assignment/shape 集与它精确闭合，模型关系和每个
  period 数值逐字段校验。
- 回归：151 assignments/138 normalized shapes；int 冒充任一费用 float、负 seed、early-stop>=rounds 均失败。

### P0-8：只新建 loader 仍无法形成唯一配置入口

- 根因：审查只看“新增模块”，没搜索已有 M3 消费者；snapshot 仍读取并 hash 整份 TOML，fetcher 和旧测试
  也直接 parse。
- 规则：唯一入口验收必须做调用图/源码搜索；C0D 显式迁移 snapshot 配置参数、fetcher spec 注入和示例测试。
  通用 settings、S0/S1、交易所日历自己的 TOML reader 不属于 M3，不能误删。
- 回归：M3 production 中只有 `config.py` import `tomllib`；snapshot/fetcher 无 `config_path`；测试消费示例
  只通过 `load_m3_config`。E3/G2 尚未完成的裸 key/最终 calendar 另保持显式 blocker。

## 3. 对实现 Agent 的反馈

这里的重点不是多写一批 `if`，而是保持“执行参数、记录参数和身份 hash 来自同一已验证对象”。不得为让
旧测试继续通过而恢复隐式默认，也不得把整份 TOML hash 同时当作 snapshot/provider/experiment identity。
任务边界和独立初验见
[`M3_C0配置加载与身份哈希实现初验任务单.md`](M3_C0配置加载与身份哈希实现初验任务单.md)。

## 4. 实现后独立初验反馈

2026-07-13 实现 Agent 自测 286 passed、Ruff/mypy 通过后，未参与实现的 Agent 使用 12+1 个未公开
反例验收，仍发现 3 个 P1 和 1 个 P2，因此 C0 已退回返工。详见
[`M3_C0配置加载与身份哈希独立初验报告.md`](M3_C0配置加载与身份哈希独立初验报告.md)。

| 问题 | 实现考虑不周的根因 | 写回的通用规则 | 返工回归 |
|---|---|---|---|
| 外层错误已脱敏，但 `raise ... from exc` 的 traceback 仍泄露物理路径 | 只测 `str/repr`，没有测异常链和结构化日志 | 脱敏必须覆盖 message、repr、formatted traceback、cause/context 和 `exc_info` | I/O 与 TOML parse 的 sentinel 路径在完整 traceback 中均不可见 |
| value 会 percent-decode，sensitive key 却不会 | key/value 维护了两套安全规范化管线 | 唯一顺序为受控重复 decode→case/hyphen normalize→classify，unknown 之前先安全扫描 | 单/双编码 token/api-key/private-key 同时报脱敏 `SECRET_VALUE` 和 `UNKNOWN_KEY` |
| direct tracking target 未复用 loader 的 name/path 检查 | 公开 helper 手写了不完整验证 | loader 和 direct API 必须共用同一 safety primitive，并用成对反例锁定接受域 | POSIX/Windows/UNC/反斜杠/编码绝对 name 在两入口产生同类错误 |
| mapping 的非字符串 key 被 `str(key)` 静默转换 | normalize 发生在 strict type validation 之前 | 严格验证先于任何有损 coercion；非字符串 key 必须稳定 `TYPE_ERROR` | 根层、嵌套层、费用 period 的非字符串 key 都拒绝，不与真实字符串键碰撞 |

这轮反例说明：“全量测试绿”只能证明已写测试的行为，不能代替独立 Agent 对公开信任边界的
未公开反例。返工应只修上述边界，不借机重构 selector/hash 主体。
