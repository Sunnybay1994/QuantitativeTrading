## 3. 必须修复的问题

### 3.1 D1：就绪审计可以放过不完整数据

1. `_check_cross_section` 使用每日截面的最大值。构造两个交易日，截面分别为 2 和 1，阈值为 2 时，审计没有返回 `CROSS_SECTION_TOO_SMALL`。准入门槛应对研究区间设定明确的逐日覆盖规则，至少不能由任意一天的最大值代替。
2. `_check_train_length` 只计算 SH 日历中的全部开市日，没有限定配置日期范围，也没有根据可用 bars/PIT 覆盖计算可训练 session；稀疏行情也可通过。
3. `_check_pit_coverage` 只要 PIT 成员与行情有任意一行交集就返回通过，不能检出按日/按证券的大量缺失。
4. 字段检查报错后函数仍继续执行依赖该字段的检查，不符合“返回结构化就绪问题”的接口预期。

返工要求：定义并实现可用训练日、PIT 覆盖和截面覆盖的明确门槛；在缺少前置字段时跳过依赖检查，但保留结构化 `ERROR`。

### 3.2 D4：snapshot 导出和验证未达到冻结契约

1. `prepare_qlib_staging` 在按 `source` 过滤前检查 `(symbol, trade_date)` 重复。clean 数据可以合法保存多个数据源的同键记录；在显式选择 source 后应只对选中的源检查重复。已复现：源 A/B 各有同一证券日行，显式请求 A 仍抛出重复异常。
2. staging 只把 `adj_factor` 改名为 `factor`，OHLC 原样输出。这与契约中“`open/high/low/close` 是同一累计因子处理后的价格”不一致。应先冻结具体复权公式和 volume 语义，再增加数值对账 fixture。
3. manifest 只记录文件路径、大小和 hash，缺少冻结契约要求的数据源、最小/最大日期和行数。
4. `validate_provider` 只检查目录存在和预期证券数为正；空目录也会被接受。契约要求从 provider 抽样回读 3 只证券、20 个日期并逐字段对账。`materialize_qlib_provider` 可继续留待真实 Qlib 环境，但 `validate_provider` 不能作为可成功返回的占位实现。

### 3.3 D5：多 horizon/模型时指标会被污染

`rank_ic_by_date` 把预测和标签只按 `(as_of, symbol)` 连接，并只按 `as_of` 分组。当 h=5 和 h=10 同时存在时，两边会多对多连接：两只证券、两个 horizon 的人工用例被合成一行日指标，`n_symbols=8`，而不是两个 horizon 各自 `n_symbols=2`。

返工要求：

- 评估入口要求唯一的 model/model_version/snapshot/fold/horizon 切片，或把这些身份列纳入连接键和分组键；
- 拒绝不唯一预测键和不唯一标签键，防止多对多连接；
- 用匹配预测数/应预测数计算真实预测覆盖率；当前的“可计算日比例”应单独命名。

### 3.4 D6：Top-k 未限定单一预测切片

`normalize_prediction_scores` 会按身份列分组重排 rank，但 `MlTopkStrategy.target_weights` 随后只按 `as_of` 过滤，再把多个 horizon/model 的行一起排序。构造同日两只证券、两个 horizon、`top_k=2`、`cash_buffer=0.1` 时，两个入选行可以来自同一证券，最终以字典覆盖成一只证券 0.45，总权重只有 0.45。

返工要求：要求每次调用只包含唯一 model/model_version/snapshot/fold/horizon 切片，不满足时显式拒绝；同时拒绝同一 symbol 冲突的资格行。本次任务单允许先实现无状态 Top-k，所以 `n_drop` 仍可留待接口评审，不作为本次失败原因。

### 3.5 D7：嵌套凭据可泄露到 MLflow

`_assert_safe_mapping` 只扫描顶层键，再把整个 value 转为字符串搜索 `token=` 或 `bearer `。例如 `{"nested": {"tushare_token": "secret-value"}}` 不会被拒绝，调用者如果传入完整配置即可把 token 写入实验记录。

返工要求：递归检查 Mapping/Sequence，对所有嵌套键和字符串值执行敏感信息与绝对路径校验；最好改用明确的参数白名单，不允许把整份配置直接交给 tracking 层。
