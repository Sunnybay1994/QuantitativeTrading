## 1. 目标与前置

实现港股通日频订单的纯内存规则判定：

```python
evaluate_connect_intent(
    intent: OrderIntent,
    state: SymbolMarketState,
    position: PositionBalance | None,
    connect_calendar: ConnectCalendarState,
    rule_config: ConnectRuleConfig,
) -> RuleDecision
```

前置仅为已通过主验的 M4-C0 与 M4-D0。M4-B2 不依赖 M3 G7；B1/B3 仍等待 G7 对应规则/成本前置。

本包封闭以下规则：双市场与通道日历、港股通 T+0、per-symbol board lot、碎股只卖、tick、上游验证的
ELO 可申报价格带、额度只阻止新买、停牌。不得实现 IO、repository、订单计划、费用、FX、账本、Gateway
或实时行情。

## 2. 权威工程语义

官方依据：

- 港股通南向交易只在香港和内地市场均开市的业务日开放；南向以 HKD 报价、人民币结算，且允许日内回转：
  <https://www.hkex.com.hk/-/media/HKEX-Market/Mutual-Market/Stock-Connect/Getting-Started/Information-Booklet-and-FAQ/Investor_Book_En.pdf>
- 南向连续交易时段只接受 enhanced limit order；HKEX 当前规则要求 ELO 不得越过对手方第 10 个价位，
  tick/报价规则会随有效期变化：
  <https://www.hkex.com.hk/Services/Trading/Securities/Overview/Trading-Mechanism?sc_lang=en>
- 2026 年 board-lot 框架分阶段生效，证明 board lot 必须来自按证券、按时点的 verified state，不能硬编码：
  <https://www.hkex.com.hk/News/Market-Communications/2026/260630news?sc_lang=en>

本项目是日频 PAPER/SHADOW，当前 `SymbolMarketState` 没有实时 best bid/ask。不得用 previous close 或
`reference_price ± N*tick` 冒充 ELO 实时边界。对 `Market.HK`，本包把 `state.limit_down` 与
`state.limit_up` 解释为上游 repository 在评估时点已验证的 ELO **可申报价格带**；两者任一缺失均拒绝，
价格必须落在闭区间内。未来实时 Gateway 可在不改变本纯函数的前提下构造该 state。

## 3. 新值对象与构造器

在 `quant.backtest.connect_execution` 新增：

```python
class ConnectRuleInputError(ValueError): ...

@dataclass(frozen=True, slots=True)
class ConnectCalendarState:
    calendar_identity: str       # builder 计算并在构造期自证的小写裸 64 hex
    route: str                   # 仅 SH_CONNECT / SZ_CONNECT
    session_date: date
    mainland_open: bool          # exact bool
    hong_kong_open: bool         # exact bool
    connect_open: bool           # exact bool；True 时前两项必须均 True
    source_version: str          # 非空稳定 id，拒绝路径/URI/控制字符

@dataclass(frozen=True, slots=True)
class ConnectRuleConfig:
    rule_identity: str           # builder 计算并在构造期自证的小写裸 64 hex
    selector: str                # 非空稳定 id，拒绝路径/URI/控制字符
    route: str                   # 仅 SH_CONNECT / SZ_CONNECT
    effective_from: date
    effective_to: date | None    # inclusive；不得早于 effective_from
```

必须提供且包根安全导出：

```python
build_connect_calendar_state(...) -> ConnectCalendarState
build_connect_rule_config(...) -> ConnectRuleConfig
evaluate_connect_intent(...) -> RuleDecision
```

identity 使用 type-tagged、strict canonical JSON bytes 的 SHA-256，覆盖除 identity 字段外的所有字段；调用者
不得自报 identity。直接 dataclass 构造的合法值可接受，但 `__post_init__` 必须重算并拒绝 forged identity。
严格拒绝 bool/int 混淆、`datetime` 冒充 `date`、子类和非法 route/id。

## 4. 输入闭包与失败语义

进入任何经济规则前，必须重验五个输入的真实类型和内容：

1. `OrderIntent` 的 `intent_id` 与全部 payload；
2. `SymbolMarketState` 的全部字段；
3. 非空 `PositionBalance` 的全部字段；
4. `ConnectCalendarState` 的 identity/payload；
5. `ConnectRuleConfig` 的 identity/payload。

可调用 D0 的公开 strict builder 重建并比较，不得只信 `isinstance` 或携带 id。任何 `object.__setattr__`
篡改、子类、非法字段或底层异常均统一为：

```python
ConnectRuleInputError("CONNECT_RULE_INPUT_INVALID")
```

异常不得包含 symbol、路径、repr 或底层文本，且 `__cause__ is None`、`__context__ is None`。因此不能在
`except` 块内直接 `raise ... from None`；先记录失败，退出 `except` 后再抛稳定错误。

以下关联不一致也属于 typed input error，而非经济拒绝：

- intent/state 不是 `Market.HK` 或币种不是 `Currency.HKD`；
- symbol、session_date 不一致；
- position 存在但 market/symbol 不一致；
- calendar route 与 config route 不一致；
- calendar session_date 与 intent 不一致。

## 5. 经济决策与稳定优先级

所有拒绝均返回 `RuleDecision`：`accepted=False`、`normalized_quantity=0`、
`normalized_limit_price=Decimal("0")`，`rule_version=rule_config.selector`。接受时 code=`ACCEPTED`，数量和
价格保持原值，禁止静默 rounding。

按以下顺序返回第一项拒绝：

1. `RULE_NOT_EFFECTIVE`：session 不在 config inclusive 有效期；
2. `RULE_VERSION_MISMATCH`：`state.rule_version != rule_config.selector`；
3. `CONNECT_CALENDAR_CLOSED`：mainland/HK/connect 任一未开；
4. `SUSPENDED`；
5. `INSUFFICIENT_SELLABLE`：卖单缺 position 或数量超过 `sellable_quantity`；不做 T+1 日期检查，体现港股 T+0；
6. `CONNECT_BUY_QUOTA_UNAVAILABLE`：仅 BUY 且 quota 不足；SELL 必须继续；
7. lot：
   - BUY 数量不是 `state.board_lot` 整数倍 → `CONNECT_BUY_BOARD_LOT_REQUIRED`；
   - SELL 允许整手，或数量严格小于一手的纯碎股；数量大于一手但非整手 → `CONNECT_SELL_MIXED_LOT`；
8. `PRICE_BAND_MISSING`：HK 的上下界任一为空；
9. `PRICE_TICK_INVALID`：limit price 不是 `state.tick_size` 的 Decimal 整数倍；
10. `PRICE_OUT_OF_RANGE`：价格不在 inclusive `[limit_down, limit_up]`；
11. `ACCEPTED`。

将上述新拒绝 code 加入 `ExecutionRejectReason` SSOT；不得在模块散落另一套字符串集合。既有枚举值不能
改名或删除。

## 7. 最低测试矩阵

实现测试至少覆盖：

- 正常 BUY 整手、正常 SELL 整手、SELL 纯碎股、同日新取得 sellable 后的 T+0 卖出；
- A 开/HK 休、HK 开/A 休、connect 单独关闭；
- quota 不足 BUY 拒绝而 SELL 接受；
- per-symbol board lot 变化、碎股 BUY、混合 lot SELL；
- tick 精确整除/不整除、边界恰等于上下界、越界、缺任一边界；
- 停牌、有效期首尾、过期、rule version mismatch；
- route/symbol/date/market/currency/position 关联不一致；
- 直接构造 forged calendar/rule identity；
- `object.__setattr__` 组合篡改 intent/state/position/calendar/config；
- 底层 strict builder 失败时顶层错误稳定、脱敏且 cause/context 均为空；
- 相同输入重复运行的 `RuleDecision` 与 identity 稳定。

实现者不得只测 happy path。独立初验至少增加三个实现者未使用的组合反例，必须包含：

1. 额度不足的 SELL + 纯碎股 + 边界价格，证明 quota 不误伤卖出；
2. intent 携带旧合法 id 后同时篡改 market 与价格，必须在经济读取前稳定 typed error；
3. calendar `connect_open=True` 但某一交易所关闭的 forged payload，必须拒绝且无异常链。
