## 1. 目标与通过边界

本包只回答下列四个问题：

1. `configs/tushare.local.toml` 中的研究 token 能否在不泄露凭据的前提下调用 G1 所需七个 Tushare
   raw 端点；
2. G1 权威 SH/SZ 自然日历能否补齐到足以解析 `2016-01-04` 前 60 个 SH session 和
   `2026-06-26` 后 10 个 SH session，并满足既有 G1 audit 的沪深日期域/开闭市一致性；
3. BaoStock reference bar 能否完成一次真实登录、取数和退出；
4. 当前 WSL/文件系统是否真实支持目录 `renameat2(RENAME_NOREPLACE)`。

R0 通过只表示真实依赖和日历前置可用，不表示 B4、G0、G1、M3 或任何 Gate 通过。不得启动完整
2015-12 至 2026-06 成分/行情回补，不得发布正式 G1 release。

### R0.2 先比对、后补齐 SH/SZ 日历

目标自然日范围固定为 `2015-01-01..2026-12-31`，必须分别更新 `market=SH` 与 `market=SZ`。

1. 在内存中分别通过 `TushareConnector.fetch_trade_calendar(market, start, end)` 抓取 raw，并通过
   对应 `TushareCalendarMapper(market)` 映射；两份都必须通过 `TradeCalendarSchema`。
2. 在任何 clean 写入前，分别读取已有 SH/SZ clean 日历，对各自交集日期逐日比较 `is_open`；同时将两份
   新 Tushare 日历按自然日一对一连接，要求日期域与 `is_open` 完全一致。若有任一差异：
   - 停止，不调用更新 pipeline；
   - 按 `SH_EXISTING/SZ_EXISTING/SH_VS_SZ` 报告差异日期数、首尾差异日期，不报告 token 或供应商内部对象；
   - 状态写“初验前阻塞”，不得自行选择某一来源覆盖。
3. 三类交集均无差异时，按 SH、SZ 顺序调用现有日历 pipeline/CLI 各完成一次正式更新；不得直接调用
   `DataFrame.write_parquet`。若 SH 已写而 SZ 随后失败，如实保留 SH 的合法幂等结果，状态仍为未通过；
   下一次只按同一合同重跑并由 clean store 幂等合并，不回滚或覆盖 raw。
4. 更新后重新读取两份 clean 文件并证明：
   - 两份自然日键均唯一、严格覆盖 `2015-01-01..2026-12-31`，无日期缺口；
   - `market` 分别全为 `SH`/`SZ`；
   - SH/SZ 日期域和 `is_open` 逐日完全一致；
   - `2016-01-04` 与 `2026-06-26` 均为开市日；
   - 用 SH 完整有序开市日调用 `resolve_history_window(..., feature_warmup_sessions=60,
     label_tail_sessions=10)` 成功，记录解析后的 `history.start/history.end`；
   - 两个市场更新前已有范围以外的合法日期不得被删除。

### R0.3 七个 Tushare G1 raw 端点烟测

只在内存调用，不落正式 G1 raw。字段参数必须直接取 `TUSHARE_FIELDS`，不得手写第二套字段清单。

| endpoint | 固定烟测请求 | 最小通过条件 |
|---|---|---|
| `index_weight` | `000300.SH`, `2026-01-01..2026-01-31` | 非空；正好 300 个唯一 `con_code`；仅一个 observation date；权重和在 `[99,101]` |
| `daily` | `000001.SZ`, `2026-01-05` | 正好一行；请求证券和日期一致 |
| `adj_factor` | 同上 | 正好一行；因子 finite 且 `>0` |
| `index_daily` | `H00300.CSI`, `2026-01-05` | 正好一行；代码和日期一致 |
| `suspend_d` | `2026-01-05` | 请求成功；允许零行；若非空，列集合和日期域合法 |
| `stk_limit` | `000001.SZ`, `2026-01-05` | 正好一行；上下限 finite 且上限不小于下限 |
| `dividend` | `000001.SZ` 全历史 | 请求成功；允许零行；若非空，证券代码一致且列集合精确 |

所有响应必须验证列顺序/集合与 `TUSHARE_FIELDS[endpoint]` 精确一致，并验证行数未达到各自配置的
`endpoint_row_limits`；达到或超过安全阈值按失败处理。报告只写 endpoint、PASS/FAIL、row count、列名、
业务范围摘要，不写完整数据行。

网络/限频异常不得无限重试：每个端点最多 2 次，第二次仅允许 `NETWORK/RATE_LIMIT/TRANSIENT_SERVER`；
两次间隔至少 60 秒。永久权限错误立即停止该端点并如实记录。不得并发请求。
