# M4 B4-P3 双配置身份闭包返工记录

状态：实现完成，等待主 Agent 双平台终验。

## 现象与根因

B4 生成的 `OrderPlan.config_identity` 是交易配置、规则、费用、FX 与最小名义金额的
planner composite identity；P3 却把它与仅覆盖 C0 `TradingConfig` 的
`trading_config_identity(config)` 比较。合法的 B4 → P3 路径因此稳定返回
`CONFIG_IDENTITY_MISMATCH`。原定向测试分别手工构造 plan，没有覆盖真实跨包路径。

## 应遵循规则

- `config_identity` 保持 planner composite 语义，避免破坏 B4/B6 与 intent 来源闭包。
- `trading_config_identity` 是新增且独立的 C0 provenance；两者都纳入 `plan_id`。
- P3 只通过 C0 公开 verifier 重算后比较新增字段，不 import portfolio，也不接受调用者自报 hash。
- service 只能消费 B4 返回的 plan，不得调用低层 builder 重建或替换身份。

## 最小复现与新增测试

最小复现是 `build_order_planner_config → portfolio.build_order_plan →
evaluate_pretrade`。新增真实跨包测试证明合法 plan 不再出现
`CONFIG_IDENTITY_MISMATCH`；D0 测试证明篡改 `trading_config_identity` 会因
`plan_id` 不匹配而 fail closed。B6 继续按 composite identity 选择 planner。

## 通过条件

- D0、B4、P3、B6 与 P4 定向测试通过；
- Ruff 与相关生产源码 mypy 通过；
- Windows 与 WSL base 都通过同一组定向测试；
- 旧开发 stage/receipt 不做隐式迁移；如 wire payload 包含 plan，必须显式升版本并 fail closed。
