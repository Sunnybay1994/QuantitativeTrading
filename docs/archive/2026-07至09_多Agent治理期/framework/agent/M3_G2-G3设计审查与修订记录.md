## 2. 已修订的 P0 问题

### P0-1：snapshot identity 与权威 calendar 缺失

- 现象：旧实现 hash 整份 TOML，且 provider calendar 只能从 staging 日期并集产生。
- 根因：把物理配置文件当 narrow identity，也把派生输出当市场日历真源。
- 规则：snapshot 只用 C0 `snapshot_config_sha256`，并发布可读 `session_calendar.parquet`；日期域来自 G1/
  config 请求。staging 日期并集必须与它完全一致。
- 反例：只改 tracking URI 不应重建 snapshot；某 SH 开市日全部证券缺行必须失败。
- 对实现 Agent 的指导：identity 应绑定会改变该产物的语义输入；验证期望值必须来自上游权威事实，不能
  从待验产物反推，否则缺失会被双方共同遗漏。

### P0-2：materializer 接口不能表达固定脚本契约

- 现象：只有输入/输出路径，调用者会猜 `dump_all`、file suffix、fields 和 workers。
- 根因：把外部脚本当黑盒命令，没有把供应链和 argv 变成数据契约。
- 规则：引入 tool/build spec，固定 `dump_all + parquet + 七 fields + max_workers=1`、当前解释器、
  `shell=False`、空 temp；禁止 update/fix/backup/limit。
- 反例：官方脚本默认 `.csv`，不传 include fields 会尝试非数值列；返回 0 也可能输出不完整。
- 指导：外部工具的默认值不是本项目 SSOT。凡是会改变字节或失败语义的参数都要显式、版本化、可测试。

### P0-3：provider manifest 与全量结构验证未定义

- 现象：3×20 sample 可能避开少证券、少字段、错 offset 或 calendar 缺日。
- 根因：把抽样数值证据误当完整性证据。
- 规则：全量核对 calendar、instruments、七 bin、offset/长度、NaN gap、未知文件/symlink 和 tree digest；
  3×20×7 只承担真实 Qlib public API 可读性证据。
- 反例：未抽中的证券缺 `$factor` 时 sample 仍可能全绿。
- 指导：先证明“集合完整”，再抽样证明“外部 API 解释一致”；两个问题不能由一个 sample 同时替代。

### P0-4：抽样和 float32 口径不确定

- 现象：随机种子、市场覆盖、日期选择和 Float64/Float32 比较由实现者临场决定。
- 根因：验收证据本身不是可复现产物。
- 规则：固定 market-stratified hash 算法，一 SH、一 SZ、第三只，首尾+18 内部日期、最多 5 gap、七字段；
  expected 先转 little-endian float32，有限值精确一致。
- 反例：只抽 SH 或只抽容易通过的日期不能证明 symbol codec 与 gap。
- 指导：验收抽样也必须有 identity、算法版本、候选 hash 和完整 keys，不能依赖 RNG 状态或人工挑样。

### P0-5：Qlib 全局状态污染

- 现象：进程内先 `qlib.init(A)` 后验证 B，缓存可能仍读 A；延迟 import 无法清理全局状态。
- 根因：把 import 隔离误认为 runtime state 隔离。
- 规则：provider validation、G3 reconciliation 和 Alpha158 feature stage 均使用 fresh Python worker；一个
  worker 只初始化一个 provider，只交换 JSON/Parquet，Qlib 对象不跨进程。
- 反例：fake 令第二次 init 不清 cache，若同进程就错误读 A。
- 指导：遇到进程级单例/全局 cache，最小可靠隔离单元是进程，不是在函数末尾“清一下变量”。

### P0-6：并发与崩溃恢复所有权不闭合

- 现象：dump 会逐步生成半成品；两个相同 key 可同时观察到 receipt 不存在。
- 根因：helper 与 StageRunner 都可能认为自己拥有 final publish。
- 规则：helper 只写唯一 temp，StageRunner 单独发布 final/receipt；同 key 单 writer/`flock`，锁内重验；
  orphan 只在重算逐字节一致时认领，冲突拒绝。
- 反例：两个进程同时 dump 到 final 会混合 bin 和 manifest。
- 指导：先明确“谁拥有最终目录”，再设计恢复。原子 rename 只解决单次发布，不自动解决多 writer。

### P0-7：G3 统一 `1e-10` 不可实现且可自洽地算错

- 现象：dump 强制 `<f4`，Qlib raw 与 Float64 clean label 通常存在约 `1e-7` 量化误差；若 benchmark 直接
  复制 label，即使日期错位也会自洽通过。
- 根因：混合了表达式正确性、独立 benchmark 正确性和存储量化误差三类问题。
- 规则：分别使用 expression/direct、独立 benchmark、provider-vs-Float64 label 三层容差；全量行键对账，
  benchmark 日期和收益独立推导。
- 反例：label 错用 `t+2` benchmark；复制 label benchmark 会假绿，独立查表会失败。
- 指导：对账必须有独立计算路径。若 expected 和 actual 复用同一中间量，测试只能证明“双方同错”。

## 3. P1 问题与处理

- `fetch_qlib_tool.py` 自行解析 TOML 违反 C0：改为注入 `QlibDumpToolSpec`。
- 官方脚本静默 `drop_duplicates(date)`：snapshot 预检与 provider 后验都拒绝重复/结构漂移。
- staging writer 可覆盖：只允许空 StageRunner temp。
- manifest 不记录绝对 argv、PID、时间戳；只记录逻辑 argv和稳定 identities。
- materialize 前检查真实依赖/精确 Qlib，缺依赖归为 G0/exit 4，不伪报数据损坏。
- Qlib MultiIndex 按命名 level 解析，时间只接受 naive midnight，symbol codec 只调用 snapshot SSOT。

## 4. Fake 与真实验收边界

fake 可证明 argv、身份、结构解析、抽样、worker 协议、三层 diff、锁和失败语义；不能证明真实 Qlib 0.9.7
能加载 provider、`D.features`/`Ref` 的真实方向、Alpha158 VWAP 或 Gate 通过。真实验收必须在兼容 WSL base
运行固定脚本、全量结构、fresh public API 3×20×7 与 h=5/h=10 全量 reconciliation。

## 5. 当前结论

上述规则已进入 SSOT、C0/E3/G4–G6/G8/G9 任务边界和新的 G2–G3 任务书。当前没有实现证据，不能把
设计审查通过写成 G2/G3 通过。实现者若发现固定脚本、真实 Qlib 或配置仍与任务书冲突，应停止对应包并
提交最小复现，由主 Agent 修改 SSOT；不得自行选择新容差、抽样或 dump 参数。

## 6. 跨文档一致性复核追加规则

第二轮只读一致性复核进一步冻结：

- 函数若返回 identity key，签名必须显式具备计算该 key 的全部输入；probe planner 接收 G8/E3 已计算的
  validation key，不隐藏读 receipt 或复制 hash。
- provider 抽样与 label reconciliation 配置使用两个独立 hash；配置身份按实际消费者拆分，避免无关失效。
- 稳定产物不得保存 PID；fresh-process 由父进程运行时 spy、worker protocol、read/import audit 证明。
- 每个业务 artifact 必须有明确生产者和严格 manifest；`label_manifest.json` 由 labels stage 与数据同 receipt
  发布，不能由 G8/G9 临时补造。
- StageRunner 的禁止隐藏读取必须由 required-input 矩阵支撑；固定 dump tool 与 G1 release 使用只读 root
  alias 纳入 receipt 输入闭包。
- 用于目录的 identity/digest 统一裸 64 位小写 hex，不带会破坏 Windows 挂载路径的冒号前缀。
- provider 物理树、manifest、validation 目录分开；manifest 只 hash Qlib tree，避免自引用。
- 验真入口接收已验真 artifact bundle，不接受裸 DataFrame 加任意 hash 字符串拼接。
