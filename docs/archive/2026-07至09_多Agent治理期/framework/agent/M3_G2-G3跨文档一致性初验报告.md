## 1. 独立初验发现与吸收结果

| 问题 | 根因 | 已冻结修订 |
|---|---|---|
| dump 配置是扁平字段，C0 任务却引用不存在的嵌套 section | spec 归属和 mapping 未指定 | 保留扁平 TOML；`QlibDumpToolSpec` 唯一在 contracts；provider 唯一 builder 显式映射；下载器只接 spec |
| probe planner 返回 validation key，却没有计算它的全部输入 | identity 计算与业务计划混层 | G8/E3 先算 key；planner 显式接收并校验，不读取 receipt、不复制 hash |
| 一个 validation hash 同时控制抽样和标签容差 | 配置身份没有按消费者拆分 | 拆为 provider-validation 与 label-reconciliation 两个 hash，形成八类配置身份 |
| `label_manifest.json` 无生产者和 validator | 稳定产物矩阵先于职责分配 | labels stage 与 labels/diagnostics 同 receipt 发布严格 manifest；G2–G3 P4 负责，G8/G9 不补造 |
| provider root、Qlib tree 和 manifest/validation 位置不唯一 | stage root 与 `--qlib_dir` 混用 | `providers/<key>/provider/**`、同级 manifest、`provider-validation/key=<key>/`；manifest 只列 tree |
| 固定 dump 脚本未进入 DAG 输入 | 外部供应链文件被 handler 隐式读取 | 新增 `EXTERNAL_QLIB` root；provider receipt 显式绑定脚本、snapshot manifest/calendar/staging |
| G2/G3 需要的 G1/snapshot 文件不在 StageNode inputs | 只冻结 outputs，禁止隐藏读取无法执行 | 稳定矩阵增加 Required inputs 和 `CONFIG/G1_RELEASE/EXTERNAL_QLIB` roots |
| fresh worker 要求把 PID 写证据，与稳定产物冲突 | 把运行时观察量当稳定身份 | PID 仅测试 spy 实时观察；持久化 worker protocol/runtime/URI hash/import+read audit |
| session calendar 无精确 Schema，full history 与 signal hash 混用 | 日历职责未分层 | 单列 `SnapshotSessionCalendarSchema(date)`；FoldPlan 分 session/signal/config 三个 hash |
| reconciliation 可拼 A 数据+B hash | 入口接受裸 DataFrame 和自报 digest | 改为 `VerifiedProviderArtifact/VerifiedLabelArtifact`；文件/receipt/hash 在启动 Qlib 前复算，worker echo |
| identity 使用 `sha256:<hex>` 直接组成挂载盘目录 | 展示格式与物理 key 混用 | 所有 key/digest 统一裸 64 位小写 hex；算法名单独字段；不兼容双格式 |

## 2. P1 契约补齐

- 3×20 是 60 emitted keys/420 comparisons；gap 另计 0–15 keys/0–105 comparisons，summary 分开计数。
- Provider、validation、reconciliation JSON 各有严格 v1 dataclass/reader，拒绝未知字段、duplicate key、
  NaN 和字符串数字。
- G3 固定四个误差序列：expression-direct、benchmark、raw-label、relative-label；后两者共同使用
  `label_return_atol`，不得合并 max。
- C0 强制 `qlib_expression_atol <= label_return_atol` 与
  `benchmark_return_atol <= label_return_atol`。
- H1 增加 `FeatureBuildSpec`，绑定 provider receipt、fold、feature config 和 worker protocol。
- G4 前置增加 G2 provider validation 与对应 horizon G3 reconciliation；G8 等待 G1–G7 handlers。
- tracking 文件名统一为 `request.json/marker.json`；logical dump argv 的占位符序列固定。
- materializer 对 tool/runtime Qlib version、runtime hash 和 provider key 做副作用前交叉重算。

## 3. 给实现 Agent 的通用指导

1. 函数签名必须具备其返回值所需的全部输入；缺输入时不要隐藏读文件。
2. 配置 hash 按实际消费者拆分；“一个总 hash 最省事”会造成无关重算和错误缓存。
3. 每个稳定业务文件都要有明确生产 stage、严格 manifest 和 verifier。
4. 运行时观察量（PID、时间）与稳定 identity 分离。
5. StageRunner 的 read audit 只在 required-input 闭包完整时才有意义。
6. 验真入口接收已验真 bundle；裸对象加字符串 hash 不能证明 lineage。
