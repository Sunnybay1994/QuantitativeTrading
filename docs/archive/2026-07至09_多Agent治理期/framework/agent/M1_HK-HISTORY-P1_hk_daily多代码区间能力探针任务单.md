# M1 HK-HISTORY-P1 `hk_daily` 多代码区间能力探针任务单

日期：2026-07-18  
执行者：主 Agent  
状态：已完成（主 Agent 验证通过）

## 1. 目标

用恰好一次 `hk_daily` 请求验证供应商是否接受逗号分隔的多代码参数并返回完整区间。这决定 HK60 是否可
从约 60 次逐交易日请求降到若干个、每批不超过 5000 行的多代码区间请求。

## 2. 冻结调用

- 距 P0 调用至少 60 分钟后执行，不提前试错、不自动重试。
- 代码固定为排序后的 `00005.HK,00700.HK`；区间固定为 clean HK 日历推导的 60 日窗口
  `2026-04-14..2026-07-10`，字段固定为
  `ts_code,trade_date,open,high,low,close,pre_close,change,pct_chg,vol,amount`。
- connector 只做一次原样请求，不在供应商拒绝多代码时偷偷改为两次单代码请求。
- 无论成功、空响应或稳定失败，都写独立任务证据；成功响应先进入
  `tushare/hk_daily_multi_symbol_probe` immutable raw，不写 clean。
- 期望每个代码覆盖各自上市后窗口；响应含目标外代码、重复键、任一目标全缺或达到 5000 行上限均判定
  该能力不能直接用于 HK60 规划。
- 异常只记录稳定码和异常类型，不输出供应商原文或 token。

## 3. 后续分支

- 两代码完整成功：只证明当前服务端的实测行为。Tushare 官方文档仅示例单代码区间和单日全市场，未明确
  承诺逗号分隔多代码；取得官方确认或冻结明确降级语义前，不把未文档化行为直接提升为生产合同。确认后
  才按 `floor(5000 / 最大需求交易日数)` 冻结保守批大小并另建可恢复 manifest；不在本探针直接放大到
  613 个代码。
- 失败/空/只返回一个代码：停止多代码方向，等待冷却后只评估官方声明支持分页的 `hk_daily_adj` 或其他
  已授权供应商；不循环试探。
- `02983.HK` 仍作为单独反例处理；不得用 `02525.HK` 改名补齐。
