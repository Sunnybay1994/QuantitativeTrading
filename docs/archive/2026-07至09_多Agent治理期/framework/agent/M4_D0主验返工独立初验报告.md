## 3. 主验四反例独立复现

内存探针（不写入仓库）逐条复现主验 P0-A / P0-B / P1-C / P1-D，结果如下。

### P0-A：OrderPlan 四 identity 混配

| 操作 | 结果 |
|---|---|
| 顶层四 identity 分别与单个 `OrderIntentSpec` 不一致（四支） | 均 `ContractError` |
| `replace(plan, target_identity=...)` | `ContractError` |
| `replace(plan, intents=(foreign_intent,))`（intent 顶层来源不一致） | `ContractError` |

**判决：PASS**（混配不再被接受为自洽 plan）

### P0-B：真实 command quantity 超量 + 旧不安全入口

| 操作 | 结果 |
|---|---|
| `build_execution_event` 公开签名 | 仅有 `command=...`；无裸 `command_id` / `command_quantity` |
| 旧 kwargs：`command_id` + `command_quantity=1000` 且 `cumulative_quantity=500` | `TypeError`（unexpected keyword `command_id`） |
| 真实 `quantity=10` 的 command：FILL/PARTIAL_FILL/CANCELLED 且 cum>10 | 均 `ContractError` |
| `_build_execution_event_from_command` | 模块私有、不接 `command_quantity`、不在 `__all__` |

**判决：PASS**（旧不安全 event builder 对外部调用不可用；超量以真实 command 为准拒绝）

### P1-C：snapshot / state 错日

| 操作 | 结果 |
|---|---|
| snapshot `2026-07-16` + 单 state `2026-07-15` | `ContractError: state.session_date must match snapshot session_date` |
| 多 state 中仅一项错日 | 同上拒绝 |
| `replace(snap, session_date=2026-07-15)`（`__post_init__`） | 同上拒绝 |

**判决：PASS**

### P1-D：非法 spec 非合同异常

| 操作 | 结果 |
|---|---|
| `OrderIntentSpec.market="SH"` | `ContractError`（非 `AttributeError`） |
| `quantity=True` / naive `generated_at` / `quote_currency=HKD` | 均 `ContractError` |
| `build_order_plan(..., intent_specs=(object(),))` | `ContractError`（排序前类型门禁，无属性泄漏） |

**判决：PASS**

## 4. 实现者未用的对抗性反例（混合嵌套错误 element）

实现者 `test_builders_reject_wrong_sequence_elements_as_contract_error` 仅对 positions / cash / states / fees / rejections / residual_cash **各用单个裸 `str`**。本初验新增以下未覆盖组合：

| 反例 | 结果 |
|---|---|
| `positions=(PositionBalance, CashBalance)`（合法 VO 错槽） | `ContractError: positions elements must be PositionBalance` |
| `fees=(FeeComponent, MoneyAmount)` | `ContractError: fees elements must be FeeComponent` |
| `intent_specs=(OrderIntentSpec, MoneyAmount)`（实现者未测 intent_specs 错 element） | `ContractError: intent_specs elements must be OrderIntentSpec` |
| 同一 `build_order_plan` 调用：`rejections=(FeeComponent,)` 且 `residual_cash=(PositionBalance,)` | `ContractError: rejections elements must be RuleDecision`（先于排序/哈希；无非合同异常外溢） |

**判决：PASS**（混合嵌套错误 element 稳定为 `ContractError`）

## 5. 代码合同抽样（只读）

与任务单 F1–F4 对齐的关键点已确认存在：

- F1：`build_order_plan` digest 前 `_require_plan_intent_source_closure`；`OrderPlan.__post_init__` 对每个 intent 重复双向闭包。
- F2：公开 `build_execution_event(*, command: OrderCommand, ...)`；`cumulative_quantity > command.intent.quantity` 拒绝；无私有裸 quantity 入口。
- F3：builder 与 `VerifiedMarketSnapshot.__post_init__` 均校验 `state.session_date == snapshot.session_date`。
- F4：`OrderIntentSpec.__post_init__` + `_require_sequence_of` 在排序/payload 前门禁。

OMS 测试仅见 `_event` 改为传 `command=` 的机械适配；未扩大 OMS 业务语义。
