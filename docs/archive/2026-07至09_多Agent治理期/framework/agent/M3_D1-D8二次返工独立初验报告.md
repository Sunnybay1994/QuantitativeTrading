## 2. P0 问题

### P0-1：readiness 把全收益基准当个股 Bar

`readiness.py` 对 benchmark 复用个股字段和 helper，要求 `symbol/volume/adj_factor`、检查 factor 并按
symbol 过滤；权威 `BenchmarkBar1dSchema` 使用
`benchmark,trade_date,OHLC,source,source_snapshot_id`。

最小复现：合法 `H00300.CSI` fixture 会得到 `BENCHMARK_MISSING_FIELDS: adj_factor,symbol,volume` 和
`BENCHMARK_EMPTY`。根因是旧测试仍使用个股式 `000300.SH` fixture，掩盖了独立基准契约。

通过条件：按 G1 任务 L0A 建独立 benchmark 校验路径；合法 Schema 无需 volume/factor/symbol 即通过，
source、重复 `(benchmark,date,source)`、OHLC finite 和日期覆盖分别测试。

### P0-2：snapshot 仍 hash 整份 TOML，且无权威 session calendar

`snapshot.py` 的 manifest 仍接收 `config_path` 并 hash 全文件；没有 `session_calendar.parquet`、history 域、
calendar digest/count。只改 tracking/acceptance/注释会产生新 snapshot；某开市日全部证券缺行也无法发现。

通过条件：完成 G2–G3 任务 P0：只接收 C0 narrow hash，发布权威 SH session calendar，staging 日期并集
必须与其完全一致，并覆盖 tracking/acceptance 不影响 snapshot 的变化传播测试。

### P0-3：D8 仍是第二个 TOML reader

`fetch_qlib_tool.py` 直接 import `tomllib`，接受 config path；一份只含 dump 四字段、其余 M3 配置非法的
TOML 仍可被独立接受。根因是遗留下载器尚未迁移到 C0。

通过条件：先交付 C0，再删除 `load_dump_script_spec`/config path；下载器只接收不可变
`QlibDumpToolSpec`，测试模块不 import tomllib、不读取配置文件。

### P0-4：fold 仍是 endpoint-only 旧契约

`folds.py` 无 `PlannedFold/FoldPlan/build_temporal_fold_plan/select_supervised_labels`，不验证 calendar 唯一/
严格递增，label cutoff 仍用 train end 而非 embargo 末日。重复日期能被当作两个训练 session。

通过条件：按 G4–G6 任务 H0 实现完整 session 列表、两个 embargo、cutoff、calendar/config/date hash、
test 非重叠；重复/逆序 calendar、embargo/step 不变量和确定性 manifest 全覆盖。

## 3. P1 问题

### P1-1：标签未 fail-closed 验证重复 calendar

`labels.py` 直接 sort 后建日期索引。重复 SH session 可令 h=2 产生相同 start/end 日期，输出 Schema 又无法
识别该交易语义错误。

通过条件：先通过 `TradeCalendarSchema`，过滤后仍验证唯一严格递增；重复 session 在计算前失败，成功
horizon 的 end 严格晚于 start。规则已写回 SSOT 4.3 和 G1 L0。

### P1-2：D3 v2 缺少独立交付证据

当前 benchmark Schema、eligible keys、finite 收益和 diagnostics 守恒已有初次代码与测试，方向基本正确；
但历史 F1–F6 报告按原范围未包含这些后续改动。SSOT 已更新为“初次实现，待 readiness/calendar 返工与
独立初验”，不得用旧 D3 绿测直接关闭 G1/G3。

## 4. 给实现 Agent 的反馈

这些问题的共同根因是“模块局部测试通过，但没有用权威上游契约做联调”。实现时应优先从 Schema、C0
和 G1 manifest 接收已验证对象，禁止为复用旧 helper 伪造字段；涉及交易日偏移的函数必须先证明 session
序列合法；内容寻址必须只绑定会改变该产物的语义输入。

当前建议返工拆分：L0A readiness 与 label calendar 归 G1；FoldPlan 归 G4 H0；snapshot calendar、typed
dump spec 归 G2–G3/C0。不得把四项塞进同一大提交后只跑旧 wildcard 测试。
