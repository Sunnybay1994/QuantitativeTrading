# M4-P5-R1 恢复与对账独立初验报告

日期：2026-08-02  
结论：**FAIL，退回补齐冻结反例与正式成功闭环证据**

## 结论

实现的主体方向正确：`recover_local_state` 使用单次只读 transaction/`RecoveryRows`，逐类 decode、canonical
wire、row key、identity、parent、ledger context/checkpoint 闭包重证；`BrokerSnapshot` 通过 builder 重算
account/event/snapshot identity；`reconcile` 为无 store 参数的纯函数，覆盖 UNKNOWN/NOT_SENT/INTRADAY、
账户和订单差异，输出稳定排序并清空异常 cause/context。

但实现测试只有 7 项，未覆盖任务单强制的关键成功路径与高风险反例，独立初验不能用代码静态存在替代运行
证据。本轮至少缺：成功 SENT callback 恢复后与 matching PAPER EOD 对账 Gate PASS、broker 重复经济事件、
SQLite 并发写入下单一一致快照、event/context/checkpoint 断链、typed local 内层对象 mutation、完整表零写入。
因此当前不满足 P5 完成标准。

## 返工项

### P1：缺少 SENT 成功恢复与 matching broker EOD 闭环

- 现象：现有成功 Gate 只覆盖空库；有命令测试只覆盖 PENDING→`LOCAL_NOT_SENT`。
- 根因：没有从已成功 callback/ledger transaction 的真实 store wire 恢复，再构造 matching broker
  order/events/account 的闭环。
- 规则：任务单要求完整 wire/aggregate/delivery/ledger/checkpoint 恢复，并证明差异为空、local READY、
  EOD 时 Gate PASS。
- 最小新增测试：经公开 service 完成 SENT→accepted/fill callback，恢复本地；broker 使用相同 order、event、
  cumulative quantity、cash、position；断言 `differences=()`、Gate PASS、重复恢复/对账 identity 相同且所有表不变。
- 通过条件：上述成功闭环通过，并分别篡改 callback event、aggregate、context、checkpoint tail 后稳定失败。

### P1：强制 corruption/concurrency 反例缺失

- 现象：未测试 duplicate economic broker event；未测试 recovery transaction 期间并发写入的一致视图。
- 根因：测试集中在空库、PENDING、unknown broker 与顶层 identity mutation，未覆盖任务单第 6、11 项。
- 最小新增测试：两个不同 event_id 表示同一经济 fill 必须产生
  `BROKER_ECONOMIC_EVENT_DUPLICATE/MANUAL_REQUIRED`；用第二连接在 recovery read 前后提交，结果只能是完整旧
  或完整新快照，禁止 command/event/ledger 撕裂。
- 通过条件：两项均通过，且异常图不含 payload、SQL、路径或 `TOKEN`。

## R1 独立复验（2026-08-02）

结论：**PASS，首轮 FAIL 项已逐项关闭，可进入主 Agent 终验。**

### 返工闭环

- SENT 完整闭环：公开 service 真实执行 partial+fill callback，恢复 command/event/aggregate/delivery、
  ledger context/checkpoint；matching PAPER `END_OF_DAY` order/events/account 得到 `differences=()`、
  `READY`、Gate PASS。RecoveryRows 前后逐项相等。
- duplicate economic event：不同 event identity、相同经济语义稳定保留
  `BROKER_ECONOMIC_EVENT_DUPLICATE/MANUAL_REQUIRED`，没有被同 subject 的 local-missing 分类吞掉。
- canonical tie-break：`_unique_sorted_differences` 先按 action priority，再按完整 `_difference_key`
  选择同 subject 结果；BrokerSnapshot builder 又把 order/event 规范排序，输入排列不影响结果。
- 并发一致视图：测试在唯一 `read_recovery_rows()` 返回后暂停 recovery transaction，第二 SQLite writer
  得到稳定 `TX_BUSY`；释放后可进入事务，恢复只观察完整旧快照。
- orphan：关闭外键后删除 command，遗留 context 恢复整体 `RECOVERY_LOCAL_INVALID`，无部分结果且
  cause/context 为空。
- 内层 mutation：对已恢复 command 的 `OrderIntent.quantity` 原地篡改后，reconcile 重算 local identity
  并稳定拒绝。
- BrokerSnapshot 自证：builder 重算 AccountSnapshot、每个 ExecutionEvent、order observation 和完整
  snapshot identity；reconcile 再次重算 account/event/snapshot，调用者构造或 mutation 不能只靠外层 hash。
