## 2. 主验三反例独立复现（非复述交付报告）

独立在 WSL `conda run -n base python` 中按主验原文构造探针（不依赖实现者测试函数名）。

### 2.1 P0-A：公开聚合对象不可表达不可能状态

| 项 | 内容 |
|---|---|
| 现象（主验） | 可直接构造 `FILLED + filled_quantity=999 + reject_code=bad + 非 hex event id` |
| 复现构造 | `OrderAggregate(status=FILLED, filled_quantity=999, reject_code="bad", applied_event_ids=("not-a-valid-hex-…",), command_quantity=100, …)` |
| 观测 | 抛出 `OmsError: filled_quantity exceeds command_quantity`（在 hex / reject 等后续检查前即 fail closed） |
| 对照 | **未**出现 `FORGED_AGGREGATE_ACCEPTED 999` |
| 结论 | **成立** — 直接构造拒绝不可能投影 |

代码依据：`OrderAggregate.__post_init__`（`filled > qty`、hex id、REJECTED/FILLED 跨字段等）。

### 2.2 P0-B：较早事件不可倒序推进状态

| 项 | 内容 |
|---|---|
| 现象（主验） | `02:05` ACCEPTED 后接受 `02:04` PARTIAL_FILL，累计成交推进到 40 |
| 复现步骤 | `new_order_aggregate` → ACCEPTED@`02:05` → PARTIAL_FILL cum=40 @`02:04` |
| 观测 | 抛出 `OmsError: event occurred_at before last_event_at` |
| 对照 | **未**出现 `REVERSE_TIME_ACCEPTED 40` |
| 结论 | **成立** — 非幂等事件时序非递减闭包 |

代码依据：`reduce_order` 中 `event.occurred_at < aggregate.last_event_at` → `OmsError`；成功应用写入 `last_event_at`。

### 2.3 P0-C：券商订单身份不可静默漂移

| 项 | 内容 |
|---|---|
| 现象（主验） | 绑定 `B-1` 后，带 `B-2` 的成交被接受并替换身份 |
| 复现步骤 | ACCEPTED `broker_order_id=B-1` → PARTIAL_FILL `broker_order_id=B-2` |
| 观测 | 抛出 `OmsError: broker_order_id mismatch with bound aggregate identity`；聚合仍为 `B-1` |
| 对照 | **未**出现 `BROKER_ID_CHANGE_ACCEPTED B-2` |
| 结论 | **成立** — 单次绑定，异值 fail closed |

代码依据：`_resolve_broker_order_id` 在 `_with_event` 统一执行。
