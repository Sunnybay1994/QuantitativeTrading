## 1. 边界

G9 实现固定质量命令、跨 Gate identity closure 和最终 acceptance receipt。它不是新的业务计算引擎，不
重新实现数据质量、标签、IC、费用或账户公式；各生产模块必须提供自己的 manifest reader/validator，
G9 只编排这些 validator、Stage registry 和 `verify_stage_receipt`。

采用主任务书 → 实现自测 → 独立初验 → 主终验。不得读取 `_old/`、Tushare token 或真实券商；除核对
当前 MLflow tracking target 外不得联网。G9 实现者不得修改 acceptance 阈值来让候选通过，也不得更新
路线图状态。

## 2. 前置修订

G9 开始前必须由对应任务包完成，不能在 acceptance.py 中打补丁：

1. `run_state.py`：receipt 增加固定版本和 `ACCEPTANCE` scope；严格字段、duplicate-key、空 stage/key、
   root 内外所有 symlink 拒绝；StageRunner 比较预期 node，不把裸 receipt 验真当 Gate 通过。
2. `contracts.py`：`DatasetSnapshot` 移除 `provider_path`；snapshot/provider 不再互相嵌套。
3. G3：发布 `label_manifest.json` 和每 horizon 的三列 Qlib reconciliation 产物。
4. G7：每个成本场景及总 backtest 发布完整 lineage manifest。
5. G8：发布 experiment manifest、稳定 REPRO outputs、research summary 和可恢复 tracking marker。
6. C0：`LoadedM3Config`、九类分层 identity（含 G1、provider-validation 与 label-reconciliation）和 tracking
   target key 已独立初验通过；E3 所有 key/digest 为裸 64 位小写 hex。

若任一项不存在，G9 应稳定报告缺证据并失败，不能使用 `SKIP`、WARNING 或空 manifest 降级。

## 3. A1：固定质量证据

新增：

- `src/quant/research/m3/quality_gate.py`
- `tests/unit/test_m3_quality_gate.py`
- `tests/unit/test_m3_import_isolation.py`

严格实现 SSOT 的 `QualityCheckResult/QualityReport/run_quality_gate`。使用当前 `python_executable` 与
`shell=False`，顺序运行固定 pytest/Ruff/mypy；另启动全新 Python 进程 import `quant.domain`、
`quant.strategies`、`quant.backtest`，确认 `qlib/lightgbm/mlflow` 不在 `sys.modules`，并 AST 扫描重依赖
import 只存在于批准的延迟适配器。

quality key 绑定 code version、dependency fingerprint、固定 argv 和 import-policy version。报告记录逻辑
`<PYTHON>` argv、退出码、规范化日志 hash 和工具版本，不记录解释器/工作区绝对路径、PID 或时间戳。
日志先将 workspace 前缀替换为 `<WORKSPACE>` 并扫描凭据。任一命令非零、超时、缺工具、依赖指纹不符
或 import 隔离失败，不发布 quality receipt。

测试使用 fake subprocess，不真实套跑全量 pytest；覆盖 argv 注入、`shell=True` 禁止、stderr 路径脱敏、
失败无 receipt、当前代码变化使旧 quality key 失效。

## 4. A2：AcceptancePlan 与身份重算

新增：

- `src/quant/research/m3/acceptance.py`
- `tests/unit/test_m3_acceptance_plan.py`

实现 `AcceptancePlan/build_acceptance_plan`。入口只接收 snapshot ID；先验真 snapshot，再用 C0 hash、实际
code/dependency、provider receipt 重算 provider/experiment key。目录名、manifest 自报 key 和用户输入都
不是信任根。

先从当前完整 `LoadedM3Config` 复算 `g1_config_sha256`，要求 G1 release manifest 的 config version/hash
一致，再沿其 manifest/receipt 验真 snapshot。rate/max-attempts/retry-base 的变化只改 full，不能让既有 G1
release 失效；endpoint/reconciliation/warmup 等 G1 selector 变化必须使旧 release 不可用于当前 acceptance。

另分别以 `provider_validation_config_sha256` 和 `label_reconciliation_config_sha256` 重算 provider-validation
及每 horizon reconciliation key；不得用总 validation hash 或目录名。固定 dump script 必须作为
`EXTERNAL_QLIB` receipt 输入重算 bytes/SHA，G1/snapshot/provider 数据文件均按 required-input 闭包验真。

从已验真的 folds manifest 读取预期 fold，再调用唯一 Stage registry/plan builder 枚举每个 required
receipt。不得 `glob/rglob/listdir` 扫描目录猜 work，不得在 acceptance 中复制 required-output 表。

冻结范围：每个 fold×horizon 都必须有完整 work 和一个独立进程 comparison receipt；不是“每 horizon
抽一折”的 canary。每个 horizon 恰有一个 summary；三个成本场景、所有 tracking target marker、G3 两个
horizon reconciliation 均必需。重复、缺失、额外身份混入、cross-experiment 路径或同一 comparison 被
两个 work 共用均失败。

## 5. A3：G0–G9 审计

实现 `GateResult/AcceptanceReport/audit_m3_acceptance` 和每 Gate 的薄 checker。至少验证：

| Gate | 必须闭合的证据 |
|---|---|
| G0 | enabled、readiness 无 ERROR、Python/Qlib 兼容、实际依赖与 experiment 相同 |
| G1 | release 全文件、source/universe/date/schema，snapshot 指向同 release |
| G2 | provider key/runtime 重算、receipt 明确含固定 dump tool 与 snapshot 输入、权威 calendar/instruments/bin 树完整、60 emitted keys/420 comparisons 及另计 gap NaN 证据完整 |
| G3 | benchmark/version/horizon/eligible identity；全量行键一致，expression-direct、benchmark、raw-label、relative-label 四个误差序列分别不超过对应三组配置容差 |
| G4 | calendar/signal domain/config hash；embargo、尾部和非重叠 test |
| G5 | model→feature/label/work，prediction→model/test；每 work 冷启动 comparison/read audit |
| G6 | evaluation→prediction/label/eligible/scorable/date；summary 同 horizon 且日期不重叠 |
| G7 | target→prediction/domain；backtest→target/G1/window/cost；三场景仅允许冻结成本项不同 |
| G8 | 全 DAG expected node receipt 精确匹配；当前 target 恰一 FINISHED MLflow run |
| G9 | 当前 code/dependency quality receipt、import isolation、限定 artifact secret/path scan |

G9 对 JSON 使用 duplicate-key 拒绝、严格字段集和 `allow_nan=false`；Parquet 调用权威 Schema/validator，
不能把字符串数字宽松转型为合法证据。所有 issue 稳定排序并尽量一次收集；上游损坏导致下游不可判定时
下游记录 `UPSTREAM_EVIDENCE_INVALID`，不能崩溃或虚报 PASS。

required metrics 的限定名称和来源只按 SSOT/config；coverage 与 computable ratio 逐 work 检查。工程 Gate
不对 RankIC、收益或超额的正负设门槛；指标为负但 finite、口径和覆盖合法可以通过。

## 6. A4：Acceptance identity、发布与 CLI

`acceptance_key` 绑定 experiment、acceptance config、tracking target、quality receipt 和全部有序 evidence
receipt。不得包含时间戳、PID、绝对路径；threshold 或 tracking target 改变必须产生新 key，不能复用旧
report。

修改 `run_m3.py` 增加 SSOT 命令 `acceptance-audit --config ... --snapshot-id ...`。配置/契约错误仍用 2，
其余 G0–G8 类别沿用 3–7，质量或 acceptance 闭合失败为 8；多问题返回最小非零码。stdout 只有一份规范
JSON，诊断写 stderr。

只有十 Gate 全 PASS 才通过 StageRunner 原子发布 report 和 ACCEPTANCE receipt。失败 report 只输出，
不得写 `complete`、空 acceptance 或可被后续误认的成功 artifact。命令不修改路线图、Git 或 MLflow run。

## 7. 集成测试

新增 `tests/integration/test_m3_acceptance.py`，使用 2 folds×2 horizons 的完整 fake artifact tree。至少覆盖：

1. 合法全链通过；
2. 单元测试全绿但候选 artifact 不存在，失败；
3. 把合法 work 复制到另一 experiment，hash 自洽仍因 key 重算失败；
4. receipt scope_key 属另一 horizon，或 JSON 有 duplicate key/未知字段/NaN；
5. h=5 label 注入 h=10 model，prediction manifest 引另一 work model；
6. target eligibility 来自另一 G1 release；
7. 三场景之一更换 target 或缩放印花税；
8. 一折 coverage 不达标但 pooled 达标，仍失败；
9. threshold/tracking target 改变后旧 acceptance 不复用；
10. marker 指向 FINISHED run 但 artifact digest 不同，或 0/2 个 matching run；
11. 父控制器运行时观察两个 repro worker 不是同一进程，但 read audit 仍读取正常 work/另一 attempt model；
    必须失败，且任何持久 JSON 不得保存 PID；
12. root 内 symlink 也拒绝；
13. `meta.enabled=false`、Qlib 缺失或 readiness ERROR 不降级；
14. 负 RankIC/负收益但证据和覆盖合法，不因此失败。
