## 4. E4C：公司行动 entitlement 账本

新增内部纯函数，函数名可在不改变语义的前提下保持简洁：

```python
def create_entitlements_at_record_close(...) -> tuple[...]: ...
def recognize_entitlements_at_ex_date(...) -> tuple[...]: ...
def settle_entitlements(...) -> tuple[...]: ...
```

不得用 ex-date 开盘持仓决定权益。record-date 收盘数量冻结 entitlement；ex-date 确认经济权利；pay/list
date 才进入现金/可交易持仓。与实际持仓相关的事件必须有 record/ex date；`cash_per_share_gross>0` 才要求
pay date，`stock_ratio>0` 才要求 stock-list date。相关日期缺失、事件冲突、非整数红股或重复入账均失败，
不允许回退到 ex-date；零现金/零送转分量不得伪造不相关结算日。本文原有 `theoretical_ex_mark` 已被现行任务
废止：P3 真实探针证明 dividend 两字段不能总能恢复官方除权参考价；G7 只能消费已验真 event-date bar，不能
在无 bar 时用公式猜 mark。精确规则以现行 G7 任务 §6 为准。

现金按税前金额入账并明确不模拟个人持有期红利税；首版不参与配股，影响持仓的未支持权益事件失败。

测试至少覆盖：record 后卖出仍有权益、ex-date 买入无权益、现金延迟派付、红股延迟上市、纯现金、纯
送转、混合事件、event-date bar 缺失 fail-closed、重复执行幂等、缺关键日期失败和价值守恒。

## 5. E4D：A 股日频账户循环

实现 `simulate_a_share_targets`，不得复制或调用 `simulate_etf_targets` 的账户循环。输入全部先通过
Schema，并拒绝跨源、重复键和日期域外数据。

先分别实现并测试 `build_open_execution_states`、`expand_targets_for_positions` 和 `plan_target_orders`，
再接账户循环；不得把三类规则埋进一个无法单测的日循环。open state 输出实现时新增唯一严格 Schema。

模拟器在创建账户状态前验证 `TargetBatchManifest`、target digest 和 `AShareBacktestData` 的 G1 identity；
结果 manifest 必须继承唯一 snapshot/fold/horizon/model lineage。多个 fold 或 horizon 必须分别运行，
不能拼成一条 NAV。

每个 `scenario={0p5x,1p0x,2p0x}` 发布独立 `manifest.json`，记录 target/G1/window/cost schedule、冻结输入
digest、成本 multiplier、六张表和 metrics hash；根 `backtest_manifest.json` 再列出三个场景 manifest hash
并证明除 SSOT 允许缩放的佣金、最低佣金和滑点外，市场事实与 targets 完全相同。manifest 必须有稳定
schema version；不得只靠目录名或 metrics 文件推断 lineage。

固定行为：

1. 当前持仓、当日目标和事件证券取并集；停牌持仓即使无 bar 也必须估值。
2. 前一 session 买入在本 session 开始前结算；同日买入不可卖。
3. 目标遗漏视为 0；预交易权益用 open/合法 carry mark 计算。
4. 先卖后买。FULL_DAY、开盘时段停牌、涨停买、跌停卖、T+1 和无执行价分别记录拒绝。
5. 买入只允许 board lot；卖出允许一次性清理零股。现金不足按 SSOT 的离散 lot 同比缩放和动态余量
   算法处理；每次候选增配必须用场景执行价、最低佣金等完整逐单费用重算，现金始终非负。
6. 不复权价格成交和估值；研究调整价、Qlib factor 和 benchmark 点位不得进入账户账本。
7. 每日闭合恒等式：`equity=cash+market_value+cash_receivable+stock_receivable_value`；累计费用与 trades
   逐笔求和一致。

必须增加一个三证券五 session golden fixture：A 正常换仓、B 涨停买入失败、C 全日停牌并跨现金分红；
逐日手算现金、股数、可卖量、NAV、费用、应收和拒绝。目标卖出超过 sellable 时先卖可卖部分，对
剩余量记 T+1 residual，不能整单拒绝。另覆盖 blocked sell 不能为 buy 提供现金、输入
顺序稳定、多个 lot 余量分配并列、零目标清仓、持仓无 bar 无停牌失败和成本 period 切换。

open execution state 只能读取当日 open、盘前已知 suspension 和 `PriceLimit1dSchema`；不得读取当日
close/high/low/全天 volume。`has_price_limit=false` 是有证据的合法无限制日，不等于 limit 行缺失。

## 6. E4E：指标、基准与三档压力

实现 `summarize_a_share_backtest` 和一个薄的 scenario 编排纯函数；不实现 `run_m3.py`。指标至少包含：

- 总收益、年化收益、最大回撤；
- 成本后 `H00300.CSI` 超额收益；
- gross/one-way turnover；
- 总费用、滑点、印花税、过户费、佣金；
- 拒绝率、未成交目标名义金额、平均现金比例；
- 公司行动异常数和无法执行日数。

另报 target/realized 的 gross 与 one-way turnover、终止时未完成退出市值、估算退出成本和
`relative_wealth`。`test_turnover` 固定为 realized one-way，`net_excess_return` 固定为简单收益差。

基准只按测试段首尾点位计算，不读训练标签。0.5×/1×/2× 三个场景使用完全相同的 targets 和市场事实；
输入 digest 必须一致，只有成本参数 hash 可不同。若低成本场景净值反而系统性低于高成本场景，测试应
暴露而不是调换标签。

构造 `BacktestWindow`：每个 fold×horizon 独立初始现金；只用 test signal dates；首日为首目标执行日，
终值为最后 test 信号下一 SH session 的收盘；不强平。基准使用相同首日 open 与终值 close，重叠 fold
不得复合。压力场景允许因现金约束产生不同 fills，不能强制复用 1× 成交。

## 7. 独立初验 Agent

初验 Agent 不修改代码，逐包映射证据，并至少追加以下未公开变体：

- 停牌持仓在当日 bar 集合中不存在但 NAV 不变为零；
- record-date 100 股，ex-date 前已卖出，仍收到权益；
- blocked sell + 两个并列余量买单，结果不依赖输入顺序；
- 两个目标缺口和不同最低佣金订单在粗略名义金额缩放下会透支，但离散 breakpoint + 逐 lot 重算不透支；
- 税率切换日处于周末附近，按交易日期而非自然日循环误选 period；
- 同一 target slice 遗漏旧持仓，必须生成 0 目标卖出而非继续持有；
- 空预测/低覆盖不能发布 ACTIVE target，更不能触发全清仓；
- 已结算 100 股、未结算 100 股的清仓只成交 100，另 100 记 T+1 residual；
- 最后周五信号在周一执行并以周一收盘和同窗口 benchmark 终值；
- scenario 仅改变可缩放成本，法定税费逐笔不变。

报告每个问题的 P0/P1/P2、文件行号、最小复现、根因、通用规则和通过条件。mock/golden fixture 通过
不能写成真实 G7 通过；真实 G1 release、公司行动覆盖审计和完整测试折仍是终验前置。
