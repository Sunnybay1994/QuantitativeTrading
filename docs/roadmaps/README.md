# 路线图索引与治理规则

本目录保存需要跨多次任务持续维护的工作流路线图。项目级里程碑、实施顺序和 Gate 验收标准仍只由
[`项目实施路线图.md`](../../项目实施路线图.md) 定义；本目录中的文件不得自行宣布项目级 Gate 完成。

## 文档层级

1. `项目实施路线图.md`：全项目里程碑、依赖顺序和验收状态的唯一事实来源。
2. `docs/roadmaps/<工作流>.md`：对应任务的范围、非目标、分支/worktree、依赖、交付队列和恢复入口。
3. `docs/agent/**`：单个任务书、交付、诊断和验收证据，不承担长期总体规划。
4. `docs/runbooks/**`：可重复执行的操作步骤，不承担项目状态。

既有 [`M3_M4实施总规划.md`](../M3_M4实施总规划.md) 已被多份证据文档引用，暂作为历史路径例外保留；
后续工作流总路线图应链接它，不复制或静默搬迁它。

## 每份任务路线图的固定内容

- 目标、范围和明确非目标；
- 当前 branch、worktree 和唯一 owner；
- 生产代码、测试、配置和文档写入白名单；
- 上游依赖、阻塞条件和共享 SSOT 锁；
- 最近安全提交点、验证证据和未验证事项；
- 基础设施债与性能 backlog：owner、影响、延期理由、触发修复条件、通过标准和临时处置；
- 下一交付队列、合流条件和分支退出条件。

路线图只记录可复现事实和待办，不复制易漂移的完整 Schema、配置数值、长测试日志或项目级 Gate 状态。

## 写入所有权

- 本索引由项目结构统筹任务单写；业务任务通过跨任务消息提交索引增量。
- 每份工作流路线图只由表中唯一维护者写。
- 根 README、根项目路线图、`docs/README.md`、`CODEX_HANDOFF.md`、
  `用户待批示与参与事项.md` 及本 `docs/roadmaps/README.md` 由项目结构统筹任务协调写入；
  `docs/research/README.md`、`docs/data/README.md`、`docs/gui/README.md` 由对应 namespace owner 维护。
- 任何任务修改共享 SSOT、移动目录或创建/合并/删除分支前，先向项目结构统筹任务登记。
