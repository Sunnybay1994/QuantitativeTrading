## 7. 验收边界

- 普通开发只运行任务直接相关的定向 pytest、Ruff、mypy 和必要冷导入；不机械重复全量测试。
- M3 长链以同一进程的自然终态、completion、receipt、原输入零漂移和 owned executable 精确清理为准。
- M4 Windows track 必须与 Linux `PAPER_REAL_TIME` 身份和 Gate 完全隔离；Windows 结果不得获得 Linux formal
  Gate eligibility。
- 所有测试和运行进程遵守资源隔离：M3 使用 CPU 0–7；M4 使用 CPU 8–11，均为 BelowNormal。
- S2 与 M4 的定向测试串行复用 CPU 8–11/BelowNormal；源码实现可在文件互斥前提下并行。

## 9. 可控基础设施债与性能门禁

当前以尽快形成可运行、可验证的业务闭环为主。以下债务允许延期，但必须维持临时边界；安全、PIT、
fail-closed、统一市场事件回放、OMS/风控/对账和人工准入不在可延期范围。

| 编号 | Owner | 影响 | 延期理由 | 触发条件 | 通过标准 | 临时处置 |
|---|---|---|---|---|---|---|
| DEBT-EXEC-REPORT-001 | 框架架构治理 | 现有 `execution.soak -> reporting -> execution` 循环增加冷导入、演进和测试顺序风险 | RUN-0W 只补 Windows-soak 业务缺口，当前拆层会扩大高风险共享改动 | RUN-0W 合流后、任何新 execution/reporting 跨层接口前，最晚在正式 runner 打包前 | 依赖图无环；reporting 只消费稳定 DTO/窄协议；cold import 与现有报告行为等价测试通过 | RUN-0W 禁止新增 execution→reporting import，不把报告逻辑塞入 runtime/soak |
| PERF-001 | M4 PAPER runtime | 未量化日运行延迟、抖动、背压、故障恢复、CPU 和内存，可能影响 09:35 调度与同机其他工作 | 尚无完整 D2 runner、真实候选/opening facts，当前优化缺少可信 workload | 在注册 28 日 soak 前；若开发测试已出现超时、积压或资源争用则提前触发 | 先形成可复现 profiling/基线产物，再冻结 p50/p95/p99 延迟、抖动、队列/背压、恢复时间、峰值 CPU/内存阈值；在受控资源上连续通过且不改变交易合同 | Python 路径保持简单；进程 BelowNormal、受控 affinity；不靠提高并行度掩盖阻塞，不提前引入 Rust |

Rust 只可在 PERF-001 profiling 证明存在稳定热点、相关合同已冻结后另立候选任务。候选必须有窄 FFI/进程边界、
