## 5. 因子库与策略库的最小维护模型

### 5.1 因子定义

每个稳定因子应有一个版本化 `factor_spec` 概念，至少记录：

- factor id/version、经济机制、方向；
- 输入字段和数据契约；
- PIT 延迟、信号频率、适用宇宙；
- 公式/实现哈希、缺失/异常值规则；
- 推荐控制变量、容量与成本敏感性；
- 状态：`IDEA / EXPLORATORY / RESEARCH_ONLY / REJECTED / RETIRED`。

当前不急于新增通用注册框架；先用代码常量、假设卡和不可变 run 证明实际需求，避免过早抽象。

### 5.2 因子实现边界

- `quant.factors`：只接受标准 DataFrame，纯函数计算，不读磁盘、不下载数据、不下单；
- `quant.research`：组织 snapshot、PIT、标签、walk-forward、成本压力和发布；
- `quant.strategies`：未来把已冻结因子转换为 `target_weight`；
- `quant.backtest`：统一市场规则和账户，不接受研究 runner 自报成交；
- `quant.execution`：只消费人工准入后的不可变策略产物。

### 5.3 策略定义

一个可维护策略至少绑定：

- 因子版本和组合规则；
- `as_of`、最早成交时点、调仓频率；
- 股票池和风险/容量约束；
- `target_weight` 归一化和无信号处理；
- 成本、市场规则和 benchmark；
- forward、暂停和退役条件。

### Wave B：现有 bar + daily_basic 的低成本证伪

按顺序串行实现，避免同时制造多个大型 runner：

1. **Amihud 非流动性**：低自由度月频聚合；
2. **自由流通换手水平/异常**：水平和相对自身历史异常分开；
3. **Downside beta vs 510300**：与低波和市场 beta 做冗余检验；
4. 只在前三项证据不足或互补时，再评估 overnight gap、ATR20、IMXD20、RESI20、VSUMD20。

前两项已完成真实不可变运行：Amihud、自由流通换手水平和 12 个月异常换手共三个候选均为
`REJECTED`。共同的关键反例是 2026 年 2 月只有 14 个开市日，低于预注册的 15 个有效日；逐信号日
coverage 因而归零。Amihud 还同时未通过 test 方向/折数和 `<0.80` 冗余门禁。原始 run 保留，禁止观察
结果后原地修改阈值重跑。

第三项 downside beta 已在独立短生命周期 worktree 中完成预注册、实现与一次真实不可变运行：精确 benchmark 为
`510300.SH`，60 个连续 session 收益、至少 15 个 benchmark 下跌观测，防御型预注册方向 `-1`；同时
以 total market beta、60-session realized volatility 和首批经典价量因子做冗余控制。该方向是低 beta/BAB
风格的可证伪延伸，不冒充经典 downside-risk 正风险溢价。coverage、方向、严格 `<0.80` 冗余和实际
target 日期与因子无关预注册调仓日的逐 fold 对账均 fail closed。真实 run `b7d022c3…c50c7a` 的 coverage、
31 个预注册调仓日对账和冗余门禁通过，但平均 test RankIC 0.006225、仅 1/3 test folds 为正、validation
方向不全为 `-1`，且 2 倍成本后链式收益 -25.7147%，因此诚实落为 `REJECTED`，不启动 PAPER。

第一批统一否证门槛：

- close 可知、最早 next-open；
- 横截面至少 100，日期中位覆盖至少 80%；
- 独立 test 的方向化 RankIC 均值至少 0.01，至少 2/3 folds 同号；
- 与预注册 controls 的中位绝对 RankCorr 小于 0.80，或未来冻结的 residual ΔRankIC 至少 0.005；
- 2 倍成本后为正；
- 不得因指标通过自动超过 `RESEARCH_ONLY`。

这些数值是本项目初筛默认值，不是论文共识；每次变更必须先更新假设卡。

### 9.1 Wave B 首个可重现性能基线

这不是“运行前基线”；它来自本轮两项顺序真实 run 的实际进程与文件时间证据。两次都使用 CPU8—11
affinity、BelowNormal 和最多 2 个数值线程，且没有第二个研究 Python 实例。

| run | 输入规模 | 面板 | wall-time proxy | CPU time | 峰值 RSS | 结论 |
|---|---:|---:|---:|---:|---:|---|
| Amihud `25c747ae…329c` | bar 17,766,134 + daily-basic 16,949,896 行 | 60,581 | 约 126 秒 | 60.84 秒 | 未捕获 | `REJECTED` |
| 换手 `2331907e…c1d4` | 同上 | 60,581 | 约 113 秒 | 60.72 秒 | 未捕获 | `REJECTED` |
| 下行 beta `b7d022c3…c50c7a` | stock 17,766,134 + fund 1,399,311 行 | 1,230,269 | 80.485 秒（单调） | `>=28.28` 秒 | `>=1,784.5 MiB` | `REJECTED` |

前两项 `wall-time proxy` 取 stdout 日志创建到最后写入的时间，不是单调计时器；下行 beta 使用单调计时器，
但 CPU 和 `PeakWorkingSet64` 来自退出前的外部采样，未覆盖最后约 20 秒，因此只记下界。三项都没有把
snapshot verify、Parquet query、因子计算、walk-forward 和发布分段计时，也没有可靠进程 I/O bytes，不能
据此宣称 I/O、CPU 或某个算法已经成为瓶颈。下一次性能任务先补同一 collector 的峰值 RSS、读取字节与阶段
耗时，再按证据选择优化；本轮不为补指标而重跑已经发布的研究。
