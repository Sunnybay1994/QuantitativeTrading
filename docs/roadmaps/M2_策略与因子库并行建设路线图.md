## 5. 因子库与策略库的最小维护模型

### 5.1 因子定义

每个稳定因子应有一个版本化 `factor_spec` 概念，至少记录：

- factor id/version、经济机制、方向；
- 输入字段和数据契约；
- PIT 延迟、信号频率、适用宇宙；
- 公式/实现哈希、缺失/异常值规则；
- 推荐控制变量、容量与成本敏感性；
- 状态：`IDEA / EXPLORATORY / RESEARCH_ONLY / REJECTED / RETIRED`。

当前不急于新增通用注册框架；先用代码常量、假设卡和不可变 run 证明实际需求，避免过早抽象。

### 5.2 因子实现边界

- `quant.factors`：只接受标准 DataFrame，纯函数计算，不读磁盘、不下载数据、不下单；
- `quant.research`：组织 snapshot、PIT、标签、walk-forward、成本压力和发布；
- `quant.strategies`：未来把已冻结因子转换为 `target_weight`；
- `quant.backtest`：统一市场规则和账户，不接受研究 runner 自报成交；
- `quant.execution`：只消费人工准入后的不可变策略产物。

### 5.3 策略定义

一个可维护策略至少绑定：

- 因子版本和组合规则；
- `as_of`、最早成交时点、调仓频率；
- 股票池和风险/容量约束；
- `target_weight` 归一化和无信号处理；
- 成本、市场规则和 benchmark；
- forward、暂停和退役条件。

## 7. 并行研究队列

### Wave A：采集期间完成

1. 收口 PIT eligibility：`VALID / MISSING_CHAIN / NON_INDUSTRIAL / INVALID_DENOMINATOR / QUARANTINED`；
2. 覆盖率按冻结候选池闭合，任一缺失不能从分母消失；
3. 月频 next-rebalance portfolio、Newey-West lag=1 和尾月排除；
4. 落盘机构基础设施与拥挤时代方法论；
5. 冻结第一批现有数据候选，不启动真实大回测。

### Wave B：现有 bar + daily_basic 的低成本证伪

按顺序串行实现，避免同时制造多个大型 runner：

1. **Amihud 非流动性**：低自由度月频聚合；
2. **自由流通换手水平/异常**：水平和相对自身历史异常分开；
3. **Downside beta vs 510300**：与低波和市场 beta 做冗余检验；
4. 只在前三项证据不足或互补时，再评估 overnight gap、ATR20、IMXD20、RESI20、VSUMD20。

第一批统一否证门槛：

- close 可知、最早 next-open；
- 横截面至少 100，日期中位覆盖至少 80%；
- 独立 test 的方向化 RankIC 均值至少 0.01，至少 2/3 folds 同号；
- 与预注册 controls 的中位绝对 RankCorr 小于 0.80，或未来冻结的 residual ΔRankIC 至少 0.005；
- 2 倍成本后为正；
- 不得因指标通过自动超过 `RESEARCH_ONLY`。

这些数值是本项目初筛默认值，不是论文共识；每次变更必须先更新假设卡。

### Wave C：财务 snapshot READY 后

1. 真实运行四个 PIT 质量因子；
2. 检查 coverage/quarantine、fold 稳定性、冗余和 0.5/1/2 成本；
3. 候选扩展到质量变化、现金流确认、资产增长和公告后漂移；
4. `fina_indicator` 只作交叉核验，不替代 canonical 报表公式；
5. 保留全部失败 run 和 trial count。

### Wave D：组合与前向

1. 按机制族内收缩，避免挑历史最优；
2. 用 leave-one-family-out 判断组合增量；
3. 冻结一次性 holdout/forward；
4. 所有预测在收益实现前写入数据/代码/参数/权重身份；
5. 没有 post-freeze evidence 时保持 `RESEARCH_ONLY`。
