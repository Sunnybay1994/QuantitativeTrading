# 项目结构与合流治理路线图

## 1. 目标与非目标

本路线图是项目结构统筹任务的长期计划，负责：

- 目录、文档、代码包和配置入口的边界；
- branch、worktree、共享文件锁、合流顺序和归档；
- 各任务路线图、文档命名空间和索引一致性；
- 发现结构债并冻结最小治理任务，避免并行开发形成重复框架。

本任务不实现策略、数据采集、回测、交易或 GUI 业务功能，不判断策略有效性，也不替代
[`项目实施路线图.md`](../../项目实施路线图.md) 的 Gate 状态。

| 文档范围 | 唯一写入者 |
| --- | --- |

跨 session 的易变运行摘要收敛到 `docs/CODEX_HANDOFF.md` 顶部。各 session 路线图应记录当前安全 SHA、阶段、
资源预算和下一队列，但不记录频繁变化的 PID、分钟级计数或完整日志；README 只给入口和稳定阶段说明，
方法论与契约文档不记录进程级状态。

## 6. 分支与 worktree 生命周期

- 只有活跃 owner、待合流成果或被运行身份绑定的任务可保留 worktree。
- clean 且无进程的闲置 worktree 优先移除；分支可暂留供语义对账。
- 删除含独有或审计价值提交的分支前，先建立指向精确提交的 `archive/*` annotated tag。
- 已完全合入、无 worktree 的冗余分支使用安全删除；禁止未经核对的强制删除。
- detached worktree 必须记录精确 HEAD、活跃输入和退出条件；不得清理其未跟踪正式配置。
- 创建新 worktree 前登记 branch、base、绝对路径、owner 和文件白名单。

统筹任务更新本文件与索引，并向受影响任务广播锁、合流顺序或还债条件。
