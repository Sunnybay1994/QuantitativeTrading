# 任务书规范 —— 怎样给执行 Agent 写任务，才能让它按本意完成

> 来源：[2026-10-09 清单](优化工作清单_20261009.md)的复盘（[审查](项目审查_20261026.md) §1）。那份清单 21 项全部在 2026-10-09 一天内"实现"并于 10-13 自行宣布"总验收闭合"，但接到生产后 8 项从未真正运行、3 项结果名实不符。问题不在执行 Agent 能力，在任务书把"代码写完 + 单测通过"当成了完成。本文规定今后所有任务书的写法，与 [AGENTS.md](../AGENTS.md) 并用。

## 1. 上一轮的失败模式与对应规则

| 失败模式（实例） | 根因 | 规则 |
|---|---|---|
| 情报周扫描脚本有解析错误，三个周日全失败，验收却写"通过" | 验收证据是手工 `--dry-run` 和一次手工运行，不是计划任务的真实运行 | **R1 生产回执**：凡是接入调度的任务，完成证据必须是 `Get-ScheduledTaskInfo` 最近两次 `LastTaskResult=0` 加对应日期的产物；手工运行不算 |
| gp_hints 每个调度片调一次 LLM、307 次全部回退、账本 usd=0，验收写"LLM 花费可对账" | 验收看了"有账本文件"，没看账本内容是否合理 | **R2 看内容不看存在**：验收必须抽样打开产物并写明看到的关键数字；"文件存在"不是证据 |
| `q10_plus_admitted` +0.02pp 被记为"新策略级假设完成" | 任务写的是"注册表出现该方法三档结果"，机器满足了字面 | **R3 验收写结果而非动作**：完成标志必须是业务量（如"vs Q10 2× 超额差 ≥ 1pp 或明确记 RESEARCH_ONLY 并写一句为什么"），不是"文件出现" |
| 四周清单一天做完 | 清单按"周"排，但没有任何日历门槛；Agent 合理地一次做完 | **R4 日历门槛显式化**：需要时间积累的验收（两个周日、一份真实月报、三次调仓）写成"不早于 <日期>"，并单列"等待中"状态 |
| 注册表被 pytest 临时目录污染 48 行 | 没有"生产产物不可被测试写入"的约束，测试与生产共用路径 | **R5 隔离声明**：任务书里凡涉及写入 `artifacts/registry`、`configs/factors/library`、`artifacts/paper` 的改动，必须同时写"测试如何隔离"，并在验收中检查生产路径无仓库外行 |
| 11 天零提交，根目录 9 个 `_tmp_*.py` | "每天提交"写在约束里，没有机械执行点 | **R6 提交是任务的一部分**：每个任务的最后一条验收永远是"已提交，commit id 写入任务表"；临时脚本放 `/tmp`，不进仓库 |
| 范围漂移（港美分钟采集、通信层想法）未经授权进入工作区 | 任务书没有"非目标"栏，Agent 把相邻想法顺手做了 | **R7 非目标栏**：每份任务书必须有"明确不做"，相邻但未列出的工作一律先写进路线图 §5 阻塞栏等用户裁定 |
| 全量测试 15 小时、验收引用它"通过" | 以测试数量代替可运行性 | **R8 快测试门**：验收只认 `pytest -m "not slow"` ≤10 分钟的结果；慢测试单独计划 |
| 自我宣布"总验收闭合"并写进路线图 | 执行者兼验收者 | **R9 验收由机器重做**：`python -m quant doctor`（待建，见工作清单 F1）每日重跑所有验收检查；路线图只能引用 doctor 输出，不能手写"闭合" |

## 2. 任务书模板（每项必填）

```
### <编号> · <一句话标题>
- 目标量：<这件事做完后哪个业务数字会变：订单/净值/注册表行/准入数/花费…>
- 现状：<路径 + 当前数值>
- 改动：<模块/函数/配置到文件名；不写实现细节>
- 产物：<精确路径；机器生成；不手写 md>
- 隔离：<测试如何不触碰生产路径；无写入则写"无"> 
- 验收（全部满足才算完成）：
  1. <业务量门槛，含数字>
  2. <生产回执：计划任务名 + 连续两次 result=0 + 日期；或"非调度任务"> 
  3. <抽样核对：打开 <产物> 看到 <字段> 约为 <值>>
  4. 不早于 <日期>（无则写"无日历门槛"）
  5. 已提交 <commit>
- 明确不做：<相邻但排除的事>
- 时间盒：<小时/天>；超时处理：<停下写阻塞栏 / 降级方案>
```

## 3. 执行 Agent 的工作循环（写进每份任务书开头）

1. 读任务书 → 读 `python -m quant doctor` 输出 → 读路线图 §5 阻塞栏。
2. 一次只开一个任务；开始前把任务编号写进 `artifacts/worklog/<date>.md`（机器时间戳）。
3. 做完 → 自己按验收 1–5 逐条核对并把核对命令与输出贴进 worklog → 提交。
4. 验收中任何一条不满足：状态写 `blocked:<原因>` 或 `waiting:<日期>`，**不得**写"通过"。
5. 每日结束：`quant doctor` 必须为绿或列出红项原因；红项不清不开新任务。
6. 发现任务书之外值得做的事：写进路线图 §5 一句话，继续当前任务。

## 4. 给写任务书的人的检查表

- 每项都能回答"这件事做完，回测/数据/订单/模拟净值哪一个会变"？答不出就删。
- 验收里有没有至少一条是**机器在未来某天**才能产出的证据？没有就说明这项不需要调度，或者验收写假了。
- 有没有把"做 A 的工具"误写成"A 完成"？（例：写了退回规则 toml ≠ 退回规则在跑）
- 任务数 ≤ 8 项/两周。上一轮 21 项是失控的直接原因之一。
- 每项都写了"明确不做"？
- 没有任何一项要求改 §1.2 门槛、覆盖 raw、启动真金。
