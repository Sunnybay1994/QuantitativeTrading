# 代码审查与验收清单

Agent 输出既不默认错误，也不默认正确；它是高产、快速但可能过度自信的候选改动。根据任务风险裁剪本
清单，关键改动应在 IDE 或等价代码导航环境中检查完整 diff、引用关系和运行证据。

## 需求与语义

- [ ] 改动解决了真实目标，而不只是字面任务。
- [ ] 用户可观察行为、成功标准和明确非目标均有对应证据。
- [ ] 关键假设已验证；需求、文档、测试、代码和真实依赖之间的冲突已解决或报告。
- [ ] 没有未经授权地改变业务语义、公共接口、默认值或兼容行为。
- [ ] 关键边界、错误路径、时间/状态变化和失败语义已考虑。

## 复杂度与范围

- [ ] 每个变更文件和主要变更行都能追溯到任务。
- [ ] 没有无关重构、格式化、依赖升级或相邻清理。
- [ ] 没有为假想未来需求增加抽象、配置、接口层或框架。
- [ ] 新增代码的当前价值高于其认知和维护成本。
- [ ] 不存在更小、更直接且同样正确的实现。

## 正确性与验证

- [ ] 测试覆盖行为和契约，而非只锁定当前实现细节。
- [ ] 缺陷修复有可复现的回归测试；边界、集成和错误路径按风险覆盖。
- [ ] 优化有测量结果，并与朴素基准、历史结果或不变量保持一致。
- [ ] 验证命令确实运行；通过、失败、阻塞、超时和未运行被准确区分。
- [ ] 真实环境、真实数据或外部依赖未验证时，没有声称已验证。

## 清理与维护

- [ ] 本次产生的临时代码、死代码、未使用导入、重复路径和无用依赖已清理。
- [ ] 没有留下新旧实现并存或互相矛盾的说明。
- [ ] 必要注释、示例、配置和文档已同步，且没有建立重复事实来源。
- [ ] 后续维护者能解释设计意图、失败模式和回滚方式。

## 安全与可逆性

- [ ] 数据、权限、凭据、迁移、生产、依赖和外部状态风险已识别。
- [ ] 所需授权明确；沙箱、dry run、备份、小批次和人工开关按风险使用。
- [ ] 回滚或故障处置路径已验证到适当程度。
- [ ] 日志、报告、代码和产物中没有敏感信息。

## 多 Agent 与证据独立性

- [ ] 多 Agent 确有解耦收益，输入、输出、文件范围和验收标准清晰。
- [ ] 执行者与独立审查者角色分离；没有同时写入同一核心文件。
- [ ] 审查者增加了执行者未使用的反例，而非只复述交付报告。
- [ ] 主 Agent 检查了冲突、跨模块不变量，并运行整合后的最终验证。

## 人工最终判断

- [ ] 人类负责人查看了与风险相称的 diff 和证据，而不只依赖 Agent 摘要。
- [ ] 方案解决的问题值得引入这些长期复杂度。
- [ ] 高风险、不可逆或产品方向决定由有权限的人明确接受。
- [ ] 接受、返工、阻塞或放弃的结论和剩余风险已记录。
