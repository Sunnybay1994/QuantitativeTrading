# 通用任务交接与报告模板

小型低风险任务可裁剪字段；任务越大、越模糊或越不可逆，模板应越完整。项目专属事实只链接到其 SSOT，
不要复制进本模板形成第二来源。

## 任务书

```markdown
# <任务名称>

## 目标与价值
- 用户可观察结果：
- 要解决的问题 / 价值：
- 明确非目标：

## 现状与权威上下文
- 当前行为：
- 相关代码、测试、配置和文档：
- 适用 SSOT / 项目规则：

## 成功标准
- [ ] 行为或契约标准：
- [ ] 回归、兼容性、性能、安全或 UX 标准：
- [ ] 范围标准：

## 事实、假设与未决问题
- 已确认事实及证据：
- 可自行决定的低影响假设：
- 必须确认的高影响问题：
- 方案权衡 / 更简单替代方案：

## 范围与约束
- 可写文件白名单：
- 只读或禁止路径：
- 允许的接口、依赖、配置或数据变更：
- 禁止事项：

## 轻量计划
1. <步骤> -> 验证：<检查>
2. <步骤> -> 验证：<检查>
3. <步骤> -> 验证：<检查>

## 验证与反例
- 聚焦测试 / 命令：
- 完整 Gate：
- 朴素基准或历史对照（如适用）：
- 至少一个关键反例：
- 真实依赖检查及授权（如适用）：

## 安全、停止和回滚
- 外部状态 / 不可逆风险：
- dry run、备份、小批次或人工开关：
- 停止并升级条件：
- 回滚 / 故障处置：

## 交付要求
- 交付报告位置或格式：
- 需要独立审查：是 / 否，原因：
```

## 执行 Agent 交付报告

```markdown
# <任务> — 交付报告

## 结果
- 状态：已交付 / 阻塞 / 需要重新冻结任务
- 修改文件及目的：
- 明确未修改的范围：

## 设计与合同证据
- 成功标准 -> 实现 / 测试证据：
- 关键假设确认或推翻：
- 反例结果：
- 与原计划不同之处及原因：

## 验证
| 命令或检查 | 结果（通过/失败/阻塞/超时/未运行） | 证据或产物 |
| --- | --- | --- |
| <检查> | <结果> | <摘要/位置> |

## 清理与范围审查
- 临时代码、本次产生的冗余和重复路径：
- 文档 / 示例 / 配置同步：
- 范围外改动：无 / <说明>：

## 风险与交接
- 已知限制和未验证事项：
- 安全 / 回滚说明：
- 需要审查者或负责人决定的问题：
```

## 独立审查报告

```markdown
# <任务> — 独立审查报告

## 独立性与范围
- 未参与实现，使用独立上下文：是 / 否
- 检查的代码、diff、测试和产物：

## 标准—证据—结论
- <成功标准> -> <独立证据> -> 通过 / 不通过 / 阻塞
- 新增的对抗性反例 -> 结果：

## 问题
- 现象：
- 根因：
- 违反的规则或不变量：
- 最小复现：
- 必须新增的测试：
- 通过条件：

## 结论
- 进入最终验收 / 返回返工 / 阻塞
```

## 主 Agent / 人工最终验收

```markdown
# <任务> — 最终验收

- 任务书、交付报告和独立审查：
- SSOT、架构、范围和安全复核：
- 最终 Gate 及实际结果：
- 人工决定（高风险时必填）：
- 状态：接受 / 返工 / 阻塞 / 放弃
- 剩余风险和下一步：
```
